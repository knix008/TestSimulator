# 터미널과 로그

편집기 아래의 **하단 패널**에는 세 개의 탭 — **터미널 · 로그 · 문제점** — 이 있습니다. 이 장은 명령을 실행하는 터미널, 프롬프트 모양을 꾸미는 프롬프트 테마, 상태 메시지 기록인 로그를 설명합니다. 문제점 탭은 [정렬과 검사](12-정렬과-검사.md) 를 보세요.

![터미널](images/terminal.png)
*그림: 하단 패널의 터미널 — 셸 탭, 색 프롬프트, 명령 출력*

## 하단 패널 열고 닫기

| 방법 | 동작 |
|---|---|
| Ctrl+\` (Markdown 문서 밖에서) | 터미널 탭 열기 / 닫기 |
| Ctrl+Shift+\` | 바로 새 터미널 열기 |
| 도구 모음의 터미널 · 로그 · 문제점 버튼 | 그 탭으로 패널 열기 |
| 보기 › 터미널 / 로그 / 문제점 / 새 터미널 | 위와 같음 |
| 시작 화면의 터미널 · 로그 카드 | 위와 같음 |
| 패널 머리 오른쪽의 × (패널 닫기) | 패널 닫기 |

- 패널은 하나이고 세 탭은 늘 함께 있습니다. 다른 탭의 버튼을 누르면 그 탭이 앞으로 오고, **지금 앞에 보이는 탭의 버튼을 한 번 더 누르면 패널이 닫힙니다**.
- 패널은 폴더 트리 아래까지 포함해 **창 왼쪽 끝에서 오른쪽 끝까지** 펼쳐집니다.
- 패널 위쪽 경계선을 끌면 높이가 바뀝니다(기억됨).
- 터미널 탭을 처음 열 때 터미널이 하나도 없으면 하나가 자동으로 시작됩니다.
- Markdown 문서에서는 Ctrl+\` 가 인라인 코드 서식이므로 도구 모음 버튼이나 보기 메뉴를 쓰세요.

## 터미널과 셸

패널 머리에서 터미널 탭 오른쪽에 열려 있는 터미널들이 작은 탭으로 늘어섭니다. 각 탭에는 셸 이름과 번호가 붙고, 마우스를 올리면 시작 디렉터리가 보입니다.

- **+ (새 터미널)**: 기본 셸로 새 터미널을 엽니다.
- **▾ (셸을 골라 새 터미널)**: 이 컴퓨터에 설치된 셸 목록에서 골라 엽니다.
  - Windows: Command Prompt · Windows PowerShell · PowerShell(7) · Git Bash · MSYS2 · Cygwin 중 설치된 것
  - macOS · Linux: 기본 셸 · bash · sh 등
- 터미널 탭의 **×** 또는 **가운데 클릭**으로 그 터미널을 닫습니다(셸이 종료됨).
- 터미널이 하나도 없으면 "터미널이 없습니다. + 를 눌러 여세요." 와 **새 터미널** 버튼이 나옵니다.
- 셸이 오류로 끝나도 탭은 사라지지 않고 다음 명령 때 셸이 다시 시작됩니다.

새 터미널은 설정 › 터미널의 **기본 셸**로, **시작 디렉터리**에서 시작합니다. 시작 디렉터리를 비워 두면 폴더 트리에 열린 폴더, 그것도 없으면 현재 문서의 폴더에서 시작합니다.

## 명령 입력

출력 맨 아래의 **프롬프트 바로 뒤**에 명령을 입력하고 Enter 를 누릅니다. 입력한 줄은 그때의 프롬프트와 함께 그 자리에 남고 결과가 이어집니다.

| 키 | 동작 |
|---|---|
| Enter | 명령 실행 |
| ↑ / ↓ | 이전 / 다음 명령 기록 |
| Tab | 자동 완성 |
| Ctrl+L, 또는 `clear` 명령 | 화면 지우기 |
| Ctrl+C (입력 칸이 비어 있을 때) | 실행 중인 명령 중단 |
| Esc | 입력 중인 줄 지우기 |

- 명령이 실행되는 동안에는 프롬프트가 사라지고, 그때 입력한 줄은 **실행 중인 프로그램의 입력**으로 전달됩니다(예: "계속할까요? (y/n)" 에 답하기).
- 여러 줄을 붙여넣으면 완성된 줄마다 차례로 실행되고, 마지막 미완성 줄은 입력 칸에 남습니다.
- 명령이 실패하거나 문법이 틀려도 셸은 종료되지 않고 오류 메시지가 그대로 나옵니다.

**Tab 자동 완성**: 첫 낱말은 셸 내장 명령과 PATH 의 실행 파일에서, 그 밖의 낱말은 경로(`..`, `~`, 절대 경로, 따옴표 포함)에서 찾습니다. 후보가 하나면 바로 채우고(파일 · 명령 뒤에는 공백, 디렉터리 뒤에는 구분자), 여럿이면 공통 부분까지 채운 뒤 **한 번 더 Tab** 을 누르면 후보 목록을 보여 줍니다.

## 터미널의 동작 방식

- 셸은 의사 터미널(PTY) 없이 파이프로 연결되어 **줄 단위로** 동작합니다. vim, top 처럼 화면 전체를 직접 그리는 프로그램은 맞지 않습니다.
- 진행 표시줄처럼 CR 로 같은 줄을 다시 그리는 출력은 실제 터미널처럼 그 줄을 덮어씁니다.
- 셸은 늘 UTF-8 로케일로 시작하므로 한글 파일 이름이 깨지지 않습니다. 명령 프롬프트 · PowerShell 에서 코드 페이지(CP949) 출력과 UTF-8 출력이 섞여 있어도 올바르게 읽습니다.
- `ls -al` 의 세 번째 · 네 번째 열(예: `shkwon 197121`)은 소유자와 **그룹**입니다. Windows 의 그룹은 이름이 없어 Git Bash · Cygwin 의 `ls` 가 숫자 ID 를 그대로 보여 주는 것이며 깨진 글자가 아닙니다. 그룹 열을 빼려면 `ls -alG` 를 쓰세요.

## 출력 색

설정 › 터미널의 **출력을 색으로 표시** (기본 켜짐)가 켜져 있으면 다음과 같이 칠해집니다. 끄면 흑백입니다.

- 프로그램이 내는 **ANSI 색**(git · npm · ls --color 등) 그대로
- **error / failed** 로 시작하는 줄은 빨강, **warning** 은 노랑, **ok / done** 은 초록
- **URL** 과 **파일:줄** 참조 강조
- `dir` · `ls -l` · `Get-ChildItem` 같은 목록은 폴더(파랑) · 링크 · 실행 파일(초록) · 압축(빨강) · 그림(보라) · 문서(노랑) · 코드(하늘색)로 이름을 칠하고, 날짜 · 크기 열은 흐리게

파이프로 연결된 프로그램은 보통 스스로 색을 내지 않으므로, 색 옵션이 있는 프로그램에는 켜 달라고 알려 줍니다(git · npm · pytest · cargo · gcc/cmake · .NET 등의 환경 변수, Git Bash 등에서는 `ls` · `grep` · `diff` · `tree` 에 `--color=always`).

## 프롬프트 테마

프롬프트는 **프롬프트 테마**로 그립니다. 설정 › 터미널의 **프롬프트** 부분에서 바꾸며, 터미널 탭에서 패널 머리 오른쪽의 **⚙ (터미널 설정)** 을 누르면 바로 그곳이 열립니다.

![터미널 설정](images/settings-terminal.png)
*그림: 설정 › 터미널 — 기본 셸, 시작 디렉터리, 프롬프트 편집*

- **미리보기**: 깨끗한 저장소 / 변경된 저장소 / 저장소 아님 세 상태로 지금 프롬프트를 보여 줍니다.
- **프리셋** 20종 카드: 누르면 바로 적용됩니다 — 기본 (My Editor), Powerline, Agnoster, Paradox (두 줄), 최소, 단순 텍스트 (색 없음), 버블, Robby Russell, Pure, Star, 슬림, Material, 클래식 (user@host:path$), 레인보우, 오션, 모노, 포레스트, 선셋, 노르드, 개발자.
- **간단 설정**: 표시할 세그먼트(OS · 사용자@호스트 · 셸 · 경로 · git · 실행 시간 · 종료 코드 · 시각), **모양**(파워라인 / 일반 / 다이아몬드(둥근)), **경로 스타일**(전체 경로, 폴더 이름만, 축약, 첫 글자 등), **두 줄**.
- **git 상태색**: 브랜치(git) 블록만 저장소 상태 색으로 칠합니다. 상태마다 색을 직접 고르고 **기본색** 으로 되돌릴 수 있으며, 체크를 끄면 프리셋 고유의 색을 씁니다.
- **고급 편집**: 왼쪽 세그먼트 목록에서 하나를 고르고 오른쪽에서 종류 · 글자색 / 배경색 · 템플릿 · 기호 등을 고칩니다. 블록(줄) 추가 · 삭제, 세그먼트 추가 · 위로 · 아래로 · 삭제, 프롬프트 뒤 공백 여부도 정합니다. 템플릿에는 `.Path`, `.Branch` 같은 변수를 씁니다(각 세그먼트 아래에 쓸 수 있는 변수가 안내됩니다).
- **현재 프롬프트를 저장**: 지금 모양을 이름을 붙여 저장하면 ★ 카드(사용자 정의 프롬프트)로 프리셋 옆에 남습니다. **변경 내용 저장**, **삭제** 도 할 수 있습니다.

세그먼트 종류: 경로 · git · 사용자@호스트 · 셸 · OS · 시각 · 종료 코드 · 실행 시간 · 관리자 · 텍스트.

### Git 상태 색

기본 프롬프트는 📁 현재 디렉터리 ▶ (Git 저장소 안이면) ⎇ 브랜치와 상태 ▶ 입력 순서입니다. 브랜치 블록은 저장소 상태에 따라 칠해집니다.

| 색 | 상태 |
|---|---|
| 초록 | 변경 없음 · 푸시됨 (정상) |
| 빨강 | 수정됨 — add 필요 |
| 노랑 | add 됨 — 커밋 필요 |
| 주황 | 커밋됨 — 푸시 필요 |
| 파랑 | 원격에 새 커밋 — pull 필요 |
| 진홍 | 충돌 — 해결 필요 |

브랜치 이름 뒤에는 해당하는 상태 기호만 붙습니다: `↑` 앞섬 · `↓` 뒤짐 · `+` 스테이지 · `~` 수정 · `?` 추적 안 함 · `!` 충돌. 마우스를 올리면 브랜치 · 업스트림과 각 개수가 나옵니다. Git 상태는 명령이 끝날 때마다 다시 읽고, 큰 저장소에서는 직전 상태로 먼저 그린 뒤 새 상태가 다르면 색을 바꿉니다. 더 빠르게 하려면 저장소에서 `git config core.fsmonitor true`, `git config core.untrackedCache true` 를 켜 두세요.

## 로그

**로그** 탭에는 상태 표시줄에 나왔던 메시지(열림, 저장됨, 오류 등)가 **시각과 함께** 차례로 쌓입니다. 상태 표시줄의 메시지를 놓쳤을 때 여기서 다시 볼 수 있습니다.

![로그](images/log.png)
*그림: 하단 패널의 로그 탭*

- 도구 모음의 **로그** 버튼이나 보기 › 로그로 엽니다.
- 머리의 **로그 지우기** 버튼으로 기록을 비웁니다. 비어 있으면 "로그가 없습니다." 가 나옵니다.
- 로그는 최근 400개까지, 이번 실행 동안만 남고 파일로 저장되지 않습니다.
