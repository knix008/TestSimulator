# 언어 · 인코딩 · 줄 끝

문서마다 세 가지 속성이 있습니다. **언어**는 구문 강조 · 주석 기호 · 자동 완성 · 정렬 · 코드 검사를 정하고, **인코딩**은 글자를 파일의 바이트로 바꾸는 방식, **줄 끝**은 줄을 나누는 문자입니다. 셋 모두 상태 표시줄에 표시되고, 누르면 바로 바꿀 수 있습니다.

## 언어 자동 판별

파일을 열면 **확장자와 파일 이름**으로 언어가 정해집니다(.js → JavaScript, .py → Python, Dockerfile → Dockerfile …). 확장자가 없거나 알 수 없으면 내용의 첫 부분을 보고 짐작하고, 그래도 모르면 일반 텍스트로 엽니다. 새 문서는 설정의 **새 문서 언어**를 따르며, 기본값 "자동" 이면 입력한 내용으로 짐작하다가 저장할 때 붙인 확장자로 다시 판별합니다.

구문 강조 문법은 150가지가 넘는 언어를 지원하며, 각 언어의 문법은 그 언어를 처음 쓸 때 불러옵니다(그래서 처음 여는 언어는 아주 잠깐 늦게 색이 칠해질 수 있습니다).

## 언어 메뉴와 언어 고르기

**언어** 메뉴에서 문서의 언어를 직접 고를 수 있습니다. 고른 언어는 그 문서에만 적용되고 세션에 기억됩니다.

![언어 메뉴](images/menu-language.png)
*그림: 언어 메뉴 — 각 언어 앞에 고유 색과 약칭 아이콘*

- **자동 (확장자로 판별)**: 직접 고른 언어를 지우고 다시 자동 판별로 돌아갑니다.
- **일반 텍스트**: 구문 강조 없이 엽니다.
- 자주 쓰는 25개 언어: JavaScript, TypeScript, JSX, TSX, HTML, CSS, JSON, Markdown, Python, C, C++, C#, Java, Go, Rust, PHP, Ruby, Shell, PowerShell, SQL, XML, YAML, TOML, Dockerfile, diff.
- **언어…**: 모든 언어의 검색 목록을 엽니다.

메뉴의 각 언어 앞에는 그 언어의 고유 색과 약칭(JS · TS · Py · C++ …)으로 된 아이콘이 붙고, 지금 선택된 항목은 체크 표시로 구분됩니다. 자동 판별 중이면 판별된 언어 옆에 "자동" 이라고 표시됩니다.

**언어…** 창(또는 상태 표시줄 언어 메뉴의 언어…)에서는 칸에 글자를 넣으면 이름이나 확장자가 맞는 언어만 남습니다. ↑ ↓ 로 고르고 Enter, 또는 항목을 누릅니다. 각 항목 오른쪽에는 대표 확장자가 보이고 현재 언어에는 체크 표시가 있습니다.

![언어 고르기](images/language-picker.png)
*그림: 언어 고르기 창 — 이름이나 확장자로 걸러짐*

상태 표시줄의 **언어 이름**을 누르면 자동 · 일반 텍스트 · 자주 쓰는 12개 언어 · 언어… 가 든 짧은 메뉴가 나옵니다.

## 인코딩 자동 판별

파일을 열 때 다음 순서로 인코딩을 판별합니다.

1. 파일 앞의 **BOM** (UTF-8 BOM, UTF-16 LE / BE BOM)
2. BOM 없는 **UTF-16** (바이트 사이의 0 무늬로 알아봄)
3. 올바른 **UTF-8** 인지 검사
4. 그것도 아니면 운영체제의 기존 코드 페이지 — 한국어 Windows 는 **한국어 (EUC-KR / CP949)**, 그 밖에는 Western (Windows-1252)

판별된 인코딩은 상태 표시줄에 표시됩니다. 지원하는 인코딩은 11가지입니다.

| 인코딩 | 비고 |
|---|---|
| UTF-8 | 기본값 |
| UTF-8 (BOM) | 파일 앞에 BOM 을 붙여 저장 |
| UTF-16 LE / UTF-16 BE | BOM 을 붙여 저장 |
| 한국어 (EUC-KR / CP949) | |
| 日本語 (Shift_JIS) | |
| 中文 (GB18030) / 中文 (Big5) | |
| Western (Windows-1252) | |
| Latin-1 (ISO-8859-1) | |
| Русский (KOI8-R) | |

## 인코딩 바꾸기와 다시 열기

**인코딩** 메뉴는 두 부분으로 되어 있습니다.

![인코딩 메뉴](images/menu-encoding.png)
*그림: 인코딩 메뉴 — 현재 인코딩, 다시 열기, 줄 끝*

- **현재 인코딩** 목록: 여기서 다른 인코딩을 고르면 **저장할 때** 그 인코딩으로 씁니다. 지금 화면의 글은 바뀌지 않고, 문서는 수정됨(●)으로 표시됩니다. 예를 들어 CP949 파일을 UTF-8 로 바꾸려면 UTF-8 을 고른 뒤 저장하면 됩니다.
- **다음 인코딩으로 다시 열기…**: 파일이 잘못된 인코딩으로 읽혀 글자가 깨져 보일 때 씁니다. 목록에서 고른 인코딩으로 디스크의 파일을 다시 읽습니다. 저장하지 않은 변경이 있으면 "현재 변경 사항이 사라집니다. 계속할까요?" 라고 먼저 묻습니다. 저장한 적 없는 새 문서에서는 꺼져 있습니다.

![다른 인코딩으로 다시 열기](images/encoding-reopen.png)
*그림: 다시 열 인코딩 고르기*

저장할 때 고른 인코딩으로 표현할 수 없는 글자(예: Windows-1252 로 저장하는 한글)가 있으면 **인코딩 경고**가 떠서 "?" 로 바뀐다고 알리고 그래도 저장할지 묻습니다.

상태 표시줄의 **인코딩 이름**을 눌러도 같은 목록과 다시 열기가 나옵니다. 새 문서의 인코딩은 설정 › 일반 › 파일의 **새 문서 인코딩**에서 정합니다.

## 줄 끝

줄 끝은 세 가지입니다.

| 메뉴 이름 | 상태 표시줄 | 문자 | 주로 쓰는 곳 |
|---|---|---|---|
| Windows (CR LF) | CRLF | \r\n | Windows |
| Unix (LF) | LF | \n | Linux · macOS · 대부분의 개발 도구 |
| Macintosh (CR) | CR | \r | 옛 Mac OS |

- 파일을 열면 줄 끝을 감지합니다. 여러 종류가 섞여 있으면 가장 많은 것을 그 파일의 줄 끝으로 봅니다. 편집기 안에서는 모두 같은 줄 바꿈으로 다루고, 저장할 때 문서의 줄 끝으로 씁니다(섞여 있던 줄 끝은 하나로 통일됩니다).
- 바꾸려면 **인코딩** 메뉴 아래쪽의 **줄 끝** 목록이나 상태 표시줄의 **CRLF / LF / CR** 을 누릅니다. 바꾸면 문서가 수정됨으로 표시되고, 저장할 때 적용됩니다.
- **새 문서 줄 끝** (기본 Unix (LF))과 **저장할 때 줄 끝** 은 설정 › 일반 › 파일에서 정합니다. 저장할 때 줄 끝을 "항상 Unix (LF)" 나 "항상 Windows (CR LF)" 로 두면 문서의 줄 끝과 관계없이 그것으로 저장합니다. "파일의 원래 줄 끝 유지" (기본)이면 문서마다 표시된 줄 끝을 씁니다.

> 팁: Git 저장소에서 줄 끝 때문에 파일 전체가 바뀐 것으로 나온다면, 상태 표시줄에서 원래 줄 끝(보통 LF)으로 되돌린 뒤 저장하세요.
