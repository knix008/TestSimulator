# 정렬과 검사

**문서 정렬**은 들여쓰기 · 줄 바꿈 · 공백을 그 언어의 관례대로 고쳐 코드를 보기 좋게 만들고, **코드 검사(Lint)** 는 문법 오류와 의심스러운 코드를 찾아 표시합니다. 두 기능 모두 언어마다 외부 도구를 쓰며, 필요한 도구를 앱 안에서 설치할 수도 있습니다.

## 문서 정렬하기

다음 중 아무것으로나 실행합니다. 지금 편집 중인 문서 **전체**가 정렬됩니다.

- **Shift+Alt+F**
- **편집 › 문서 정렬**
- 도구 모음의 **문서 정렬** 버튼
- 편집 영역 또는 탭의 오른쪽 클릭 메뉴 › 문서 정렬

정렬한 뒤에도 커서는 같은 줄에 머뭅니다. 결과는 상태 표시줄에 "정렬 완료: 도구", "이미 정렬되어 있습니다 (도구)", 실패하면 "정렬 실패 (도구)" 와 이유로 나옵니다. 문서가 비어 있거나, 그 언어의 정렬이 꺼져 있거나, 이미 정렬되어 있으면 버튼과 메뉴가 흐리게 꺼집니다(마우스를 올리면 이유가 나옵니다). 정렬도 Ctrl+Z 로 되돌릴 수 있습니다.

**저장할 때 자동 정렬**(설정 › 정렬, 기본 꺼짐)을 켜면 저장할 때마다 먼저 정렬합니다.

## 정렬 도구 고르기

도구 모음의 문서 정렬 버튼 오른쪽에는 **이 문서에 쓰일 정렬 도구 이름**이 보입니다. 누르면 그 언어의 정렬 방식을 고르는 목록이 나오고, 설정 › 정렬 탭에서는 모든 언어를 한 번에 정합니다.

![정렬 설정](images/settings-format.png)
*그림: 설정 › 정렬 — 언어마다 정렬 도구 선택*

언어마다 고를 수 있는 것은 다음과 같습니다.

- **자동 (도구 이름)**: 설치되어 있는 첫 도구(내장 Prettier 포함). 하나도 없으면 편집기 들여쓰기만 정리합니다.
- **각 도구**: 설치되지 않은 도구에는 "설치 안 됨 · 정렬할 때 자동 설치" 또는 "설치 안 됨 · 직접 설치 필요" 가 붙습니다.
- **편집기 들여쓰기만**: 편집기의 문법 규칙으로 들여쓰기만 다시 맞춥니다.
- **사용 안 함**: 그 언어의 정렬을 끕니다.

| 언어 | 정렬 도구 |
|---|---|
| JavaScript · TypeScript · JSX · TSX · JSON · HTML · CSS · SCSS · LESS · Markdown · YAML · Vue | **Prettier (내장)** — 아무것도 설치하지 않아도 됨. 프로젝트나 PATH 의 Prettier 도 선택 가능 |
| JSON · XML | 내장 JSON 정렬 · 내장 XML 정렬도 있음 |
| Python | black · ruff format · autopep8 · yapf |
| C · C++ · C# · Objective-C | clang-format |
| Java | google-java-format · clang-format |
| Go | gofmt · goimports |
| Rust | rustfmt |
| Shell | shfmt |
| PowerShell | PSScriptAnalyzer (Invoke-Formatter) |
| SQL (MySQL · PostgreSQL · SQLite 포함) | sql-formatter |
| XML | xmllint |
| Ruby | rubocop · rufo |
| PHP | php-cs-fixer |
| Lua | stylua |
| Dart | dart format |
| Kotlin | ktlint |
| Swift | swiftformat |

- 내장 Prettier 는 파일 옆의 `.prettierrc` 설정을 따르고, 탭 크기와 탭/공백은 편집기 설정을 씁니다.
- 외부 도구는 프로젝트의 `node_modules/.bin` 을 먼저, 그다음 PATH(와 `~/.cargo/bin`, `~/go/bin`, Python 모듈)에서 찾습니다.
- 도구를 새로 설치했는데 "설치 안 됨" 으로 나오면 설정 › 정렬의 **다시 찾기** 를 누르거나, PATH 에 추가한 뒤 앱을 다시 시작하세요.

## 도구 설치

설치되지 않은 정렬 도구는 앱에서 바로 설치할 수 있습니다.

- **정렬할 때 자동 설치**: "설치 안 됨 · 정렬할 때 자동 설치" 인 도구를 고른 뒤 문서 정렬을 누르면 "지금 내려받아 설치할까요?" 라고 묻습니다. **설치** 를 누르면 진행 창이 뜨고, 끝나면 바로 정렬합니다.
- **설정에서 직접 설치**: 설정 › 정렬의 각 언어 옆 **⬇ (설치)** 또는 **↻ (다시 설치)** 버튼. 이미 설치된 도구는 **지우고 새로 설치 / 위에 덮어 설치 / 취소** 중에서 고릅니다.

설치 진행 창은 **패키지 관리자 확인 → 패키지 내려받기 → 설치 → 사용 준비** 네 단계를 체크 목록으로 보여 주고, 실행하는 명령과 **설치 로그 보기**(실시간 출력)를 펼쳐 볼 수 있습니다. 취소할 수 있고, 실패하면 **다시 시도** 할 수 있습니다.

| 도구 | 설치 방법 |
|---|---|
| Prettier · sql-formatter | npm — 앱 설정 폴더 안(tools/node)에 설치 |
| black · ruff · autopep8 · yapf · clang-format | pip (`pip install --user`, 실행은 `python -m …`) |
| stylua | cargo |
| shfmt · goimports | go |
| rubocop · rufo | gem |
| rustfmt | rustup |
| PSScriptAnalyzer | PowerShell (Install-Module) |
| gofmt · dart · ktlint · swiftformat · php-cs-fixer · google-java-format · xmllint | 직접 설치 필요 — 설치 방법을 안내 |

필요한 패키지 관리자(Python, Node.js 등)가 없으면 무엇이 필요한지 알려 주고, 공식 설치 프로그램으로 먼저 설치할지 묻기도 합니다. 설치가 끝나면 이어서 도구 설치를 진행합니다.

## 코드 검사 (Lint)

문서를 열거나 고치고 잠시(약 0.7초) 지나면, 그 언어의 검사 도구가 **백그라운드**(별도 프로세스)에서 돌아 문제를 찾습니다. 입력은 전혀 막히지 않고 결과는 준비되는 대로 나타납니다. 저장하지 않은 내용을 그대로 검사하며, 파일 옆에 아무것도 만들지 않습니다.

![문제점 패널](images/lint.png)
*그림: 줄 번호 옆의 점, 물결 밑줄, 아래의 문제점 패널*

검사 결과는 여러 곳에 나타납니다.

- 줄 번호 옆 **거터의 점**: 빨강 오류 · 노랑 경고 · 파랑 정보
- 문제가 있는 위치의 **물결 밑줄**. 마우스를 올리면 메시지가 보입니다.
- **상태 표시줄**의 검사 항목: `✕ 오류 수 ⚠ 경고 수 ℹ 정보 수`, 문제가 없으면 **✓**, 이 언어의 검사 도구가 없으면 **—**. 마우스를 올리면 사용한 도구 이름이 나오고, 누르면 문제점 패널이 열립니다.
- **F8** (편집기 › 다음 문제): 커서 다음의 문제 위치로 이동합니다.

켜고 끄는 곳: **편집기 › 코드 검사 (Lint)**, 설정 › 일반 › 편집 보조, 설정 › 검사 탭 맨 위(기본 켜짐). 끄면 점 · 밑줄 · 상태 표시줄 항목이 사라집니다.

## 문제점 패널

도구 모음의 **문제점** 버튼, **보기 › 문제점**, **편집기 › 문제 목록**, 상태 표시줄의 검사 항목으로 하단 패널의 **문제점** 탭을 엽니다. 코드 검사가 꺼져 있을 때 이 탭을 열면 검사가 켜집니다.

- 머리에 현재 문서 이름과 요약("eslint · 오류 2 · 경고 1 · 정보 0", 검사 중이면 "검사 중…")이 나오고, **다시 검사** 버튼으로 바로 다시 검사합니다.
- 목록에는 현재 문서의 문제가 심각도 표시 · 줄:열 · 메시지(규칙 이름)로 나옵니다. **누르면 그 위치로** 커서가 갑니다.
- 패널 머리 오른쪽의 **⚙ (문제점 설정)** 은 설정 › 검사 탭을 바로 엽니다.
- 상황에 따라 "코드 검사가 꺼져 있습니다", "열린 파일이 없습니다", "이 파일은 코드 검사를 하지 않습니다"(이진 파일 등), "문제가 없습니다", "이 언어의 검사 도구가 없거나 설치되지 않았습니다" 같은 안내가 나옵니다.

## 검사 도구 고르기

설정 › 검사 탭에서 언어마다 어떤 도구를 쓸지 고릅니다. **자동**은 설치된 첫 도구, **사용 안 함**은 그 언어의 검사를 끕니다.

![검사 설정](images/settings-lint.png)
*그림: 설정 › 검사 — 언어마다 검사 도구 선택*

| 언어 | 검사 도구 (자동일 때 이 순서로) |
|---|---|
| JavaScript · JSX | ESLint → node --check (문법 검사) |
| TypeScript · TSX | ESLint |
| Python | ruff → pyflakes → python 문법 검사 |
| JSON | 내장 검사 |
| YAML | 내장 YAML 검사 · 내장 Kubernetes 검사 · kubeconform · kubectl --dry-run · yamllint |
| Shell | shellcheck |
| PowerShell | PSScriptAnalyzer |
| C | gcc · clang · cc (`-fsyntax-only -Wall`) |
| C++ | g++ · clang++ · gcc · clang |
| Go | gofmt · go vet |
| PHP | php -l |
| Ruby | RuboCop → ruby -c |
| Dockerfile | hadolint |
| Markdown | markdownlint |
| CSS · SCSS · LESS | stylelint |
| Java | javac |

- **Kubernetes 매니페스트**(YAML)는 내장 검사로 필수 필드, 컨테이너의 name/image, 태그 없는 이미지, 셀렉터와 레이블의 일치, containerPort 가 숫자인지 등을 확인합니다.
- ESLint · stylelint 는 프로젝트에 설정 파일이 없으면 앱에 들어 있는 기본 설정으로 검사합니다.
- 설치되지 않은 도구("설치 안 됨 · 선택하면 설치 여부 확인")를 고르면 **설치 순서**(패키지 관리자 확인 → 내려받기 → 설치 → 이 언어의 검사 도구로 사용)를 보여 주고, 동의하면 정렬 도구와 같은 진행 창으로 설치합니다. 언어 옆 ⬇ 버튼으로도 설치할 수 있습니다.
- **다시 찾기** 는 설치된 도구를 다시 확인합니다.
