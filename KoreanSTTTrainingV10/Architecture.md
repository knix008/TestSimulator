# 구조

이 프로그램은 10개 이하의 짧은 한국어 명령을 구분한다. 문장 받아쓰기를 하지 않는다. 클래스에는 사용자가 등록한 명령과, 명령이 아닌 소리를 거절하는 `무음`이 항상 포함된다.

기본 명령은 출근, 퇴근, 경비, 해제이다. 따라서 배포용 연습 모델은 5클래스이다.

## 데이터 흐름

1. 16 kHz 모노로 맞춘다. 녹음 길이는 2초이고, 모델 창은 1.0초이다. 2초보다 길면 명령 확률이 가장 높은 1초를 고른다.
2. 1초보다 길면 에너지가 가장 큰 1초를 고른다. 짧으면 가운데를 0으로 채운다.
3. DC 제거, pre-emphasis 0.97, 피크가 0.01 이상이면 0.9로 정규화, [-1, 1] 절단.
4. 25 ms 해닝 창(400샘플), 10 ms 홉(160샘플), 512-point FFT. 프레임 98, 주파수 빈 257.
5. HTK 멜 필터 40개, 80 Hz–7600 Hz. `log(mel + 1e-6)` 뒤 학습 때의 멜 평균과 표준편차로 나눈다. 표준편차 바닥은 1e-3.
6. 입력 텐서 `logmel`, NCHW `[1, 1, 40, 98]`, float32.
7. 네트워크 출력 `logits`. 소프트맥스는 호출하는 쪽에서 계산한다.
8. 1등이 `무음`이거나 최대 확률이 임계값(기본 0.70)보다 낮으면 결과는 `대기`이다.

시간 이동, 소음, SpecAugment는 학습에만 쓴다. 멜 필터, 창, 평균, 표준편차는 추론 때 다시 계산하지 않고 바이너리로 읽는다. Python `kws/features.py`와 C++ `cpp/logmel.hpp`가 같은 순서를 따른다. 특징 버전은 `FEATURE_VERSION = 1`이다.

## 네트워크

네트워크는 두 가지이다. 학습 탭이나 `--arch`로 고르고, 결과 폴더의 `meta.json` `arch`에 기록된다. 추론, 다시 저장, 추가 학습은 이 값으로 같은 네트워크를 만든다. 두 구조 모두 입력 `logmel [1, 1, 40, 98]`, 출력 `logits`이므로 특징 계산, C++ 예제, 판정 규칙은 같다.

| `arch` | 화면 이름 | 5클래스 파라미터 | 10명령(11클래스) | 권장 학습률 |
| --- | --- | --- | --- | --- |
| `dscnn_v2` | DS-CNN v2 (기본) | 17,637 | 18,027 | 0.002 |
| `bcresnet1` | BC-ResNet-1 | 9,001 | 9,199 | 0.01 |

### DS-CNN v2

이름 `dscnn_v2`. 공개 음성 모델의 가중치를 가져오지 않는다. `dscnn_v1` 가중치와는 마지막 층이 달라 이어서 학습할 수 없다.

- Stem: Conv 1→32, 커널 3, GroupNorm, ReLU
- Depthwise separable 블록 6개. 채널과 stride는 (32,1), (32,2), (32,1), (64,2), (64,1), (64,1)
- 각 블록은 depthwise 3×3, GroupNorm, ReLU, pointwise 1×1, GroupNorm, ReLU
- 주파수는 평균으로 모으고 시간은 4칸을 남긴다. 칸마다 채널별 가중치로 섞은 뒤 Dropout 0.15, Linear
- 학습 손실에는 라벨 스무딩을 넣지 않는다. 정답 확률이 임계값 아래로 눌리는 것을 막기 위해서다.

GroupNorm 그룹 수는 채널이 8로 나누어떨어지면 8이다. 명령 녹음은 배치가 작아서 배치 정규화의 이동 평균 대신 이 정규화를 쓴다.

### BC-ResNet-1

이름 `bcresnet1`. Kim 외, "Broadcasted Residual Learning for Efficient Keyword Spotting"(Interspeech 2021)의 구조를 기준 채널 8로 만든다. 공개 가중치는 가져오지 않는다.

- 머리: Conv 1→16, 커널 5, stride (2, 1), BatchNorm, ReLU. 주파수 40 → 20
- BC 블록 12개. 단계별 반복 2, 2, 4, 4, 채널 8, 12, 16, 20
- 2단계와 3단계의 첫 블록은 주파수 stride 2 (20 → 10 → 5). 시간 dilation은 1, 2, 4, 8
- 각 블록: 주파수 3×1 depthwise와 SubSpectralNorm(주파수 5구간) → 주파수 평균 → 시간 1×3 depthwise, BatchNorm, SiLU, pointwise, Dropout2d 0.1 → 2D 결과에 주파수 방향으로 방송해 더함. 채널이 같으면 입력도 더함
- 채널이 바뀌는 블록은 앞에 1×1 Conv, BatchNorm, ReLU를 둔다
- 분류기: 5×5 depthwise(주파수 5 → 1), pointwise 20→32, BatchNorm, ReLU, 시간 평균, 1×1 Conv로 로짓

논문과 같은 12클래스로 만들면 파라미터는 9,232개이다(논문 표기 9.2K). 배치 정규화를 쓰지만 BatchNorm은 배치×주파수×시간 전체로 통계를 내므로 배치 1에서도 학습된다. 좁고 깊어서 AdamW 학습률 0.002로는 같은 에폭 안에 수렴이 느리다. 권장 학습률은 0.01, 추가 학습은 0.0025이다.

2026-10-16, 테스트용 5클래스 모델에서 측정했다. 스레드 1개, 같은 i7-14700K이다.

| 항목 | DS-CNN v2 | BC-ResNet-1 |
| --- | --- | --- |
| `command_kws.onnx` | 98,074바이트 | 79,082바이트 |
| ONNX 실행 중앙값 (90퍼센트) | 0.65 ms (0.71 ms) | 0.28 ms (0.42 ms) |
| 가장 큰 활성화 맵 | `[1, 32, 40, 98]` 501,760바이트 | `[1, 16, 20, 98]` 125,440바이트 |
| 동적 INT8 | 더 작아서 저장 | 실수형보다 커서 저장하지 않음 |

BC-ResNet-1의 ONNX에는 SubSpectralNorm 때문에 BatchNormalization과 Reshape 노드가 남는다. ONNX Runtime은 그대로 실행하고, C++ 예제는 바꿀 것이 없다. 로그멜 계산(약 3.4 ms)이 판정 시간의 대부분이므로 아래 CPU 클록 계산은 두 구조에 모두 맞는 상한이다.

5클래스(명령 4개 + 무음) 학습 가능 파라미터는 17,637개이다. float32 가중치는 70,548바이트이다. 명령이 10개이면 마지막 Linear만 커지고 파라미터는 18,027개이다. 앞쪽 합성곱 크기는 클래스 수와 관계가 없다.

ONNX는 opset 17, 배치 1 고정, 입력 이름 `logmel`, 출력 이름 `logits`이다.

## 실행 메모리

인식 한 번은 1초 파형에서 로그멜을 만들고 ONNX를 한 번 실행하는 일이다. 아래 프로세스 메모리는 같은 PC에서 ONNX Runtime 세션을 만들기 직전과 직후를 비교한 값이다. 스레드는 1개이다.

| 구간 | 측정 |
| --- | --- |
| 공식 Windows CPU `onnxruntime.dll` | 19,288,928바이트 (18.4 MiB) |
| 세션 생성으로 늘어난 private bytes | 2.9 MB |
| 세션 생성으로 늘어난 working set | 6.9 MB |
| 워밍업 실행까지 포함한 private bytes 증가 | 6.2 MB |
| 로그멜 입력 | 15,680바이트 |
| float32 가중치 | 70,548바이트 |

가장 큰 활성화 맵은 stem 출력 `[1, 32, 40, 98]` float32로 501,760바이트이다. FFT 파워는 98×257 float32로 100,744바이트이다. 1초 파형 float32는 64,000바이트이다. 특징과 활성화만 보면 2 MB 안에 들어간다.

Python용 `onnxruntime_pybind11_state.pyd`(약 19.1 MB)는 C++ 장치에 넣지 않는다.

장치에 둘 최소 RAM은 다음을 기준으로 한다.

- 공식 `onnxruntime.dll`과 세션, 오디오 버퍼를 한 프로세스에 올린다.
- 측정된 라이브러리 18.4 MB와 세션 working set 약 7 MB에 여유를 둔다.
- 최소 메모리는 32 MB이다.

더 작은 ONNX Runtime 빌드를 쓰면 DLL이 줄어 32 MB보다 작아질 수 있다. 그 경우에도 세션과 스크래치로 측정된 약 8 MB는 남긴다. 학습용 PyTorch 프로세스는 이 예산에 포함하지 않는다. 학습은 데스크톱에서 한다.

## CPU 클록

측정 장비는 Intel Core i7-14700K이다. 기본 클록은 3.4 GHz이고, P-core 최대 터보는 5.6 GHz이다. 추론 동안 클록을 고정하지 않았다. 사이클 수는 측정이 최대 터보에서 이뤄졌다고 가정한 상한이다.

| 단계 | 중앙값 |
| --- | --- |
| 로그멜 | 3.37 ms |
| ONNX 실행 | 0.64 ms |
| 로그멜과 ONNX | 3.84 ms (40회, 90퍼센트 4.05 ms) |

상한 사이클은 `0.00384 s × 5.6 GHz = 2,150만 사이클`이다.

실시간 조건은 GUI와 같다. 마이크 루프는 약 0.2초마다 직전 1초를 판정한다. 한 번의 판정이 0.2초를 넘으면 다음 주기를 놓친다.

최소 클록은 그 2,150만 사이클을 0.2초 안에 처리하는 값이다.

`2,150만 / 0.2 s = 1억 750만 Hz`, 약 110 MHz.

이 값은 i7-14700K의 P-core와 한 클록에 처리하는 일량이 비슷한 코어 하나에 대한 것이다. 캡처, 화면, 다른 작업을 같은 코어에서 하려면 판정을 50 ms 안에 끝내는 편이 안전하다.

`2,150만 / 0.05 s = 4억 3000만 Hz`, 즉 430 MHz이다. 여유를 두어 권장 클록은 450 MHz이다.

따라서 이 문서의 최소 클록은 110 MHz이고, 같은 코어에서 다른 일을 함께 할 때의 권장 클록은 450 MHz이다. Cortex-M처럼 명령당 처리량이 다른 코어에는 이 헤르츠를 그대로 쓰지 않는다. 그 코어에서는 같은 2,150만 사이클이 더 오래 걸릴 수 있다.
