# MyICOMaker — Architecture

## Overview

```
┌──────────────────────── one web bundle (Vite + React) ────────────────────────┐
│ main.jsx routes by URL:                                                       │
│   (none)             → App.jsx         main window: StartScreen | editor        │
│   ?viewer=guide      → GuideWindow.jsx user's guide (docs/UsersGuide*.html)   │
│   ?popup=print       → PrintWindow.jsx print preview                           │
│ lib/  model + drawing + export (pure, tested in Node)                         │
│ lib/platform.js  the only module that knows desktop vs. web                   │
└───────────────┬───────────────────────────────────────────────┬──────────────┘
                │ invoke()                                       │ browser APIs
┌───────────────▼────────────── Tauri 2 (Rust) ───────┐   ┌──────▼─────── web ───────┐
│ lib.rs   windows: main (frameless), doc-guide,      │   │ <input type=file>,       │
│          popup-print (frameless, owned by main);    │   │ downloads, ZIP (jszip),   │
│          files (read/write, atomic), print, drag,   │   │ guide in a tab, print     │
│          single instance, startup files             │   │ preview in a frame        │
│ files.rs, window_state.rs (place + install markers) │   └───────────────────────────┘
└─────────────────────────────────────────────────────┘
```

## Front end

| Module | Role |
|---|---|
| `lib/shapes.js` | The 81 flat shapes as paths in a 100×100 unit box (+ 12 solids). `scalePath` maps a unit path onto any box (absolute M L H V C S Q T A Z; arc radii scale, mirrored boxes flip the sweep). Holes use `evenodd` or reversed sub-paths. |
| `lib/iconCanvas.js` | The design model (512×512): `createObject`, `bbox`, move/resize/align/clone, SVG for every object (fills, gradients, outlines, dashes, arrowheads, solids with shaded faces, gloss overlay), the effect filter (3D bevel, glow, blur, shadow), `serializeSvg`, rasterizing and `buildIco/buildIcoEach/buildPngs/buildIcns`. |
| `lib/ico.js` | ICO and ICNS writers (PNG entries). |
| `lib/decode.js` | Picture import → typed `data:` URL (TIFF, HEIC, DICOM decoded; an SVG drawn as an image may not load `blob:` URLs, and designs keep their pictures). |
| `lib/project.js` | `.myico` (JSON) read/write, validation, recent-file list. |
| `lib/history.js` | Undo/redo of design snapshots; changes under one key within 700 ms merge (slider drags). |
| `lib/settings.js` | Preferences in `localStorage` (shared by all windows: same origin), installer reset and installer language. |
| `lib/themes.js` | 40 themes (20 dark, 20 light, derived from hue + accent) and the custom theme, as CSS variables for every window and the canvas (checkerboard, grid, rulers). |
| `lib/printLayout.js` | Page layouts in mm (size samples, one large, sticker sheet); `docFont` for the guide. |
| `lib/emoji.js` | Generated by `scripts/build-emoji.mjs` from `@twemoji/svg` (dev dependency): 190 emoji in 8 categories with Korean and English names, and each emoji's vector art (inside of a 36 × 36 SVG; ids made unique). An `emoji` object stores only the code; `bodyToSvg` nests the art in an `<svg>` fitted to the box, so exports are sharp. |
| `lib/examples.js` | The 20 example designs of the start screen (shapes, emoji, text, effects); built fresh like templates. |
| `lib/userLibrary.js` | What the user adds: "My emoji" (pictures or a selection as SVG, `myicomaker.userEmoji`) and "My examples" (whole designs + thumbnail, `myicomaker.userExamples`). Own localStorage keys, not the shared settings. |
| `lib/model3d.js` | 3D models: three.js (loaded only when needed) and its loaders for OBJ, STL, PLY, glTF/GLB, FBX, DAE, 3MF, 3DS, AMF, VRML; the model is centred and scaled to 1 unit, lit, and rendered from a view (yaw, pitch, roll, zoom, light, one colour, wireframe, contact shadow) to a transparent PNG. `components/Model3DDialog.jsx` is the import window. |
| `lib/docPages.js` | The user's guide cut into printed pages (from MyImage2Text): measure blocks in a hidden box as wide as the text area, plan pages (a heading never ends a page, long tables repeat the header row, lists keep numbering), then lay each page out in a probe and give back blocks until it really fits. |
| `icons/glyphs.js` | Colour icons (24×24 SVG); shape buttons are drawn from the shape geometry. |
| `components/` | `controls.jsx` (Icon, Btn, Slider −/+, Stepper, ColorField, Toggle, IconSelect, Segmented, ContextMenu, Modal, Card), `Chrome.jsx` (title bar, toolbar with priority label hiding, status bar with grip, preview strip), `IconCanvas.jsx`, `LeftPanel.jsx`, `RightPanel.jsx`, `Dialogs.jsx`. |
| `start/` | `StartScreen.jsx`; `startboard.js`, `startlayout.js` and `background.js` come from MyUMLMaker (card board, 20 animated backgrounds). |

### Files from outside

`openIncoming(items)` in `App.jsx` takes files from the picker, from the browser's drag-and-drop (the whole page) or from Tauri's drag-drop event (desktop: the webview gets paths, not HTML drops), and routes them by kind: `.myico` opens (after the unsaved-changes question), pictures go on the canvas, a 3D model opens the import window, anything else is named in the status bar. A drop overlay shows while dragging.

### Editing flow

`App.jsx` owns the design. `apply(fn, { record, key })` pushes the current design to the history (unless `record: false`) and sets `fn(design)`. A drag calls `record()` once at the press and `apply(..., { record: false })` while moving, so one drag is one undo step. The canvas registers stable window listeners that call the handlers of the latest render (a re-render during a drag must not remove them).

The work in progress is kept in `localStorage` (`myicomaker.session`) for **Continue** on the start screen.

### Windows

* **Main** — frameless; the title bar is the drag area (`window_drag` → `WM_SYSCOMMAND` on Windows, so moves snap like normal windows); the status bar grip resizes. Shown by `main_ready` after the first paint (15 s fallback).
* **Guide** — `doc-guide`, system title bar, one instance (asking again brings it back and switches language); opened from the toolbar, title bar, start screen or F1. The theme's colours (and `color-scheme`, page background) are written into the guide document; the frame is shown once themed. The HTML is generated by `scripts/build-docs.mjs` from the program's own lists. **Print** writes a guide job (`{ kind: 'guide', lang }`) to `myicomaker.print` and opens the print window.
* **Print** — `popup-print`, frameless, a window of its own (not owned: own taskbar button, stays when the main window is minimized; in the browser a window of its own via `openBrowserWindow`, a frame only when popups are blocked). The main window writes the job (`myicomaker.print`: SVG, name, sizes) to `localStorage`; the preview listens to `storage` events and `popup-refresh`. A guide job switches it to document mode: every page of the guide in the preview, text size instead of the icon options. Printing goes straight to the chosen printer (`print_direct`), through the system dialog, or into a PDF (`print_pages_to_pdf`), with `@page` from the chosen paper and one sheet per page.

## Backend (src-tauri)

* `lib.rs` — commands: app info, language, startup files, text/base64 read/write, several files into a folder, open external, reveal, window ready, guide/print windows, print, window drag, quit. Single instance (`tauri-plugin-single-instance`) unless `MYICOMAKER_MULTI` is set; a second start hands its `.myico` files to the first (`open-files` event).
* `files.rs` — atomic writes (temp + rename), safe file names, design files from arguments.
* `window_state.rs` — window place per window (only on a connected monitor), installer markers `install-reset` and `install-language` (read once).

## Installer (Windows, NSIS)

`tauri.conf.json`: `languages: [Korean, English]`, `displayLanguageSelector: true`. `windows/hooks.nsh` (UTF-8 **with BOM**):
language selector always shown with both languages; the chosen language is written to `%APPDATA%\com.shkwon.myicomaker\install-language` so the program starts in it; earlier installation → remove and reinstall?; user data → delete?; running copies are closed; a **Shortcuts** page (desktop / Start menu with the user's guide).

## Tests

`npm test` (`scripts/test.mjs`): unit (node:test, 33+), Rust (cargo test), web build, GUI (`test/gui.mjs`: builds the debug program into `src-tauri/target/e2e`, runs it with a temporary WebView2 profile and config folder and the DevTools port, and drives it — start screen, icons and alignment, templates, drawing, undo/redo, shapes, effects, exports, print window, guide window, language and theme). `--shots` also saves the guide pictures in both languages.
