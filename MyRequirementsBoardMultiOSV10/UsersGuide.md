# 사용자 매뉴얼 (User Guide)

> 개발·설치·빌드 방법은 [README.md](README.md)를 참고하세요.  
> 이 문서는 **MyRequirementsBoard** 화면을 어떻게 사용하는지 설명합니다.

---

## 1. 처음 시작하기

### 1.1 앱 실행

- **웹**: `npm run dev:web` 실행 후 브라우저에서 http://127.0.0.1:5175 접속
- **데스크톱**: `npm run dev` 실행 후 Electron 창이 열립니다
- **설치판**: 패키징된 실행 파일을 더블클릭합니다

### 1.2 데이터베이스

앱은 다음 순서로 DB를 선택합니다.

1. **외부 DB 설정이 있으면** — MariaDB, MySQL, PostgreSQL, MS SQL Server 중 설정된 DB 사용
2. **설정이 없으면** — **SQLite** 로컬 파일을 자동으로 사용 (별도 DB 서버 불필요)

처음 실행 시 SQLite가 자동으로 만들어지므로, **바로 로그인**할 수 있습니다.  
회사/팀 DB를 쓰려면 관리자가 **설정 → 데이터베이스 설정**에서 MariaDB 등을 연결하세요. (기본 DB 종류: **MariaDB**)

### 1.3 최초 로그인

| 항목 | 값 |
|------|-----|
| ID | `admin` |
| 비밀번호 | `admin` |

로그인 후 **설정 → 내 프로필**에서 비밀번호를 반드시 변경하세요.

---

## 2. 로그인 / 계정 등록 요청

### 2.1 로그인

- ID와 비밀번호를 입력하고 **로그인**을 누릅니다.
- 세션은 약 7일간 유지됩니다.

### 2.2 계정 등록 요청 (신규 사용자)

1. 로그인 화면에서 **등록 요청**을 선택합니다.
2. ID, 비밀번호, 이름, 이메일(선택)을 입력하고 요청을 보냅니다.
3. **관리자**가 **사용자** 메뉴에서 승인하면 로그인할 수 있습니다.
4. 거절된 경우 다시 등록 요청을 해야 합니다.

---

## 3. 화면 구성

상단 메뉴(권한에 따라 일부만 표시):

| 메뉴 | 설명 | 최소 권한 |
|------|------|-----------|
| **요구사항** | 현재 프로젝트의 요구사항 목록 | VIEWER |
| **프로젝트** | 프로젝트 생성·삭제 | ADMIN |
| **사용자** | 사용자·등록 승인 관리 | ADMIN |
| **AI 정제** | Ollama로 요구사항 정제 테스트 | EDITOR |
| **설정** | 프로필, DB, Ollama 설정 | VIEWER |

오른쪽 **프로젝트 선택** 드롭다운으로 작업할 프로젝트를 바꿀 수 있습니다.

---

## 4. 프로젝트 관리 (ADMIN)

**프로젝트** 메뉴에서 여러 프로젝트를 관리합니다.

- **새 프로젝트**: 코드(예: `PROJ01`), 이름, 설명을 입력해 생성합니다.
- **기본 프로젝트** (`DEFAULT`)는 삭제할 수 없습니다.
- 프로젝트를 삭제하면 해당 프로젝트의 요구사항·테스트 케이스도 함께 삭제됩니다.

요구사항은 **선택한 프로젝트**에만 속합니다. 상단 드롭다운에서 프로젝트를 전환한 뒤 작업하세요.

---

## 5. 요구사항 관리

### 5.1 목록 보기

- **검색**: 코드, 제목, 카테고리로 검색합니다.
- **필터**: 상태(초안/승인/진행중/완료), 우선순위(낮음/보통/높음)로 좁힐 수 있습니다.
- **선택 삭제** (EDITOR 이상): 체크박스로 여러 건을 선택 후 삭제합니다.

### 5.2 새 요구사항 (EDITOR 이상)

1. **새 요구사항**을 누릅니다.
2. 제목, 설명, 카테고리, 우선순위, 상태를 입력합니다.
3. **코드는 직접 입력하지 않습니다.** 카테고리 접두사로 자동 부여됩니다.
   - 카테고리 `UI` → `UI-01`, `UI-02`, …
   - 카테고리 비움 → `REQ-01`, `REQ-02`, …

### 5.3 수정 / 삭제 (EDITOR 이상)

- **편집** 링크로 내용을 수정합니다.
- **Ollama로 정제** 버튼으로 로컬 LLM이 제목·설명·카테고리 등을 다듬어 줍니다. (Ollama 실행 필요)
- 카테고리를 바꾸면 코드가 해당 접두사 기준으로 **전체 재정렬**됩니다.
- 삭제 시 연결된 테스트 케이스도 함께 삭제되고, 남은 코드가 빈틈없이 재정렬됩니다.

### 5.4 테스트 케이스

- 요구사항 편집 화면 하단에서 연결된 테스트 케이스를 **조회**할 수 있습니다.
- (향후 버전에서 편집 UI 추가 예정)

## 6. AI 요구사항 정제 (Ollama)

**AI 정제** 메뉴 또는 요구사항 편집 화면의 **Ollama로 정제**를 사용합니다.

### 6.1 사전 준비

```bash
ollama pull llama3    # 또는 사용할 모델
ollama serve
```

### 6.2 설정 (ADMIN)

**설정 → Ollama 설정**에서:

- **Base URL**: 기본 `http://127.0.0.1:11434`
- **모델**: 설치된 모델 중 선택 (비우면 자동 선택)

### 6.3 정제 사용

1. 제목·설명·카테고리 등을 입력합니다.
2. **Ollama로 정제**를 누르면 JSON 형태로 정제된 결과가 반환됩니다.
3. 편집 화면에서는 결과가 폼에 자동 반영됩니다.

Ollama가 꺼져 있으면 "연결 불가" 메시지가 표시됩니다.

## 7. 사용자 관리 (ADMIN)

**사용자** 메뉴에서:

### 7.1 등록 승인 대기

- 등록 요청 목록에서 **승인** 또는 **거절**합니다.
- 승인 시 요청 시 입력한 ID/비밀번호로 계정이 생성됩니다.

### 7.2 사용자 직접 추가

- ID, 비밀번호, 이름, 역할(VIEWER/EDITOR/ADMIN)을 입력해 생성합니다.

### 7.3 사용자 목록

- **비활성화/활성화**: `admin` 계정은 비활성화할 수 없습니다.
- 역할 변경·비밀번호 초기화는 사용자 편집 API를 통해 확장할 수 있습니다.

## 8. 설정

### 8.1 시스템 정보

- 현재 DB 모드 (SQLite / 외부 DB), 연결 경로 또는 서버 정보를 확인합니다.

### 8.2 데이터베이스 설정 (ADMIN)

| 동작 | 설명 |
|------|------|
| **외부 DB 연결** | DB 종류(기본 MariaDB), 서버, 포트, DB명, 사용자, 비밀번호 입력 후 연결 |
| **테이블 생성** | 접속은 되었으나 테이블이 없을 때 스키마 생성 |
| **SQLite로 전환** | 외부 DB 설정을 해제하고 로컬 SQLite로 돌아감 |

연결 성공 시 `data/db-config.json`에 설정이 저장됩니다.  
다음 실행부터 저장된 외부 DB를 우선 사용합니다.

### 8.3 내 프로필

- 이름, 이메일, 회사, 부서를 수정합니다.
- 비밀번호 변경 시 **현재 비밀번호**와 **새 비밀번호**를 입력합니다.

### 8.4 Ollama 설정 (ADMIN)

- Base URL, 모델 선택 및 저장 (6장 참고).

## 10. 데스크톱 vs 웹

| 항목 | Electron (데스크톱) | 웹 |
|------|---------------------|-----|
| 데이터 저장 위치 | OS 사용자 데이터 폴더 내 `data/` | 프로젝트 `data/` 폴더 |
| DB 설정 파일 | 사용자 데이터 폴더 | `data/db-config.json` |
| 오프라인 | SQLite 사용 시 가능 | 서버 실행 필요 |
| 패키징 | `npm run dist:win` 등 | `npm run build && npm start` |

## 11. 자주 묻는 질문

**Q. DB를 설정하지 않았는데도 앱이 동작합니다.**  
A. 정상입니다. 외부 DB 설정이 없으면 **SQLite**를 자동으로 사용합니다.

**Q. MariaDB에 연결할 수 없습니다.**  
A. 서버 주소·포트·방화벽, 계정 권한, 인증 방식(`mysql_native_password` 등)을 확인하세요. README의 MariaDB 계정 예시를 참고하세요.

**Q. 외부 DB 연결 후 SQLite 데이터는 어떻게 되나요?**  
A. SQLite 파일과 외부 DB는 **별도 저장소**입니다. 외부 DB로 전환하면 외부 DB의 데이터를 사용하며, SQLite 파일은 로컬에 그대로 남습니다. **SQLite로 전환**하면 다시 로컬 SQLite를 사용합니다.

**Q. 요구사항 코드를 직접 수정할 수 없나요?**  
A. 코드는 카테고리 기준으로 시스템이 자동 관리합니다. 접두사를 바꾸려면 **카테고리**를 변경하세요.

**Q. 비밀번호를 잊었습니다.**  
A. 관리자에게 문의하세요. 관리자가 **사용자** 화면에서 계정을 관리할 수 있습니다. 최초 `admin`/`admin`으로 복구할 수도 있습니다(SQLite 초기화 또는 DB에서 직접 수정).

**Q. Ollama 정제가 실패합니다.**  
A. `ollama serve`가 실행 중인지, **설정**에서 URL·모델이 올바른지 확인하세요. `ollama list`로 설치된 모델을 확인합니다.

**Q. Excel 가져오기/보내기는 없나요?**  
A. 현재 버전에서는 UI가 없습니다. 향후 업데이트 예정입니다 (`exceljs` 라이브러리 포함).
