# 사용 설명서

마이크로 말하거나 WAV 파일을 넣으면 한국어를 글자로 받아쓰는 프로그램입니다.
인터넷에 보내지 않고 **내 컴퓨터에서만** 처리합니다.

기본 설정은 **"출근" 과 "퇴근" 만** 받아쓰고 각각 따로 셉니다(출퇴근 기록용).
받을 말은 창에서 바꿀 수 있습니다 — 6장을 보세요.

- 설치는 [INSTALL.md](INSTALL.md)
- 코드 구조는 [ARCHITECTURE.md](ARCHITECTURE.md)

---

## 1. 무엇을 쓸 수 있나

| 프로그램 | 설명 |
|---|---|
| `kstt-gui` | 창이 뜨는 보통의 사용 방법. OS 네이티브 GUI (Windows=Win32, macOS=Cocoa, Linux=GTK4) |
| `kstt-gui-gtk4` | 어느 OS 에서나 같은 모습인 GTK4 판 (따로 빌드했을 때) |
| `kstt-cli` | 콘솔에서 쓰는 판. 자동화·일괄 변환에 좋습니다 |

```bash
./run.sh              # GUI           (Windows: .\run.ps1)
./run.sh gui-gtk4     # GTK4 판
./run.sh cli --help   # CLI 도움말
```

## 2. 최소·권장 하드웨어

인식은 CPU 로만 합니다(GPU 를 쓰지 않습니다). 작은 한국어 모델
`vosk-model-small-ko-0.22` 기준입니다.

| | 최소 | 권장 |
|---|---|---|
| CPU | 64비트 2코어 1.5GHz 이상 (x86_64 / arm64) | 4코어 2.5GHz 이상 |
| 메모리 | **2GB** (프로그램이 약 0.5GB 를 씁니다) | 4GB 이상 |
| 디스크 | 300MB (모델 253MB + libvosk 25MB) | 1GB (빌드 산출물 포함) |
| 마이크 | 아무 입력 장치 (16kHz 모노로 열립니다) | 노이즈가 적은 헤드셋 마이크 |
| OS | Windows 10 1607↑ / Ubuntu 20.04↑ 같은 glibc 2.31↑ / macOS 11↑ | 최신판 |

메모리는 측정값입니다. 모델을 올린 채 대기할 때 **약 470MB**, 인식하는 동안
**최대 약 527MB** 를 썼습니다. 1GB 메모리 기기(라즈베리파이 등)에서는 빠듯합니다.

> **인터넷**은 설치할 때(모델·라이브러리 내려받기)만 필요하고, 인식할 때는
> 전혀 쓰지 않습니다.

## 3. 인식 속도

### 측정값

측정 환경: Intel Core i7-14700K (20코어/28스레드), 64GB RAM, Windows 11 Pro,
MinGW64 g++ 15.1 Release(-O3), `vosk-model-small-ko-0.22`.

| 항목 | 값 |
|---|---|
| 모델 적재 (프로그램 시작 시 한 번) | **0.8초** |
| 61.4초짜리 WAV 파일 받아쓰기 | **3.4초** (적재 제외) |
| 실시간 대비 속도 | **약 18배** (실시간 계수 RTF ≈ 0.056) |
| 부분 결과가 화면에 나오는 간격 | 약 0.1초 |
| 최종 문장이 확정되는 시점 | 말이 끊긴 뒤 바로 |

Vosk 의 인식은 **한 코어**만 씁니다. 그러므로 코어 수가 아니라 **한 코어의
성능**이 속도를 좌우하고, 코어가 많아도 한 스트림이 더 빨라지지는 않습니다
(대신 여러 파일을 동시에 돌릴 수는 있습니다).

### 다른 기기에서는

아래는 위 측정값을 단일 코어 성능으로 환산한 **추정**입니다. 실제 값은 기기마다
다릅니다.

| 기기 | 실시간 계수(추정) | 뜻 |
|---|---|---|
| 요즘 데스크톱 (i5/i7 12세대↑, Ryzen 5000↑) | 0.05 ~ 0.1 | 1분 음성을 3~6초에 |
| 노트북 (저전력 CPU, 2019년 전후) | 0.15 ~ 0.3 | 1분 음성을 9~18초에 |
| 라즈베리파이 4 / 저사양 ARM | 0.6 ~ 1.0 | 실시간에 가깝거나 아슬아슬 |

**실시간 계수가 1보다 작으면 말하는 속도를 따라갑니다.** 즉 위 어느 경우든
마이크 받아쓰기는 됩니다. 1에 가까우면 말이 길어질수록 자막이 조금씩 밀립니다.

### 파일 변환은 가능한 한 빨리

WAV 파일을 넣으면 재생 속도를 기다리지 않고 CPU 가 낼 수 있는 최대 속도로
처리합니다. 위 환경에서 1시간짜리 녹음이면 약 3.5분입니다.

## 4. GUI 사용법

### 화면 구성

```
┌───────────────────────────────────────────────────────────┐
│ 한국어 음성 인식 (Vosk)                        ─  □  ×   │
├───────────────────────────────────────────────────────────┤
│ 설정                                                       │
│   모델  [ …/models/vosk-model-small-ko-0.22 ] [찾아보기…] [모델 적재] │
│   받는 말 [ 출근, 퇴근 ]  쉼표로 구분. 비우면 모두 받아씀  │
│   입력  [ 시스템 기본 입력 장치          ▾ ] [새로 고침]  │
│                                                            │
│ [● 인식 시작] [■ 중지] [WAV 파일 인식…] ☑진행 중 표시  ▓▓░░ │
│ 준비됨 · 모델 vosk-model-small-ko-0.22 · libvosk.dll       │
│                                                            │
│ 인식 결과   출근 2회 · 퇴근 1회            [지우기] [저장…]│
│ ┌────────────────────────────────────────────────────────┐ │
│ │ [09:02:11] 출근                                         │ │
│ │ [18:31:40] 퇴근                                         │ │
│ └────────────────────────────────────────────────────────┘ │
│ … 지금 말하고 있는 중간 결과가 흐리게                      │
└───────────────────────────────────────────────────────────┘
```

### 차례대로

1. **모델** 칸이 비어 있으면 `찾아보기…` 로 모델 폴더를 고릅니다. 보통은
   `models/` 아래에서 자동으로 찾아 채워집니다.
2. 상태줄이 `준비됨 · 모델 …` 이 되면 준비 끝입니다. (처음 적재에 1초 안팎)
3. **받는 말** 을 확인합니다. 기본은 `출근, 퇴근` 이고, 비우면 들리는 대로
   모두 받아씁니다 (6장).
4. **입력** 에서 마이크를 고릅니다. 장치를 꽂거나 뺐으면 `새로 고침`.
5. **인식 시작** 을 누르고 말합니다.
   - 말하는 동안 맨 아래 흐린 줄에 중간 결과가 계속 바뀝니다.
   - 말이 끊기면 그 문장이 확정되어 시각과 함께 결과 창에 쌓입니다.
   - **입력 레벨** 막대가 움직이지 않으면 마이크가 소리를 못 받고 있는 것입니다.
   - 중간 결과가 거슬리면 **진행 중 표시** 체크를 풀면 됩니다 (6장 참고).
6. **중지** 를 누르면 멈추고, 마지막 문장까지 확정해서 남깁니다.
7. **저장…** 으로 결과를 텍스트 파일로 내보냅니다 (UTF-8).

### WAV 파일 받아쓰기

`WAV 파일 인식…` 으로 파일을 고르면 결과 창에 `── 파일이름 ──` 줄을 긋고 받아쓰기
결과를 채웁니다.

- **16비트 PCM WAV** 를 받습니다. 표본율과 채널 수는 알아서 맞춥니다
  (스테레오는 모노로 섞고, 8kHz·44.1kHz 등은 16kHz 로 변환).
- MP3·M4A 같은 압축 형식은 받지 않습니다. 먼저 WAV 로 바꿔 주세요:
  `ffmpeg -i 녹음.m4a -ar 16000 -ac 1 녹음.wav`

## 5. CLI 사용법

```bash
./run.sh cli [옵션]
```

| 옵션 | 설명 |
|---|---|
| `--model <디렉터리>` | 모델 경로 (생략하면 자동 탐색) |
| `--lib <경로>` | libvosk 경로 (생략하면 자동 탐색) |
| `--wav <파일>` | WAV 파일을 받아쓰기 (마이크 대신) |
| `--device <번호>` | 마이크 장치 번호 |
| `--list-devices` | 입력 장치 목록만 보여 주고 끝 |
| `--seconds <초>` | 마이크를 몇 초 동안 들을지 (생략하면 Enter 칠 때까지) |
| `--rate <Hz>` | 표본율 (기본 16000) |
| `--words` | 낱말마다 시작·끝 시각과 신뢰도까지 출력 |
| `--paths` | 모델·라이브러리를 어디서 찾았는지 보여 줌 |

말하지 않은 것을 받아쓰지 않기 위한 설정 (6장 참고):

| 옵션 | 설명 |
|---|---|
| `--no-gate` | 무음·잡음 거르기를 끈다 (들어온 소리를 전부 인식) |
| `--silence <0..1>` | 유성음 판정 RMS 기준. 기본은 잡음 바닥을 추적해 자동 |
| `--min-speech <ms>` | 결과로 인정할 최소 발화 길이 (기본 200ms) |
| `--min-conf <0..1>` | 이 신뢰도 미만 낱말은 버린다 (기본 0.4, `0` 이면 끔) |
| `--partial <모드>` | 진행 중 표시: `off` / `stable`(기본) / `raw` |
| `--max-zcr <0..1>` | 영교차율이 이보다 높으면 잡음으로 본다 (기본 0.35, `1` 이면 끔) |
| `--min-voiced <0..1>` | 낱말 구간에서 실제 발화가 차지해야 할 비율 (기본 0.6) |
| `--max-word <초>` | 낱말 하나가 이보다 길면 버린다 (기본 2.0, `0` 이면 끔) |
| `--vocab "말1,말2"` | 받아쓸 말을 한정 (기본: 출근, 퇴근) |
| `--free` | 한정하지 않고 자유 받아쓰기 |

### 예시

```bash
# 입력 장치 보기
./run.sh cli --list-devices

# 마이크로 10초 받아쓰기
./run.sh cli --seconds 10

# 파일 받아쓰기 (낱말 시각 포함)
./run.sh cli --wav 회의녹음.wav --words

# 결과만 파일로 모으기
./run.sh cli --wav 회의녹음.wav | grep '^  >' > 회의록.txt
```

`--words` 를 주면 이렇게 나옵니다.

```
  > 안녕하세요
      [  0.06-  1.14] 안녕하세요       conf 1.00
```

`conf` 는 그 낱말을 얼마나 확신하는지(0~1)입니다. 낮은 낱말은 틀렸을 가능성이
높으니, 자동 처리에서는 이 값으로 걸러낼 수 있습니다.

## 6. 받을 말 한정하기 (출근 · 퇴근)

### 기본 동작

**받는 말** 칸에 적힌 말만 받아씁니다. 처음에는 `출근, 퇴근` 입니다.

- "출근합니다", "지금 출근했습니다" → **출근** 한 건
- "이제 퇴근하겠습니다" → **퇴근** 한 건
- "오늘 회의가 있습니다" → 아무것도 기록되지 않음
- "출근. 퇴근. 출근." → **각각 따로** 세 건 (한 줄에 묶이지 않습니다)

말 하나가 사건 하나입니다. 결과 창에 들린 시각과 함께 한 줄씩 쌓이고, 머리말 옆에
`출근 2회 · 퇴근 1회` 처럼 집계가 나옵니다. **지우기** 를 누르면 집계도 함께
0 으로 돌아갑니다.

### 왜 한정하는가

작은 모델로 자유 받아쓰기를 하면 짧은 낱말을 자주 틀립니다. 이 프로그램의 시험
음원에서 실제로:

| | 자유 받아쓰기 | 받을 말을 한정 |
|---|---|---|
| "출근" | **체육 은** ✗ | **출근** ✓ |
| "퇴근" | 퇴근 ✓ | 퇴근 ✓ |

받을 말을 정해 주면 인식기가 그 말들만 후보로 두기 때문에 훨씬 정확합니다.

### 바꾸는 법

- **창에서**: 받는 말 칸에 `출근, 퇴근, 외출, 복귀` 처럼 쉼표로 적습니다.
  칸을 **비우면** 들리는 대로 모두 받아쓰는 일반 받아쓰기가 됩니다.
- **명령줄에서**: `--vocab "출근,퇴근,외출,복귀"` 또는 `--free`

> 모델이 모르는 낱말은 쓸 수 없습니다. 그런 말을 적으면 프로그램이 "모델이 모르는
> 말이 있어 그 말은 인식되지 않습니다" 라고 알려 줍니다. 짧고 흔한 두 글자 낱말이
> 가장 잘 동작합니다.

## 7. 말하지 않은 것이 받아쓰기에 섞일 때

인식기는 들어온 소리에 어떻게든 낱말을 붙이려 합니다. 그래서 아무 말도 하지
않았는데 주변 소음에 단어가 뜨거나, 확정 전 추측이 "좋 습니까" 처럼 엉뚱하게
흔들리는 일이 생깁니다. 기본 설정에서 세 가지 장치가 이를 막습니다.

| 장치 | 하는 일 | 기본값 | 끄는 법 |
|---|---|---|---|
| 발화 구간 검출 | 사람 목소리 크기의 소리가 200ms 이상 없었던 구간의 결과를 버립니다. 마이크 감도에 좌우되지 않도록 **잡음 바닥을 계속 추적**해 기준을 스스로 정합니다 | 켬 | `--no-gate` |
| 잡음 성질 판별 | 선풍기·바람·키보드처럼 **쉭쉭거리는 소리**는 크기가 충분해도 말소리로 치지 않습니다 (영교차율) | 0.35 | `--max-zcr 1` |
| 발화 비율 검사 | 인식된 낱말이 차지한 시간 동안 실제로 목소리가 60% 이상 나고 있어야 인정합니다. 짧은 소음이 긴 낱말로 둔갑하는 것을 막습니다 | 0.6 | `--min-voiced 0` |
| 길이 검사 | 낱말 하나가 2초를 넘으면 버립니다 | 2.0초 | `--max-word 0` |
| 신뢰도 거르기 | 인식기가 자신 없게(신뢰도 0.4 미만) 끼워 넣은 낱말을 결과에서 뺍니다 | 0.4 | `--min-conf 0` |
| 받을 말 한정 | 정해 둔 말이 아니면 아예 기록하지 않습니다 (6장) | 출근, 퇴근 | `--free` |
| 진행 중 표시 다듬기 | 확정 전 추측은 **직전 추측과 겹치는 앞부분만** 보여 줍니다 | `stable` | `--partial raw` 또는 `off` |

진행 중 표시가 실제로 어떻게 달라지는지 (같은 음원):

```
--partial raw (인식기가 주는 그대로)       --partial stable (기본)
──────────────────────────────────        ──────────────────────────────
… 오늘 날씨가 참                           … 오늘 날씨가 참
… 오늘 날씨가 참 좋 습니까   ← 추측         … 오늘 날씨가 참 초
… 오늘 날씨가 참 초                        … 오늘 날씨가 참 초 습니다
… 오늘 날씨가 참 초 습니다                  … 음성 인식
… 음성인식                   ← 추측         … 음성 인식 시험
… 음성 인식
… 음성 인식 시험일           ← 추측         (13번 바뀌던 것이 8번으로,
… 음성 인식 시험                             엉뚱한 추측은 아예 안 보임)
```

GUI 에서는 **진행 중 표시** 체크를 풀면 중간 추측을 아예 보지 않고 확정된 문장만
쌓입니다. 받아쓰기 결과 자체는 똑같습니다.

조용한 방에서 마이크를 10초 켜 두고 측정했을 때 잘못 기록된 건수는 **0** 이었습니다.

> 주변이 꽤 시끄럽거나 마이크 감도가 높아 여전히 헛인식이 섞인다면
> `--silence 0.02` 처럼 기준을 직접 올려 보세요. 반대로 작게 말하는 편이라 말이
> 잘려 나간다면 `--silence 0.004` 로 낮추거나 `--no-gate` 로 끌 수 있습니다.

## 8. 정확도를 높이려면

작은 모델은 가볍고 빠른 대신 받아쓰기가 완벽하지 않습니다. 예를 들어 시험 음원의
"오늘 날씨가 참 좋습니다" 는 "오리 날씨 가 참 초 습니다" 로 나옵니다.

도움이 되는 것들:

- **마이크를 가까이**. 1m 를 넘으면 정확도가 눈에 띄게 떨어집니다.
- **조용한 곳에서**. 에어컨·키보드 소리도 섞입니다.
- **또박또박, 보통 속도로**. 너무 빠르거나 뭉개면 떨어집니다.
- **헤드셋 마이크**가 노트북 내장 마이크보다 훨씬 낫습니다.
- 녹음 파일이라면 **16kHz 이상**으로 녹음된 것을 쓰세요. 전화 녹음(8kHz)은
  변환해서 넣어도 원래 정보가 없어 정확도가 낮습니다.
- 숫자·영어·전문 용어는 특히 약합니다. 중요한 자리에서는 사람이 한 번 보셔야 합니다.

더 정확한 한국어 모델이 공개되면 `fetch_deps` 로 받아 모델 칸만 바꾸면 됩니다.
(2026년 10월 기준 alphacephei.com 이 내놓은 한국어 모델은 작은 모델 하나뿐입니다.)

```bash
./fetch_deps.sh --model <모델 이름>
```

## 9. 자주 묻는 것

**인터넷에 음성이 올라가나요?**
아니요. 모델도 라이브러리도 내 컴퓨터에 있고, 인식은 전부 이 PC 안에서 끝납니다.

**몇 시간짜리 녹음도 되나요?**
됩니다. 파일은 통째로 메모리에 올려 변환하므로, 1시간 16kHz 모노 WAV 는 약
115MB 를 더 씁니다. 아주 긴 파일은 나눠서 넣는 쪽이 안전합니다.

**말하는 사람을 구분해 주나요?**
아니요. 화자 분리는 들어 있지 않습니다. (Vosk 에 화자 식별 기능이 있으나 이
프로그램에서는 쓰지 않습니다.)

**결과에 문장부호가 없습니다.**
Vosk 는 문장부호를 찍지 않습니다. 말이 끊긴 지점이 한 줄씩 나뉘므로, 그것을
문장 경계로 보시면 됩니다.

**GUI 가 뜨는 데 1초쯤 걸립니다.**
모델을 올리는 시간입니다. 그동안 창은 멈추지 않고, 다 되면 상태줄이 `준비됨` 으로
바뀝니다.

**같은 프로그램을 여러 개 띄워도 되나요?**
됩니다. 다만 각각 모델을 따로 올리므로 메모리를 그만큼 더 씁니다(개당 약 0.5GB).
