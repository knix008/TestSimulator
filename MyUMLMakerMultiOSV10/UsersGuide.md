# MyUMLMaker 사용 설명서

MyUMLMaker는 StarUML과 같은 방식으로 UML과 소프트웨어 다이어그램을 **모델 기반**으로 그리는 프로그램입니다. 클래스·시퀀스·상태 머신·액티비티 같은 UML 2 다이어그램 15종과 ER·순서도·데이터 흐름·SysML·BPMN·C4·마인드맵·와이어프레임·클라우드(AWS·Azure·GCP)·네트워크, 간트 차트·WBS·타임라인, ArchiMate 3, JSON·YAML·EBNF·정규식 다이어그램을 그리고, 요구사항을 관리·추적하고, 모델을 검증하고, Java·C#·C++·Python·TypeScript·Kotlin·PHP 코드와 SQL DDL을 만들고, 거꾸로 소스 코드를 읽어 모델로 바꿀 수 있습니다. 기준선으로 모델 변화를 비교하고, Word·PDF·HTML 문서를 만들고, StarUML(.mdj)·XMI(Enterprise Architect 등)·PlantUML·Mermaid와 모델을 주고받습니다. Windows · macOS · Linux 데스크톱 앱과 웹 브라우저에서 같은 화면으로 동작합니다.

이 설명서는 하는 일 순서로 정리되어 있습니다. 화면의 메뉴·명령 이름은 프로그램에 표시되는 이름 그대로 적었습니다(예: **파일 › 내보내기 › HTML 문서 (.html)…**는 "파일" 메뉴의 "내보내기" 하위 메뉴에 있는 "HTML 문서 (.html)…" 명령). 그림은 튜토리얼 화면을 캡처한 것입니다. 단축키는 Windows·Linux 기준이며 macOS에서는 `Ctrl` 대신 `Cmd`를 씁니다.

## 시작하기

### 처음 실행

처음 실행하면 **MyUMLMaker에 오신 것을 환영합니다** 창이 뜹니다. 튜토리얼이 예제 프로젝트로 모델 탐색기와 다이어그램부터 빠른 편집·관계·서식·레이아웃·코드 생성·내보내기·설정까지 모든 기능을 차례로 보여 준다는 안내와 함께, 튜토리얼·예제 프로젝트·사용 설명서를 찾는 곳이 적혀 있습니다.

![환영 창과 시작 페이지](docs/tutorial/images/01-welcome.jpg)

| 버튼 | 하는 일 |
|---|---|
| **튜토리얼 시작** | 예제 프로젝트로 모든 기능을 하나씩 보여 주는 튜토리얼을 시작합니다 |
| **예제 열기** | "온라인 쇼핑몰" 예제 프로젝트를 엽니다 |
| **나중에** | 창을 닫습니다. 튜토리얼은 언제든 **도움말 › 튜토리얼**(`F11`)로 볼 수 있습니다 |

환영 창은 한 번만 뜹니다. MyUMLMaker 데스크톱 앱은 여러 개를 함께 실행할 수 있습니다. 다시 실행할 때마다 창이 하나씩 더 열립니다([여러 창으로 실행하기](#여러-창으로-실행하기) 참고).

### 시작 페이지

프로젝트를 열지 않았을 때(또는 메뉴 막대 맨 앞의 **홈** 버튼, `Ctrl+Shift+H`) 보이는 화면입니다. 뒤에서는 배경이 계속 움직입니다. 메뉴 막대의 **홈** 버튼은 열어 둔 프로젝트를 닫지 않습니다. **홈** 버튼(`Ctrl+Shift+H`)을 한 번 더 누르면 그 프로젝트로 돌아갑니다.

| 영역 | 내용 |
|---|---|
| 위쪽 | 프로그램 이름·버전, "UML과 소프트웨어 다이어그램을 모델 기반으로 그리고, 코드를 만들고, 문서로 내보냅니다." 문구, 문서 단추 셋 — **사용 설명서** · **튜토리얼 문서** · **튜토리얼 동영상**(누르면 각자 별도의 창이 열림, [문서 창](#문서-창) 참고) —, **도움말** 버튼(누르면 튜토리얼 · 튜토리얼 문서 · 튜토리얼 동영상 · 사용 설명서 · 단축키 목록 · 설정 · 프로그램 정보가 나옴)과 **튜토리얼 시작** 버튼. 튜토리얼을 아직 마치지 않았다면 "처음이세요?" 안내 띠와 **시작하기** 버튼이 함께 보입니다 |
| **새로 만들기** | 21가지 템플릿 타일, **열기…**, **StarUML 프로젝트 열기 (.mdj)…**, **역공학 (코드 → 모델)**, **Mermaid / PlantUML 가져오기…** |
| **최근 파일** · **최근 폴더** | 최근에 연 파일과 폴더. ✕로 하나씩, **모두 지우기** · **폴더 기록 모두 지우기**로 한 번에 지웁니다. 폴더를 누르면 그 폴더에서 열기 창이 열립니다 |
| **도움말** | **튜토리얼 문서**, **사용 설명서**, **튜토리얼 동영상**, **단축키 목록…** |
| **예제 프로젝트** | 설치된 예제 파일(지금 언어의 것만 보임). 설치 폴더에 예제가 없으면 **온라인 쇼핑몰 (예제)** 하나가 보입니다 |
| **움직이는 배경** | 20가지 애니메이션 고르기, **움직이는 배경 바꾸기**(무작위), **배경 이미지…**, **움직임 속도**(0–300%), **시작할 때 무작위**, **자동 변경**(끄기 · 15초 · 30초 · 1분 · 2분 · 5분마다) |
| 아래쪽 | **시작할 때 시작 페이지 표시** 체크 상자 |

어떤 부분을 보일지, 최근 파일을 몇 개 보일지는 **설정 › 시작 화면**에서 정합니다. 시작 페이지를 오른쪽 클릭하면 새 프로젝트 · 열기 · 최근 파일 · 배경 바꾸기 · 튜토리얼 · 프로그램 정보 메뉴가 나옵니다.

### 템플릿으로 새 프로젝트 만들기

![새 프로젝트 만들기](docs/tutorial/images/03-templates.jpg)

시작 페이지의 템플릿 타일이나 **파일 › 템플릿으로 새 프로젝트**에서 고릅니다. 템플릿마다 맞는 다이어그램 하나와 작은 예제 그림이 들어 있습니다.

| 템플릿 | 들어 있는 것 |
|---|---|
| **빈 프로젝트** | 모델 하나와 빈 클래스 다이어그램 |
| **클래스 모델** | 클래스·상속·연관 예제 |
| **유스케이스** | 액터·유스케이스·시스템 경계 |
| **시퀀스** | 라이프라인과 메시지 |
| **상태 머신** | 상태와 전이 |
| **액티비티** | 액션·결정·흐름 |
| **컴포넌트** | 컴포넌트와 인터페이스 |
| **배치** | 노드·장치·아티팩트 |
| **ER 다이어그램** | 테이블·열·관계 (DDL 생성) |
| **순서도** | 처리·판단·흐름 |
| **데이터 흐름도** | 외부 엔터티·프로세스·저장소 |
| **SysML 요구사항** | 요구사항·블록·추적 |
| **BPMN** | 풀·태스크·게이트웨이·이벤트 |
| **C4** | 사람·시스템·컨테이너 |
| **마인드맵** | 가운데 주제와 가지 |
| **와이어프레임** | 화면 스케치 |
| **AWS 아키텍처** | VPC·서비스·연결 |
| **간트 차트** | 달력·작업·마일스톤·선후 관계 |
| **작업 분해 구조 (WBS)** | 프로젝트를 작업 항목으로 나눈 나무 |
| **ArchiMate 뷰** | 비즈니스·애플리케이션 계층과 관계 |
| **네트워크 다이어그램** | 네트워크·노드·주소 |

툴바의 **새 프로젝트**(`Ctrl+N`)는 빈 프로젝트를 만듭니다. 프로젝트는 한 번에 하나만 열리므로 새 프로젝트·템플릿·예제를 열면 지금 프로젝트를 대신합니다. 지금 프로젝트에 저장하지 않은 변경이 있으면 먼저 **저장** · **저장 안 함** · **취소**를 묻습니다([저장하지 않은 변경](#저장하지-않은-변경) 참고). 템플릿으로 만든 프로젝트는 아직 파일이 없으므로 처음 저장할 때 파일 이름을 묻습니다.

### 튜토리얼

**도움말 › 튜토리얼**(`F11`), 툴바 오른쪽의 학사모 버튼, 시작 페이지의 **튜토리얼 시작**으로 시작합니다. 튜토리얼은 실제 프로그램을 움직이며 66단계로 기능을 하나씩 보여 줍니다.

- 오른쪽 아래의 안내 상자에서 **다음** · **이전 단계** 버튼, **자동 재생**(▶)으로 넘깁니다. 자동 재생 중에는 **자동 재생 멈춤**으로 멈춥니다. 마지막 단계에서는 **마치기**를 누릅니다.
- **장 고르기** 목록으로 시작 · 모델 · 그리기 · 다이어그램 종류 · 서식·정렬 · 모델 도구 · 파일·내보내기 · 꾸미기 · 도움말 중 원하는 장으로 갑니다.
- 각 단계가 설명하는 화면 부분은 테두리로 표시됩니다. 안내 상자는 끌어서 옮길 수 있습니다. `Esc`나 ✕(**튜토리얼 끝내기 (Esc)**)로 끝냅니다.
- 튜토리얼은 자기 예제 프로젝트를 따로 열어 쓰고, 끝나면 그것을 닫고 원래 열려 있던 프로젝트로 돌아갑니다. 내 프로젝트는 바뀌지 않고, 튜토리얼이 바꾼 설정(테마·언어·배경 등)은 끝날 때 원래대로 돌아갑니다.

**튜토리얼 문서** — 튜토리얼의 모든 단계를 화면과 함께 정리한 문서입니다. 시작 페이지 위쪽의 **튜토리얼 문서** 단추나 메뉴의 **도움말 › 튜토리얼 문서**로 열면 별도의 창에 나타납니다([문서 창](#문서-창) 참고).

![튜토리얼 문서](docs/tutorial/images/65-tutorialDoc.jpg)

### 문서 창

**사용 설명서**와 **튜토리얼 문서**는 프로그램 창과 따로 움직이는 별도의 창에 열립니다. 시작 페이지 위쪽의 단추, 시작 페이지의 **도움말** 목록, 메뉴의 **도움말** 어디서 열어도 같습니다. 창은 문서마다 하나이고, 이미 열려 있으면 다시 고를 때 그 창이 앞으로 나옵니다. 보통 창처럼 제목 표시줄로 옮기고, 가장자리로 크기를 바꾸고, 최대화하고, 닫습니다. 창 위치와 크기는 다음에 열 때 그대로입니다. 프로그램(주 창)을 닫으면 문서 창도 함께 닫힙니다.

| 위쪽 막대 | 하는 일 |
|---|---|
| **장으로 이동** | 문서의 장·절 목록. 고르면 그곳으로 갑니다. 읽는 동안 지금 장이 표시됩니다 |
| **문서에서 찾기** (`Ctrl+F`) | 찾을 말을 쓰면 문서 안의 모든 곳이 표시되고 "3/12"처럼 몇 번째인지 나옵니다. `Enter`/`F3`은 다음, `Shift+Enter`/`Shift+F3`은 이전, `Esc`는 지우기 |
| **한국어** / **English** | 문서 언어를 바꿉니다 (프로그램 언어는 그대로) |
| **인쇄** (`Ctrl+P`) | 문서를 인쇄합니다 |
| **브라우저로 열기** | 같은 문서를 기본 웹 브라우저로 엽니다 |

문서의 색은 프로그램 테마를 따릅니다. 웹 브라우저판에서는 같은 문서 보기 화면이 새 탭으로 열립니다.

### 튜토리얼 동영상

튜토리얼 전체(66단계)를 자동 재생하며 녹화한 동영상입니다. 시작 페이지 위쪽의 **튜토리얼 동영상** 단추나 **도움말 › 튜토리얼 동영상**으로 열면 별도의 창에서 재생됩니다(창은 [문서 창](#문서-창)과 같이 움직입니다).

- 동영상 아래 막대로 재생·일시 정지·이동·소리·전체 화면을 다룹니다. `Space`는 재생/일시 정지, `←`/`→`는 5초 이동, `F`는 전체 화면입니다.
- 위쪽 막대: **장으로 이동**(장 목록, 시작 시각과 함께), **재생 속도**(0.5× – 2×), **전체 화면**, 한국어/English(장 이름의 언어), **플레이어로 열기**(시스템의 기본 동영상 플레이어).
- 오른쪽 목록에는 장과 단계가 시각과 함께 있고, 누르면 그곳부터 재생합니다. 지금 장이 표시되고, 동영상 아래 띠에 장이 시작하는 곳이 눈금으로 보입니다.
- 동영상은 설치 폴더의 `docs/video/MyUMLMaker-Tutorial.mp4`입니다. 동영상이 없으면 "튜토리얼 동영상이 아직 없습니다. npm run tutorial:video 로 만들 수 있습니다."라고 알려 줍니다.

## 화면 구성

위에서부터 **메뉴 막대**와 **툴바**(한 줄)가 있고, 그 아래 왼쪽에 **도구 상자**, 오른쪽에 **모델 탐색기**(위)와 **편집기**(아래)가 있습니다. 가운데 위쪽에는 프로젝트 이름과 **다이어그램 탭**이 있는 줄, 그 아래에 **다이어그램 종류 탭**(두 줄)이 있고, 그 아래가 위쪽·왼쪽에 눈금자가 붙은 다이어그램입니다. 맨 아래는 **상태 표시줄**입니다. 패널 사이의 구분자를 끌면 너비가 바뀌고, 모델 탐색기와 편집기 사이의 가로 구분자를 끌면 높이 비율이 바뀝니다. 창 오른쪽 아래 모서리를 끌면 창 크기가 바뀝니다. 창은 툴바 버튼과 메뉴가 가려지지 않는 폭보다 좁아지지 않습니다.

### 툴바

툴바 버튼은 왼쪽부터 다음 묶음으로 나뉩니다. 버튼 위에 포인터를 올리면 이름과 단축키가 나옵니다.

| 묶음 | 버튼 |
|---|---|
| 파일 | **새 프로젝트** · **열기…** · **저장** · **그림으로 내보내기…**(옆의 ▾는 **내보내기 형식 고르기** 메뉴) |
| 실행 취소 | **실행 취소** · **다시 실행** (포인터를 올리면 무엇을 되돌리는지 보입니다) |
| 클립보드·찾기 | **잘라내기** · **복사** · **붙여넣기** · **모델에서 삭제** · **찾기…**(`Ctrl+F`, [찾기](#찾기) 참고) |
| 도구 | **포인터** · **다이어그램 추가** |
| 색과 선 | **채우기 색** · **선 색** (왼쪽 반은 마지막 색을 바로 칠하고, ▾는 색 고르기 창을 엽니다) · **선 모양** |
| 배치 | **맞춤** · **자동 레이아웃** |
| 확대·표시 | − · 확대 비율 입력란 · + · **다이어그램 전체 보기** · **격자** · **눈금자** · **이동·확대 창** (켜져 있는 동안 눌린 모양, **보기 › 표시 › 격자** · **눈금자** · **이동·확대 창**과 같음) |

확대 비율 입력란에는 숫자를 직접 쓰거나 위/아래 방향키로 한 단계씩 바꿀 수 있습니다.

### 다이어그램 탭 줄

프로젝트는 한 번에 하나만 열립니다. 다이어그램 위의 줄 맨 앞에는 프로젝트 이름이 있고, 저장하지 않은 변경이 있으면 이름 옆에 ●가 붙습니다(포인터를 올리면 파일 경로). 그 뒤로 프로젝트의 **모든 다이어그램이 하나씩 탭**으로 모델 순서대로 늘어서고, 끝의 **+**는 **다이어그램 추가** 메뉴를 엽니다. 탭이 줄에 다 들어가지 않을 때만 오른쪽 끝에 ‹ ›(**왼쪽 탭으로** · **오른쪽 탭으로**)가 나타나 탭 줄을 밉니다. 자세한 사용법은 [다이어그램 탭](#다이어그램-탭)을 보세요.

그 아래의 두 줄은 **다이어그램 종류 탭**입니다. 위 줄에서 묶음을, 아래 줄에서 다이어그램 종류를 고릅니다([다이어그램 종류 탭](#다이어그램-종류-탭) 참고).

**파일 › 프로젝트 닫기**(`Ctrl+W`)는 프로젝트를 닫고 시작 페이지로 돌아갑니다.

### 도구 상자 (왼쪽)

지금 열린 다이어그램 종류에 맞는 도구가 묶음별로 나옵니다. 자세한 사용법은 [그리기](#그리기)를 보세요. 다이어그램이 열려 있지 않으면 "다이어그램을 열면 그 종류에 맞는 도구가 여기에 나옵니다."라는 안내만 보입니다.

### 모델 탐색기와 편집기 (오른쪽)

오른쪽 위의 **모델 탐색기**에는 프로젝트의 모든 요소가 트리로 나오고, 아래의 **편집기**에는 선택한 요소의 **속성** · **스타일** · **문서** · **태그·제약** 탭이 있습니다. 자세한 내용은 [모델과 다이어그램](#모델과-다이어그램)을 보세요.

### 패널 접기

![패널](docs/tutorial/images/13-toolbox.jpg)

도구 상자와 오른쪽 패널은 머리글의 화살표 버튼(**도구 패널 접기** · **속성 패널 접기**), 툴바의 패널 버튼, `Ctrl+Shift+1` · `Ctrl+Shift+2`로 접습니다. 접으면 아이콘과 제목("도구" · "모델")만 남은 좁은 줄이 되고, 맨 위의 **펼치기** 버튼으로 다시 엽니다. 접힌 도구 상자 줄에도 포인터와 자주 쓰는 도구 몇 개가 남아 있어 바로 쓸 수 있습니다.

### 상태 표시줄

| 항목 | 내용 |
|---|---|
| 알림 | 마지막 작업의 결과("저장했습니다", "실행 취소: …" 등). 평소에는 **준비** |
| 현재 다이어그램 | 지금 다이어그램의 이름 |

| 선택 | 뷰 하나를 선택하면 종류·위치·크기(예: "클래스 · 380, 40 · 160 × 120"), 여럿이면 "N개 선택", 아무것도 없으면 "뷰 N개" |
| 포인터 위치 | 다이어그램 좌표 |
| 그리기 도구 | 도구를 고른 동안만 보입니다. 누르면 포인터로 돌아갑니다 |

| 테마 · 언어 | 지금 테마 이름과 언어 |
| 확대 | 확대 비율 슬라이더와 %, **다이어그램 전체 보기** 버튼 |

상태 표시줄을 오른쪽 클릭하면 표시줄 숨기기 · 확대·축소 · 테마 · 언어 메뉴가 나옵니다.

## 모델과 다이어그램

### 모델과 뷰

MyUMLMaker에서 가장 중요한 개념은 **모델**과 **뷰**의 구분입니다. 다이어그램에 보이는 상자는 모델 요소의 "뷰"입니다. 같은 요소를 여러 다이어그램에 보여 줄 수 있고, 어느 곳에서 이름을 바꾸면 모든 다이어그램이 함께 바뀝니다.

| 동작 | 결과 |
|---|---|
| `Delete` (**다이어그램에서 삭제**) | 이 다이어그램의 뷰만 지웁니다. 요소는 모델에 남아 모델 탐색기에 계속 보입니다 |
| `Ctrl+Delete` (**모델에서 삭제**) | 요소를 모델에서 지웁니다. 모든 다이어그램의 뷰와 그 요소가 있어야 하는 관계도 함께 지워집니다 |

**모델에서 삭제** 전에는 지울 요소 목록과 함께 확인 창이 뜹니다(**설정 › 일반 › 모델에서 요소를 삭제하기 전에 묻기**로 끌 수 있습니다). 메모·텍스트·사각형 같은 주석은 모델 요소가 아니라 뷰뿐이므로 어느 쪽으로 지워도 같습니다.

**모델 › 다이어그램에 없는 요소**는 어느 다이어그램에도 보이지 않는 요소를 목록으로 보여 주고, 항목을 누르면 그 요소로 갑니다. **모델 › 모델 통계**는 요소·뷰·다이어그램 수와 종류별 개수를 보여 줍니다.

### 모델 탐색기

![모델 탐색기](docs/tutorial/images/07-explorer.jpg)

프로젝트의 모든 요소가 트리로 나옵니다: 모델·패키지·클래스와 그 속성·오퍼레이션, 관계, 다이어그램. 이름 없는 관계는 "(연관) Customer → Order"처럼 종류와 양 끝으로 표시됩니다.

| 동작 | 하는 일 |
|---|---|
| 누르기 | 요소를 선택하고, 지금 다이어그램에 있는 그 요소의 뷰도 함께 선택합니다. 편집기에 그 요소의 속성이 나옵니다 |
| `Ctrl`+누르기 | 여러 요소를 함께 선택합니다 |
| 두 번 누르기 | 다이어그램이면 엽니다. 다른 요소면 이름을 바꿉니다 |
| `F2` | 이름 바꾸기 (`Enter`로 적용, `Esc`로 취소) |
| 위/아래 방향키 | 선택을 옮깁니다. 오른쪽은 펼치기, 왼쪽은 접기 |
| `Enter` | 다이어그램을 엽니다 |
| `Delete` | 모델에서 삭제 |
| 다른 행으로 끌기 | 그 요소 안으로 옮깁니다(예: 클래스를 다른 패키지로). 넣을 수 없는 곳이면 "그곳으로 옮길 수 없습니다." |
| 다이어그램으로 끌기 | 그 다이어그램에 요소의 뷰를 만듭니다([탐색기에서 끌어 놓기](#탐색기에서-끌어-놓기) 참고) |
| `Ctrl+Up` · `Ctrl+Down` | 같은 부모 안에서 순서를 바꿉니다 (**모델에서 위로** · **모델에서 아래로**) |

트리 위의 도구는 다음과 같습니다.

- **모델에서 찾기** 입력란 — 이름이나 종류로 트리를 좁힙니다. 맞는 요소와 그 부모만 남고 모두 펼쳐집니다.
- **이름순 정렬** — 다이어그램, 구성원, 요소, 관계 순으로 묶은 뒤 이름순으로 정렬합니다.
- **모두 펼치기** · **모두 접기**

패널 머리글의 **다이어그램 추가** · **요소 추가** 버튼은 선택한 요소 아래에 새 다이어그램이나 요소를 넣습니다. 요소 추가 메뉴는 선택한 요소가 가질 수 있는 종류만 보여 주고, 종류가 많으면 분류자 · 행위 · 인스턴스 · 패키지·모델 등으로 묶어 하위 메뉴로 보여 줍니다. 새 요소는 바로 이름을 바꿀 수 있는 상태가 됩니다.

![모델과 뷰](docs/tutorial/images/08-modelView.jpg)

### 다이어그램 추가

**모델 › 다이어그램 추가**, 툴바의 **다이어그램 추가**, 모델 탐색기 머리글이나 다이어그램 탭 줄 끝의 **+**에서 고릅니다. 메뉴는 UML · ERD · 순서도 · 데이터 흐름 · SysML · BPMN · C4 · 마인드맵 · 와이어프레임 · 클라우드 · 프로젝트 관리 · ArchiMate · 네트워크 · 데이터로 묶여 있습니다(38종, [다이어그램 종류](#다이어그램-종류) 참고).

새 다이어그램은 모델 탐색기에서 선택한 패키지·모델 아래(없으면 지금 다이어그램이 있는 패키지)에 만들어지고 바로 열립니다. 종류에 따라 필요한 소유자가 자동으로 생깁니다: 시퀀스·커뮤니케이션·타이밍 다이어그램은 인터랙션 안에, 상태 머신 다이어그램은 상태 머신 안에, 액티비티·인터랙션 개요 다이어그램은 액티비티 안에, ER 다이어그램은 데이터 모델 안에, 간트 차트·WBS·타임라인은 프로젝트 계획 안에, ArchiMate 다이어그램은 ArchiMate 모델 안에, 네트워크 다이어그램은 네트워크 모델 안에, JSON·YAML·EBNF·정규식 다이어그램은 데이터 명세 안에 만들어집니다.

[다이어그램 종류 탭](#다이어그램-종류-탭) 줄 끝의 **+**(**새 {종류} 추가**)는 지금 다이어그램과 같은 종류의 다이어그램을 하나 더 만듭니다.

### 다이어그램 탭

![다이어그램 탭](docs/tutorial/images/09-workingDiagrams.jpg)

다이어그램 위의 줄에는 프로젝트의 다이어그램마다 탭이 하나씩, 모델 탐색기와 같은 순서로 있습니다. 지금 다이어그램의 탭이 강조되고, 포인터를 올리면 이름과 종류가 보입니다.

- 탭을 누르면 그 다이어그램을 엽니다. 모델 탐색기에서 다이어그램을 두 번 눌러도 됩니다.
- `Ctrl+Tab` · `Ctrl+Shift+Tab` 또는 `Ctrl+PageDown` · `Ctrl+PageUp`(**다음 다이어그램** · **이전 다이어그램**)으로 다음·이전 탭으로 갑니다.
- 탭을 두 번 누르면 그 자리에서 이름을 바꿉니다.
- 탭을 오른쪽 클릭하면 **이름 바꾸기** · **모델 탐색기에서 선택** · **이전 다이어그램** · **다음 다이어그램** · 내보내기(그림 · SVG · Mermaid · PlantUML) 메뉴가 나옵니다.
- 끝의 **+**는 **다이어그램 추가** 메뉴를 엽니다.
- 탭이 줄에 다 들어가지 않으면 오른쪽 끝에 ‹ ›(**왼쪽 탭으로** · **오른쪽 탭으로**)가 나타납니다. 다른 다이어그램을 열면 그 탭이 보이도록 줄이 저절로 밀립니다.
- 다이어그램을 지우려면 모델 탐색기에서 **모델에서 삭제**합니다. 탭에는 닫기 단추가 없습니다.

### 다이어그램 종류 탭

다이어그램 탭 줄 아래에는 두 줄짜리 **다이어그램 종류 탭**이 있습니다.

| 줄 | 내용 |
|---|---|
| 위 줄 (**다이어그램 묶음**) | UML 구조 · UML 행위 · ER · 순서도 · 데이터 흐름 · SysML · BPMN · C4 · 마인드맵 · 와이어프레임 · 클라우드 · 프로젝트 · ArchiMate · 데이터 |
| 아래 줄 (**다이어그램 종류**) | 고른 묶음의 다이어그램 종류. 예: UML 구조는 클래스 · 패키지 · 객체 · 복합 구조 · 컴포넌트 · 배치 · 프로파일, UML 행위는 유스케이스 · 액티비티 · 상태 머신 · 시퀀스 · 커뮤니케이션 · 타이밍 · 인터랙션 개요 · 정보 흐름, SysML은 요구사항 · 블록 정의 · 내부 블록 · 매개변수, 클라우드는 AWS · Azure · GCP · 네트워크, 프로젝트는 간트 차트 · WBS · 타임라인, 데이터는 JSON · YAML · EBNF · 정규식 |

- 묶음을 누르면 아래 줄이 그 묶음의 종류로 바뀝니다. 다이어그램을 열면 그 다이어그램의 묶음이 저절로 골라집니다.
- 종류 옆의 숫자는 프로젝트에 있는 그 종류의 다이어그램 수입니다.
- 종류를 누르면 그 종류에서 마지막으로 연 다이어그램(없으면 첫 다이어그램)이 열리고, 그 종류의 다이어그램이 아직 없으면 새로 만듭니다(포인터를 올리면 **{종류} 열기** 또는 **{종류} 만들기 (아직 없음)**).
- **도구 상자**에는 그 다이어그램 종류에 필요한 도구만 나옵니다.
- 아래 줄 끝의 **+**(**새 {종류} 추가**)는 지금 종류의 다이어그램을 하나 더 만듭니다.

![다이어그램 종류 탭](docs/tutorial/images/11-diagramTypes.jpg)

### 편집기

![편집기](docs/tutorial/images/12-editors.jpg)

모델 탐색기 아래의 편집기는 선택한 요소를 편집합니다. 다이어그램에서 뷰를 선택하면 그 요소, 모델 탐색기에서 고르면 그 요소, 아무것도 고르지 않으면 지금 다이어그램(다이어그램이 없으면 프로젝트)을 보여 줍니다. 모든 변경은 실행 취소 한 단계입니다. 글을 쓰는 칸은 `Enter`를 누르거나 다른 곳으로 옮기면 적용됩니다.

| 탭 | 내용 |
|---|---|
| **속성** | 요소의 모든 필드: 이름, 스테레오타입, 가시성, 추상·리프·최종 같은 표시, 타입, 다중성, 기본값, 다른 요소 참조 등. 위에는 **전체 이름**(패키지 경로)이 보입니다 |
| **스타일** | 선택한 뷰의 색·글꼴·선 모양·표시 옵션 ([서식과 정렬](#서식과-정렬) 참고) |
| **문서** | 요소에 대한 설명. 문서는 HTML·Markdown 문서와 생성한 코드의 주석에 들어갑니다 |
| **태그·제약** | 태그 값과 제약 |

**속성** 탭에는 다음 부분이 있습니다.

- **일반** — 요소 종류에 따른 필드. 타입 칸은 프로젝트의 클래스 이름과 기본 타입(int · long · String · boolean · Date …)을, ER 열의 타입 칸은 SQL 타입(INTEGER · VARCHAR · TIMESTAMP …)을 목록으로 제안합니다. 스테레오타입 칸도 entity · control · boundary · service 같은 표준 이름을 제안합니다. 참조 칸(예: 라이프라인이 나타내는 요소, 메시지의 서명)은 맞는 종류의 요소만 고를 수 있고, 옆의 **이 요소로 가기** 버튼으로 그 요소로 갑니다. 다중성은 `1`, `0..1`, `0..*`, `1..*`, `2..5` 같은 형식이어야 합니다.
- **끝 1 (꼬리)** · **끝 2 (머리)** — 연관 같은 관계의 양 끝: 이름, 가시성, 탐색 가능 여부, 집합(공유·복합), 다중성, 한정자, 파생·읽기 전용 등.
- **구성원** — 속성 · 오퍼레이션 · 매개변수 · 리터럴 · 열 · 피연산자 · 포트 · 파트 · 슬롯 · 영역 · 시간 구간 등의 목록. 머리의 **+**로 추가하고, 줄마다 **위로** · **아래로** · **삭제** 버튼이 있습니다. 구성원 이름을 누르면 그 구성원을 선택해 속성을 편집합니다(오퍼레이션을 고르면 그 매개변수를 다시 편집할 수 있습니다).
- **나타나는 다이어그램** — 이 요소를 보여 주는 다이어그램 목록. 누르면 그 다이어그램을 열고 요소를 선택합니다.
- **다이어그램 옵션** — 다이어그램을 선택했을 때. 시퀀스·커뮤니케이션 다이어그램에는 **메시지 번호 표시**, **메시지 서명**(없음 · 이름만 · 타입만 · 이름과 타입), 시퀀스 다이어그램에는 **활성 막대 표시**가 있습니다. **뷰 수**도 보입니다.

**파일 › 프로젝트 속성**은 프로젝트 자체(이름 · 작성자 · 회사 · 저작권 · 버전)를 편집기에 띄웁니다.

**태그·제약** 탭에서는 **태그 추가**로 이름 · 종류(문자열 · 참/거짓 · 숫자 · 참조 · 숨김) · 값을 넣고, **제약 추가**로 이름과 명세(예: `age >= 0`)를 넣습니다. 숨김이 아닌 태그는 다이어그램에 `{이름=값}`으로 표시됩니다.

## 그리기

### 도구 상자

![도구 상자](docs/tutorial/images/13-toolbox.jpg)

도구 상자는 지금 다이어그램 종류에 맞는 도구를 보여 줍니다. [다이어그램 종류 탭](#다이어그램-종류-탭)에서 종류를 바꾸면 도구 상자도 그 종류의 도구로 바뀝니다. 맨 위에 다이어그램 종류 이름이 있고, 그 아래에 **도구 찾기** 입력란과 **포인터** 도구가 있습니다. 도구 묶음(예: 클래스 · 관계 · 주석)은 머리를 눌러 접고 펼치며, 머리 옆의 숫자는 도구 개수입니다. 머리글의 **아이콘만 보기** 버튼은 이름을 숨기고 아이콘만 촘촘히 보여 줍니다.

| 도구 종류 | 쓰는 법 |
|---|---|
| 요소 도구 | 도구를 누른 뒤 다이어그램을 누르면 기본 크기로, 끌면 끈 크기로 만듭니다. 도구를 다이어그램 위로 끌어다 놓아도 됩니다 |
| 관계 도구 | 한 요소에서 다른 요소로 끌어 연결합니다 |

- 만든 뒤에는 포인터로 돌아갑니다. `Shift`를 누른 채 만들거나 도구를 두 번 누르면 도구가 유지되어 같은 것을 여러 개 만들 수 있습니다.
- `Esc` 또는 `Ctrl+1`로 **포인터**로 돌아갑니다. 상태 표시줄의 도구 이름을 눌러도 됩니다.
- 모든 다이어그램에는 **주석** 묶음이 있습니다: 메모 · 메모 연결 · 텍스트 · 제약 · 프레임 · 사각형 · 둥근 사각형 · 타원 · 하이퍼링크 · 그림 · 자유선.

### 요소 만들기

![클래스 만들기](docs/tutorial/images/14-createClass.jpg)

클래스를 만들면 바로 이름을 쓸 수 있습니다. `Enter`로 적용하고 `Esc`로 취소합니다. 빈 곳을 두 번 누르면(또는 오른쪽 클릭 › **여기에 추가**) 그 자리에 추가할 요소를 고르는 메뉴가 나옵니다.

속성·오퍼레이션 같은 구성원은 그것을 가질 수 있는 요소 안에 놓아야 합니다. 빈 곳에 놓으면 "속성은(는) 그것을 가질 수 있는 요소(예: 클래스) 안에 놓으세요."라고 알려 줍니다. 패키지·시스템 경계·노드·파티션 같은 컨테이너 안에 요소를 놓으면 모델에서도 그 안의 요소가 됩니다.

### 빠른 편집

![빠른 편집](docs/tutorial/images/15-quickEdit.jpg)

클래스(인터페이스·데이터 타입·시그널·열거형·엔터티 포함)를 두 번 누르거나 `F2`·`Enter`를 누르면 이름·속성·오퍼레이션을 글로 한 번에 고칩니다(StarUML의 빠른 편집). 첫 줄은 이름, `--` 줄 다음에 속성, 또 `--` 다음에 오퍼레이션을 한 줄씩 씁니다. `Ctrl+Enter`로 적용, `Esc`로 취소합니다.

```
«entity» Order
--
-id: long {id}
-orderedAt: DateTime
-status: OrderStatus = NEW
+lines: OrderLine [1..*] {ordered}
--
+total(): Money {query}
+cancel()
+addLine(in product: Product, quantity: int = 1): OrderLine
```

| 쓰는 법 | 뜻 |
|---|---|
| `+` · `-` · `#` · `~` | public · private · protected · package 가시성 |
| `/name` | 파생 속성 |
| `name: Type` | 타입. 프로젝트에 같은 이름의 클래스가 하나 있으면 그 클래스를 가리키는 참조가 됩니다 |
| `[0..*]` | 다중성 |
| `= 1` | 기본값 |
| `{readOnly}` · `{ordered}` · `{unique}` · `{id}` | 읽기 전용 · 순서 있음 · 유일 · 식별자 |
| `op(a: int, out b: String): bool` | 오퍼레이션과 매개변수(`in` · `out` · `inout`), 반환 타입 |
| `{query}` · `{abstract}` | 조회(상태를 바꾸지 않음) · 추상 오퍼레이션 |
| `«stereotype» Name` 또는 `<<stereotype>> Name` | 스테레오타입 |

구성원은 줄 순서대로 맞춰지므로, 기존 속성의 이름만 바꾸면 그 속성의 다른 설정과 연결은 그대로 남습니다.

다른 요소의 경우:

- **열거형** — `--` 아래에 리터럴을 한 줄에 하나씩 씁니다.
- **ER 엔터티** — `--` 아래에 열을 `PK id: INTEGER`, `FK customer_id: INTEGER`, `name: VARCHAR(100)`처럼 씁니다.
- **결합 프래그먼트** — 피연산자의 가드를 한 줄에 하나씩 씁니다. 줄을 늘리면 피연산자가 늘어납니다.
- **메시지** — `getItems(id)`처럼 쓰면 이름과 인자가 나뉘어 들어갑니다.
- **제약** · **상태 불변** · **BPMN 텍스트 주석** — 명세나 텍스트를 씁니다.
- **메모** · **텍스트** · 도형 — 여러 줄 텍스트를 씁니다(`Ctrl+Enter`로 적용).
- 그 밖의 요소와 선 — 이름을 씁니다. `«스테레오타입» 이름`도 됩니다.

### 빠른 단추

![빠른 단추](docs/tutorial/images/16-quickButtons.jpg)

요소 하나를 선택하면 그 아래에 작은 단추가 나옵니다. 클래스에는 **속성 추가** · **오퍼레이션 추가** · **관련 요소 추가**, 열거형에는 **리터럴 추가**, 엔터티에는 **열 추가**, 객체에는 **슬롯 추가**, 결합 프래그먼트에는 **피연산자 추가**, 타이밍 라이프라인에는 **시간 구간 추가**가 있습니다. 구성원을 추가하면 바로 빠른 편집이 열립니다. 단추는 **보기 › 표시 › 빠른 편집 단추** 또는 **설정 › 다이어그램**에서 끕니다.

### 관련 요소 추가

![관련 요소 추가](docs/tutorial/images/18-addRelated.jpg)

빠른 단추의 **관련 요소 추가**(▾)나 오른쪽 클릭 › **관련 요소 추가**는 새 요소를 옆에 만들고 관계로 이어 줍니다. 새 요소는 바로 이름을 쓸 수 있습니다.

| 선택한 요소 | 만들 수 있는 관련 요소 |
|---|---|
| 클래스 | 하위 클래스 · 상위 클래스 · 연관 클래스 · 방향 연관 클래스 · 집합 (부분) 클래스 · 합성 (부분) 클래스 · 의존 클래스 · 실체화하는 인터페이스 |
| 인터페이스 | 실체화 클래스 · 상위 클래스 · 하위 클래스 · 의존 클래스 |
| 유스케이스 | 포함 유스케이스 · 확장 유스케이스 · 연관 액터 |
| 액터 | 연관 유스케이스 · 하위 클래스 · 상위 클래스 |
| 상태 | 다음 상태 |
| 액션 | 다음 액션 |
| 마인드맵 노드 | 하위 노드 |
| 엔터티 | 참조하는 엔터티 (1:N) |
| 순서도의 처리·판단·시작/끝·데이터 | 다음 단계 |

### 관계 그리기

![관계](docs/tutorial/images/17-relationships.jpg)

관계 도구(연관 · 방향 연관 · 집합 · 합성 · 의존 · 일반화 · 인터페이스 실체화 …)를 고르고 한 요소에서 다른 요소로 끕니다. 끄는 동안 놓을 요소에 테두리가 생기고, 그 관계로 이을 수 없는 요소면 빨갛게 표시됩니다. 빈 곳에서 시작하면 "관계는 요소에서 시작해 다른 요소로 끕니다.", 빈 곳에 놓으면 "연결할 요소 위에서 놓으세요."라고 알려 줍니다.

- **메모 연결**과 **연관 클래스 링크**는 선(관계)에도 이을 수 있습니다.
- 시퀀스 다이어그램의 메시지는 끌기 시작한 높이에 놓이고, 같은 라이프라인에 놓으면 자기 메시지가 됩니다.
- 커뮤니케이션 다이어그램의 **메시지 (커넥터에)** 도구는 커넥터 위를 누르면 그 방향으로 메시지를 붙입니다.

### 선 다루기

선을 선택하면 양 끝에 네모 손잡이, 꺾임점에 채운 손잡이, 각 구간 가운데에 흰 동그라미가 나타납니다.

| 동작 | 결과 |
|---|---|
| 끝 손잡이를 다른 요소로 끌기 | 그 끝을 다른 요소로 다시 연결합니다. 모델의 관계 끝도 함께 바뀝니다 |
| 구간 가운데의 동그라미 끌기 | 그 자리에 꺾임점을 만듭니다 |
| 꺾임점 끌기 | 꺾임점을 옮깁니다 |
| 꺾임점 두 번 누르기 | 그 꺾임점을 지웁니다 |
| **서식 › 선 모양 › 꺾임점 지우기** | 손으로 꺾은 점을 모두 지웁니다 |
| 선 두 번 누르기 | 선의 이름(레이블)을 씁니다 |

### 옮기기와 크기

![옮기기와 크기](docs/tutorial/images/19-moveResize.jpg)

- **선택** — 누르면 선택, `Shift`나 `Ctrl`을 누른 채 누르면 선택에 더하거나 뺍니다. 빈 곳에서 끌면 사각형 안에 완전히 들어간 뷰를 고릅니다(`Shift`·`Ctrl`과 함께 끌면 기존 선택에 더합니다). `Ctrl+A`는 모두 선택, `Esc`는 선택 해제입니다.
- **옮기기** — 끌어서 옮깁니다. 위치는 격자에 맞춰지고(`Alt`를 누르면 맞추지 않음), `Shift`를 누르면 가로나 세로로만 움직입니다. 방향키는 격자만큼, `Shift`+방향키는 1픽셀씩 옮깁니다. 창 가장자리로 끌면 화면이 따라 움직입니다.
- **컨테이너** — 패키지·시스템 경계·노드·파티션·프레임 같은 컨테이너를 옮기면 안의 요소도 함께 움직입니다. 요소를 패키지 안에 놓으면 모델에서도 그 패키지로 옮겨집니다(**설정 › 다이어그램 › 패키지 안에 놓으면 모델에서도 옮기기**).
- **크기** — 선택한 뷰의 여덟 손잡이를 끌어 크기를 바꿉니다. 손으로 크기를 바꾸면 **자동 크기**가 꺼집니다.
- **잠금** — 스타일의 **잠금 (움직이지 않음)**을 켠 뷰는 옮기거나 크기를 바꾸거나 이름을 고칠 수 없습니다.

### 탐색기에서 끌어 놓기

![탐색기에서 끌어 놓기](docs/tutorial/images/20-dragFromExplorer.jpg)

모델 탐색기의 요소를 다이어그램에 끌어다 놓으면 그 요소의 뷰가 생기고, 이미 다이어그램에 있는 요소와의 관계도 함께 보입니다. 여러 요소를 골라 한꺼번에 놓을 수도 있습니다. 이미 그 다이어그램에 있는 요소는 새로 만들지 않고 선택만 합니다. 시퀀스 다이어그램에 클래스를 놓으면 그 클래스를 나타내는 라이프라인이 됩니다. 다이어그램을 끌어다 놓으면 그 다이어그램이 열립니다.

**모델 › 관계 모두 표시**는 다이어그램에 있는 요소들 사이의 관계 중 아직 보이지 않는 것을 모두 그려 줍니다.

### 잘라내기·복사·붙여넣기

- 다이어그램에서 복사하면 선택한 뷰와 그 요소가 복사되고, 복사한 요소들 사이의 선도 따라옵니다. 붙여넣기는 새 요소(이름이 겹치면 번호가 붙음)와 뷰를 조금 비켜서 만듭니다. 오른쪽 클릭 › **붙여넣기**는 누른 자리에 붙입니다.
- 다이어그램에서 **잘라내기**는 복사한 뒤 뷰를 다이어그램에서 지웁니다.
- 모델 탐색기에서 복사하면 요소만 복사되고, 붙여넣기는 탐색기에서 선택한 요소 안에 넣습니다. 탐색기에서 잘라내기는 모델에서 삭제합니다.
- **복제**(`Ctrl+D`)는 복사와 붙여넣기를 한 번에 합니다.
- 복사한 요소 이름은 시스템 클립보드에도 글로 들어가 다른 프로그램에 붙일 수 있습니다.

### 실행 취소와 다시 실행

![실행 취소](docs/tutorial/images/22-undo.jpg)

모든 편집은 **실행 취소**(`Ctrl+Z`)와 **다시 실행**(`Ctrl+Y` 또는 `Ctrl+Shift+Z`)으로 되돌립니다. 끌어서 옮기기, 빠른 편집, 속성 변경, 자동 레이아웃 등은 각각 한 단계입니다. 툴바 버튼에 포인터를 올리면 "실행 취소: 옮기기"처럼 무엇을 되돌리는지 보이고, 되돌린 뒤에는 상태 표시줄에 알려 줍니다. 실행 취소 기록은 열린 프로젝트에 딸려 있어, 다른 프로젝트를 열면 새로 시작합니다.

### 유스케이스 다이어그램

![유스케이스 다이어그램](docs/tutorial/images/23-useCase.jpg)

액터·유스케이스·시스템 경계를 놓고 연관·포함(«include»)·확장(«extend»)·일반화로 잇습니다. 유스케이스의 **확장점**은 속성 탭의 구성원 목록에서 추가합니다. 시스템 경계 안에 놓은 유스케이스는 함께 움직입니다.

### 시퀀스 다이어그램

![시퀀스 다이어그램](docs/tutorial/images/24-sequence.jpg)

라이프라인 사이에 동기·비동기·응답·생성·삭제 메시지를 그리면 번호와 활성 막대가 자동으로 붙습니다. 생성 메시지를 받은 라이프라인은 그 높이에서 시작하고, 삭제 메시지를 받은 라이프라인은 그 자리에서 ×로 끝납니다.

- 메시지를 선택하고 가운데의 동그란 손잡이(또는 메시지 자체)를 위아래로 끌면 순서를 바꿉니다.
- 메시지의 속성에서 **메시지 종류**, **서명 (오퍼레이션)**(받는 쪽 클래스의 오퍼레이션), **인자**, **결과 대입**, **가드**를 정합니다. 서명을 정하면 메시지 이름 대신 오퍼레이션이 표시됩니다.
- 다이어그램 옵션의 **메시지 번호 표시** · **메시지 서명** · **활성 막대 표시**로 보이는 모양을 바꿉니다.
- 라이프라인의 **나타내는 속성**으로 어떤 역할(속성)을 나타내는지 정하면 머리에 "이름: 타입"이 표시됩니다.

### 결합 프래그먼트

![결합 프래그먼트](docs/tutorial/images/25-fragments.jpg)

alt · opt · loop · par · break · critical · neg · strict · seq · ignore · consider · assert의 12가지 결합 프래그먼트, 인터랙션 사용(ref), 상태 불변, 연속, 끝점과 게이트가 있습니다. 프래그먼트를 두 번 누르면 피연산자의 가드를 한 줄에 하나씩 고치고, 빠른 단추의 **피연산자 추가**로 피연산자를 늘립니다. 인터랙션 사용의 **참조 인터랙션**은 다른 인터랙션을 가리킵니다.

### 상태 머신 다이어그램

![상태 머신 다이어그램](docs/tutorial/images/26-stateMachine.jpg)

상태(**진입 시 (entry)** · **머무는 동안 (do)** · **나갈 때 (exit)** 활동), 복합 상태, 서브머신 상태, 시작·종료·선택·접합·분기·합류·얕은 이력·깊은 이력·진입점·탈출점·종료 의사 상태가 있습니다. 전이에는 **트리거**, **가드**, **효과**를 넣으면 "트리거 [가드] / 효과"로 표시됩니다. 전이의 **종류**는 외부 · 내부 · 지역 중에서 고릅니다. 복합 상태 안에 상태를 놓으면 그 상태의 영역 안에 들어갑니다.

### 액티비티 다이어그램

![액티비티 다이어그램](docs/tutorial/images/27-activity.jpg)

액션과 행위 호출·오퍼레이션 호출·시그널 보내기·이벤트 받기·시간 이벤트, 결정·병합·분기·합류, 오브젝트 노드와 입력·출력 핀, 수영 레인(파티션)과 구조적·확장·중단 가능 영역이 있습니다. 제어 흐름과 오브젝트 흐름에 **가드**를 넣으면 `[가드]`로 표시됩니다. 파티션은 세로·가로 두 가지가 있고, 안에 놓은 액션은 함께 움직입니다.

### 컴포넌트·배치 다이어그램

![컴포넌트 다이어그램](docs/tutorial/images/28-component.jpg)

컴포넌트 다이어그램에는 컴포넌트·인터페이스(롤리팝 아이콘)·포트·아티팩트와 제공/필요 인터페이스, 조립·위임 커넥터가 있습니다. **인터페이스 (아이콘)** 도구는 인터페이스를 동그라미(롤리팝)로 그리며, 어떤 인터페이스든 **서식 › 스테레오타입 표시 › 아이콘 (인터페이스 롤리팝)**으로 바꿀 수 있습니다.

![배치 다이어그램](docs/tutorial/images/29-deployment.jpg)

배치 다이어그램에서는 노드·장치·실행 환경 안에 아티팩트를 배치하고 통신 경로로 잇습니다. 노드 같은 컨테이너 안에 놓은 요소는 함께 움직입니다.

### 그 밖의 UML 다이어그램

- **객체 다이어그램** — 객체의 **분류자**를 정하고 **슬롯 추가**로 "속성 = 값"을 넣습니다. 객체끼리는 링크로 잇습니다.
- **복합 구조 다이어그램** — 큰 클래스 안에 파트와 포트를 놓고 커넥터로 잇습니다.
- **패키지·프로파일 다이어그램** — 패키지 사이의 가져오기·병합, 스테레오타입이 메타클래스를 확장하는 관계를 그립니다.
- **커뮤니케이션 다이어그램** — 라이프라인을 커넥터로 잇고, 커넥터 위에 메시지를 붙입니다. 번호는 자동입니다.
- **타이밍 다이어그램** — 타이밍 라이프라인의 **상태 목록 (쉼표로)**을 정하고 **시간 구간 추가**로 상태와 길이를 이어 붙입니다.
- **인터랙션 개요 다이어그램** — 인터랙션 사용과 인터랙션 프레임을 제어 흐름으로 잇습니다.
- **정보 흐름 다이어그램** — 정보 항목이 **전달 항목**으로 오가는 흐름을 그립니다.

### ER 다이어그램

![ER 다이어그램](docs/tutorial/images/30-erd.jpg)

엔터티와 열(PK·FK·타입·길이), 까마귀발 표기의 관계를 그립니다. 관계 도구는 일대다 (1:N) · 일대일 (1:1) · 일대영또는일 (1:0..1) · 다대다 (N:M) · 비식별 일대다가 있습니다. 열 속성에는 **기본 키 (PK)**, **외래 키 (FK)**, **참조 열**, **NULL 허용**, **유일 (UNIQUE)**, **기본값**이 있고, 엔터티에는 **약한 엔터티** 표시가 있습니다. **도구 › SQL DDL 생성…**으로 MySQL·PostgreSQL·SQLite·SQL Server·Oracle 스크립트를 만듭니다([코드 생성](#코드-생성) 참고).

- **마인드맵 다이어그램** — 마인드맵 노드와 가지. 빠른 단추의 **관련 요소 추가 › 하위 노드**로 가지를 빠르게 늘립니다. 노드의 **방향**(자동 · 왼쪽 · 오른쪽)을 정할 수 있습니다.
- **와이어프레임 다이어그램** — 데스크톱 창 · 웹 페이지 · 모바일 화면 · 패널 프레임과 버튼 · 텍스트 · 링크 · 입력란 · 여러 줄 입력 · 체크 상자 · 라디오 단추 · 스위치 · 드롭다운 · 슬라이더 · 탭 · 그림 · 아바타 · 목록 · 표 · 구분선 · 진행 막대 · 아이콘 위젯. 위젯에는 **선택됨** · **사용 안 함** · **항목 (쉼표로)** 필드가 있습니다.
- **AWS 다이어그램** · **Azure 다이어그램** · **GCP 다이어그램** — 클라우드·리전·VPC·서브넷 같은 그룹과 서비스 타일(컴퓨트 · 스토리지 · 데이터베이스 · 네트워크 · 보안 · 분석 · 통합 · ML · 관리 · 개발 도구 · 사용자 분류별 색), 연결. 예를 들어 AWS에는 EC2 · Lambda · S3 · RDS · DynamoDB · CloudFront · API Gateway · IAM · SQS 등이 있습니다. 타일은 MyUMLMaker가 직접 그린 그림이며 각 회사의 로고는 쓰지 않습니다.

### 그 밖의 다이어그램 9종

![간트·WBS·ArchiMate·네트워크·데이터](docs/tutorial/images/32-moreDiagrams.jpg)

PlantUML과 Enterprise Architect가 그리는 종류들입니다. 다이어그램 종류 탭에서는 **프로젝트**(간트 차트 · WBS · 타임라인), **ArchiMate**, **클라우드**(네트워크), **데이터**(JSON · YAML · EBNF · 정규식) 묶음에 있습니다. 모두 PlantUML로 가져오고 내보낼 수 있습니다([PlantUML과 Mermaid](#plantuml과-mermaid) 참고).

| 다이어그램 | 도구 상자 |
|---|---|
| **간트 차트** | 달력 · 작업 · 마일스톤 · 구분선 / 선후 관계 |
| **WBS 다이어그램** | 작업 항목 / 하위 작업 |
| **타임라인 다이어그램** | 시간 축 · 사건 · 기간 / 연결 |
| **ArchiMate 다이어그램** | 비즈니스 · 애플리케이션 · 기술 · 물리 · 동기 · 전략 · 구현과 이전 · 기타 묶음의 요소 / 합성 · 집합 · 할당 · 실현 · 서비스 제공 · 접근 · 영향 · 촉발 · 흐름 · 특수화 · 연관 |
| **네트워크 다이어그램** | 네트워크 · 네트워크 노드 · 장치별 노드(database · router · switch · firewall · pc · laptop · mobile · storage · cloud · printer · queue) · 노드 그룹 / 네트워크 연결 |
| **JSON 다이어그램** · **YAML 다이어그램** | JSON 문서 · YAML 문서 / 참조 |
| **EBNF 다이어그램** | EBNF 규칙 / 참조 |
| **정규식 다이어그램** | 정규식 / 참조 |

- **간트 차트** — **달력**(**시작** · **일 수 (0 = 자동)** · **하루 너비** · **쉬는 요일** · **쉬는 날짜**)이 날짜 눈금과 왼쪽 작업 이름 칸을 그리고, 작업·마일스톤은 놓은 줄에서 날짜에 맞는 가로 위치로 저절로 옮겨지고, 구분선은 달력 폭에 맞춰집니다. **작업**에는 **시작** · **끝** · **길이**(쉬는 날을 뺀 일 수) · **진척률 (%)** · **담당자**, **마일스톤**에는 **날짜**가 있습니다. 시작 날짜가 없는 작업은 **선후 관계**로 이어진 앞 작업이 끝나는 날(없으면 프로젝트 시작일)에 시작합니다. 막대에는 진척률만큼 진하게 칠해지고 담당자가 옆에 보입니다. 작업의 빠른 단추 **다음 작업 추가**는 선후 관계로 이어진 작업을 바로 아래에 만듭니다.
- **WBS 다이어그램** — **작업 항목**(**번호** · **방향**)을 **하위 작업** 선으로 나무처럼 잇습니다. 빠른 단추 **하위 작업 추가**로 가지를 늘립니다.
- **타임라인 다이어그램** — **시간 축**(**시작** · **끝** · **하루 너비**) 위에 **사건**(**날짜**)과 **기간**(**시작** · **끝**)을 놓으면 날짜 위치로 옮겨집니다. 사건은 **연결**로 잇습니다.
- **ArchiMate 다이어그램** — ArchiMate 3의 모든 계층 요소(비즈니스 액터 · 비즈니스 프로세스 · 애플리케이션 컴포넌트 · 노드 · 목표 · 역량 · 작업 패키지 …)를 계층 색과 모양으로 그립니다. 요소의 **종류**를 바꾸면 다른 요소가 됩니다. **그룹화**는 안에 요소를 담는 틀이고, **접합 (그리고)** · **접합 (또는)**(**접합 종류**)으로 관계를 나누거나 모읍니다. **접근** 관계에는 **접근 방식**(쓰기 · 읽기 · 접근 · 읽기/쓰기), **영향**에는 **강도**, **연관**에는 **방향 있음**이 있습니다.
- **네트워크 다이어그램** — PlantUML nwdiag처럼 가로로 긴 **네트워크**(**주소** · **설명**)에 **네트워크 노드**(**장치** · **설명**)를 **네트워크 연결**(**주소**)로 붙입니다. **노드 그룹**은 노드를 묶는 틀입니다.
- **JSON · YAML 다이어그램** — 데이터 문서의 **텍스트**를 쓰면 키와 값이 나무 표로 그려집니다(**형식**: JSON · YAML).
- **EBNF · 정규식 다이어그램** — EBNF 규칙의 **식**이나 정규식을 철도 다이어그램으로 그립니다. 문서·규칙은 **참조**로 서로 잇습니다.

날짜는 `YYYY-MM-DD`로 씁니다. 잘못된 날짜, 끝이 시작보다 앞선 기간, 문법 오류가 있는 JSON·YAML·EBNF·정규식은 [모델 검증](#모델-검증)이 알려 줍니다.

## 서식과 정렬

### 스타일

![스타일](docs/tutorial/images/33-style.jpg)

편집기의 **스타일** 탭은 선택한 뷰의 모양을 정합니다(머리에 "뷰 스타일 (N개)"). 여러 뷰를 선택하면 바꾼 항목이 모두에 적용됩니다.

| 항목 | 내용 |
|---|---|
| **채우기 색** · **선 색** · **글자 색** | 색 고르기 창을 엽니다. ✕(**기본값으로**)는 다이어그램 색 구성의 색으로 되돌립니다 |
| **글꼴** · **글자 크기** | 이 뷰만의 글꼴과 크기(9–32px). 비우면 **설정 › 다이어그램**의 글꼴을 씁니다 |
| **글자 모양** | 굵게 · 기울임 |
| **선 두께** | 1 · 1.5 · 2 · 3 · 4px |
| **선 모양** | 선일 때: 기본 (설정) · 직각 · 직선 · 둥근 직각 · 곡선 |
| **스테레오타입 표시** | 레이블 («…») · 장식 아이콘 · 아이콘 (인터페이스 롤리팝) · 표시 안 함 |
| **그림자** · **자동 크기** · **이름 줄바꿈** · **잠금 (움직이지 않음)** | 요소 뷰의 표시 |
| 분류자 표시 | **속성 숨기기** · **오퍼레이션 숨기기** · **리셉션 숨기기** · **리터럴 숨기기** · **가시성 표시 (+ - # ~)** · **네임스페이스 표시** · **오퍼레이션 서명 표시** · **속성 문자열 {…} 표시** · **타입 표시** · **다중성 표시** |
| 선 표시 | **가시성 표시** · **다중성 표시** · **탐색 불가 끝에 × 표시** · **잠금** |
| **스타일 모두 지우기** | 이 뷰에 준 스타일을 모두 지웁니다 |
| **내용에 맞게** | 글에 맞는 크기로 줄이거나 늘립니다 |

같은 명령은 **서식** 메뉴와 오른쪽 클릭 메뉴에도 있습니다: **서식 › 글꼴**(굵게 `Ctrl+B` · 기울임 `Ctrl+I` · 글꼴 크게 `Ctrl+Shift+>` · 글꼴 작게 `Ctrl+Shift+<` · 글자 색), **서식 › 표시**, **서식 › 스테레오타입 표시**, **내용에 맞춰 자동 크기**(글이 바뀌면 크기가 따라감), **내용에 맞게 크기 조정**(한 번만 맞춤).

### 색

![색](docs/tutorial/images/34-colors.jpg)

툴바의 **채우기 색** · **선 색** 단추는 선택한 뷰의 색을 바꿉니다. 단추의 왼쪽 반은 아래 막대에 보이는 마지막 색을 바로 칠하고, ▾는 색 고르기 창을 엽니다. 색 고르기 창에는 **부드러운 색** 12가지와 **표준 색** 18가지, **기본값**(다이어그램 색 구성으로), **다른 색…**(시스템 색 고르기)이 있습니다.

### 선 모양

![선 모양](docs/tutorial/images/36-lineStyle.jpg)

선은 **직각** · **직선** · **둥근 직각** · **곡선** 중에서 고릅니다. 선을 고르고 툴바의 **선 모양**, **서식 › 선 모양** 또는 스타일 탭에서 바꿉니다. 모양을 바꾸면 손으로 꺾은 점은 지워집니다. 새 선의 기본 모양은 **보기 › 기본 선 모양** 또는 **설정 › 다이어그램 › 새 선의 기본 모양**에서 정하며, 스타일이 **기본 (설정)**인 선은 이 설정을 따라 함께 바뀝니다.

### 다이어그램 배경

![다이어그램 배경 창 (무늬)](docs/tutorial/images/35-diagramBackground.jpg)

다이어그램마다 자기 배경을 가질 수 있습니다. 다이어그램 색 구성(**보기 › 다이어그램 색 구성**)은 그대로 두고 그 다이어그램의 배경만 바꿉니다. 글자와 선의 색은 색 구성을 따릅니다.

- **편집기 패널**: 다이어그램의 빈 곳을 눌러 아무것도 고르지 않으면 속성 탭의 **다이어그램 옵션** 아래에 **배경** 묶음이 나옵니다. 바꿀 때마다 바로 적용되고 한 번씩 되돌리기(`Ctrl+Z`)됩니다.
- **서식 › 다이어그램 배경…**(다이어그램 빈 곳과 다이어그램 탭의 오른쪽 클릭 메뉴에도 있음, 배경 묶음 머리의 단추로도 엶)은 같은 항목과 **미리 보기**가 있는 창을 엽니다. **확인**을 누르면 한 번에 적용되고 한 번에 되돌려집니다.

| 항목 | 설명 |
|---|---|
| **종류** | **기본**(색 구성의 배경) · **색** · **그림** · **무늬** |
| **배경색** | 색 견본 12가지, **사용자 지정 색**, **기본값**(색 구성의 배경색). 그림과 무늬는 이 색 위에 그려집니다 |
| **색 불투명도** | 배경색 층의 불투명도 0–100 %. 0 %면 배경색이 완전히 투명해 화면에서는 프로그램 배경이 비칩니다 |
| **그림** | **그림 고르기…** · **지우기**. 긴 변이 2560 px보다 큰 그림은 고를 때 2560 px로 줄입니다. 그림은 프로젝트 파일 안에 함께 저장됩니다 |
| **맞춤** | **채우기**(잘라서 꽉 채움) · **맞추기**(전체가 보이게) · **바둑판식**(원래 크기로 반복) · **가운데**(원래 크기로 가운데) · **늘이기**(비율 무시) |
| **그림 불투명도** | 그림 층의 불투명도 0–100 % |
| **무늬** | **점** · **격자** · **가로줄** · **세로줄** · **사선** · **엇갈린 사선** · **체크무늬** · **크로스해치** · **물결** · **육각형** (견본을 눌러 고름) |
| **무늬 색** | 무늬를 그리는 색 (색 견본, 사용자 지정 색, **기본값**은 색 구성의 격자 색) |
| **무늬 불투명도** | 무늬 층의 불투명도 0–100 % |
| **무늬 크기** | 50–300 % |

편집 화면에서 배경은 격자와 뷰 아래에 깔리고 미니맵에도 보입니다. 바둑판식 그림과 무늬는 페이지의 0, 0에서 시작해 내보낸 그림과 같은 자리에 놓이고, 나머지 맞춤의 그림은 보이는 영역에 맞춰 놓입니다. 그림 · SVG · PDF로 내보내기, 인쇄, 발표, 문서 만들기(HTML · Word · PDF · Markdown)의 다이어그램 그림에도 배경이 들어갑니다. 다만 **그림으로 내보내기**에서 **투명**을 고르면 배경 없이 완전히 투명하게 나가고, 인쇄에서 **다이어그램 배경 인쇄**를 끄면 흰 종이에 인쇄됩니다. 불투명도가 100 %보다 낮은 부분은 PNG · WebP · BMP · TIFF · SVG에서 그만큼 투명하게 남고, 투명을 지원하지 않는 JPEG와 인쇄에서는 흰색 위에 겹쳐집니다.

배경은 .myuml 프로젝트와 StarUML(.mdj) 파일에 저장되어 다시 열어도 그대로이고, XMI로 내보낼 때는 빠집니다. 기준선 비교에서는 다이어그램의 필드 변경(배경 종류, 배경색 …)으로 나옵니다.

### 맞춤과 분배

![맞춤](docs/tutorial/images/37-align.jpg)

뷰를 둘 이상 선택하고 툴바의 **맞춤** 또는 **정렬 › 맞춤·분배**를 씁니다.

| 명령 | 하는 일 |
|---|---|

| **위쪽 맞춤** · **중간 맞춤** · **아래쪽 맞춤** | 세로 위치를 맞춥니다 |
| **가로로 균등 분배** · **세로로 균등 분배** | 셋 이상의 간격을 고르게 합니다 |
| **같은 너비** · **같은 높이** · **같은 크기로** | 크기를 맞춥니다 |

뷰를 하나만 골랐으면 "뷰를 두 개 이상 선택하세요.", 분배할 때 둘만 골랐으면 "뷰를 세 개 이상 선택하세요."라고 알려 줍니다.

### 자동 레이아웃

![자동 레이아웃](docs/tutorial/images/38-layout.jpg)

툴바의 **자동 레이아웃** 또는 **정렬 › 자동 레이아웃**에서 방향을 고릅니다: **위에서 아래로** · **아래에서 위로** · **왼쪽에서 오른쪽으로** · **오른쪽에서 왼쪽으로**. 계층형 레이아웃으로 요소를 다시 배치하며, 상속은 부모가 위(첫 줄)로 갑니다. 뷰를 둘 이상 선택했으면 선택한 뷰만 다시 배치합니다. 시퀀스 다이어그램에서는 라이프라인과 메시지 간격을 고릅니다. 배치한 뒤에는 다이어그램 전체가 보이도록 맞추고 "뷰 N개를 다시 배치했습니다."라고 알려 줍니다. 마음에 들지 않으면 `Ctrl+Z`로 되돌립니다.

### 확대와 이동

![확대와 이동](docs/tutorial/images/39-zoom.jpg)

| 방법 | 하는 일 |
|---|---|
| `Ctrl`+휠 | 포인터 자리를 기준으로 확대·축소 (10%–800%) |
| `Ctrl+=` · `Ctrl+-` · `Ctrl+0` | 확대 · 축소 · 100%로 보기 |
| `Ctrl+Shift+W` | 다이어그램 전체 보기 |
| **보기 › 확대·축소 › 선택 영역 확대** | 선택한 뷰가 화면에 차도록 확대 |
| 툴바의 −·+와 비율 입력란, 상태 표시줄 슬라이더 | 단계별로 또는 원하는 값으로 |
| 가운데 단추로 끌기, `Space`+끌기 | 화면 이동 |
| 휠 · `Shift`+휠 | 위아래 · 좌우 스크롤 |

다이어그램은 끝이 없는 바탕이라 가장자리로 그리면 저절로 넓어집니다. 오른쪽 아래의 **이동·확대 창**(미니맵)에는 다이어그램 전체와 지금 보이는 부분이 표시되고, 누르거나 끌면 그 부분으로 이동합니다. 툴바의 **이동·확대 창** 단추나 **보기 › 표시 › 이동·확대 창**으로 끄고 켭니다. 격자는 **보기 › 표시 › 격자**(또는 툴바의 **격자** 버튼), 격자 맞추기는 **격자에 맞추기**로 켜고 끕니다.

**격자** — 격자는 선으로 그려집니다. 격자 간격마다 가는 선이, 5칸마다 더 진하고 굵은 선이 있어 굵은 선으로 나뉜 큰 칸 하나가 5×5 칸입니다. 선 색은 [다이어그램 색 구성](#다이어그램-색-구성)을 따릅니다. 격자 간격(**설정 › 다이어그램 › 격자 크기**, 5–40px)은 100%일 때 한 칸의 크기입니다. 확대·축소하면 격자도 다이어그램과 함께 커지고 작아지다가, 한 칸이 화면에서 격자 크기의 절반보다 작아지거나 2.5배보다 커지는 임계점을 넘으면 한 단계 성기게(5칸이 1칸) 또는 촘촘하게(1칸이 5칸) 새로 그려집니다. 그래서 한 단계의 진한 선이 다음 단계의 가는 선이 되어 5×5 무늬가 이어집니다. 예를 들어 격자 크기가 10px이면 50–240%에서는 다이어그램 좌표 10마다(화면 5–24px), 250%를 넘으면 2마다, 50% 아래에서는 50마다 선이 있습니다. 격자에 맞추기와 방향키 이동은 지금 보이는 격자 한 칸을 따릅니다.

**눈금자** — 다이어그램 위쪽과 왼쪽 가장자리에 눈금자가 있습니다. 다이어그램 좌표를 보여 주며, 진한 격자선 자리에 숫자가 붙고 포인터의 위치가 표시됩니다. 숫자 간격은 확대 비율에 맞춰 바뀝니다(예: 50%에서는 100마다, 200%에서는 25마다). **보기 › 표시 › 눈금자**, 툴바의 **눈금자** 버튼 또는 **설정 › 다이어그램 › 눈금자**로 켜고 끕니다. 툴바의 **격자** · **눈금자** 버튼은 켜져 있는 동안 눌린 모양으로 보입니다.

다이어그램 밖(패널·메뉴 위)에서 `Ctrl`+휠을 돌리면 프로그램 화면 전체의 크기(**설정 › 글꼴 › 확대/축소**, 50–200%)가 바뀝니다.

## 모델 도구

### 모델 검증

![모델 검증](docs/tutorial/images/40-validate.jpg)

**모델 › 모델 검증**(`Ctrl+Shift+V`, 툴바의 **모델 검증**)은 모델을 34개 규칙으로 검사합니다. 문제가 없으면 "모델에 문제가 없습니다."라고 알리고, 있으면 검증 결과 창에 오류·경고 수와 목록이 나옵니다. 항목을 누르면 그 요소를 모델 탐색기와 다이어그램에서 보여 줍니다. 결과는 상태 표시줄에도 "오류 N · 경고 N"으로 남습니다. 아래쪽 [문제 패널](#문제-패널)이 열려 있으면 같은 검사가 편집할 때마다 백그라운드에서 돌아 목록과 개수가 저절로 새로 고쳐집니다. 문제 패널을 닫아 두었을 때는 **설정 › 다이어그램 › 편집할 때마다 모델 검증 (문제 패널이 닫혀 있을 때 상태 표시줄에 개수)**을 켜면 상태 표시줄의 개수만 새로 고쳐집니다.

| 규칙 | 심각도 |
|---|---|
| 이름이 없습니다 | 오류 |
| 같은 네임스페이스에 같은 이름이 있습니다 | 오류 |
| 일반화가 순환합니다 | 오류 |
| 서로 다른 종류 사이의 일반화입니다 | 오류 |
| 인터페이스 속성은 static 또는 읽기 전용이어야 합니다 | 경고 |
| 추상 클래스가 아닌 클래스에 추상 오퍼레이션이 있습니다 | 오류 |
| 실체화 대상이 인터페이스가 아닙니다 | 오류 |
| 연관 끝이 아무것도 가리키지 않습니다 | 오류 |
| 관계의 끝 요소가 없습니다 | 오류 |
| 다중성 형식이 잘못되었습니다 (n, n..m, *, n..*) | 오류 |
| 열거형에 리터럴이 없습니다 | 경고 |
| 라이프라인이 나타내는 요소가 없습니다 | 경고 |

| 종료 상태에서 나가는 전이가 있습니다 | 오류 |
| 결정 노드에서 나가는 흐름이 2개 미만입니다 | 경고 |

| 빈 다이어그램입니다 | 경고 |

| 끝 날짜가 시작 날짜보다 앞섭니다 | 오류 |
| 내용에 문법 오류가 있습니다 | 오류 |

날짜 규칙은 간트 차트·타임라인의 날짜 필드에, 문법 규칙은 JSON·YAML 문서, EBNF 규칙, 정규식에 쓰입니다. 요구사항의 충족·검증 규칙은 상태가 **승인** · **구현** · **검증됨**이고 하위 요구사항이 없는 요구사항에만 쓰입니다(하위 요구사항이 있는 요구사항은 그 하위 요구사항들이 충족·검증합니다). **제안** · **거부** · **보류** 상태는 검사하지 않습니다.

ER 다이어그램 규칙에서 열 이름과 엔터티 이름은 SQL처럼 대소문자를 가리지 않고 비교합니다(`email`과 `EMAIL`은 같은 이름). 외래 키 타입은 길이를 빼고 같은 뜻의 이름을 하나로 보아 비교합니다(`INT` = `INTEGER` = `SERIAL`, `NUMERIC` = `DECIMAL`, `VARCHAR(20)` = `VARCHAR`). 관계 규칙은 관계로 이어진 두 엔터티 중 어느 한쪽에 다른 쪽 열을 참조하는 외래 키 열이 있으면 통과합니다.

### 문제 패널

![문제 패널](docs/tutorial/images/41-problemsPanel.jpg)

다이어그램 아래의 **문제** 패널은 IDE처럼 모델을 백그라운드에서 계속 검사해, ERD나 UML에서 잘못된 곳과 고칠 자리를 보여 줍니다. 편집·실행 취소·다시 실행·파일 열기 뒤에 편집이 잠시 멈추면(약 0.4초) 쉬는 시간에 검사하므로 입력이나 끌기가 끊기지 않습니다. 검사가 오래 걸리는 큰 모델은 그만큼 더 기다렸다가(최대 3초) 검사하고, 끄는 동안에는 검사하지 않습니다.

- **열고 닫기** — **보기 › 표시 › 문제 패널**, 툴바의 **문제 패널** 버튼, `Ctrl+J`, 패널 오른쪽 위의 **×**, **설정 › 다이어그램 › 문제 패널**. 상태 표시줄의 "오류 N · 경고 N"을 눌러도 열립니다. 닫아도 필터와 선택은 그대로이고, 시작 페이지에서는 보이지 않습니다.
- **머리글** — 오류·경고 개수, **전체** · **오류** · **경고** 필터, **현재 다이어그램만**(지금 보고 있는 다이어그램에 그려진 요소의 문제만), 메시지·요소·경로·다이어그램 이름으로 거르는 입력란, 검사한 문제 수와 걸린 시간, **모두 검증**(지금 다시 검사).
- **목록** — 오류를 먼저, 그다음 경고를 요소 경로순으로 보여 줍니다. 한 줄에 심각도, 메시지, 요소 이름과 경로(`패키지::…`), 요소 종류, 그 요소가 그려진 다이어그램, 규칙 ID가 있습니다. 다이어그램에 직접 그려지지 않는 열·속성은 그것을 담은 엔터티·클래스의 다이어그램이 나옵니다.
- **찾아가기** — 줄을 누르면 모델 탐색기에서 그 요소를 펼쳐 선택하고, 그것을 보여 주는 첫 다이어그램(지금 다이어그램에 있으면 지금 다이어그램)을 열어 뷰를 선택하고 화면에 보이게 합니다. 두 번 누르면 속성 편집기에서 고칠 필드(이름, 타입, 다중성 …)로 바로 갑니다. 목록에서는 위·아래 방향키로 고르고 `Enter`로 찾아가며(`Ctrl+Enter`는 두 번 누르기와 같음), `Esc`는 다이어그램으로 돌아갑니다.
- **다이어그램 표시** — 패널이 열려 있는 동안 문제가 있는 요소의 뷰 오른쪽 위 모서리(선은 가운데)에 빨간(오류) 또는 주황(경고) **!** 표시가 붙습니다. 포인터를 올리면 메시지가 보이고, 누르면 그 문제가 목록에서 선택됩니다.
- **크기** — 패널 위의 경계를 끌어 높이를 바꿉니다(90픽셀부터 창 높이의 60%까지). 높이는 기억되어 다음 실행에도 그대로입니다.

### 찾기

![찾기](docs/tutorial/images/42-find.jpg)

**편집 › 찾기…**(`Ctrl+F`)는 **모델에서 찾기** 창을 엽니다. **찾을 내용**을 쓰고 **찾기**를 누르면 이름·문서·종류·타입으로 모델 전체에서 요소를 찾습니다. **옵션**은 **대/소문자 구분** · **단어 단위** · **문서 포함**입니다. 결과에는 이름, 종류, 전체 이름(패키지 경로)이 보이고, 누르면 그 요소를 모델 탐색기에서 펼쳐 선택하고 그 요소가 있는 다이어그램을 엽니다.

모델 탐색기 위의 **모델에서 찾기** 입력란은 트리를 바로 좁히는 더 가벼운 방법입니다.

### 코드 생성

![코드 생성](docs/tutorial/images/43-codegen.jpg)

**도구 › 코드 생성…**(`Ctrl+Shift+G`)은 **코드 생성** 창을 엽니다. 왼쪽에서 설정을 고르면 오른쪽에 생성될 파일 목록과 내용이 바로 미리 보입니다(**파일 N개**).

| 항목 | 내용 |
|---|---|
| **언어** | Java · C# · C++ · Python · TypeScript · Kotlin · PHP · SQL (DDL) |
| **범위** | **프로젝트 전체** 또는 모델 탐색기(다이어그램)에서 선택한 요소(패키지·클래스 등) |
| **저장** | 데스크톱 앱: **폴더에 파일로** 또는 **ZIP 하나로**. 웹 버전은 ZIP |
| 언어별 옵션 | **들여쓰기 칸 수** · **탭으로 들여쓰기** · **머리 주석 넣기** · **머리 주석 내용** · **문서를 주석으로** · **getter/setter 만들기**(Java·C#·PHP) · **컬렉션 타입**(List · std::vector · list · array) · **TODO 주석** · **타입 힌트**(Python·PHP) · **#pragma once**(C++) |
| SQL 옵션 | **SQL 방언**(MySQL / MariaDB · PostgreSQL · SQLite · SQL Server · Oracle) · **DROP TABLE 먼저** · **이름에 따옴표** · **외래 키 제약** |

**생성**을 누르면 폴더를 고르거나(폴더에 파일로) ZIP 파일 이름을 정합니다.

- 클래스 · 인터페이스 · 열거형 · 데이터 타입 · 시그널마다 파일 하나가 생깁니다(C++는 `.h`와 `.cpp` 두 개).
- 패키지는 폴더가 되고, 언어에 맞는 package · namespace 선언이 붙습니다.
- 상속·인터페이스 구현·연관(탐색 가능한 끝은 필드, 다중성이 여럿이면 컬렉션)·오퍼레이션과 매개변수·반환 타입이 들어가고, 요소의 문서가 문서 주석이 됩니다.
- 타입 이름은 언어에 맞게 바뀝니다(예: `String` → C#의 `string`, C++의 `std::string`, Python의 `str`).
- SQL은 선택 범위 안의 ER 데이터 모델에서 테이블·열·기본 키·외래 키를 만듭니다. **도구 › SQL DDL 생성…**은 언어를 SQL로 골라 둔 채 같은 창을 엽니다.
- 모델 탐색기의 오른쪽 클릭 › **코드 생성…**으로 그 요소만 바로 만들 수도 있습니다.
- 코드를 만들 분류자가 없으면 "코드를 만들 분류자가 없습니다."라고 알려 줍니다.

### 역공학 (코드 → 모델)

![역공학](docs/tutorial/images/47-reverse.jpg)

**도구 › 역공학 (코드 → 모델)**(`Ctrl+Shift+R`, 툴바 버튼, 시작 페이지)은 언어를 고르는 메뉴를 엽니다.

| 메뉴 항목 | 읽는 파일 |
|---|---|
| Java (.java) | 패키지·클래스·인터페이스·열거형, 필드·메서드·생성자, extends·implements |
| C# (.cs) | 네임스페이스·클래스·인터페이스·열거형·구조체, 필드·속성·메서드 |
| C++ (.h, .hpp, .hh, .hxx, .cpp, .cc, .cxx) | 네임스페이스 → 패키지, 클래스·구조체·공용체·열거형(`enum class` 포함), `public:` · `protected:` · `private:` 구역, 필드(static, const → 읽기 전용)·메서드(순수 가상 `= 0` → 추상)·생성자, 기반 목록 → 일반화·실체화. 순수 가상 메서드만 있는 클래스는 인터페이스가 됩니다. `std::vector` · `std::array` 같은 컬렉션은 다중성 `*`, 포인터는 `0..1`, 스마트 포인터(`std::unique_ptr` 등)는 그 대상 타입이 됩니다 |
| Python (.py, .pyi) | 모듈 폴더·클래스·속성·메서드, 타입 힌트 |
| TypeScript (.ts, .tsx, .mts, .cts) | 폴더·클래스·인터페이스·열거형, 속성·메서드 |
| SQL (DDL) (.sql, .ddl) | `CREATE TABLE` → ER 데이터 모델의 엔터티·열·기본 키·외래 키 관계 |
| **폴더 전체 (언어 자동 판별)…** | 데스크톱 앱: 폴더 안의 소스를 모두 찾아 가장 많은 언어로 읽습니다 |

파일을 여러 개 고를 수 있습니다. 읽은 결과는 모델 탐색기에서 선택한 모델·패키지(없으면 첫 모델) 안에 들어갑니다. 패키지·네임스페이스·폴더는 패키지가 되고, 상속과 구현은 일반화·인터페이스 실체화가 되며, 읽은 클래스 타입의 필드는 탐색 가능한 연관이 됩니다. 코드를 읽으면 "역공학 결과" 클래스 다이어그램이, SQL을 읽으면 ER 다이어그램이 만들어지고 자동으로 배치됩니다. 풀지 못한 타입 등은 **역공학 경고** 창에 나옵니다. 소스 파일을 창에 끌어다 놓아도 역공학합니다.

### PlantUML과 Mermaid

![Mermaid·PlantUML 가져오기](docs/tutorial/images/48-textImport.jpg)

**파일 › 가져오기 › Mermaid / PlantUML 가져오기…**는 텍스트를 모델 요소와 다이어그램으로 바꿉니다. **형식**(Mermaid · PlantUML)을 고르고 글을 붙여 넣은 뒤 **가져오기**를 누릅니다. **예제** 목록에서 고르면 그 예제 글이 들어갑니다(Mermaid: 클래스 · 시퀀스 · 순서도 · ER · 상태, PlantUML 21가지: 클래스 · 객체 · 유스케이스 · 시퀀스 · 액티비티 · 상태 · 컴포넌트 · 배치 · 타이밍 · ER · 마인드맵 · 간트 · WBS · 타임라인 · ArchiMate · 네트워크 · JSON · YAML · EBNF · 정규식 · Salt 화면).

| 형식 | 가져오고 내보낼 수 있는 다이어그램 |
|---|---|
| PlantUML `@startuml` | PlantUML의 모든 UML 다이어그램: 클래스 · 객체 · 패키지 · 프로파일 · 유스케이스 · 컴포넌트 · 배치 · 복합 구조 · 정보 흐름 · 시퀀스 · 액티비티(새 문법과 옛 문법) · 상태 · 타이밍 · ER(IE `entity` 표기), ArchiMate(archimate 스프라이트·매크로) |
| PlantUML의 다른 블록 | `@startmindmap`(마인드맵) · `@startgantt`(간트 차트) · `@startwbs`(WBS) · `@startchronology`(타임라인) · `@startnwdiag`(네트워크) · `@startjson` · `@startyaml` · `@startebnf` · `@startregex` · `@startsalt`(와이어프레임) |
| Mermaid | 가져오기: `classDiagram` · `sequenceDiagram` · `flowchart`/`graph` · `erDiagram` · `stateDiagram`/`stateDiagram-v2` |

- PlantUML 전처리기를 따릅니다. 주석, `!define`과 `!$변수` 치환, `!if` · `!ifdef`를 적용하고, `!include` · `skinparam` · 스타일 · 범례 · 머리글·바닥글 같은 꾸밈은 건너뜁니다.
- 건너뛰었거나 이해하지 못한 줄이 있으면 가져온 뒤 **가져오기 경고 N개** 창에 목록으로 보여 줍니다.
- 가져온 요소와 다이어그램은 선택한 패키지(없으면 첫 모델)에 들어가고 다이어그램이 열립니다.
- `.mmd` · `.mermaid` · `.puml` · `.plantuml` · `.pu` 파일을 열거나 창에 끌어다 놓으면 이 창이 그 내용으로 열립니다. `@start…`로 시작하는 어떤 PlantUML 블록(`@startuml` · `@startgantt` · `@startjson` …)이나 Mermaid 글을 복사해 두고 **붙여넣기**(`Ctrl+V`)하거나 창에 끌어다 놓아도 열립니다.
- 다른 종류의 Mermaid 다이어그램은 "이 Mermaid 다이어그램 종류는 가져올 수 없습니다 (클래스·시퀀스·순서도·ER·상태만)."라고 알려 줍니다.

반대로 **파일 › 내보내기 › PlantUML (.puml)…** · **Mermaid (.mmd)…**는 지금 다이어그램을 텍스트로 씁니다. PlantUML은 위 표의 모든 종류(와이어프레임은 Salt로)를 내보냅니다. 커뮤니케이션 다이어그램은 시퀀스로, 인터랙션 개요는 액티비티로, 프로파일은 클래스 다이어그램으로 씁니다. Mermaid는 클래스 · 시퀀스 · 순서도 · ER · 상태 머신 · 유스케이스 · 액티비티(유스케이스와 액티비티는 flowchart로) 다이어그램을 내보냅니다.

## 요구사항과 추적

Enterprise Architect처럼 요구사항마다 속성을 관리하고, 요구사항과 다른 요소 사이의 추적 관계를 표와 행렬로 다룹니다. 요구사항은 SysML 요구사항 다이어그램의 **요구사항** 도구로 만듭니다.

### 요구사항 속성

요구사항의 속성 탭에는 다음 필드가 있습니다.

| 필드 | 값 |
|---|---|
| **ID** | 새 요구사항을 만들면 프로젝트에서 가장 큰 `REQ-` 번호 다음 번호가 저절로 붙습니다(새 프로젝트는 `REQ-001`). 직접 고칠 수 있습니다 |
| **텍스트** | 요구사항 본문 |
| **종류** | 기능 · 비기능 · 성능 · 인터페이스 · 사용성 · 신뢰성 · 보안 · 설계 제약 · 물리 · 비즈니스 · 사용자 |
| **상태** | 제안 · 승인 · 구현 · 검증됨 · 거부 · 보류 |
| **우선순위** | 높음 · 중간 · 낮음 |
| **난이도** · **안정성** | 낮음 · 중간 · 높음 |
| **위험** | (없음) · 낮음 · 중간 · 높음 |
| **검증 방법** | (없음) · 분석 · 시연 · 검사 · 시험 |
| **버전** · **작성자** · **단계** | 자유 입력. 작성자는 처음에 프로젝트 속성의 작성자로 채워집니다 |

다이어그램의 요구사항 상자에는 `Id`와 `Text` 아래에 `Status = …, Priority = …`가, 위험이나 검증 방법을 정했으면 `Risk = …, Verify = …`가 함께 보입니다.

### 요구사항 목록

![요구사항 목록](docs/tutorial/images/44-requirements.jpg)

**모델 › 요구사항 목록**은 프로젝트의 모든 요구사항을 표로 보여 줍니다.

- 열: **ID** · **이름** · **종류** · **상태** · **우선순위** · **위험** · **검증 방법** · **충족** · **검증** · **파생**(만족·검증·파생 관계로 이어진 요소 수).
- 머리글을 누르면 그 열로 정렬하고, 다시 누르면 반대로 정렬합니다.
- 위쪽의 입력란(**ID, 이름, 본문으로 거르기**)과 **모든 상태** · **모든 우선순위** 목록으로 거르고, 오른쪽에 "N개 중 M개"가 보입니다.
- **상태**와 **우선순위**는 표에서 바로 바꿉니다(실행 취소 한 단계, **요구사항 편집**).
- 승인 · 구현 · 검증됨 상태의 하위 요구사항 없는 요구사항에 충족·검증 요소가 없으면 그 칸이 강조됩니다("승인된 요구사항인데 연결된 요소가 없습니다").
- ID를 누르면 그 요구사항을 모델 탐색기와 다이어그램에서 보여 줍니다.
- **CSV 내보내기**는 지금 보이는(거른) 행을 CSV 파일로 저장합니다.

목록은 열려 있는 동안 편집·실행 취소를 따라 새로 고쳐집니다.

### 추적 매트릭스

![추적 매트릭스](docs/tutorial/images/45-traceMatrix.jpg)

**모델 › 추적 매트릭스**는 요소 사이의 관계를 격자로 보여 줍니다. 처음에는 행이 요구사항, 열이 요구사항과 가장 많이 이어진 요소 종류입니다.

| 항목 | 내용 |
|---|---|
| **행** · **열** | 요소 종류(**행 요소 종류** · **열 요소 종류**, 괄호 안은 개수)와 패키지(**행 패키지** · **열 패키지**, 기본은 **프로젝트 전체**). 가운데 단추는 **행과 열 바꾸기** |
| **관계** | **모든 관계** 또는 한 가지 관계 종류(만족 · 검증 · 파생 · 추적 · 의존 …) |
| **새 관계** | 칸을 눌러 만들 관계의 방향: **행 → 열** · **열 → 행** |

- 칸에는 관계 방향이 표시됩니다: → 행이 출발, ← 행이 대상, ↔ 방향 없음. 포인터를 올리면 관계 종류가 보입니다.
- **관계**에서 한 종류를 고르면 칸을 눌러 그 관계를 만들거나(빈 칸) 지웁니다(있는 칸). 모두 실행 취소할 수 있습니다(**추적 관계 변경**). **모든 관계**일 때 칸을 누르면 "칸을 눌러 관계를 만들거나 지우려면 관계 종류를 하나 고르세요."라고 알려 줍니다.
- 관계가 하나도 없는 행은 강조되고, 위쪽에 "관계 없는 행 N / M"이 보입니다. 마지막 행·열(Σ)은 합계입니다.
- 행·열 머리글을 누르면 그 요소로 갑니다. 행·열이 많으면 아래쪽의 쪽 단추로 넘깁니다.
- **복사**는 매트릭스를 표 형식 텍스트로 클립보드에 넣고, **CSV 내보내기**는 CSV 파일로 저장합니다.

### 문서에 들어가는 요구사항

**HTML 문서 (.html)…** · **Markdown 문서 (.zip)…**와 [문서 생성](#문서-생성)의 문서에는 요구사항 표(ID · 이름 · 종류 · 상태 · 우선순위 · 위험 · 검증 방법 · 충족 · 검증 · 본문)가 들어갑니다. 요구사항 규칙은 [모델 검증](#모델-검증)을 보세요.

## 기준선과 문서

### 기준선

![기준선과 비교](docs/tutorial/images/46-baselines.jpg)

**기준선**은 어느 시점의 모델을 이름 붙여 남겨 둔 스냅숏입니다. **모델 › 기준선…**으로 **기준선** 창을 엽니다.

- **이름**(비우면 프로젝트 이름과 날짜) · **메모** · **범위**(**프로젝트 전체** 또는 모델 탐색기에서 고른 패키지)를 정하고 **기준선 만들기**를 누릅니다.
- 목록에는 기준선마다 이름, 만든 때, 범위, 요소 수, 메모가 있고, 오른쪽 단추로 **현재 모델과 비교** · **.myuml 로 내보내기**(그 시점 모델을 프로젝트 파일 하나로) · **삭제**를 합니다.
- 기준선은 `.myuml` 프로젝트 파일 안에 함께 저장됩니다. 만들기와 삭제도 실행 취소할 수 있습니다. 템플릿(`.mumlt`)과 StarUML `.mdj`로 저장할 때는 기준선이 빠집니다.
- 창 아래의 **파일과 비교…**(또는 **모델 › 파일과 비교…**)는 다른 `.myuml` · `.mumlt` · `.mdj` 파일과 지금 모델을 비교합니다.

### 비교

비교 창(**{이름} 과(와) 비교**)은 기준선(또는 파일)과 지금 모델의 차이를 보여 줍니다.

- 위쪽에 **추가 N** · **삭제 N** · **변경 N** 개수가 있습니다.
- **보기**에서 추가 · 삭제 · 변경과 요소 · 멤버 · 관계 · 다이어그램을 골라 거르고, **글자로 거르기**로 이름을 찾습니다.
- 왼쪽 목록은 바뀐 요소를 소유자 아래에 나무처럼 보여 주고(이름이 바뀌면 "… 에서 이름 바뀜"), 행을 고르면 오른쪽에 **항목** · **이전** · **현재** 표로 바뀐 필드가 나옵니다. 다이어그램은 추가·삭제·이동·크기 변경·모양이 바뀐 뷰 수로 보입니다.
- **요소로 이동**은 그 요소를 모델 탐색기와 다이어그램에서 보여 줍니다(행을 고르기만 해도 갑니다).
- **기준선에서 복원**은 바뀐 요소를 기준선의 내용으로 되돌리거나 지워진 요소를 원래 소유자 안에 다시 넣습니다. 실행 취소 한 단계입니다(**기준선에서 복원**).

### 문서 생성

![문서 생성](docs/tutorial/images/53-generateDocument.jpg)

**도구 › 문서 생성…**은 템플릿으로 Word · PDF · HTML 문서를 만듭니다.

| 항목 | 선택 |
|---|---|
| **범위** | **프로젝트 전체** 또는 모델 탐색기에서 고른 패키지 |
| **템플릿** | **전체 모델 보고서** · **요구사항 명세서** · **설계 문서 (클래스 + 다이어그램)** · **유스케이스 명세서** · **데이터 사전 (ER)** |
| **구성** | **표지** · **목차** · **다이어그램 그림** · **설명** · **속성 값** · **속성 / 열** · **오퍼레이션** · **관계** · **태그와 제약** · **요구사항 표** (템플릿을 고르면 맞는 항목이 켜지고, 하나씩 끄고 켤 수 있습니다) |
| **언어** | 한국어 · English |
| **형식** | Word (.docx) · PDF · HTML |
| **제목** · **작성자** · **버전** · **날짜** | 표지에 들어갑니다. 처음에는 프로젝트 이름·작성자·버전과 오늘 날짜 |

템플릿은 문서에 넣을 요소와 다이어그램을 고릅니다. 요구사항 명세서는 요구사항과 요구사항 다이어그램, 설계 문서는 클래스·인터페이스·컴포넌트·블록 등과 구조·행위 다이어그램, 유스케이스 명세서는 액터·유스케이스와 유스케이스 다이어그램, 데이터 사전은 ER 엔터티와 ER 다이어그램을 담습니다. **생성**을 누르면 파일 이름을 묻고 저장합니다. 마지막으로 고른 템플릿·구성·언어·형식은 기억됩니다.

- **Word (.docx)** — 제목·장 스타일, 목차, 표, 다이어그램 PNG 그림, 쪽 번호가 들어갑니다. 목차는 Word에서 문서를 열 때 갱신됩니다.
- **PDF** — A4 쪽마다 그림으로 만들어지므로 한글이 보이는 그대로 인쇄됩니다(쪽의 글자는 선택·검색되지 않습니다).
- **HTML** — 다이어그램이 SVG로 들어간 파일 하나입니다.

## 파일과 내보내기

### 저장

![저장](docs/tutorial/images/49-save.jpg)

프로젝트는 모델과 모든 다이어그램을 담은 `.myuml` 파일 하나에 저장됩니다(JSON 형식). 예전 형식인 `.muml` 파일도 그대로 열리며, 저장할 때는 `.myuml` 파일 이름을 묻습니다.

| 명령 | 하는 일 |
|---|---|
| **저장** (`Ctrl+S`) | 지금 파일에 저장합니다. 새 프로젝트·템플릿·가져온 파일은 파일 이름을 묻습니다 |
| **다른 이름으로 저장…** (`Ctrl+Shift+S`) | 새 파일 이름으로 저장합니다 |
| **템플릿으로 저장…** | `.mumlt` 템플릿으로 저장합니다 |

`Ctrl+Alt+S`(**모두 저장**)도 그대로 쓸 수 있습니다. 프로젝트가 하나만 열리므로 수정된 프로젝트를 저장합니다.

**설정 › 다이어그램 › 자동 저장 (저장된 파일)**을 1 · 5 · 10 · 30분으로 정하면 한 번 저장한 파일을 그 간격마다 저장합니다(데스크톱 앱). **설정 › 일반 › 시작할 때 지난번에 연 파일 다시 열기**를 켜면 다음 실행 때 열어 둔 파일을 다시 엽니다. 데이터베이스를 설정해 두면 저장할 때 데이터베이스에도 함께 저장됩니다([데이터베이스 저장](#데이터베이스-저장) 참고).

### 파일 메뉴

![파일 메뉴](docs/tutorial/images/50-fileMenu.jpg)

### 열기

**열기…**(`Ctrl+O`)는 `.myuml`(프로젝트, 예전 `.muml`도), `.mumlt`(템플릿), `.mdj`(StarUML 프로젝트), `.xmi` · `.xml` · `.uml`(XMI 2.x, [XMI로 주고받기](#xmi로-주고받기) 참고)을 엽니다. 프로젝트는 한 번에 하나만 열리므로, 연 파일이 지금 프로젝트를 대신합니다. 지금 프로젝트에 저장하지 않은 변경이 있으면 먼저 **저장하지 않은 변경** 창에서 **저장** · **저장 안 함** · **취소**를 묻습니다. 파일을 여러 개 고르면 첫 파일만 열립니다. 지금 열려 있는 파일을 다시 열면 "이미 열려 있습니다"라고 알려 줍니다. 최근 파일, 끌어다 놓기, 데이터베이스에서 열기도 같은 방식으로 지금 프로젝트를 대신합니다. 템플릿을 열면 그 내용으로 새 프로젝트가 만들어지고(원본 템플릿은 그대로), StarUML·XMI 파일을 열면 가져온 프로젝트가 되어 저장할 때 `.myuml` 이름을 묻습니다.

데스크톱 앱을 설치하면 `.myuml`과 `.mumlt` 파일이 MyUMLMaker에 연결되어, 탐색기·Finder에서 두 번 누르면 바로 열립니다. 설치하면 `.myuml` 파일에는 "MYUML"이라고 적힌 MyUMLMaker 프로젝트 문서 아이콘이 붙습니다.

### 템플릿

**파일 › 템플릿으로 저장…**은 지금 프로젝트를 `.mumlt`로 저장합니다. 템플릿을 열면 늘 이름 없는 새 프로젝트가 만들어지므로, 자주 쓰는 패키지 구조·스테레오타입·예제 다이어그램을 담아 두고 새 작업의 출발점으로 쓰기 좋습니다. 템플릿에서 만든 프로젝트는 다이어그램 탭 줄 맨 앞의 프로젝트 이름 옆 아이콘이 템플릿 모양입니다.

### StarUML과 주고받기

![StarUML 호환](docs/tutorial/images/55-starUml.jpg)

- **파일 › 가져오기 › StarUML 프로젝트 열기 (.mdj)…**(또는 **열기…**)는 StarUML 프로젝트의 모델과 다이어그램을 그대로 엽니다. MyUMLMaker의 모델은 StarUML과 같은 요소 종류와 필드 이름을 쓰므로 모델 부분은 그대로 옮겨지고, 다이어그램의 뷰도 변환됩니다.
- **파일 › 내보내기 › StarUML 프로젝트 (.mdj)…**는 지금 프로젝트를 StarUML에서 열 수 있는 `.mdj`로 씁니다(기준선은 빠집니다).

### XMI로 주고받기

![XMI와 PlantUML](docs/tutorial/images/54-xmi.jpg)

XMI 2.x(OMG UML 2.5 XMI)로 Enterprise Architect · MagicDraw(Cameo) · Papyrus 같은 도구와 모델을 주고받습니다.

- **파일 › 가져오기 › XMI 열기 (Enterprise Architect, MagicDraw, Papyrus)…** — `.xmi` · `.xml` · `.uml` 파일을 가져온 프로젝트로 엽니다(지금 프로젝트를 대신함). **열기…**와 끌어다 놓기로도 열립니다. Enterprise Architect 2.1 / 2.5 내보내기는 다이어그램과 요소 위치, 태그 값, 메모까지 읽고, MagicDraw · Papyrus 파일은 다이어그램 정보(UML DI · GMF)가 있으면 그것을 씁니다. 다이어그램 정보가 없으면 패키지마다 클래스 다이어그램을 만들어 자동으로 배치합니다.
- 읽지 못한 부분은 건너뛰고, 열고 나면 "…을(를) 가져왔습니다. 경고 N개 — 첫 번째: …"처럼 경고 수와 첫 경고를 알려 줍니다. XMI 가져오기는 오류로 멈추지 않습니다.
- **파일 › 내보내기 › Enterprise Architect용 XMI 2.5 (.xmi, 다이어그램 포함)…** — 모델과 함께 Enterprise Architect 확장으로 다이어그램과 요소 위치를 써서, EA에서 가져오면 그린 모양 그대로 보입니다.
- **파일 › 내보내기 › XMI 2.5, 모델만 (.xmi)…** — 다이어그램 없이 표준 XMI 모델만 씁니다(MagicDraw · Papyrus 등).

주고받는 것: 패키지·모델·프로파일, 클래스·인터페이스·데이터 타입·열거형·시그널·컴포넌트·노드·아티팩트·액터·유스케이스와 그 속성·오퍼레이션·매개변수·리터럴, 일반화·인터페이스 실체화·연관(끝 포함)·여러 종류의 의존·포함·확장·프로파일 확장, 상태 머신·액티비티·인터랙션, 인스턴스, 메모와 문서, 스테레오타입 적용. ER · BPMN · C4 같은 UML이 아닌 표기는 XMI로 내보내지 않습니다.

### 모델 조각

모델 조각(`.mfj`)은 요소 하나(예: 패키지 하나와 그 안의 모든 것)를 담은 파일로, StarUML과도 주고받을 수 있습니다.

- **파일 › 내보내기 › 모델 조각 내보내기 (.mfj)…** 또는 모델 탐색기의 오른쪽 클릭 › **모델 조각 내보내기 (.mfj)…** — 선택한 요소를 조각으로 저장합니다.
- **파일 › 가져오기 › 모델 조각 가져오기 (.mfj)…** — 조각을 모델 탐색기에서 선택한 요소(넣을 수 없으면 첫 모델) 안에 넣습니다. `.mfj` 파일을 열거나 창에 끌어다 놓아도 됩니다.

### 그림으로 내보내기

![그림으로 내보내기](docs/tutorial/images/51-exportImage.jpg)

**파일 › 내보내기 › 그림으로 내보내기…**(툴바의 내보내기 버튼)는 **이미지로 내보내기** 창을 엽니다. 마지막으로 고른 설정이 기억됩니다.

| 항목 | 선택 |
|---|---|
| **파일 형식** | PNG · JPEG · WebP · BMP · TIFF · SVG |
| **배경** | 투명 · 흰색 (JPEG는 투명 배경을 지원하지 않아 흰색). 흰색을 고르면 다이어그램 배경([다이어그램 배경](#다이어그램-배경))이 함께 나갑니다 |
| **내보낼 영역** | 다이어그램 전체 · 선택한 뷰 |
| **배율** | 1× · 2× · 3× (SVG는 벡터라 배율과 상관없이 선명) |
| **품질** | JPEG · WebP의 압축 품질 (40–100%) |
| **이미지 크기** | 만들어질 그림의 픽셀 크기 |

투명 배경으로 저장하면 문서·슬라이드 위에 바로 겹쳐 쓸 수 있습니다. 그 밖에:

- **SVG로 내보내기 (현재 다이어그램)…** — 지금 다이어그램(뷰를 선택했으면 선택한 뷰만)을 SVG로 바로 저장합니다.
- **모든 다이어그램을 그림으로 (.zip)…** — 프로젝트의 모든 다이어그램을 2배 PNG로 만들어 번호를 붙인 ZIP 하나로 저장합니다.
- **PDF로 내보내기 (모든 다이어그램)…** — 모든 다이어그램을 인쇄 설정(용지·방향·여백·머리글·바닥글)대로 배치한 PDF로 저장합니다.

내보내기와 인쇄에는 **다이어그램 색 구성**과 기본 선 모양이 그대로 쓰입니다.

### 문서로 내보내기

![문서와 다른 형식](docs/tutorial/images/52-exportDocs.jpg)

- **HTML 문서 (.html)…** — 검색할 수 있는 한 장짜리 HTML 문서를 만듭니다. 왼쪽에 모델의 탐색 트리, 오른쪽에 요소마다 종류·전체 이름·문서·속성·구성원·관계·나타나는 다이어그램이 있고, 모든 다이어그램이 SVG로 들어갑니다. 검색 상자로 요소와 다이어그램을 거르고, 밝은/어두운 색은 시스템 설정을 따릅니다. 파일 하나로 되어 있어 그대로 메일로 보내거나 웹에 올릴 수 있습니다.
- **Markdown 문서 (.zip)…** — Markdown 문서 하나와 다이어그램 SVG 그림(`images/` 폴더)을 ZIP 하나로 저장합니다.

문서의 제목과 머리글은 지금 언어(한국어·영어)로 만들어집니다. 편집기의 **문서** 탭에 쓴 설명이 문서에 들어가고, 요구사항이 있으면 요구사항 표도 들어갑니다. 템플릿을 고르고 표지·목차가 있는 Word · PDF 문서를 만들려면 **도구 › 문서 생성…**을 씁니다([문서 생성](#문서-생성) 참고).

### 최근 파일과 폴더

최근에 연 파일 10개와 폴더 10개가 기억됩니다.

- **파일 › 최근 파일…**(`Ctrl+R`) — **최근 파일과 폴더** 창. 파일·폴더 목록에서 **열기**(**이 폴더에서 열기**), 휴지통 버튼(**목록에서 지우기**), **모두 지우기** · **폴더 기록 모두 지우기**가 있습니다.
- **파일 › 최근 폴더** — 폴더를 고르면 그 폴더에서 열기 창이 열립니다.
- **파일 › 최근 파일·폴더 기록 모두 지우기** — 두 목록을 한 번에 지웁니다.
- 없어진 파일을 열려고 하면 **파일이 없습니다** 창에서 **그대로 두기** 또는 **목록에서 지우기**를 고릅니다. **설정 › 최근 기록**에서는 없어진 파일에 **없음** 표시가 붙습니다.

### 끌어다 놓기

파일을 창에 끌어다 놓으면 "여기에 놓으면 엽니다" 안내가 뜨고, 놓은 파일의 종류에 따라 처리합니다.

| 놓은 것 | 하는 일 |
|---|---|
| `.myuml` · `.muml` · `.mumlt` · `.mdj` · `.xmi` · `.xml` · `.uml` | 프로젝트로 엽니다(지금 프로젝트를 대신함) |
| `.mfj` | 모델 조각을 가져옵니다 |
| `.mmd` · `.mermaid` · `.puml` · `.plantuml` · `.pu` | Mermaid / PlantUML 가져오기 창을 그 내용으로 엽니다 |
| Java · C# · C++ · Python · TypeScript · SQL 소스 | 역공학합니다 |
| 그림 파일 (PNG · JPEG · GIF · WebP · BMP · SVG 등) | 프로그램 배경 이미지로 씁니다 |

웹 버전에서는 Mermaid·PlantUML 텍스트를 끌어다 놓아도 가져오기 창이 열립니다.

### 인쇄와 미리 보기

![인쇄와 미리 보기](docs/tutorial/images/56-print.jpg)

**파일 › 인쇄…**(`Ctrl+P`)는 **인쇄 미리 보기** 창을 엽니다. 왼쪽에서 설정을 바꾸면 오른쪽 미리 보기가 바로 바뀌고, 아래쪽의 ‹ ›로 쪽을 넘깁니다. 설정은 기억되어 다음 인쇄와 PDF 내보내기에 쓰입니다.

| 탭 | 항목 |
|---|---|
| **인쇄 범위** | **모든 페이지**(모든 다이어그램) · **현재 페이지**(지금 다이어그램) · **페이지 범위**(**처음 다이어그램**–**마지막 다이어그램** 번호), **인쇄할 내용**(다이어그램 N개 · 용지 N장) |
| **용지 설정** | **용지**(A3 · A4 · A5 · B4 · B5 · Letter · Legal · Tabloid) · **방향**(세로 · 가로) · **여백**(없음 · 좁게 · 보통 · 넓게) · **크기**(용지에 맞춤 · 실제 크기 · 배율) · **배율**(10–400%) · **용지 가운데에** · **다이어그램 배경 인쇄** |
| **머리글·바닥글** | **머리글**과 **머리글 문구**(비우면 프로젝트 이름) · **바닥글**과 **바닥글 문구** |

**실제 크기**나 큰 배율로 인쇄하면 큰 다이어그램은 여러 장에 나뉘어 인쇄됩니다. **인쇄**를 누르면 시스템 인쇄 창이 열립니다.

## 데이터베이스 저장

데스크톱 앱은 프로젝트를 파일과 함께 데이터베이스에도 저장할 수 있습니다. 웹 브라우저는 DB 서버나 SQLite 파일에 직접 연결할 수 없으므로 웹 버전에서는 쓸 수 없습니다.

### 연결 설정

**설정 › 데이터베이스** 탭에서 **DB 종류**를 고릅니다: **사용 안 함** · SQLite · MariaDB · MySQL · PostgreSQL.

| DB 종류 | 입력할 것 |
|---|---|
| SQLite | **SQLite 파일**(예: `C:\Data\myumlmaker.db`). **찾아보기…**로 고르거나 새 파일 이름을 정합니다 |
| MariaDB · MySQL · PostgreSQL | **서버 주소**, **포트**(MariaDB·MySQL 3306, PostgreSQL 5432가 기본), **데이터베이스 이름**(영문·숫자·`_`·`$`·`-`만), **사용자**, **비밀번호** |

- **비밀번호를 설정에 저장**을 끄면 비밀번호는 저장하지 않고 프로그램을 닫을 때까지만 기억합니다.
- **연결 테스트**를 누르면 연결해 보고 "연결됨 — (서버 버전)" 또는 오류를 보여 줍니다.
- 프로젝트를 담을 표는 처음 저장할 때 자동으로 만들어집니다.

### 저장하고 열기

- 데이터베이스를 설정해 두면 **저장**(`Ctrl+S`)이 파일과 데이터베이스에 함께 저장하고 "저장됨 — 파일과 데이터베이스"라고 알려 줍니다. 툴바의 저장 버튼 설명에도 저장할 곳이 보입니다.
- **파일 › 데이터베이스에 저장**은 데이터베이스에만 저장합니다. 아직 파일이 없는 새 프로젝트도 저장할 수 있습니다.
- **파일 › 데이터베이스에서 열기…**는 저장된 프로젝트 목록(이름 · 저장 시각 · 크기)을 보여 줍니다. **열기**로 열고(지금 프로젝트를 대신하며, 저장하지 않은 변경이 있으면 먼저 묻습니다), 휴지통 버튼(**데이터베이스에서 삭제**)으로 지우며(되돌릴 수 없음), **새로 고침**으로 목록을 다시 읽습니다.
- 연결 설정이 덜 되었으면 "먼저 설정 › 데이터베이스에서 연결을 설정하세요"라는 안내와 함께 설정 창이 열립니다.

## 꾸미기와 설정

### 테마

![테마](docs/tutorial/images/57-theme.jpg)

툴바 오른쪽의 테마 버튼은 누를 때마다 무작위로 다른 테마를 고릅니다. 옆의 ▾(**테마 고르기**)는 다크 20개와 라이트 20개를 두 줄로 보여 주고, 위쪽에 **시스템 설정**(운영체제의 밝은/어두운 모드를 따름)과 **사용자 정의**가 있습니다. 아래의 **사용자 정의 테마 편집…**은 설정의 테마 탭을 엽니다.

**설정 › 테마**에서는 다크 · 라이트 · 사용자 정의 묶음을 오가며 고릅니다. 사용자 정의 테마는 바탕 · 표면 · 패널 · 글자 · 흐린 글자 · 테두리 · 강조 · 강조 위 글자 · 줄무늬 행 · 차트 바탕 · 툴바 · 상태 표시줄 색을 하나씩 고치고, **어두운 테마** 스위치로 어두운 계열인지 정합니다. **지금 테마의 색 가져오기**로 지금 테마에서 시작할 수 있고, 글자가 잘 안 보일 만큼 대비가 낮으면 "글자가 잘 안 보일 수 있습니다"라고 경고합니다. **사용자 정의 테마 사용**으로 적용합니다. 창 제목 표시줄도 테마의 밝기를 따릅니다.

### 다이어그램 색 구성

![다이어그램 색 구성](docs/tutorial/images/58-diagramTheme.jpg)

**보기 › 다이어그램 색 구성** 또는 **설정 › 다이어그램 › 다이어그램 색 구성**에서 다이어그램 전체의 색을 **클래식 (흰색)** · **파스텔** · **청사진** · **어두운** 중에서 고릅니다. 프로그램 테마와 따로 정하며, 그림·SVG·PDF 내보내기와 인쇄, 프레젠테이션에도 같은 색이 쓰입니다. 뷰마다 준 색(스타일)은 색 구성보다 우선합니다.

### 언어

![언어](docs/tutorial/images/59-language.jpg)

툴바의 국기 버튼(`Ctrl+Shift+L`)으로 한국어와 영어를 바꿉니다. 한국어일 때는 영국 국기, 영어일 때는 태극기가 보입니다. **설정 › 일반 › 언어**에서도 바꿀 수 있습니다. 메뉴·창·오류 메시지와 새로 만드는 요소의 기본 이름, 내보내는 문서의 머리글이 그 언어를 따릅니다. 이미 만든 요소의 이름은 바뀌지 않습니다.

### 글꼴

**설정 › 글꼴**에서 프로그램 화면(표·목록·메뉴)의 **글꼴**(시스템에 설치된 글꼴 목록), **글자 크기**(9–28px), **굵기**, **스타일**(보통 · 기울임), **행 높이**, **확대/축소**(50–200%)를 정합니다. 다이어그램 안의 글꼴은 **설정 › 다이어그램**의 **다이어그램 글꼴**과 **다이어그램 글자 크기**(9–24px)에서 따로 정합니다.

### 시작 화면과 움직이는 배경

### 오류 창

오류가 나면 **오류** 창이 뜹니다. 메시지, **시각**, **위치**(무슨 작업 중이었는지)와 **자세한 내용**이 있고, **내용 복사** 버튼으로 전부 복사해 문제를 알리거나 기록할 수 있습니다.

| 오류 제목 | 흔한 원인 |
|---|---|
| 파일을 열 수 없습니다 | MyUMLMaker 파일이 아님("MyUMLMaker 파일이 아닙니다 (JSON 형식이 아님)."), 더 새 버전의 MyUMLMaker으로 만든 파일, StarUML 프로젝트(.mdj)가 아님 |
| 저장할 수 없습니다 · 내보낼 수 없습니다 | 쓰기 권한이 없는 폴더, 다른 프로그램이 파일을 잡고 있음, 그 시스템이 지원하지 않는 그림 형식(WebP 등) |
| 가져올 수 없습니다 | 모델 조각(.mfj)이 아님, 가져올 수 없는 Mermaid·PlantUML 다이어그램 종류, 가져올 내용이 없음 |
| 코드를 만들 수 없습니다 · 역공학을 할 수 없습니다 | 코드를 만들 요소가 없음, 소스를 읽을 수 없음(문법 오류 등) |
| 데이터베이스에 저장하지 못했습니다 · 데이터베이스 작업을 하지 못했습니다 | 서버 주소·포트·사용자·비밀번호가 틀림, 데이터베이스가 없음, SQLite 파일에 쓸 수 없음 |
| 인쇄할 수 없습니다 | 프린터나 인쇄 대화 상자 문제 |
| 배경 이미지 오류 | 읽을 수 없는 그림 파일 |
| 문서 창을 열 수 없습니다 · 사용 설명서를 열 수 없습니다 | 설치 폴더의 `docs` 폴더가 지워짐 |

### 여러 창으로 실행하기

MyUMLMaker 데스크톱 앱은 여러 개를 함께 실행할 수 있습니다. 시작 메뉴나 바로 가기로 다시 실행하면 창이 하나 더 열리고, 창마다 프로젝트를 하나씩 엽니다. 탐색기에서 `.myuml` 파일을 두 번 누르면 MyUMLMaker가 이미 열려 있어도 새 창이 열려 그 파일을 엽니다.

- 나중에 연 창은 앞 창과 겹치지 않도록 오른쪽 아래로 조금씩(32px) 비켜 열리고, 화면 밖으로 나가지 않습니다. 앞 창이 최대화되어 있어도 새 창은 보통 크기로 열립니다.
- **설정 › 일반 › 시작할 때 지난번에 연 파일 다시 열기**는 다른 창이 없을 때 연 첫 창만 따릅니다. 나중에 연 창은 시작 페이지(또는 두 번 누른 파일)로 열리고, 다음 실행 때 다시 열 파일 목록은 첫 창에 열려 있던 프로젝트로 남습니다.
- 설정, 최근 파일·폴더, 데이터베이스 연결, 배경 그림은 모든 창이 함께 씁니다. 한 창에서 바꾸면 다른 창에도 바로 반영됩니다.
- 창 위치와 크기는 마지막으로 닫은 창의 것이 기억됩니다.
- 창 하나를 닫거나 **파일 › 끝내기**를 해도 그 창만 끝나고 다른 창은 계속 열려 있습니다.
- 같은 프로젝트 파일을 두 창에서 함께 고치면 나중에 저장한 쪽이 앞의 저장을 덮어씁니다. 한 파일은 한 창에서만 고치세요.

### 설치와 다시 설치 (Windows)

MyUMLMaker는 컴퓨터에 하나만 설치됩니다. 설치 프로그램은 이전 설치(어느 버전이든)를 찾으면 완전히 지운 뒤 새로 설치합니다. MyUMLMaker 창이 열려 있으면 몇 개든 모두 닫아야 하므로 먼저 **확인**(닫고 계속) · **취소**(설치 그만두기)를 묻습니다. 저장하지 않은 변경은 사라지므로 설치 전에 저장하세요.

이전 설치나 예전에 쓰던 사용자 데이터가 있으면, 설치 화면이 뜨기 전에 설치 언어(한국어·영어)로 "이전에 사용하던 사용자 데이터(설정, 최근 파일·폴더, 열린 프로젝트 목록, 데이터베이스 연결, 배경 그림, 튜토리얼 기록, 창 위치)를 삭제할까요?"라고 묻습니다.

| 선택 | 결과 |
|---|---|
| **예** | 사용자 데이터를 모두 지우고 처음 설치한 상태로 시작합니다 (`%APPDATA%\com.shkwon.myumlmaker`, `%LOCALAPPDATA%\com.shkwon.myumlmaker`) |
| **아니오** (기본) | 사용자 데이터는 그대로 둡니다. 설치 후 첫 실행 때 환경 설정(테마, 글꼴, 확대/축소, 패널, 보기 옵션, 창 위치 등)만 기본값으로 돌아갑니다 |
| **취소** | 아무것도 바꾸지 않고 설치를 그만둡니다 |

조용한 설치(`/S`)는 묻지 않고 사용자 데이터를 그대로 둡니다. 직접 만든 프로젝트 파일(`.myuml`)은 사용자 데이터가 아니므로 어느 경우에도 지워지지 않습니다.

### 저장하지 않은 변경

프로젝트는 한 번에 하나만 열리므로, 다른 프로젝트가 지금 프로젝트를 대신하기 전에 묻습니다. 수정한 프로젝트가 열려 있을 때 새 프로젝트 · 템플릿 · 예제 · **열기…** · 최근 파일 · 끌어다 놓기 · 데이터베이스에서 열기를 하면 **저장하지 않은 변경** 창에 "(프로젝트 이름)에 저장하지 않은 변경 내용이 있습니다. 다른 프로젝트를 열기 전에 저장할까요?"라고 뜹니다: **저장** · **저장 안 함** · **취소**. **취소**하면 지금 프로젝트가 그대로 남습니다. **프로젝트 닫기**(`Ctrl+W`)도 "저장하지 않은 변경 내용이 있습니다. 저장할까요?"라고 같은 세 가지를 묻고, 프로그램을 끝낼 때도 저장하지 않은 프로젝트가 있으면 같은 질문을 합니다. 웹 버전에서는 페이지를 닫으려 할 때 브라우저가 경고합니다.

### 그 밖에

| 증상 | 해결 |
|---|---|
| 요소를 지웠는데 모델 탐색기에 남아 있음 | `Delete`는 다이어그램에서만 지웁니다. 모델에서 지우려면 `Ctrl+Delete`(**모델에서 삭제**) |
| 이름을 바꿨더니 다른 다이어그램도 바뀜 | 같은 요소의 뷰이기 때문입니다. 따로 쓰려면 **복제**로 새 요소를 만드세요 |
| 요소가 움직이지 않거나 이름을 고칠 수 없음 | 스타일 탭의 **잠금 (움직이지 않음)**을 확인합니다 |
| 끌 때 원하는 곳에 멈추지 않음 | `Alt`를 누른 채 끌거나 **격자에 맞추기**를 끕니다 |
| 패키지에 놓았더니 모델 위치가 바뀜 | **설정 › 다이어그램 › 패키지 안에 놓으면 모델에서도 옮기기**를 끕니다 |
| 속성을 클래스 밖에 놓을 수 없음 | 속성·오퍼레이션은 그것을 가질 수 있는 요소 안에 놓아야 합니다. 빠른 단추나 빠른 편집이 편합니다 |
| 관계를 이을 수 없다고 나옴 | 그 관계가 두 요소 종류 사이에 허용되지 않습니다(예: 인터페이스 실체화는 인터페이스로) |
| 선이 이상하게 꺾임 | **꺾임점 지우기**로 손으로 꺾은 점을 지우거나 **선 모양**을 바꿉니다 |
| 다이어그램이 안 보이거나 너무 작음 | `Ctrl+Shift+W`(다이어그램 전체 보기) 또는 `Ctrl+0`(100%로 보기) |
| 프로그램 화면이 너무 크거나 작음 | 다이어그램 밖에서 `Ctrl`+휠, 또는 **설정 › 글꼴 › 확대/축소** |
| 빠른 단추가 보이지 않음 | **보기 › 표시 › 빠른 편집 단추**를 켭니다 |
| 웹 버전에서 최근 파일이 안 열림 | 브라우저 보안 때문에 **열기**로 파일을 다시 골라야 할 수 있습니다 |
| 웹 버전에 데이터베이스·폴더 역공학이 없음 | 데스크톱 앱에서만 쓸 수 있는 기능입니다 |
| 설정을 처음으로 | **설정 › 기본값으로** |

### 웹 버전

웹 버전도 같은 화면과 기능을 쓰지만 몇 가지가 다릅니다. 파일은 브라우저의 열기·저장 창으로 주고받고(브라우저가 허용하면 같은 파일에 다시 저장), 최근 파일은 브라우저에서 연 파일로 표시됩니다. 데이터베이스 저장, 폴더 전체 역공학, 코드를 폴더에 바로 쓰기(웹은 ZIP), 자동 저장은 데스크톱 앱에서만 됩니다. 프레젠테이션은 브라우저 전체 화면을 씁니다.
