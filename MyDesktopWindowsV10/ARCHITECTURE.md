# MyDesktop 구조

바탕화면 항목을 반투명 판("펜스")에 묶어 두는 WPF(.NET 10, `net10.0-windows`) 앱입니다. 서비스도
드라이버도 셸 확장도 없이, 사용자 모드 프로세스 하나가 P/Invoke로 셸과 이야기합니다.

이 문서는 **코드를 고치려는 사람**을 위한 것입니다. 조각들이 어떻게 맞물리는지, 그리고 더 중요하게는
몇몇 부분이 왜 그렇게 생겼는지를 적었습니다. 셸은 몇 군데에서 "당연해 보이는 구현"을 가혹하게
벌하기 때문입니다.

---

## 1. 핵심 발상

바탕화면 아이콘은 탐색기가 자기 `SysListView32`에 직접 그립니다. 그 아이콘과 배경화면 **사이에**
창을 끼워 넣을 수도, 순서를 바꿀 수도 없습니다. 그래서 "MyDesktop이 바탕화면을 그림"을 켜면 더
무식한 방법을 씁니다.

1. 탐색기의 아이콘 층을 **끕니다** — 바탕화면 우클릭 ▸ 보기 ▸ 바탕 화면 아이콘 표시와 같은 토글이고,
   탐색기는 아이콘 뷰를 아예 파괴합니다.
2. z-order 맨 아래에 고정한 전체 화면 창을 띄우고, 바탕화면을 **직접** 그립니다 — 휴지통 등 셸
   항목과 Desktop 폴더의 낱개 항목들.
3. 펜스에 들어 있는 항목은 그 그림에서 그냥 빼 버립니다.

**파일은 움직이지 않습니다.** 펜스로 끌어 넣은 항목도 여전히 `%USERPROFILE%\Desktop`에 있고,
다만 배경화면 위에 *그려지지* 않을 뿐입니다. 이게 전부이며, 그렇기 때문에 제거나 강제 종료 경로는
**반드시** 탐색기 아이콘을 다시 켜야 합니다. 안 그러면 사용자는 텅 빈 바탕화면을 마주하게 됩니다.

```
        ┌──────────────────────────────────────────────┐
        │  FenceWindow   FenceWindow   FenceWindow      │  ← 펜스 하나당 창 하나
        ├──────────────────────────────────────────────┤
        │  DesktopLayerWindow                          │  ← MyDesktop이 그리는 아이콘
        ├──────────────────────────────────────────────┤
        │  탐색기의 WorkerW / Progman (배경화면)          │
        └──────────────────────────────────────────────┘
```

## 2. 소스 배치

| 폴더 | 들어 있는 것 |
| --- | --- |
| `Models/` | 저장되는 상태. `WorkspaceData`, `FenceData`, `FenceItem`, `AppSettings`와 열거형들. 변경 알림 말고는 동작이 없는 순수 관찰 가능 객체 |
| `Services/` | 창도 P/Invoke도 아닌 모든 것. 펜스 관리자, 저장소, 폴더 미러링, 정렬, 셸 작업, 번역 |
| `Interop/` | P/Invoke 표면과, **오직 Windows가 그렇게 동작하기 때문에** 존재하는 조각들. 창 고정, 마우스 훅, 트레이 아이콘, 드래그 고스트 |
| `Views/` | WPF 창들과 메뉴를 만드는 헬퍼 |
| `installer/` | WiX 소스와, 게시·패키징을 수행하는 스크립트 |

C# 약 6,500줄. `Views/FenceWindow.xaml.cs`가 단일 파일로는 압도적으로 큽니다(약 1,270줄). 거의
모든 제스처가 펜스에서 끝나기 때문입니다.

## 3. 시작 순서

`App.OnStartup` ([App.xaml.cs](App.xaml.cs))이 배선을 전부 담당합니다.

1. **단일 인스턴스.** 이름 있는 뮤텍스 `Local\MyDesktop.SingleInstance`. 두 번째 사본은 첫 번째와
   바탕화면을 두고 다투지 않고 즉시 종료합니다.
2. **`WorkspaceStore`** 가 `%LOCALAPPDATA%\MyDesktop\fences.json`을 읽습니다.
3. **`FenceManager.Start()`** 가 펜스마다 창을 열고, 데스크톱 제스처를 설치하고, 휴지통 감시를
   시작하고, 그려지는 바탕화면을 켭니다.
4. **`TrayIcon`** 이 알림 영역 아이콘과 메뉴를 올립니다.
5. **안전망.** `ProcessExit` 과 `SessionEnding` 둘 다 `DesktopIcons.Restore()` 를 부릅니다.

순서에서 한 가지가 중요합니다. `FenceManager.Start()`는 창을 하나라도 열기 **전에**
`Strings.Language`를 확정합니다. 펜스는 자기가 표시될 때 스스로를 번역하므로, 반대로 하면 시작
과정에서 열린 창들이 처음 걸린 언어 그대로 남습니다.

## 4. 구성 요소

### `FenceManager` — 중심

[Services/FenceManager.cs](Services/FenceManager.cs)가 펜스와 그 창, 폴더 포털, 데스크톱 제스처를
소유합니다. 나머지는 전부 여기에 매달려 있습니다. 펜스 id를 키로 하는 사전 두 개(`FenceWindow`,
`PortalSync`)를 들고 있고, `Fences` 컬렉션에 더하면 창이 열리고 빼면 닫힙니다.

### `WorkspaceStore` — 저장

[Services/WorkspaceStore.cs](Services/WorkspaceStore.cs)가 `fences.json`을 읽고 씁니다. 저장은
**600ms 디바운스**됩니다. 펜스를 화면 가로질러 끌 때 마우스가 움직일 때마다 파일을 쓰지 않기
위해서입니다. 종료 시 `Flush()`가 밀린 쓰기를 내보냅니다.

이름이 바뀌어도 상태를 이어받습니다. 새 파일이 없으면 이전 이름 시절의
`%LOCALAPPDATA%\Palisades\fences.json`을 찾아 읽습니다. 옛 파일은 그대로 두므로 예전 빌드로
돌아가도 자기 배치를 그대로 찾습니다.

### `DesktopLayer` / `DesktopLayerWindow` — 그려지는 바탕화면

[Services/DesktopLayer.cs](Services/DesktopLayer.cs)가 바탕화면에 있어야 할 것을 계산합니다 —
켜져 있는 셸 항목 + Desktop 폴더 내용 − 이미 펜스에 든 것.
[Views/DesktopLayerWindow.xaml.cs](Views/DesktopLayerWindow.xaml.cs)가 그 목록을 그립니다.

빈 영역은 **완전히 투명**해서 클릭이 진짜 바탕화면으로 떨어집니다. 예외는 드래그가 진행되는
동안뿐입니다. `SetDragCapture(true)`가 배경에 알파 1을 줍니다 — 눈에 보이지 않으면서 드롭 대상이
되게 하는 최소값입니다. 이게 없으면 펜스에서 끌어낸 항목이 탐색기가 가진 같은 파일 위에 떨어져
셸이 이름 충돌을 묻기 시작합니다.

### `PortalSync` — 폴더 포털

[Services/PortalSync.cs](Services/PortalSync.cs)가 `FileSystemWatcher`로 폴더를 펜스에 비춰,
펜스 내용이 폴더를 따라다니게 합니다.

### `ShellIconService` · `ShellDrop` · `ShellFileOperations`

셸을 마주하는 삼총사입니다. 바로 가기 오버레이까지 포함한 48px 실제 아이콘, 대상이 하는 일을
그대로 하는 드롭(휴지통은 삼키고, 프로그램은 열고, 폴더는 받아들임), 그리고 `FOF_ALLOWUNDO`를 준
`SHFileOperation` 삭제 — 그래서 파일은 휴지통으로 가고 되돌릴 수 있습니다.

### `Strings` / `Localizer`

[Services/Strings.cs](Services/Strings.cs)는 **영어 원문 자체를 키로 쓰는** 사전입니다. 번역이 없는
문구는 그냥 영어로 남고, 아무것도 사라질 수 없습니다.

[Views/Localizer.cs](Views/Localizer.cs)는 창의 비주얼 트리를 걸으며 만나는 텍스트를 바꿔칩니다.
덕분에 XAML은 평범한 영어로 남고 별도 리소스 파일을 나란히 관리할 필요가 없습니다. 여기 두 규칙은
선택이 아닙니다.

- **영어 원문을 요소에 기억시킵니다**(첨부 속성). 제자리에서 바꿔치면 단방향이 됩니다. 화면의
  텍스트가 한국어가 되는 순간 그것은 더 이상 표의 키가 아니므로, 영어로 되돌릴 때 찾을 것이
  없습니다.
- **데이터 바인딩된 속성은 건너뜁니다.** 바인딩된 속성에 값을 쓰면 바인딩이 고정값으로 대체되어
  그 요소는 다시는 자기 데이터를 따라가지 못합니다.

또한 **실제로 번역할 것이 있을 때만** 요소를 떠맡습니다. 펜스의 말기 버튼은 평생 `▲`와 `▼` 사이를
오가는데, 보자마자 기억해 버린 요소는 언어를 바꿀 때 걷는 이가 처음 지나갈 때 마침 보이던 화살표로
되돌려집니다.

설정 창 드롭다운의 열거형은 `EnumLabelConverter`([Converters.cs](Converters.cs))를 거칩니다.
열거형에 그대로 바인딩하면 WPF가 `ToString()`을 불러 **멤버 이름**을 화면에 올립니다.

### `MenuArt`

[Views/MenuArt.cs](Views/MenuArt.cs)가 이 앱의 모든 메뉴 항목을 만듭니다. 그래서 전부 아이콘을
답니다. 글리프는 Segoe Fluent Icons에서 오고, Windows 10에서는 Segoe MDL2 Assets로 떨어집니다.

스위치 항목은 WPF의 `IsCheckable`을 **쓰지 않습니다.** 그 체크 표시는 아이콘과 같은 칸에 그려지므로,
토글만 아이콘 없는 항목이 되어 버립니다. 대신 상태를 아이콘으로 그립니다 — 체크된/빈 상자, 또는
그 편이 더 잘 말해 주는 곳에서는 열린/닫힌 자물쇠.

## 5. 셸과 싸우는 부분

여기는 "당연해 보이는 구현"이 틀린 곳들입니다. `Interop/` 안을 고치기 전에 반드시 읽으십시오.

### 5.1 창 고정 — `DesktopAnchor`

펜스는 배경화면 위·모든 앱 창 아래에 떠 있어야 하고, Alt+Tab에서 빠져야 합니다.

`HWND_BOTTOM`만으로는 부족합니다. Windows가 그것을 셸의 바탕화면 창보다 **아래**에 두어 펜스가
배경화면 뒤로 사라집니다. 그래서 `DesktopAnchor.Sink()`는 두 번 움직입니다 — 펜스를 맨 아래로 내린
뒤, 바탕화면 창을 그 펜스보다 한 칸 더 아래로 밀어냅니다.

`WM_WINDOWPOSCHANGING` 훅이 위치가 바뀔 때마다 `hwndInsertAfter`를 `HWND_BOTTOM`으로 되돌리고,
4초 주기 감시자가 전체를 다시 가라앉힙니다. 탐색기 재시작과 배경화면 변경이 바탕화면 창을 새로
만들어 순서를 초기화하기 때문입니다.

### 5.2 데스크톱 제스처 — `DesktopMouseHook`

빈 바탕화면에는 제스처가 둘 있습니다. 우클릭 드래그로 사각형을 그려 펜스를 만들기, 더블클릭으로 모든
펜스를 숨기거나 되돌리기. 둘 다 `WH_MOUSE_LL` 훅이 필요하고, **저수준 마우스 훅은 이 코드베이스에서
가장 위험한 물건입니다. Windows는 콜백이 반환할 때까지 시스템의 다른 모든 마우스 메시지를
붙잡아 둡니다.**

여기서 규칙 세 가지가 나오고, 셋 다 하중을 받고 있습니다.

**콜백 안에서 느린 일을 하지 않는다.** 창을 띄우거나 옮기거나 크기를 바꾸지 않고, 포그라운드를 가져
오지 않고, 탐색기와 이야기하지 않고, 디스크를 건드리지 않습니다 — **로깅 포함.** 작업은
`AfterTheHook()`으로 디스패처에 실어 보내고, 훅이 비켜난 직후에 실행됩니다. 고무줄도 창이므로 그
갱신 역시 미루고, 프레임당 한 번으로 합칩니다.

**오른쪽 버튼은 down/up 대칭으로 삼킨다.** 탐색기는 바탕화면에서 오른쪽 버튼 *down*을 보는 순간
마우스 캡처를 가져가고, 짝이 되는 *up*에서만 놓습니다. down을 통과시키고 up만 삼키면 바탕화면이
시스템의 모든 마우스 이벤트를 붙잡은 채로 남습니다. 다른 무언가가 버튼을 놓아 줄 때까지 포인터가
아무것에도 반응하지 않고, 이것은 **기계 전체가 멈춘 것과 똑같아 보입니다.** 그래서 제스처가 시작될
수 있는 상황이면 누름도 함께 붙잡아 둡니다. 정말 제스처였는지는 뗄 때 비로소 드러납니다.

- 드래그였다 → 양쪽 다 보류했으므로 어디에도 캡처가 남지 않고, 펜스를 만듭니다.
- 그냥 클릭이었다 → `SendInput`으로 클릭을 되돌려 주어 평범한 바탕화면 메뉴가 그대로 뜹니다.

되돌린 이벤트는 `dwExtraInfo`에 표식(`0x50414C49`)을 달고 갑니다. 훅이 자기 주입을 알아보고 그
위에 제스처를 또 걸지 않도록 통과시키기 위해서입니다.

**훅은 아직 UI 스레드에 있습니다.** `AfterTheHook`은 일을 미루지만, **훅을 소유한 바로 그 스레드로**
미룹니다. 펜스 창을 만드는 동안 훅이 응답하지 못하고, 그동안 시스템의 모든 마우스 이벤트가
`LowLevelHooksTimeout`(기본 300ms)만큼 밀립니다. 근본 해결은 자체 메시지 루프를 가진 전용 스레드로
훅을 옮기는 것인데, 그 전에 `IsOverDrawnIcon`을 잠금 없는 아이콘 사각형 스냅숏으로 바꿔야 합니다.
지금 그 콜백은 WPF 히트 테스트를 하고, WPF는 스레드 친화성이 있기 때문입니다.

### 5.3 탐색기 아이콘 끄기 — `DesktopIcons`

`SHELLDLL_DefView`에 `WM_COMMAND` `0x7402`. 탐색기 자신의 보기 메뉴가 보내는 바로 그 메시지입니다.
`SendMessageTimeout` + `SMTO_ABORTIFHUNG`으로 보냅니다. 평범한 `SendMessage`였다면 셸이 바쁜 동안
MyDesktop이 통째로 멈춥니다.

시작 전 상태를 기억했다가 종료 시 되돌립니다. **강제 종료는 그 과정을 건너뜁니다.** 그래서
`common.ps1`이 앱을 멈춘 뒤 아이콘을 복원하고, 앱은 `ProcessExit`과 `SessionEnding`을 둘 다
겁니다.

### 5.4 드래그 고스트 — `DragGhost`

셸에는 드래그 중 커서 밑 그림을 그려 주는 헬퍼가 있고 탐색기도 그걸 씁니다. 다만 드롭 대상이 셸에게
그려 달라고 요청하고 **동시에** 데이터 객체가 이미지를 돌려줄 때만 동작합니다. WPF의 드롭 대상은
절대 요청하지 않고, WPF `DataObject`는 셸의 요청에 `DV_E_FORMATETC`로 답합니다. 그래서 MyDesktop은
자기 고스트를 들고 다닙니다 — 끌리는 항목의 스냅숏을 담은, 클릭이 통과하는 최상위 창.

### 5.5 픽셀

마우스 훅은 **물리** 픽셀을, WPF는 **장치 독립** 단위를 씁니다. `DisplayScale`이 둘을 변환합니다.
배율이 걸린 디스플레이에서 고무줄이 커서와 어긋난다면 대개 이 둘을 섞은 것입니다.

## 6. 저장되는 상태

`%LOCALAPPDATA%\MyDesktop\`

| 파일 | 내용 |
| --- | --- |
| `fences.json` | 모든 펜스와 그 항목, 위치와 외형, 바탕화면 아이콘 위치, 그리고 모든 설정 |
| `diagnostics.log` | 데스크톱 제스처가 무엇을 하는지에 대한 몇 줄. 200KB를 넘으면 지웁니다. 마우스 훅은 조용히 실패하는 유일한 부분이라 흔적을 남깁니다 |

"Windows 시작 시 실행"은 사용자별 Run 항목입니다 —
`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, 값 이름 `MyDesktop`.

## 7. 빌드

```powershell
.\build.ps1                     # Debug
.\build.ps1 -Release            # Release
.\build.ps1 -Release -Clean     # 중간 산출물 지우고
.\build.ps1 -Release -Publish   # .\publish 에 단일 exe
.\build.ps1 -Installer          # .msi, 프로젝트 루트로 복사
.\run.ps1                       # 빌드 후 실행
```

`build.ps1`은 떠 있는 사본을 먼저 멈춥니다. 앱이 자기 exe를 잠그기 때문입니다. 그리고 바탕화면
아이콘을 되돌려 놓습니다. 강제 종료가 앱의 정리 과정을 건너뛰기 때문입니다.

설치 프로그램([installer/build-installer.ps1](installer/build-installer.ps1))은 `win-x64`로
**자체 포함** 게시한 뒤 WiX 7로 묶습니다. 그래서 설치된 사본은 자기 .NET을 들고 다니며, 런타임을
한 번도 깔아 본 적 없는 기계에서도 실행됩니다. WiX 도구가 필요합니다.

```powershell
dotnet tool install --global wix
```

WiX 소스([installer/MyDesktop.wxs](installer/MyDesktop.wxs))는 파일을 나열하는 대신
`<Files Include="...">` 와일드카드로 게시 폴더를 수확합니다. 런타임의 파일 구성이 바뀌어도 아무도
이 파일을 고칠 필요가 없게 하기 위해서입니다. `Program Files\MyDesktop`에 기계 전체 범위로 설치하고
시작 메뉴 바로 가기를 만들며, `MajorUpgrade` 덕분에 예전 빌드 위에 설치하면 교체됩니다.

## 8. 규약

- **사용자가 읽을 수 있는 모든 문구에 `Strings.T()`.** 키는 영어 원문입니다.
- **주석은 무엇이 아니라 왜를 적습니다.** `Interop/`의 주석 대부분은, 어떤 셸 동작이 그 코드를
  강요했는지 알기 전까지는 코드가 틀려 보이기 때문에 존재합니다.
- **마우스 훅 안에서는 느린 일을 하지 않습니다.** §5.2 참고. 이 규칙을 어기면 버그 리포트가 아니라
  사용자의 기계가 멈춥니다.
- **바탕화면을 아이콘 없이 두지 않습니다.** 프로세스를 끝낼 수 있는 모든 경로는
  `DesktopIcons.Restore()`를 지나야 합니다.
