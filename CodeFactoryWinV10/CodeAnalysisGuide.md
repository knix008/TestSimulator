# Code Analyzer — 분석 결과 해석 가이드

이 문서는 Code Analyzer가 산출하는 **메트릭·인사이트·경고**가 무엇을 의미하는지, 실무에서 **어떤 결정에 도움이 되는지** 설명합니다.

분석 설정(포함 항목·임계값)은 **분석 설정...** 대화상자에서 조정하며, `%LocalAppData%\CodeAnalyzer\settings.json`에 저장됩니다. 임계값을 바꾼 뒤에는 **분석을 다시 실행**해야 결과에 반영됩니다.

## 1. 분석 흐름과 뷰

### 분석 단계

분석 실행 시 선택한 **검사 항목**에 따라 다음 작업이 수행됩니다.

| 단계 | 내용 | 관련 검사 예 |
|------|------|----------------|
| 호출 그래프 | 함수 간 호출 관계 구축 | Fan-out, 순환 호출, 결합도, 고립 함수 |
| 타입 구조 | 클래스·인터페이스·상속·의존 | 타입 탭, LCOM, DIT, Halstead |
| 코드 메트릭 | 함수·파일·타입·패키지 수치 계산 | CC, MI, God file, 패키지 I |
| 중복 코드 | 동일 줄 블록 그룹 검색 | 중복 코드 그룹, 파일 중복 줄 |
| 파일 품질 스캔 | TODO, 주석, 보안 패턴, Git log | Git 핫스팟, 보안 smell |
| 아키텍처 인사이트 | 위 결과를 요약·경고 목록으로 정리 | 아키텍처 탭 전체 |

불필요한 항목을 끄면 분석 시간이 줄어듭니다.

### 결과를 보는 뷰

| 뷰 | 용도 |
|----|------|
| **호출 그래프** | 실행·호출 흐름, 허브 함수, 순환 호출 탐색 |
| **클래스 / 상속 / 시퀀스 / 데이터 흐름** | 타입 구조·협력·데이터 이동 이해 |
| **파일·디렉터리 관계** | 모듈·폴더 간 의존과 결합 |
| **코드 메트릭** | 수치 기반 품질·우선순위 목록 (함수/파일/타입/패키지/아키텍처 탭) |
| **중복 코드** | DRY 위반 구간과 복사 위치 |
| **전역 변수** | 공유 상태·숨은 결합 |
| **DB ERD** | 스키마·테이블 관계 (탐지된 경우) |

코드 메트릭 탭의 **열 헤더에 마우스를 올리면** 해당 열의 간단한 설명 툴팁이 표시됩니다.

## 2. 경고 수준과 임계값

### 경고 수준

| 수준 | 의미 |
|------|------|
| **정상** | 설정한 임계값 범위 안 |
| **경고** | 임계값 1회 초과(또는 MI·주석%·테스트%처럼 **미만**인 경우 해당 기준 미달) |
| **심각** | 임계값의 약 2배(또는 MI 60% 미만 등) — 즉시 검토 권장 |

목록에서 경고·심각 행은 색으로 강조됩니다.

### 기본 임계값 (분석 설정에서 변경 가능)

| 검사 | 기본값 | 비교 | 해석 |
|------|--------|------|------|
| 순환 복잡도 (CC) | 15 | ≥ | 분기·루프가 많은 함수 |
| 인지 복잡도 | 15 | ≥ | 중첩으로 읽기 어려운 함수 |
| 중첩 깊이 | 4 | ≥ | if/for 안쪽 단계 과다 |
| 매개변수 개수 | 6 | ≥ | API·책임 과다 신호 |
| return 개수 | 5 | ≥ | 제어 흐름 출구 과다 |
| 매직 넘버 | 5 | ≥ | 이름 없는 숫자 리터럴 |
| Fan-out | 10 | ≥ | 직접 호출 대상 과다 |
| 유지보수 지수 (MI) | 65 | **&lt;** | 낮을수록 유지보수 어려움 |
| TODO/100코드줄 | 3.0 | ≥ | 기술 부채 표식 밀도 |
| God file (코드줄) | 800 | ≥ | 한 파일에 역할 과다 |
| 주석% (코드 50줄 이상 파일) | 10% | **&lt;** | 설명·문서 부족 |
| God type (멤버+연산) | 20 | ≥ | 단일 타입 책임 과다 |
| 함수 문장 수 | 50 | ≥ | 함수 길이 과다 |
| switch/case 수 | 10 | ≥ | 분기 폭발 |
| public API 수 (파일) | 30 | ≥ | 표면 API 과다 |
| 테스트 코드 비율 | 10% | **&lt;** | 테스트 부족(근사) |
| 패키지 불안정성 (I) | 0.7 | ≥ | 변경 파급 위험 |
| LCOM (응집도 부족) | 0.6 | ≥ | 타입 응집 저하 |
| 상속 깊이 (DIT) | 5 | ≥ | 상속 설계 복잡 |
| Git 변경 줄 (6개월) | 500 | ≥ | 자주 수정되는 핫스팟 |
| 보안 smell | 1 | ≥ | 의심 패턴 1건 이상 |
| 중복 최소 줄 | 10 | — | 중복 블록 인정 기준(경고와 별도) |

## 3. 함수 메트릭

함수(메서드) 단위로 계산되며, **함수** 탭과 파일·타입 집계에 사용됩니다.

| 지표 | 의미 | 어떤 도움이 되나 |
|------|------|------------------|
| **줄 수** | 함수 본문 물리 줄 | 리팩터링·분리 후보 크기 감 |
| **CC (순환 복잡도)** | if·switch·루프·catch 등 분기 수 (+1 기본) | **테스트 케이스 수·리팩터링 우선순위** — CC가 높을수록 모든 경로 검증이 어려움 |
| **인지 복잡도** | 중첩된 조건·루프에 가중치 | CC보다 **실제 읽기·이해 난이도**에 가깝습니다. 코드 리뷰·가독성 개선에 유용 |
| **중첩 깊이** | if/for/while/catch 등 최대 안쪽 단계 | 깊을수록 **버그 삽입·수정 부작용** 위험이 큼. early return·메서드 추출 검토 |
| **매개변수** | 시그니처 파라미터 수 | **파라미터 객체·빌더 패턴** 필요 여부, API 단순화 |
| **return 수** | 본문 `return` 문 개수 | 제어 흐름 추적 난이도. 단일 출구·가드 절 패턴 검토 |
| **매직 넘버** | 0·1·-1 등 일부 제외 숫자 리터럴 | **명명 상수** 추출로 의도 전달·오류 감소 |
| **Fan-In** | 이 함수를 호출하는 대상 수 (호출 그래프) | **핵심 API·변경 영향 범위** — 수정 시 회귀 테스트 범위 판단 |
| **Fan-Out** | 이 함수가 직접 호출하는 대상 수 | **허브·파사드 부재** 신호. 과하면 책임 분리·조정 계층 검토 |
| **MI (유지보수 지수)** | 줄 수·CC·인지·매개변수 등 종합 (0~171, 높을수록 좋음) | **유지보수 비용** 거시 지표. 낮은 함수부터 리팩터링 큐에 넣기 |
| **문장 수** | 실행 문장 개수 | 함수 길이·복잡도 보조 지표 |
| **switch/case 수** | `case` 분기 수 | **전략·다형**으로 분기 테이블 대체 검토 |
| **catch 품질** | 빈 catch + `catch(Exception)` 등 | 예외 삼키기·디버깅 어려움. 로깅·재throw·구체적 예외 처리 |
| **async void** | async void 사용 여부 | WinForms 이벤트 외에는 **Task 반환** 권장 — 예외 전파·테스트 문제 |
| **미사용 가능** | non-public, fan-in/out 0, 진입점 제외 등 | **dead code** 후보. 삭제·통합 전 수동 확인 |
| **Halstead Volume** | 연산자·피연산자 어휘·길이 기반 | 코드 **크기·난이도** 추정. 비슷한 기능 간 비교 |
| **WMC** | 메서드 CC 가중 합 (타입 기여분) | 타입 복잡도에 기여하는 정도 |
| **정밀도** | Semantic / Syntax / Approximate | C#(Roslyn) &gt; Tree-sitter &gt; 패턴. 수치 신뢰도 판단 |

**활용 예:** CC·인지가 높고 Fan-out도 큰 함수 → 먼저 단위 테스트 보강 후 메서드 분리. Fan-in이 높은 함수 → 변경 시 영향 분석·API 안정성 검토.

## 4. 파일 메트릭

파일 단위 집계로 **파일** 탭과 아키텍처 인사이트에 표시됩니다.

| 지표 | 의미 | 어떤 도움이 되나 |
|------|------|------------------|
| **코드줄** | 주석·빈 줄 제외 근사 LOC | 모듈 크기·God file 판단 |
| **함수 수** | 파일 내 분석된 함수 수 | 책임 분산 여부 |
| **CC↑ / 인지↑ / 중첩↑** | 파일 내 함수 최댓값 | **가장 위험한 함수**가 있는 파일 식별 |
| **Out↑ / In↑** | 파일 내 Fan-out/in 최댓값 | 파일 단위 **결합·허브** 감 |
| **매직 Σ** | 파일 내 매직 넘버 합 | 상수 정리·설정 추출 후보 |
| **MI↓** | 파일 내 최저 MI | 파일 전체 유지보수 난이도 |
| **TODO / TODO/100** | 미완료 표식 개수·밀도 | **기술 부채·백로그** 우선순위 |
| **경고 함수 수** | 임계값 초과 함수 개수 | 파일 품질 한눈에 비교 |
| **주석%** | 100코드줄당 주석 비율 | 온보딩·API 문서화 부족 구간 |
| **중복 참여 줄** | 중복 그룹에 포함된 줄 수 | DRY 위반 **범위** |
| **public API 수** | public 타입·멤버 근사 | **표면 API 축소**·캡슐화 검토 |
| **Git 변경 줄** | 최근 6개월 `git log` numstat 합 | **결함·회귀가 잦은 핫스팟** — 리팩터링·테스트 집중 |
| **보안 smell** | 하드코딩 비밀·SQL 연결·`.Wait()` 등 패턴 | 보안·동시성 **1차 스크리닝** (전용 도구 보완) |
| **문장↑ / case↑ / async Σ** | 파일 내 집계 | 복잡도·비동기 안티패턴 분포 |

**활용 예:** Git 변경 줄이 많고 경고 함수가 많은 파일 → 리팩터링 스프린트 대상. 주석%가 낮은 대형 파일 → 모듈 문서·README 보강.

## 5. 타입 메트릭

클래스·구조체·인터페이스 등 **타입** 단위입니다.

| 지표 | 의미 | 어떤 도움이 되나 |
|------|------|------------------|
| **멤버 / 연산 / 함수** | 필드·속성, 메서드, 메트릭 매칭 함수 수 | **God type** — 단일 책임 원칙(SRP) 위반 |
| **CC↑ / 인지↑ / MI↓** | 타입 내 함수 집계 | 타입 단위 복잡도 |
| **의존→ / ←의존** | 타입이 참조·참조당하는 타입 수 | **결합 방향** — 변경 전파 경로 |
| **LCOM** | Lack of Cohesion, 0~1 (높을수록 응집 부족) | 메서드가 공통 상태를 쓰지 않고 뭉쳐 있음 → **클래스 분리** |
| **DIT** | Depth of Inheritance, 상속 깊이 | **fragile base class**, 이해·테스트 비용 |
| **NOC** | Number of Children, 하위 타입 수 | 부모 변경 시 **영향 받는 타입 수** |
| **WMC** | Weighted Methods per Class, 메서드 CC 합 | 클래스 **복잡도 총량** |
| **RFC** | Response For Class, 호출 가능 메서드 추정 | 한 타입이 **얼마나 많은 동작**을 노출하는지 |

**활용 예:** LCOM이 높고 멤버가 많은 타입 → 역할별로 클래스 분리. DIT·NOC가 모두 크면 상속 대신 composition 검토.

## 6. 패키지 메트릭

디렉터리(폴더)를 **패키지**로 보고 모듈 수준 결합을 측정합니다.

| 지표 | 공식·의미 | 어떤 도움이 되나 |
|------|-----------|------------------|
| **Ca (Afferent)** | 다른 패키지가 이 패키지에 의존하는 수 | **안정 핵심 모듈** — 변경 시 영향 큼 |
| **Ce (Efferent)** | 이 패키지가 다른 패키지에 의존하는 수 | 외부에 **얼마나 의존하는지** |
| **I (Instability)** | Ce / (Ca + Ce), 0~1 (1에 가까울수록 불안정) | 자주 바뀌고 의존이 많은 **불안정 모듈** 식별 |
| **A (Abstractness)** | 추상 타입 비율 | 구현 vs 추상 균형 |
| **D (Distance)** | \|A + I − 1\|, 0에 가까울수록 Main Sequence 상 균형 | **아키텍처 균형 이탈** — 너무 구체적이면서 불안정하거나, 추상만 많은 경우 |

**활용 예:** I가 높은 패키지 → 인터페이스·의존성 역전으로 결합 완화. Ca가 높은 패키지 → API 안정성·버전 관리·테스트 강화.

## 7. 아키텍처 인사이트

**아키텍처** 탭에 유형별로 나열되며, 더블클릭 시 호출 그래프·파일·중복 뷰로 이동할 수 있습니다.

| 유형 | 내용 | 어떤 도움이 되나 |
|------|------|------------------|
| **요약** | 파일·함수·중복·순환·TODO 등 전체 개괄 | 스프린트·보고서 **한 줄 요약** |
| **순환 호출** | A→B→…→A 호출 체인 | **무한 루프·스택·초기화 순서** 문제. 의존성 끊기·이벤트·인터페이스 도입 |
| **파일 / 디렉터리 결합** | 서로 많이 참조하는 파일·폴더 쌍 | **모듈 경계** 재설계, 순환 의존 제거 |
| **Fan-out / Fan-in 허브** | 호출이 몰리는 함수 | **오케스트레이터** 여부 확인. 책임 분산·파사드 |
| **고립 함수** | 호출 그래프에서 연결 거의 없음 | 진입점·콜백·미사용·분석 누락 구분 |
| **중복 코드 그룹** | 동일 블록이 여러 위치 | **공통 함수·라이브러리** 추출 |
| **God file / 주석 부족** | 대형 파일·문서화 부족 | 파일 분리·주석·가이드 |
| **미사용 가능 코드** | 호출·참조 없는 non-public 등 | 정리·감소 **기술 부채 상환** |
| **catch / async void** | 예외·비동기 안티패턴 목록 | 안정성·테스트 개선 |
| **테스트 코드 비율** | 테스트로 추정되는 LOC 비율(근사) | 커버리지 도구 전 **거시 감** |
| **패키지 불안정성** | I ≥ 임계값인 디렉터리 | 모듈화·레이어 정리 |
| **계층 위반** | 상위 레이어가 하위를 역참조 | 클린 아키텍처·헥사고날 **의존 방향** 점검 (domain → infra → app → UI 키워드 기반) |
| **LCOM / DIT·NOC** | 응집·상속 문제 타입 | 타입 설계 리뷰 목록 |
| **Git 핫스팟** | 최근 6개월 변경이 큰 파일 | **결함 예방** 리팩터링·회귀 테스트 |
| **보안 smell** | 의심 문자열·동기 대기 등 | 보안 리뷰 **체크리스트** |
| **전역 변수 / DB 스키마** | 공유 상태·스키마 요약 | 숨은 결합·데이터 모델 이해 |

## 8. 중복 코드

- **최소 줄 수**(기본 10): 이 길이 이상 동일한 연속 줄이 **두 곳 이상**이면 하나의 그룹으로 묶습니다.
- 비교 전 **공백 정규화**와 `//` 스타일 주석 제거를 적용합니다.
- **중복 코드** 뷰에서 그룹별 위치·샘플 텍스트를 확인하고, **파일** 탭의 **중복 참여 줄**과 **아키텍처** 탭 인사이트와 연계됩니다.

**활용:** 복사-붙여넣기로 퍼진 로직을 **공통 모듈**로 추출할 때 우선순위를 정합니다. 도메인 규칙이 중복되면 버그 수정이 한 곳만 반영되는 **불일치 위험**이 큽니다.

## 9. 호출 그래프·구조 다이어그램

### 호출 그래프

- **시작 함수**를 고르면 호출 트리가 펼쳐집니다.
- **순환 호출**은 사이클로 표시되며 해당 경로는 더 확장하지 않습니다.
- 레이아웃·연결선 스타일을 바꿔 **발표·문서**용으로 활용할 수 있습니다.

**활용:** 신규 기능이 기존 호출 경로에 미치는 영향, 레거시 진입점, 과도한 중간 계층 파악.

### 클래스·상속·시퀀스·데이터 흐름

- 타입 간 관계·메시지 흐름·데이터 이동을 **UML 스타일**로 요약합니다.
- 온보딩·설계 리뷰·리팩터링 범위 설명에 적합합니다.

### 파일·디렉터리 관계

- 파일·폴더 단위 **import/using·참조** 관계를 그래프로 표시합니다.
- 빌드 순서·순환 참조·모듈 분리 계획에 도움이 됩니다.

## 10. 분석 정밀도와 한계

### 정밀도 수준

| 수준 | 방식 | 대표 언어 |
|------|------|-----------|
| **Semantic** | 컴파일러 API(Roslyn) 의미 분석 | C#, VB.NET |
| **Syntax** | Tree-sitter 구문 트리 | Python, Java, Go, Rust, JS/TS … |
| **Approximate** | 정규식·휴리스틱 | Kotlin 등 |

함수 탭 **정밀** 열로 해당 함수 수치의 신뢰도를 확인하세요.

### 알아두면 좋은 한계

- **동적 호출**, 리플렉션, 매크로, 조건부 컴파일은 호출 그래프·메트릭에서 **누락**될 수 있습니다.
- **Fan-in/out·순환 호출**은 그래프에 포함된 함수에만 의미가 있습니다.
- **Git 핫스팟**은 저장소·`git` 사용 가능 여부에 의존하며, 브랜치·머지 전략에 따라 왜곡될 수 있습니다.
- **보안 smell·테스트 비율**은 패턴 기반 **1차 스크리닝**이며, SonarQube·Coverlet 등 전용 도구를 대체하지 않습니다.
- **계층 위반**은 폴더·네임스페이스 **키워드 휴리스틱**입니다. 실제 배포 아키텍처와 다를 수 있습니다.
- **LCOM·DIT·NOC**는 분석된 타입·상속 정보 범위 안에서만 계산됩니다.

## 11. 실무 활용 워크플로

### 신규 코드베이스 온보딩

1. 전체 분석 실행 → **아키텍처 요약**·**호출 그래프**로 진입점 파악
2. **파일** 탭에서 God file·Git 핫스팟 → 자주 읽을 파일 우선순위
3. **타입·패키지** 탭으로 모듈 경계·결합 이해

### 리팩터링 스프린트 계획

1. **함수** 탭을 CC·인지·MI로 정렬 → 상위 N개 함수 목록
2. **아키텍처**에서 순환 호출·계층 위반·중복 그룹 병행 확인
3. **분석 보고서**(HTML/PDF)로 이해관계자와 범위 공유

### 릴리스 전 품질 게이트 (가벼운 기준)

1. 심각 경고 함수·파일 0건 목표(또는 팀 합의 임계값)
2. 순환 호출·보안 smell 신규 증가 없음
3. 변경한 핫스팟 파일의 경고 함수 수 감소 추세

### 설정·보고 팁

- 팀 규모·도메인에 맞게 **분석 설정...**에서 임계값을 맞추고 `settings.json`을 공유할 수 있습니다.
- **메트릭 CSV**는 스프레드시트·대시보드 연동에, **Markdown/HTML 보고서**는 위키·PR 설명에 활용하세요.
- 임계값 변경 후에는 반드시 **재분석**하세요.
