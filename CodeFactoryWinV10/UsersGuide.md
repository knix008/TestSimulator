## 1. 시작하기

### 요구 사항

- Windows 10 이상
- [.NET 8](https://dotnet.microsoft.com/download) 런타임(개발자 빌드 시 SDK)
- Git 핫스팟 분석: 분석 대상 폴더가 Git 저장소이고 `git` 명령을 사용할 수 있을 것

### 실행 방법

**명령줄**

```powershell
dotnet run --project CodeAnalyzer
```

**Visual Studio**

1. `CodeAnalyzer.sln`을 엽니다.
2. 시작 프로젝트를 **CodeAnalyzer**로 지정합니다.
3. **F5**로 실행합니다.

**MSI 설치**

Release 빌드로 생성한 MSI를 설치한 뒤 시작 메뉴에서 실행합니다.

```powershell
dotnet build .\CodeAnalyzer.sln -c Release
```

MSI 경로: `CodeAnalyzer.Setup\bin\Release\CodeAnalyzer.Setup.msi`

자세한 빌드 방법은 [CodeAnalyzer.Setup/README.md](CodeAnalyzer.Setup/README.md)를 참고하세요.

## 2. 화면 구성

```
┌─────────────────────────────────────────────────────────────┐
│ [파일 ▼] [설정 ▼]  🔍 찾기: [________]  ◀ 이전   다음 ▶    │  ← 메뉴·검색
├──────────────┬──────────────────────────────────────────────┤
│ [루트 경로][찾아보기]                                        │
│ ┌─ 분석할 프로그래밍 언어 ─┐                                 │
│ │ ☑ C#  ☑ Python  …       │  ← 왼쪽 사이드바                 │
│ └─────────────────────────┘                                 │
│ ┌─ 하위 디렉터리 ─────────┐  뷰: [호출 그래프 ▼]  …         │  ← 툴바
│ │ ☑ src  ☐ bin  ☐ obj   │                                 │
│ └─────────────────────────┘                                 │
│ [분석 실행] [분석 항목 설정]      다이어그램 / 목록 영역     │
├──────────────┴──────────────────────────────────────────────┤
│ 상태 표시줄 · 진행률                                         │
└─────────────────────────────────────────────────────────────┘
```

| 영역 | 설명 |
|------|------|
| **왼쪽 상단** | 루트 디렉터리 경로 입력·**찾아보기** |
| **왼쪽 중간** | **분석할 프로그래밍 언어**, **하위 디렉터리** (체크한 폴더만 분석) |
| **왼쪽 하단** | **분석 실행**, **분석 항목 설정** |
| **상단 툴바** | 뷰 전환, 시작 함수·타입, 레이아웃·연결선, 펼치기/접기, 뒤로, 뷰 초기화 |
| **중앙** | 선택한 뷰의 그래프 또는 표 |
| **메뉴·검색** | 파일·설정 작업, 함수·파일·타입 검색 |
| **하단 상태줄** | 진행률, 분석 요약, 마지막 작업 결과 |

## 3. 분석 실행

### 기본 순서

1. **루트 디렉터리** — 경로를 입력하거나 **찾아보기**로 분석할 프로젝트 폴더를 선택합니다.
2. **분석할 프로그래밍 언어** — C#, Python, Java 등 필요한 항목을 체크합니다. (최소 1개)
3. **하위 디렉터리** — **체크한 폴더만** 분석 대상입니다. `bin`, `obj`, `.git` 등은 기본적으로 체크 해제되어 있습니다. 분석할 폴더를 하나 이상 체크해야 합니다.
4. **(선택) 분석 항목 설정...** — 검사 항목·임계값·중복 코드 최소 줄 수를 조정합니다.
5. **분석 실행** — 분석이 끝날 때까지 기다립니다. 실행 중에는 버튼이 **멈춤**으로 바뀌며, 클릭하면 중지를 요청할 수 있습니다.

### 분석 완료 후

- **분석 완료** 대화상자에 요약(함수 수, 순환 호출, 버그 위험, DB 접근 등)이 표시됩니다.
- **요약 복사**로 텍스트를 클립보드에 복사할 수 있습니다.
- 상태 표시줄에 소요 시간·파일 수·메트릭 요약이 나타납니다.

### 주의

- 경로가 없거나 언어·하위 디렉터리를 하나도 선택하지 않으면 분석을 시작할 수 없습니다.
- **분석 설정**이나 임계값을 바꾼 뒤에는 **다시 분석**해야 결과에 반영됩니다.
- 설정은 `%LocalAppData%\CodeAnalyzer\settings.json`에 자동 저장됩니다.

## 4. 파일 메뉴

**파일** 메뉴와 각 하위 항목 앞에 아이콘이 표시됩니다.

| 메뉴 | 단축키 | 설명 |
|------|--------|------|
| **프로젝트 불러오기...** | Ctrl+Shift+O | `.caproj` 프로젝트 파일을 불러옵니다 (경로·언어·포함 폴더·분석 설정). |
| **프로젝트 저장...** | Ctrl+Shift+S | 현재 작업 환경을 `.caproj`로 저장합니다. |
| **결과 불러오기...** | Ctrl+O | 이전에 저장한 JSON 분석 결과를 불러옵니다. |
| **결과 저장...** | Ctrl+S | 현재 분석 결과를 JSON으로 저장합니다. |
| **메트릭 CSV보내기...** | — | 함수·파일·타입·패키지·전역 변수·접근 관계를 CSV로 저장합니다. |
| **분석 보고서보내기 (HTML/MD/Word/PDF)...** | — | 종합 보고서를 HTML, Markdown, Word, PDF 중 선택해 저장합니다. |
| **이미지로 내보내기...** | Ctrl+E | 현재 그래프·다이어그램 뷰를 PNG 이미지로 저장합니다. |

분석 결과가 없으면 저장·보내기 메뉴는 비활성화됩니다. 분석 중에는 **결과 불러오기**를 사용할 수 없습니다.

### 프로젝트 파일 vs 분석 결과

| 형식 | 확장자 | 용도 |
|------|--------|------|
| **프로젝트** | `.caproj` | 루트 경로, 선택 언어, 포함 디렉터리, 분석 설정 등 **작업 환경** 저장 |
| **분석 결과** | `.json` | 분석이 끝난 **결과 데이터** 저장 (재분석 없이 화면 복원) |

## 5. 설정 메뉴

| 메뉴 | 설명 |
|------|------|
| **분석 항목 설정...** | 검사 항목·품질 임계값·중복 코드 최소 줄 수 (사이드바 **분석 항목 설정**과 동일) |
| **DB 연결 설정...** | MariaDB/MySQL/PostgreSQL 연결 정보. 분석 완료 시 결과를 DB에 자동 저장할 수 있습니다. |

DB 연결 설정은 `%LocalAppData%\CodeAnalyzer\settings.json`에 저장됩니다. 비밀번호도 로컬 설정 파일에 보관되므로 공유 PC에서는 주의하세요.

## 6. 검색

메뉴 오른쪽 **🔍 찾기** 상자에서 함수·타입·파일·디렉터리를 검색합니다.

| 동작 | 방법 |
|------|------|
| 검색 시작 | Ctrl+F로 포커스 이동 후 텍스트 입력 |
| 결과 목록 | 입력하면 아래에 일치 항목 팝업 표시 |
| 항목 선택 | ↓/↑ 이동, Enter로 해당 위치로 이동 |
| 다음 / 이전 | **다음 ▶** (F3), **◀ 이전** (Shift+F3) |
| 닫기 | Esc |

검색으로 선택한 함수는 **호출 그래프**의 시작 함수로 설정되거나, 해당 파일·위치로 이동합니다.

## 7. 도구 모음(툴바)

| 컨트롤 | 설명 |
|--------|------|
| **뷰** | 호출 그래프, 코드 메트릭, DB 테이블 접근, 버그 위험 등 **15종** 뷰 전환 |
| **시작 함수** | 호출 그래프·일부 구조 뷰의 루트 함수 선택 (자동 진입점 포함) |
| **레이아웃** | 좌→우 / 위→아래 트리 배치 |
| **연결선** | 직선 / 직각(orthogonal) / 베지어 |
| **모두 펼치기 / 접기** | 트리형 그래프 노드 일괄 펼침·접음 |
| **← 뒤로** | 이전에 보던 그래프 루트·파일·디렉터리로 되돌아감 (Alt+←) |
| **뷰 초기화** | 줌·스크롤을 기본 상태로 |

표 형태 뷰(코드 메트릭, 중복 코드, 전역 변수, DB 테이블 접근, 버그 위험, 정보 보호 및 보안, 분석 Summary)에서는 레이아웃·연결선·펼치기가 비활성화됩니다. **전역 변수·DB 테이블 접근 그래프**를 볼 때는 레이아웃·연결선만 사용할 수 있습니다.

## 8. 뷰 종류

뷰 콤보에서 다음 항목을 선택합니다.

| 뷰 | 용도 |
|----|------|
| **호출 그래프** | 함수 간 호출 관계를 트리로 탐색 |
| **클래스 다이어그램** | 타입 간 관계 |
| **시퀀스 다이어그램** | 호출·메시지 흐름 |
| **상속 다이어그램** | 상속 계층 |
| **데이터 흐름** | 데이터 이동 요약 |
| **파일 관계** | 파일 단위 참조·호출 |
| **디렉터리 관계** | 폴더(패키지) 단위 관계 |
| **코드 메트릭** | 함수·파일·타입·패키지·아키텍처 수치 표 |
| **중복 코드** | 동일 코드 블록 그룹 |
| **전역 변수** | 전역 변수 목록·접근 함수·접근 그래프 |
| **DB ERD** | 탐지된 DB 스키마·테이블·관계 |
| **DB 테이블 접근** | 테이블·필드별 SQL/ORM 접근 함수·CRUD·접근 그래프 |
| **버그 위험 분석(Lint)** | 미사용·복잡·예외 무음·리소스 누수 등 |
| **정보 보호 및 보안** | 언어별 보안 smell 규칙 결과 (분석 설정에서 활성화 시) |
| **분석 Summary** | 검사 범위별 요약·하이라이트 대시보드 |

### 더블클릭·탐색

- 그래프 **노드 더블클릭**: 해당 항목을 새 루트로 설정하거나 관련 뷰로 이동
- **코드 메트릭·아키텍처** 행 더블클릭: 관련 함수·파일·그래프·중복 코드로 이동
- **중복 코드** 그룹 더블클릭: 해당 파일 위치로 이동

## 9. 코드 메트릭 탭

**코드 메트릭** 뷰 상단 탭:

| 탭 | 내용 |
|----|------|
| **함수** | CC, 인지 복잡도, Fan-in/out, MI, Halstead 등 |

| **타입** | LCOM, DIT, NOC, WMC, RFC, 타입 간 의존 |

- **열 헤더에 마우스를 올리면** 해당 지표 설명 툴팁이 표시됩니다.
- 임계값을 넘는 행은 **경고·심각** 색으로 강조됩니다.
- 열 헤더 클릭으로 정렬할 수 있습니다.

## 10. 전역 변수 뷰

**전역 변수** 뷰는 공유 상태와 숨은 결합을 파악하는 데 사용합니다.

### 화면 구성

- **상단 목록**: 전역 변수 이름, 파일, 줄, 접근 함수 수 등
- **접근 함수**: 선택한 변수를 읽거나 쓰는 함수 목록 (종류: Read / Write / ReadWrite)
- **미리보기**: 선언 주변 소스 코드

### 주요 동작

| 동작 | 방법 |
|------|------|
| 접근 그래프 보기 | 변수 **더블클릭**, **접근 함수 그래프** 버튼, 또는 우클릭 메뉴 |
| 선언 파일 열기 | **선언 위치 파일 열기** 버튼 또는 우클릭 메뉴 |
| 접근 함수로 이동 | 접근 함수 목록 **더블클릭** → 해당 함수 위치로 이동 |

### 접근 그래프

- **왼쪽**: 접근하는 함수들
- **오른쪽**: **하나의** 전역 변수 노드 (`[G]` 표시)
- 모든 접근 함수에서 전역 변수로 **화살표**가 연결됩니다.
- 접근 함수가 없으면 전역 변수 노드만 표시됩니다.
- 그래프를 본 뒤 **뷰**를 다른 항목으로 바꾸면 일반 분석 화면으로 돌아갑니다.

## 11. DB ERD 뷰

**DB ERD** 뷰는 프로젝트에서 탐지한 **테이블·컬럼·관계**를 ER 다이어그램으로 보여 줍니다.

- 스키마는 SQL DDL, EF 마이그레이션, JPA/Prisma/TypeORM 등 엔티티·스키마 파일에서 추출됩니다.
- 지원 **DB 종류**: **MySQL/MariaDB**, **PostgreSQL**, **SQL Server**, **SQLite** 등
- **줌**(Ctrl+휠), **패닝**, **연결선 스타일** 변경, **PNG 내보내기**를 사용할 수 있습니다.
- 테이블 노드를 더블클릭하면 **DB 테이블 접근** 뷰에서 해당 테이블을 중심으로 볼 수 있습니다.

**분석 설정**에서 **DB 스키마** 검사를 끄면 ERD와 테이블 접근 분석이 수행되지 않습니다.

---

## 12. DB 테이블 접근 뷰

**DB 테이블 접근** 뷰는 코드가 **어떤 테이블·필드를 어떤 함수에서** 읽거나 쓰는지 정리합니다.  
SQL 리터럴, DB 실행 API(`query`, `ExecuteSqlRaw`, Dapper 등), EF DbSet·ORM 호출을 **함수 단위**로 추적합니다.

### 상단 탭

| 탭 | 내용 |
|----|------|
| **DB 인스턴스** | 연결 문자열·JDBC URI·SQLite 파일 등에서 탐지한 DB 카탈로그와 접근 함수 목록 |
| **테이블·필드** | 테이블별 접근 함수·필드·엔트리(INSERT/UPDATE 값) 상세 |
| **DB 영향 함수** | 전체 테이블을 가로지르는 함수 목록 (쓰기 필터 지원) |

### DB 인스턴스 탭 열

| 열 | 설명 |
|----|------|
| **#** | 순번 |
| **DB** | 탐지된 DB 인스턴스(카탈로그) 이름 |
| **접근 함수** | 해당 인스턴스에 연결·관리하는 함수 수 |
| **DB 종류** | MySQL, MariaDB, PostgreSQL, SQLite, SQL Server 등 |
| **출처** | 연결 문자열, JDBC, SQLite 파일, API 패턴 등 |

열 헤더에 마우스를 올리면 각 열 설명 툴팁이 표시됩니다.

### 테이블·필드 탭 레이아웃

- **상단**: 테이블 목록 (스키마, 접근 함수 수 등)
- **하단**: 선택 테이블의 접근 정보
  - **미리보기**: 스키마 선언 또는 관련 코드 주변
  - **테이블 접근**: 함수, Read/Write, CRUD, 패턴(SQL / EF / 엔티티)
  - **필드 접근**: 컬럼 단위 접근 함수
  - **엔트리 접근**: INSERT·UPDATE 등에 등장하는 값·필드

### 주요 동작

| 동작 | 방법 |
|------|------|
| 접근 함수 그래프 | **접근 함수 그래프** 버튼, 테이블 **더블클릭**, 또는 우클릭 메뉴 |
| 스키마 파일 열기 | **스키마 위치 파일 열기** |
| 접근 함수로 이동 | 접근 목록 **더블클릭** |
| 쓰기만 보기 | **DB 영향 함수** 탭의 **쓰기(Create/Update/Delete)만 보기** 체크 |

### 접근 함수 그래프

- **왼쪽**: 테이블에 접근하는 함수들
- **오른쪽**: **하나의** 테이블 노드
- 함수에서 테이블로 화살표가 연결됩니다.

### 분석 범위·한계

- **MySQL/MariaDB**, **PostgreSQL**, **SQL Server(LocalDB·Azure SQL 포함)**, **SQLite** 연결·실행 패턴을 인식합니다.
- **12개 프로그래밍 언어**별 SQL 캡처 규칙이 적용됩니다.
- Java/Kotlin·JavaScript/TypeScript는 ORM·스키마 파일 자동 탐색 범위가 넓습니다.
- C/C++는 DB API 호출이 명확한 경우에만 집계하여 일반 식별자 오탐을 줄입니다.
- `SELECT … FROM`처럼 **구조가 분명한 SQL**과 **알려진 DB API** 호출만 테이블 접근으로 집계합니다.
- 런타임에 조립되는 SQL, ORM이 생성하는 동적 쿼리, 스키마에 없는 테이블은 표시되지 않을 수 있습니다.

## 13. 버그 위험 분석 뷰

**버그 위험 분석(Lint)** 뷰는 유지보수·결함 가능성이 높은 코드 패턴을 목록으로 보여 줍니다.

### 검출 카테고리 예

- **Lint** — 언어별 정적 규칙 위반
- **미사용** — 사용되지 않을 가능성이 있는 private 멤버
- **복잡·중첩** — 높은 복잡도·깊은 중첩
- **예외 무음** — 빈 catch, 예외 삼킴
- **리소스 누수** — IDisposable 미해제 등
- **미사용 변수**

### 화면 구성

- **언어 필터** — 분석에 포함된 언어별로 결과 필터
- **카테고리/심각도 필터** — Critical / Warning / Info
- **목록 + 하단 미리보기** — 선택 항목의 파일·줄·설명
- **더블클릭** — 해당 소스 위치로 이동

분석 완료 대화상자·**분석 Summary**·보고서에도 버그 위험 건수가 요약됩니다.

## 14. 정보 보호 및 보안 뷰

**정보 보호 및 보안** 뷰는 **분석 설정**에서 **정보 보호 및 보안 뷰** 또는 **언어별 보안 smell 검사**를 켠 경우에 표시됩니다.

- 규칙별 **심각도**, **의미**, **권장 조치**, **파일·줄**을 표 형태로 제공합니다.
- **필터**로 심각도·규칙 종류를 좁힐 수 있습니다.
- 항목 **더블클릭**으로 소스 위치로 이동합니다.

보안 smell은 **휴리스틱**이며 SonarQube·전용 SAST 도구를 대체하지 않습니다.

## 16. 분석 설정

**분석 항목 설정...** 버튼(또는 **설정** 메뉴)에서 다음을 한곳에서 관리합니다.

### 검사 항목 포함·제외

- 코드 메트릭 종류, 아키텍처 인사이트, 중복 코드, Git 핫스팟 등
- **DB 스키마** — ERD·DB 테이블 접근·DB 인스턴스 카탈로그 분석
- **정보 보호 및 보안** — 보안 smell 및 보안 전용 뷰
- 불필요한 항목을 끄면 **분석 시간이 단축**됩니다.

### 품질 경고 임계값

- CC, 인지 복잡도, God file, LCOM, 패키지 I, Git 핫스팟 등
- 각 항목 옆 **?** 또는 헤더 툴팁으로 설명 확인

### 중복 코드

- **최소 줄 수**(기본 10): 이 길이 이상 동일한 연속 줄이 두 곳 이상이면 중복 그룹으로 묶습니다.

**확인**을 누르면 설정이 저장되며, 다음 **분석 실행**부터 적용됩니다.

## 17. 결과 저장·불러오기·보내기

### JSON 결과 저장·불러오기

| 작업 | 형식 | 포함 내용 |
|------|------|-----------|
| 저장 | `.json` | 호출 그래프, 메트릭, 중복, 전역 변수·접근, DB 스키마·접근, 버그 위험, 구조 등 |
| 불러오기 | `.json` | 저장 당시와 동일한 분석 결과를 다시 표시 (재분석 불필요) |

불러오기 시 저장 파일에 기록된 **루트 디렉터리**가 복원됩니다. 소스 파일 열기·Git 분석은 해당 경로가 유효할 때 정상 동작합니다.

### CSV (메트릭)

- 함수, 파일, 타입, 패키지, **전역 변수**, **전역 변수 접근** 섹션 포함
- Excel·스프레드시트·BI 도구 연동에 적합

### 분석 보고서

HTML / Markdown / Word / PDF 형식. 주요 섹션:

1. 개요  
2. 적용 임계값  
3. 품질 요약·주요 발견  
4. 우선 조치 로드맵  
5. 함수·파일·타입·패키지 메트릭 (상위·경고 위주)  
6. 중복 코드  
7. **전역 변수 및 접근 함수**  
8. **버그 위험**  
9. 아키텍처 인사이트  
10. 지표 용어집(부록)

각 항목에 **권장 조치** 문구가 포함될 수 있습니다. 대형 프로젝트는 행 수가 제한됩니다.

### PNG 이미지

현재 표시 중인 **호출 그래프·구조 다이어그램·DB ERD·접근 그래프** 등을 캡처합니다. 표 뷰(메트릭, 중복, 전역 변수, DB 테이블 접근, 버그 위험, 보안, Summary)는 내보내기 대상이 아닙니다.

### 오류 발생 시

분석·저장·다이어그램 표시 중 오류가 나면 **상세 오류** 창이 열립니다. 예외 형식·메시지·스택 추적을 한 화면에서 확인하고 **오류 내용 복사**로 클립보드에 복사할 수 있습니다.

## 19. 자주 묻는 질문

**Q. 분석이 오래 걸립니다.**  
A. **분석 설정**에서 불필요한 검사를 끄거나, 분석 대상 하위 디렉터리·언어 수를 줄여 보세요. JavaScript/TypeScript 대형 프로젝트는 DB·Lint 분석에 시간이 더 걸릴 수 있습니다.

**Q. 호출 그래프에 함수가 없습니다.**  
A. 해당 언어가 선택되었는지, 파일이 포함 디렉터리에 들어가 있는지 확인하세요. 동적 호출·리플렉션은 정적 분석에서 누락될 수 있습니다.

**Q. Git 핫스팟이 0입니다.**  
A. 루트가 Git 저장소가 아니거나 `git`을 실행할 수 없을 때 발생합니다.

**Q. 경고 색이 안 바뀝니다.**  
A. **분석 설정**에서 임계값을 변경한 뒤 **분석을 다시 실행**했는지 확인하세요.

**Q. 전역 변수 접근 함수가 비어 있습니다.**  
A. 함수 본문에서 해당 변수를 참조하지 않거나, 분석 범위·언어 밖일 수 있습니다. C#/VB는 Roslyn, 그 외는 Tree-sitter/패턴 기반이라 정확도가 다릅니다.

**Q. DB ERD는 보이는데 테이블 접근이 0건입니다.**  
A. 스키마(DDL·마이그레이션·엔티티)는 탐지됐지만, 코드에 **정적 SQL 리터럴**이나 **알려진 DB API** 호출이 없을 수 있습니다. 동적 쿼리 빌더·런타임 SQL 조립은 집계되지 않습니다. **DB 스키마** 검사가 켜져 있는지, 해당 함수가 분석 언어·포함 폴더 범위 안인지 확인하세요.

**Q. C/C++ 프로젝트에 없는 DB 테이블이 보입니다.**  
A. C/C++에서는 DB API 호출이 명확한 경우에만 집계합니다. 그래도 오탐이 있으면 **DB 스키마** 검사를 끄거나, 해당 폴더를 분석 대상에서 제외해 보세요.

**Q. 테이블 접근에 기대한 함수가 없습니다.**  
A. 함수 본문에 DB API 신호(`SqlConnection`, `query(`, `FromSqlRaw` 등)나 구조적 SQL(`SELECT … FROM`)이 없으면 접근으로 잡히지 않을 수 있습니다. ORM은 **스키마에 등록된 엔티티/DbSet**만 매칭합니다.

**Q. 정보 보호 및 보안 뷰가 콤보에 없습니다.**  
A. **분석 설정 → 정보 보호 및 보안**에서 **정보 보호 및 보안 뷰** 또는 **언어별 보안 smell 검사**를 활성화한 뒤 다시 분석하세요.

**Q. MSI가 생성되지 않습니다.**  
A. **Release** 구성으로 빌드했는지 확인하세요. Debug에서는 MSI가 만들어지지 않습니다. Visual Studio에서는 **Release | Any CPU**로 **CodeAnalyzer** 프로젝트를 Rebuild하고, 출력에 `MSI ready:` 메시지가 있는지 확인하세요. 경로: `CodeAnalyzer.Setup\bin\Release\CodeAnalyzer.Setup.msi`

**Q. 보고서와 화면 숫자가 조금 다릅니다.**  
A. 보고서는 상위·경고 항목 위주로 **행 수를 제한**합니다. 전체 데이터는 CSV·JSON 저장을 사용하세요.
