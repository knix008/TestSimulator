# 사용자 매뉴얼 (User Guide)

> 개발/설치 방법은 [README.md](README.md)를 참고하세요. 이 문서는 화면을 어떻게 사용하는지 설명합니다.
> 화면 우측 상단의 **EN / 한국어** 버튼으로 언어를 바꿀 수 있습니다.

## 1. 처음 접속할 때

1. 브라우저에서 사이트 주소로 접속하면, 서버가 아직 DB에 연결되어 있지 않은 경우 자동으로 **DB 접속** 화면(`/connect-db`)으로 이동합니다.
2. 회사/팀의 MySQL 또는 MariaDB 접속 정보(호스트, 포트, 데이터베이스명, 사용자, 비밀번호)를 입력하고 "DB 접속"을 누릅니다.
3. 테이블이 아직 없다는 안내가 나오면 "테이블 생성/동기화"를 눌러 테이블을 만듭니다. 이때 기본 관리자 계정 `admin` / `admin`이 자동으로 만들어집니다.
4. 로그인 화면으로 이동되면 `admin` / `admin`으로 로그인한 뒤, **반드시 내 계정 화면에서 비밀번호를 바꾸세요.**

> 이 DB 접속 정보는 서버가 켜져 있는 동안에만 기억됩니다. 서버를 재시작하면 1~3번 과정을 다시 해야 하지만, DB와 테이블은 그대로 남아있으므로 데이터가 사라지지는 않습니다.

## 2. 로그인 / 계정 등록 요청

- 이미 계정이 있다면 로그인 화면에서 아이디/비밀번호로 로그인합니다.
- 계정이 없다면 로그인 화면의 **"계정 등록 요청"** 링크로 이동해, 사용하고 싶은 아이디/비밀번호와 이름, 이메일, 회사, 부서, 희망 권한(EDITOR 또는 VIEWER)을 입력해 요청을 보냅니다.
- 관리자가 승인하면 로그인할 수 있습니다. 거절되면 다시 요청해야 합니다.

## 3. 요구사항 관리

### 3.1 목록 보기 (`/requirements`)
- 코드/제목/분류로 검색하거나, 상태·우선순위로 필터링할 수 있습니다.
- 목록의 체크박스로 항목을 선택한 뒤 **"선택 내보내기"**를 누르면 선택한 요구사항만 Excel로 받을 수 있습니다.

### 3.2 새 요구사항 만들기 (EDITOR 이상)
- "+ 새 요구사항"을 눌러 제목/설명/분류/우선순위/상태를 입력합니다.
- **코드는 직접 입력하지 않습니다.** 입력한 "분류(Category)" 글자를 그대로 접두사로 사용해 자동으로 부여됩니다.
  예) 분류를 `UI`로 입력하면 `UI-01`, 그 다음 UI 요구사항은 `UI-02`가 됩니다.
- 분류를 비워두면 기본 접두사 `REQ`가 사용됩니다.

### 3.3 수정 / 삭제 (EDITOR 이상)
- 분류를 바꾸면 해당 요구사항의 코드가 새 분류의 접두사로 다시 부여되고, 전체 코드가 빈틈없이 재정렬됩니다.
- 삭제하면 그 요구사항에 연결된 테스트케이스도 모두 함께 삭제되며, 남은 요구사항들의 코드가 분류별로 다시 빈틈없이 재정렬됩니다 (예: UI-02가 삭제되면 UI-03이 UI-02로 바뀝니다).

## 4. 테스트케이스 관리

- 요구사항 상세 화면에서 그 요구사항에 연결된 테스트케이스를 보고, "+ 테스트케이스 추가"로 새로 만들 수 있습니다 (EDITOR 이상).
- 테스트케이스는 코드, 제목, 테스트 절차, 예상 결과, 상태(미실행/통과/실패/차단)를 가집니다.
- 테스트케이스의 코드는 자동 부여되지 않으므로 직접 입력합니다 (예: `TC-001`).

## 5. Excel 가져오기 / 내보내기

### 5.1 가져오기 (`/import`, EDITOR 이상)
- 헤더 행에 `code, title, description, category, priority, status` 컬럼이 있는 `.xlsx` 파일을 올립니다.
- `code`가 이미 있는 요구사항이면 내용을 업데이트하고, 없으면 새로 만듭니다.
- `priority`는 `LOW/MEDIUM/HIGH`, `status`는 `DRAFT/APPROVED/IN_PROGRESS/DONE` 중 하나여야 합니다.
- 화면의 "샘플 파일 다운로드" 링크(`sample/sample_requirements.xlsx`)로 형식을 확인할 수 있습니다.
- 업로드가 끝나면 생성/업데이트 건수와 행별 오류 목록이 표시됩니다.

### 5.2 내보내기 (`/export`, 모든 권한)
- "전체 내보내기"를 누르면 모든 요구사항을 받습니다.
- 요구사항 목록에서 일부만 선택해 "선택 내보내기"를 누르면 선택한 항목만 받습니다.
- 받은 Excel은 시트 2개로 구성됩니다: `Requirements`(요구사항)와 `TestCases`(테스트케이스, `requirementCode` 컬럼으로 어느 요구사항에 속하는지 표시).

## 6. 내 계정 (`/account`)

- 아이디, 이름, 이메일, 회사, 부서, 비밀번호를 직접 변경할 수 있습니다.
- 변경하려면 항상 **현재 비밀번호**를 입력해야 합니다.
- 저장 후에는 변경 내용을 반영하기 위해 다시 로그인해야 합니다.

## 7. 관리자 전용 기능

### 7.1 사용자 관리 (`/users`)
- **가입 요청**: 대기 중인 등록 요청을 승인(계정 생성) 또는 거절할 수 있습니다.
- **새 사용자 추가**: 가입 요청 과정 없이 관리자가 직접 계정을 만들 수 있습니다.
- **사용자 목록**: 각 사용자의 권한(VIEWER/EDITOR/ADMIN)을 바꾸거나, 계정을 비활성화/활성화하거나, **비밀번호를 초기화**할 수 있습니다(새 비밀번호를 입력받는 창이 뜹니다).

### 7.2 DB 설정 (`/settings`)
- 현재 서버가 사용 중인 DB 접속 정보를 보고, 다른 DB로 다시 접속하거나 테이블을 재생성할 수 있습니다.
- 여기서 바꾼 접속 정보도 `.env`에는 저장되지 않고, 서버가 켜져 있는 동안에만 메모리에 유지됩니다.

## 9. 자주 묻는 질문

**Q. 서버를 재시작했더니 로그인 화면이 안 나오고 DB 접속 화면이 나옵니다.**
A. 정상입니다. DB 접속 정보는 메모리에만 있어 재시작하면 사라집니다. 같은 접속 정보를 다시 입력하면 기존 데이터에 그대로 접속됩니다.

**Q. 요구사항 코드를 직접 수정할 수 없나요?**
A. 네, 코드는 분류(Category) 기준으로 시스템이 자동으로 관리하므로 직접 수정할 수 없습니다. 코드를 바꾸려면 분류를 바꾸세요.

**Q. 비밀번호를 잊어버렸어요.**
A. 관리자에게 요청하면 "사용자 관리" 화면에서 비밀번호를 초기화해 줄 수 있습니다.
