## 1. 시작하기

### 프로그램 실행

- **설치한 경우**: 시작 메뉴 또는 바탕 화면의 **DBTools** 실행. `.mdprj` 파일을 더블클릭해도 열립니다.
- **개발 빌드**:

```bash
dotnet run --project DBToolsWinV10.csproj -c Debug
```

### 설치 (MSI)

Release 빌드로 생성된 `DBToolsWinV10Setup.msi`를 실행하여 설치합니다.

| 설치 옵션 | 설명 |
|-----------|------|
| 바탕 화면 바로 가기 | 선택 시 바탕 화면에 바로 가기 생성 |
| 시작 메뉴 바로 가기 | 선택 시 시작 메뉴에 바로 가기 생성 |
| 파일 연결 | `.mdprj` 프로젝트 파일을 DBTools와 연결 |
| 기존 버전 업그레이드 | 이전 설치가 있으면 제거 후 재설치 동의 확인 |
| 제거 시 작업 데이터 | `%AppData%\DBToolsWinV10` 삭제 여부 선택 |

### 새 프로젝트

1. **파일 → 새 프로젝트** 또는 툴바 **새로 만들기** (Ctrl+N)
2. 빈 스키마가 열립니다. 기본 대상 DB는 **SQLite**입니다.

### 프로젝트 열기

1. **파일 → 프로젝트 불러오기** (Ctrl+O)
2. `.mdprj` 파일을 선택합니다.

### 저장

- **파일 → 저장** (Ctrl+S): 현재 경로에 저장
- **파일 → 다른 이름으로 저장** (Ctrl+Shift+S): 새 경로에 저장

변경 사항이 있으면 제목 표시줄에 `●` 표시가 나타나며, 새 프로젝트·다른 파일 열기·종료 시 저장 여부를 묻습니다.

## 2. 화면 구성

```
┌──────────────────────────────────────────────────────────────────────┐
│  메뉴 (파일 | 편집 | 보기 | 분석 | 정보)                              │
├──────────────────────────────────────────────────────────────────────┤
│  툴바 (새로 만들기, 열기, DB 열기, 저장, 테이블, 관계, 줌, Sample …) │
├──────────┬───────────────────────────────────────┬───────────────────┤
│  도구    │         ER 다이어그램 캔버스           │  구조 / 정규화    │
│  패널    │         (눈금자, 테이블, 관계선)       │  분석 / 속성      │
│          │                                       │  [접기]           │
├──────────┴───────────────────────────────────────┴───────────────────┤
│  상태 표시줄 (스키마 이름, DB 종류, 테이블·관계 수 등)               │
└──────────────────────────────────────────────────────────────────────┘
```

### 좌측 도구 패널

| 도구 | 설명 |
|------|------|
| 선택 | 테이블·관계 선택 및 이동 |
| 테이블 | 새 테이블 추가 |
| 1:1 / 1:N / N:M | 관계 유형 선택 후 테이블 간 연결 |
| 확대 / 축소 / 맞춤 | 캔버스 뷰 조절 |

### 우측 패널

- **구조**: 스키마 트리 (테이블, 컬럼, 관계)
- **정규화 분석**: 1NF/2NF/3NF 검사 결과 목록 (심각도·문제 컬럼·권장 사항)
- **속성**: 선택 항목의 속성 그리드. 상단에 **분류별** / **사전순** 정렬 버튼

### 분할선 조절

- **구조 ↔ 속성**: 우측 패널 상단의 가로 분할선을 드래그하여 구조·분석 영역과 속성 영역의 높이를 조절합니다. 기본값은 두 영역이 같은 높이입니다.

### 우측 패널 표시/숨김

- **보기 → 우측 패널 표시/숨김** 또는 툴바/캔버스 가장자리 토글 버튼

## 3. 프로젝트 관리

### 프로젝트 파일 (.mdprj)

- JSON 형식, UTF-8 인코딩
- 포함 내용: 스키마 이름, 대상 DB 종류, 테이블·컬럼·관계, 다이어그램 레이아웃
- DBTools에서 **저장**할 때 사용하는 기본 형식입니다.
- MSI 설치 시 탐색기에서 `.mdprj` 파일을 더블클릭하면 DBTools로 열립니다.

### 최근 파일

**파일 → 최근 파일**에서 최근에 연 프로젝트 최대 10개를 다시 열 수 있습니다.

## 4. DB 파일 가져오기

**파일 → DB 파일 열기** (Ctrl+Shift+O)로 기존 데이터베이스를 분석해 ER 다이어그램으로 표시합니다.

| 형식 | 확장자 | 설명 |
|------|--------|------|
| SQLite | `.db`, `.sqlite`, `.sqlite3`, `.db3` | SQLite 데이터베이스 파일 |
| SQLCipher | `.db` 등 | 암호화된 SQLite (SQLCipher) |
| Vector Index | Faiss, hnswlib 등 | 벡터 DB 인덱스 파일 |
| SQL DDL | `.sql` | CREATE TABLE 등 DDL 스크립트 |
| SQL Server | `.mdf` | SQL Server 데이터 파일 (LocalDB 등) |
| Access | `.mdb`, `.accdb` | Microsoft Access 데이터베이스 |

가져온 스키마는 메모리에 로드되며, `.mdprj`로 저장하기 전까지 프로젝트 파일과 연결되지 않습니다.

> Access 가져오기는 ACE OLEDB가 설치되어 있어야 합니다. 일부 관계 정보는 가져오지 못할 수 있습니다.

## 5. 스키마 편집

### 테이블 추가

| 방법 | 설명 |
|------|------|
| **편집 → 테이블 추가** (Ctrl+T) | 새 테이블 대화상자 |
| 툴바 **테이블 추가** | 위와 동일 |
| 좌측 **테이블** 도구 | 캔버스에 테이블 배치 |
| 캔버스 빈 곳 우클릭 | **여기에 새 테이블 추가** |

### 컬럼 추가

1. 테이블을 선택합니다.
2. **편집 → 컬럼 추가** (Ctrl+L) 또는 구조 트리에서 테이블 우클릭

컬럼 속성: 이름, 데이터 타입, PK, 자동 증가, NULL 허용, UNIQUE, 기본값, 설명 등

### 관계 추가

1. 좌측에서 **1:1**, **1:N**, **N:M** 중 관계 유형을 선택합니다.
2. 소스 테이블의 컬럼에서 타겟 테이블의 컬럼으로 드래그하여 연결합니다.

또는 **편집 → 관계 추가** (Ctrl+R)로 대화상자에서 설정할 수 있습니다.

### 선택 항목 편집 / 삭제

| 방법 | 설명 |
|------|------|
| **편집 → 선택 항목 편집** (F2) | 테이블·컬럼·관계 속성 대화상자 |
| 우측 속성 패널 | 그리드에서 직접 편집 |
| **편집 → 선택 항목 삭제** (Delete) | 선택한 테이블 또는 관계 삭제 |
| 더블 클릭 | 테이블·관계 편집 대화상자 |

### 캔버스 조작

- **테이블 이동**: 선택 도구로 드래그
- **캔버스 이동(팬)**: 선택 도구 또는 관계 도구 상태에서 빈 영역을 드래그
- **확대/축소**: 툴바 버튼, **보기** 메뉴, 또는 Ctrl + +/-
- **전체 맞춤**: Ctrl+0 또는 **보기 → 전체 맞춤**
- **배율 100% 복원**: 툴바의 배율(%) 버튼 클릭, 또는 캔버스 빈 곳 우클릭 → **배율 100%로 복원**

### 캔버스 빈 곳 우클릭 메뉴

| 항목 | 설명 |
|------|------|
| 여기에 새 테이블 추가 | 클릭 위치에 테이블 생성 |
| 화면 맞춤 | 모든 테이블이 보이도록 맞춤 |
| 확대 / 축소 | 배율 조절 |
| 배율 100%로 복원 | 줌을 100%로 되돌림 |

### 속성 패널 정렬

속성 패널 상단의 정렬 버튼 또는 우클릭 메뉴에서 선택합니다.

| 모드 | 설명 |
|------|------|
| **분류별** | 일반 / 제약조건 / 정보 등 카테고리별로, 정의 순서대로 표시 |
| **사전순** | 카테고리 헤더는 유지하고, 각 카테고리 안에서 속성 이름 순으로 정렬 |

예: `제약조건` 카테고리에서 **분류별**은 `기본 키 → 자동 증가 → …` 순, **사전순**은 `기본값 → 자동 증가 → …` 순으로 표시됩니다.

## 6. 대상 데이터베이스 종류

**보기 → 데이터베이스 종류** 또는 툴바 DB 드롭다운에서 대상 DB를 선택합니다.

| DB | 용도 |
|----|------|
| SQLite | 기본값. 타입 매핑 및 DDL보내기 |
| PostgreSQL | DDL보내기 타입 (BIGSERIAL, TIMESTAMPTZ 등) |
| MySQL | DDL보내기 |
| MariaDB | DDL보내기 |
| SQL Server | DDL보내기 |
| FAISS (Vector DB) | 벡터 DB 스키마 설계 및 타입 표시 |

대상 DB를 바꾸면 컬럼에 표시되는 데이터 타입 목록과 SQL보내기 결과가 해당 DB에 맞게 조정됩니다.

## 7.보내기

**파일 →보내기**에서 현재 스키마를 외부 형식으로 저장합니다.

### SQL DDL보내기

- 현재 **대상 DB 종류**에 맞는 CREATE TABLE, 제약 조건 DDL을 생성합니다.
- 파일 확장자는 보통 `.sql`입니다.

### JSON보내기

- 스키마 전체를 JSON으로 저장합니다 (`.mdprj`와 유사한 구조).

## 8. 정규화 분석

**분석 → 정규화 검사 실행** (F5) 또는 툴바 **분석** 버튼

- 1NF, 2NF, 3NF 관점에서 스키마를 검사합니다.
- 스키마를 수정하면 우측 **정규화 분석** 탭이 자동으로 갱신됩니다.
- F5를 누르면 분석 탭으로 이동하며 결과를 강조합니다.

### 결과 표시

| 항목 | 설명 |
|------|------|
| 상단 요약 | 문제 없음(녹색) 또는 오류·경고·정보 건수 |
| 수준 | 1NF / 2NF / 3NF 그룹별 목록 |
| 심각도 | 오류(빨강), 경고(노랑), 정보(보라) 색상으로 표시 |
| 문제 컬럼 | 해당 테이블에서 문제가 되는 컬럼 이름 |
| 권장 | 개선 방향 안내 |

결과 항목을 **더블클릭**하면 해당 테이블이 다이어그램에서 선택됩니다.

## 9. 보고서 작성

**분석 → 보고서 작성** (Ctrl+Shift+R)

Markdown 형식의 스키마 보고서를 생성합니다. 포함 내용:

- 스키마 개요 (이름, 대상 DB, 테이블·관계 수)
- 테이블별 컬럼 정의 표
- 관계 목록
- 정규화 검사 결과

Template 폴더의 `OnlineShop_report.md`가 이 형식의 예제입니다.

## 10. Sample 생성

**파일 → Sample 생성** 또는 툴바 **Sample** 드롭다운에서 DB별 예제 파일을 생성합니다.

### 메뉴 항목

| 항목 | 생성 내용 |
|------|-----------|
| 전체 Sample 생성 | 모든 형식 일괄 생성 |
| SQLite Sample | `.db` 파일 |
| PostgreSQL / MySQL / MariaDB Sample | 해당 DB용 `.sql` DDL |
| SQL Server Sample | `.sql` DDL 및 `.mdf` (LocalDB 필요) |
| Access Sample | `.accdb` (ACE OLEDB 필요) |

폴더 선택 대화상자가 열리며, 기본 경로는 `{실행 폴더}/Template`입니다.

### OnlineShop 예제 스키마

5개 테이블, 4개 관계의 간단한 쇼핑몰 스키마입니다.

- `users` — 회원
- `categories` — 상품 카테고리
- `products` — 상품
- `orders` — 주문
- `order_items` — 주문 상세

### 콘솔에서 생성

```bash
dotnet run --project Sample/Sample.csproj
```

`Template/` 폴더에 모든 Template 파일을 재생성합니다.

| 항목 | 경로 |
|------|------|

```

├── OnlineShop_postgres.sql
├── OnlineShop_mysql.sql
├── OnlineShop_mariadb.sql
├── OnlineShop_sqlserver.sql
├── OnlineShop_sqlserver.mdf
├── OnlineShop_access.accdb
└── OnlineShop_report.md
```

## 13. 자주 묻는 질문

### Q. DB 파일을 열었는데 관계가 보이지 않습니다.

일부 DB 형식(특히 Access)에서는 외래 키·관계 메타데이터를 완전히 읽어오지 못할 수 있습니다. SQL DDL이나 `.mdprj` 프로젝트 파일을 사용하면 관계 정보를 더 정확히 유지할 수 있습니다.

### Q. SQL Server MDF Sample이 생성되지 않습니다.

SQL Server LocalDB가 설치되어 있는지 확인하세요. LocalDB 없이도 `.sql` DDL Sample은 생성됩니다.

### Q. Access Sample이 생성되지 않습니다.

[Microsoft Access Database Engine](https://www.microsoft.com/download/details.aspx?id=54920) (ACE) 64비트/32비트가 앱과 동일한 비트 수로 설치되어 있어야 합니다.

### Q.보낸 SQL을 다른 DB에서도 쓰일 수 있나요?

**보기 → 데이터베이스 종류**에서보낼 대상 DB를 먼저 선택한 뒤 SQL DDL을보내세요. DB마다 타입·구문이 다릅니다.

### Q. 속성 패널에서 분류별과 사전순의 차이는 무엇인가요?

**분류별**은 카테고리 안에서 속성이 정의된 순서대로 표시됩니다. **사전순**은 카테고리 헤더는 그대로 두고 각 카테고리 안에서 속성 이름 순으로 정렬합니다. 속성 패널 상단의 **분류별** / **사전순** 버튼 또는 우클릭 메뉴에서 전환할 수 있습니다.

### Q. 속성 패널 아래에 빈 공간이 보입니다.

하단 설명 영역은 사용하지 않도록 비활성화되어 있습니다. Designer에서 공백이 보이면 `HelpVisible = false` 설정이 적용된 최신 버전인지 확인하세요.

### Q. Release 빌드 시 MSI가 생성되지 않습니다.

WiX Toolset SDK가 NuGet으로 복원되는지, `installer\DBToolsWinV10.Installer.wixproj`가 존재하는지 확인하세요. 설치 패키지만 건너뛰려면 `-p:SkipInstaller=true`를 사용합니다.

### Q. 빌드 후 실행 파일이 잠겨 있습니다.

이전에 실행 중인 `DBToolsWinV10.exe`를 종료한 뒤 다시 빌드하세요.

### Q. 오류가 발생하면 어떤 정보가 표시되나요?

오류 대화상자에 예외 유형, 메시지, 발생 위치(소스 파일·줄)가 표시되며, **세부 정보** 영역에서 전체 스택 트레이스를 확인할 수 있습니다.
