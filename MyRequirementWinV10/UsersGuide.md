## 1. 시작하기

### 프로그램 설치 (MSI)

1. `ReqTraceSetup-1.0.0.msi`를 실행합니다.
2. 설치 마법사에서 다음 옵션을 선택할 수 있습니다.
   - **Start Menu shortcut** (시작 메뉴 바로 가기) — 기본 선택
   - **Desktop shortcut** (바탕 화면 바로 가기)
   - **Associate .reqtproj files** (`.reqtproj` 파일 연결) — 기본 선택
3. 설치가 완료되면 시작 메뉴 또는 바탕 화면의 ReqTrace 아이콘으로 실행합니다.

바로 가기는 프로그램 아이콘(`app-icon.ico`)을 사용합니다. `.reqtproj` 파일은 프로젝트 전용 아이콘으로 표시됩니다.

### 프로그램 실행

- **설치본**: 시작 메뉴 또는 바탕 화면의 **ReqTrace** 실행
- **`.reqtproj` 더블 클릭**: ReqTrace가 실행되며 해당 프로젝트 파일을 엽니다.
- **개발 빌드**:

```bash
cd ReqTrace
dotnet run --project ReqTrace.csproj -c Debug
```

- **Visual Studio**: `ReqTrace.slnx`를 연 뒤 F5로 실행

### 마지막 프로젝트 자동 열기

프로그램을 시작하면 **마지막으로 작업한 프로젝트**를 자동으로 엽니다. 저장된 경로의 파일이 없으면 최근 프로젝트 목록에서 찾거나, 빈 새 프로젝트로 시작합니다.

### 새 프로젝트

1. **파일 → 새 프로젝트** 또는 툴바 **새로 만들기** (Ctrl+N)
2. 프로젝트 이름을 입력합니다.
3. 빈 요구사항 목록으로 시작합니다.

### 샘플 프로젝트

설치 폴더 또는 저장소의 `Sample` 디렉터리에 예제 프로젝트가 있습니다.

| 파일 | 설명 |
|------|------|
| `Sample/Sample.reqtproj` | 영문 샘플 (요구사항 12건, 테스트 케이스 포함) |
| `Sample/Sample.xlsx` | 영문 Excel import 샘플 |
| `Sample/SampleKo.reqtproj` | 한글 샘플 (동일 구조, 한글 요구사항·테스트 케이스) |
| `Sample/SampleKo.xlsx` | 한글 Excel import 샘플 (한글 헤더·우선순위·상태) |

**파일 → 프로젝트 열기**로 해당 `.reqtproj`를 선택하면 바로 살펴볼 수 있습니다.

### 프로젝트 열기

1. **파일 → 프로젝트 열기...** (Ctrl+O)
2. `.reqtproj` 파일을 선택합니다.
3. **파일 → 최근 프로젝트**에서 최근 파일을 바로 열 수 있습니다.

### 저장

- **파일 → 저장** (Ctrl+S): 현재 경로에 저장
- **파일 → 다른 이름으로 저장...** (Ctrl+Shift+S): 새 경로에 저장

편집 내용이 있으면 상태 표시줄 파일 경로 뒤에 `*`가 표시됩니다. **실제로 변경한 내용이 있을 때만** 종료·새 프로젝트 시 저장 여부를 묻습니다.

## 2. 화면 구성

```
┌──────────────────────────────────────────────────────────────────┐
│  메뉴 (파일 | 편집 | 보기 | 도구 | 도움말)                       │
├──────────────────────────────────────────────────────────────────┤
│  툴바 (새로 만들기, 열기, 저장, 가져오기, 내보내기, …)          │
├─────────────────────┬──────────────────────────────────────────┤
│  요구사항           │  요구사항 상세                           │
│  (목록)             │  (코드, 제목, 카테고리, 우선순위, …)     │
│                     ├──────────────────────────────────────────┤
│                     │  테스트 케이스 (그리드)                  │
├─────────────────────┴──────────────────────────────────────────┤
│  상태 표시줄 (프로젝트 경로·아이콘, 요구사항 수, 커버리지, …)   │
└──────────────────────────────────────────────────────────────────┘
```

### 패널 조절

- **좌↔우**, **상↔하** 분할선을 드래그하여 각 패널 크기를 조절합니다.
- 패널 제목 바(요구사항 / 요구사항 상세 / 테스트 케이스)로 영역을 구분합니다.
- 요구사항 목록 패널은 **좌측·상·하** 여백과 테두리가 있고, **우측**은 분할선과 맞닿습니다.
- 상세·테스트 케이스 패널은 **네 방향** 여백과 테두리가 있습니다.

### 상태 색상

요구사항·테스트 케이스의 **최근 실행 상태**에 따라 글자색이 달라집니다.

| 상태 | 의미 |
|------|------|
| 통과 | 모든 테스트가 통과 |
| 실패 | 하나 이상 실패 |
| 차단 | 차단된 테스트 포함 |
| 미실행 | 실행 기록 없음 또는 미완료 |

행을 선택하면 파스텔 톤 배경으로 강조됩니다.

## 3. 프로젝트 관리

### ReqTrace 프로젝트 파일 (.reqtproj)

- JSON 형식, UTF-8 인코딩
- 포함 내용: 프로젝트 이름, 요구사항, 테스트 케이스, 실행 이력, Parent 관계
- 저장 시 기존 파일은 `.bak` 백업이 생성됩니다.
- MSI 설치 시 **파일 연결**을 선택하면 탐색기에서 `.reqtproj` 더블 클릭으로 열 수 있습니다.

### 변경 사항 추적

- 요구사항·테스트·실행 기록을 수정하면 **저장되지 않은 변경** 상태가 됩니다.
- 변경 없이 **새 프로젝트**, **다른 프로젝트 열기**, **종료** 시에는 확인 대화상자가 표시되지 않습니다.
- 변경 후 위 작업을 하면 **저장 여부**를 묻습니다 (예: 저장 후 계속 / 저장하지 않고 계속 / 취소).

## 4. 데이터베이스 연결

ReqTrace는 파일(`.reqtproj`) 외에도 **MySQL, MariaDB, PostgreSQL, SQLite3, MS SQL Server**에 직접 연결하여 프로젝트를 저장·불러올 수 있습니다.

### 연결하기

1. **데이터베이스 → 데이터베이스 연결...**
2. 데이터베이스 종류를 선택합니다.
   - **MySQL / MariaDB / PostgreSQL / MS SQL Server**: 서버, 포트, 데이터베이스 이름, 사용자, 비밀번호 입력 (MS SQL Server는 **Windows 통합 인증** 사용 가능)
   - **SQLite3**: 파일 경로만 지정 (없으면 새로 생성)
3. **연결 테스트**로 접속 가능 여부를 확인합니다.
4. **확인**을 누르면 연결 정보가 현재 세션에 저장됩니다.

> 지정한 데이터베이스나 테이블(Requirements, TestCases, TestSteps, TestRuns)이 아직 없으면 **처음 연결할 때 자동으로 생성**됩니다. 별도의 DB 초기화 작업이 필요 없습니다.

### 저장 / 불러오기

| 메뉴 | 동작 |
|------|------|
| **데이터베이스 → 데이터베이스에 저장** | 현재 프로젝트(요구사항·테스트 케이스·실행 이력)를 DB에 통째로 저장 (기존 데이터 교체) |
| **데이터베이스 → 데이터베이스에서 불러오기** | DB에 저장된 프로젝트를 불러와 현재 작업을 대체 |

아직 연결하지 않은 상태에서 두 메뉴를 선택하면 연결 대화상자가 먼저 표시됩니다.

### 참고

- 비밀번호 등 연결 정보는 **디스크에 저장되지 않고** 프로그램 실행 중에만 메모리에 유지됩니다. 프로그램을 다시 시작하면 다시 연결해야 합니다.
- 파일(`.reqtproj`) 저장과 데이터베이스 저장은 **서로 별개**입니다. 한쪽에 저장해도 다른 쪽은 자동으로 갱신되지 않습니다.

## 5. 언어 설정

ReqTrace는 **한국어**(기본)와 **English**를 지원합니다.

1. **파일 → 언어 설정**
2. **한국어** 또는 **English** 선택
3. 메뉴·패널·대화상자가 **즉시** 선택한 언어로 바뀝니다.

선택한 언어는 `%AppData%\ReqTrace\settings.json`에 저장되어 다음 실행 시에도 유지됩니다.

## 6. 요구사항 작업

### 요구사항 추가

1. **편집 → 요구사항 추가** 또는 툴바 **요구사항 추가** (Ctrl+Shift+N)
2. 코드, 제목, 설명, 카테고리, 우선순위, 상태, 출처, 상위 요구사항을 입력합니다.
3. **확인**을 누르면 목록에 추가됩니다.

> **제목**은 필수입니다. 코드를 비워 두면 자동 생성됩니다.

### 요구사항 편집

다음 방법으로 편집할 수 있습니다.

| 방법 | 설명 |
|------|------|
| **상세 패널 인라인 편집** | 목록에서 요구사항 선택 후 우측 상단 패널에서 코드·제목·카테고리·설명·우선순위·상태를 직접 수정 (포커스 이동 시 자동 저장) |
| **편집 대화상자** | **편집 → 요구사항 편집** (F2), 상세 패널 **요구사항 편집...** 버튼, 또는 목록 **더블 클릭** |
| **출처·상위 편집** | 편집 대화상자에서 Source, Parent 등 전체 필드 수정 |

상세 패널의 우선순위·상태는 드롭다운(콤보 박스)으로 선택합니다.

### 요구사항 삭제

1. 목록에서 요구사항 선택
2. **편집 → 요구사항 삭제** (Delete)
3. 확인 시 해당 요구사항과 **연결된 모든 테스트 케이스**가 함께 삭제됩니다.

### 상위 요구사항 (Parent)

편집 대화상자에서 **상위**를 지정하면 계층 관계가 생깁니다. **보기 → 계층별 그룹**에서 트리 형태로 표시할 수 있습니다.

## 7. Excel에서 가져오기

### 준비

- Excel 파일 형식: **`.xlsx`**
- 첫 행(또는 지정한 행)에 **열 헤더**가 있어야 합니다.
- **제목** 열은 필수입니다. (매핑 화면에서 반드시 지정)

### 가져오기 절차

1. **파일 → Excel에서 가져오기...** (Ctrl+I)
2. Excel 파일 선택
3. **가져오기 매핑** 대화상자에서 설정:
   - **시트**: 데이터가 있는 시트
   - **헤더 행**: 헤더가 있는 행 번호 (기본 1)
   - **열 매핑**: Code, Title, Description, Category, Priority, Status, Source, ParentCode
   - **미리보기**: 상위 10행 확인
4. 옵션:
   - **코드가 없으면 ID 자동 생성**: Code 열이 비어 있어도 REQ-001 형식으로 생성
   - **제목/설명에서 테스트 케이스 자동 생성**: import 시 기본 테스트 케이스 생성
5. **가져오기** 클릭 → 진행률 표시 후 완료
6. **가져오기 요약**에서 처리·건너뜀·추가 건수 확인

### 자동 열 매핑 (한글 헤더 예)

| 필드 | 인식 가능한 헤더 예 |
|------|---------------------|
| Code | 코드, 요구사항 ID, 식별자 |
| Title | 제목, 요구사항명, 요구사항 |
| Description | 설명, 내용, 상세 |
| Category | 분류, 카테고리, 모듈 |
| Priority | 우선순위, 중요도 |
| Status | 상태, 진행상태 |
| ParentCode | 상위, 부모, 상위요구사항, 상위 코드 |

**우선순위·상태 값**은 영문(`high`, `approved`, `inProgress` 등)과 한글(`높음`, `승인됨`, `진행 중` 등) 모두 인식합니다.

매핑이 잘못되면 미리보기와 경고 메시지를 확인하세요.

### 중복 코드

프로젝트에 이미 같은 **코드**의 요구사항이 있으면, **한 번** 덮어쓰기 여부를 묻습니다. **예**를 선택하면 중복 항목을 모두 덮어쓰고, **아니오**를 선택하면 중복 항목은 건너뛰고 새 코드만 추가합니다.

### Excel 사용 시 참고

- Excel에서 파일을 **읽기 전용**으로 열어 두어도 가져오기가 가능합니다.
- 파일이 **다른 프로그램에서 독점 잠금**되어 있으면 오류가 날 수 있습니다. Excel을 닫고 다시 시도하세요.
- 병합된 셀·표 아래쪽의 데이터도 읽도록 처리되어 있습니다.

## 8. 테스트 케이스

### 테스트 케이스 추가

1. **요구사항 목록에서 부모 요구사항 선택**
2. **편집 → 테스트 케이스 추가** (Ctrl+T)
3. 코드, 제목, 전제 조건, 예상 결과, **단계**(동작 / 예상 결과) 입력
4. **확인**

요구사항을 선택하지 않으면 안내 메시지가 표시됩니다.

### 테스트 케이스 편집 / 삭제

- 그리드에서 행 선택 → **편집 → 테스트 케이스 편집** (Shift+F2) 또는 **더블클릭**
- **편집 → 테스트 케이스 삭제** (Shift+Delete)

### Excel import 시 자동 생성

가져오기 옵션 **테스트 케이스 자동 생성**을 켜면 요구사항마다 기본 테스트(정상·비정상·경계 등)가 만들어질 수 있습니다. 생성되는 제목·전제 조건·단계 문구는 **현재 UI 언어 설정**(한국어/English)을 따릅니다.

## 9. 테스트 실행 기록

1. 요구사항과 **테스트 케이스**를 선택
2. **편집 → 테스트 실행 기록** (F5) 또는 툴바 **실행 기록**
3. 상태(통과/실패/차단/미실행), 실행자, 실행 일시, 빌드/버전, 메모 입력
4. 하단 **실행 이력**에서 과거 기록 확인
5. **확인**

기록 후 테스트 케이스의 **최근 상태**와 요구사항 **집계 상태**가 갱신됩니다.

## 10. 목록 보기 및 정렬

### 요구사항 목록 열

목록에는 다음 **9개 열**이 표시됩니다.

| 열 | 내용 |
|----|------|
| Code | 요구사항 코드 |
| Title | 제목 |
| Description | 설명 |
| Category | 카테고리 |
| Priority | 우선순위 |
| Requirement Status | 요구사항 상태 |
| Test Status | 테스트 집계 상태 |
| Source | 출처 |
| Parent | 상위 요구사항 코드 |

### 요구사항 목록 정렬

**열 헤더**를 클릭하면 해당 열 기준으로 정렬됩니다. 같은 헤더를 다시 클릭하면 오름차순 ↔ 내림차순이 바뀝니다 (헤더에 ▲/▼ 표시).

### 보기 모드

| 메뉴 | 설명 |
|------|------|
| **보기 → 카테고리별 그룹** | 평면 목록 (기본) |
| **보기 → 계층별 그룹** | Parent 관계에 따른 들여쓰기 트리 |

계층 보기에서 Parent 관계가 끊긴 요구사항도 목록 **하단**에 표시됩니다.

### 새로 고침

**보기 → 새로 고침** (Ctrl+R)으로 화면을 다시 그립니다.

## 11. 추적성 요약

**도구 → 추적성 요약** (Ctrl+Shift+T)을 선택하면 다음 정보를 확인할 수 있습니다.

- 전체 요구사항 수
- 테스트가 연결된 요구사항 수
- 전체 테스트 케이스 수
- **커버리지** (%): 테스트가 있는 요구사항 비율
- **통과율** (%): 실행된 테스트 중 통과 비율

상태 표시줄에도 요구사항 수·커버리지·통과율이 요약 표시됩니다.

## 12. 보고서 내보내기

1. **파일 → 보고서 내보내기...** (Ctrl+E)
2. **형식** 선택: Excel, Word, Markdown, PDF (복수 선택 가능)
3. **범위**:
   - 모든 요구사항
   - 테스트 케이스가 있는 요구사항만
4. **전체 실행 이력 포함** (선택)
5. **출력 폴더** 지정 → **찾아보기...**
6. **내보내기**

파일 이름 형식: `{프로젝트명}_Traceability_yyyyMMdd_HHmm.{확장자}`

완료 후 **폴더 열기** 여부를 선택할 수 있습니다.

## 15. 자주 묻는 질문

### Excel 가져오기 후 목록에 항목이 없어요

- **가져오기 요약**의 추가 건수가 0인지 확인하세요.
- **제목** 열 매핑과 **헤더 행** 번호가 맞는지 확인하세요.
- Title이 비어 있는 행은 건너뜁니다. Description만 있는 경우 Description을 Title로 사용합니다.
- **보기 → 카테고리별 그룹**으로 전환해 전체 목록을 확인하세요.

### 상태 표시줄 요구사항 수와 목록 개수가 다릅니다

- **보기 → 새로 고침** (Ctrl+R)을 실행하세요.
- **계층별 그룹** 모드에서는 Parent 관계에 따라 들여쓰기만 다를 뿐, 누락된 항목은 하단에 표시됩니다.

### Excel 파일을 열 수 없다는 오류가 납니다

- Excel에서 해당 파일을 닫거나, 다른 프로그램의 **독점 잠금**을 해제한 뒤 다시 시도하세요.

### 종료할 때 저장 확인이 뜹니다

- 실제로 요구사항·테스트·실행 기록을 **수정한 경우**에만 확인 대화상자가 표시됩니다.
- 변경 없이 종료하면 확인 없이 바로 종료됩니다.

### .reqtproj 파일이 ReqTrace로 열리지 않아요

- MSI 설치 시 **파일 연결** 옵션을 선택했는지 확인하세요.
- Windows **기본 앱** 설정에서 `.reqtproj` 연결을 ReqTrace로 지정할 수 있습니다.

### 보고서 PDF 생성

QuestPDF **Community license**를 사용합니다. 상업적 대량 배포 시 QuestPDF 라이선스 조건을 확인하세요.

### 영어 UI로 바꾸려면

**파일 → 언어 설정 → English**를 선택하세요. 재시작 없이 즉시 적용됩니다.

### 데이터베이스 연결이 "Unknown database" 오류로 실패합니다

- ReqTrace가 대상 데이터베이스를 자동 생성하지만, 연결 계정에 **데이터베이스 생성 권한**이 없으면 실패할 수 있습니다. DBA에게 권한을 요청하거나, 미리 빈 데이터베이스를 만들어 두세요.
- 데이터베이스 이름은 영문자·숫자·언더스코어만 허용됩니다.

### 데이터베이스에 저장했는데 파일(.reqtproj)에는 반영되지 않아요

- 파일 저장과 DB 저장은 서로 독립적입니다. 두 곳 모두에 보관하려면 **파일 → 저장**과 **데이터베이스 → 데이터베이스에 저장**을 각각 실행하세요.

## 16. 웹 애플리케이션 (Webapp)

ReqTrace 데스크톱 앱과는 **완전히 독립적인** 브라우저 기반 클라이언트가 `Webapp/` 디렉터리에 포함되어 있습니다. Node.js + Express 서버와 React 프론트엔드로 구성되며, 데스크톱 앱과 마찬가지로 MySQL·MariaDB·PostgreSQL·SQLite3·MS SQL Server에 연결해 요구사항/테스트 케이스를 조회·편집하고 대시보드로 현황을 볼 수 있습니다.

- 데스크톱 앱과 **별도의 테이블 스키마**(snake_case)를 사용하므로, 같은 DB라도 데스크톱 앱이 만든 데이터와는 호환되지 않습니다.
- 실행 방법, 폴더 구조, API 구성 등 자세한 내용은 [Webapp/README.md](Webapp/README.md)를 참고하세요.
