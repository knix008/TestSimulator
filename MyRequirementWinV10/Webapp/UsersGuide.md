# ReqTrace Web 사용자 가이드

ReqTrace Web은 브라우저에서 요구사항과 테스트 케이스를 관리하고 현황을 확인하는 웹 애플리케이션입니다. 데스크톱 ReqTrace 앱과는 별개의 독립적인 프로그램이며, 별도의 데이터베이스 스키마를 사용합니다.

## 1. 구성 요소

ReqTrace Web은 두 개의 화면으로 이루어져 있습니다.

| 화면 | 주소(기본값) | 용도 | 누가 쓰나요 |
|------|--------------|------|-------------|
| **서버 관리 콘솔** | `http://localhost:4000/admin` | DB 연결 설정, 사용자 추가/삭제/권한 변경, 서버 현황 확인 | 관리자(운영 담당자) |
| **요구사항 관리 클라이언트** | `http://localhost:5173` | 요구사항/테스트 케이스 조회·편집, 대시보드 확인 | 모든 사용자 |

두 화면은 서로 다른 로그인 세션을 사용합니다. 관리 콘솔에 로그인했다고 해서 클라이언트에 자동으로 로그인되지는 않습니다(반대도 마찬가지).

## 2. 최초 설정 (서버 관리 콘솔)

서버를 처음 실행하면 아직 어떤 데이터베이스에도 연결되어 있지 않으므로, 로그인에 사용할 `users` 테이블 자체가 없습니다.

1. 브라우저에서 `http://localhost:4000/admin`에 접속합니다.
2. 페이지에 **"관리자 로그인"** 화면이 나타납니다(브라우저 자체 팝업이 아니라 페이지 안의 입력 폼입니다). 이 단계에서는 **고정된 부트스트랩 로그인**(기본값 `admin` / `admin`, 운영자가 환경 변수로 변경 가능)을 입력합니다.
3. 로그인하면 "DB 설정" 화면이 보입니다. 데이터베이스 종류(MySQL/MariaDB/PostgreSQL/SQLite3/MS SQL Server)와 접속 정보를 입력합니다. **데이터베이스** 이름은 기본값으로 `reqtrace`가 채워져 있습니다.
4. **저장 및 연결**을 누르면 연결을 시도하고, 대상 데이터베이스와 테이블이 없으면 자동으로 생성합니다. `users` 테이블이 새로 만들어지면 **DB 안에** 기본 관리자 계정(`admin` / `admin`)도 함께 생성됩니다.
5. 연결되면 화면이 바뀌어 일반 로그인 폼이 나타납니다. 이번에는 방금 DB에 생성된 관리자 계정(`admin` / `admin`)으로 다시 로그인하세요. 부트스트랩 로그인은 더 이상 사용할 수 없습니다.
6. 로그인하면 콘솔 상단에 **DB 설정 / 사용자 설정 / 관리자 설정** 세 개의 탭이 나타나고, 어느 페이지든 자유롭게 골라 들어갈 수 있습니다.

> 이미 `users` 테이블이 있는 DB(예전에 한 번 연결했던 DB)를 다시 연결하면, 그 안의 계정과 비밀번호를 그대로 사용합니다 — 다시 시드하지 않습니다.

## 3. 로그인

`http://localhost:5173`에 접속하면 로그인 화면이 나타납니다. 사용자 ID와 비밀번호를 입력하세요. (관리 콘솔의 부트스트랩 로그인과는 다른, DB에 저장된 사용자 계정으로 로그인합니다.)

- 처음 설정한 경우 기본 관리자 계정(`admin` / `admin`)으로 로그인할 수 있습니다. **로그인 후 즉시 ID와 비밀번호를 변경**하세요(관리 콘솔에서 "ID 변경" / "비밀번호 변경").
- 다른 사용자는 관리자가 관리 콘솔에서 만들어준 ID/비밀번호로 로그인합니다.
- 로그인 세션은 브라우저에 저장되며, 화면 우측 상단의 **로그아웃** 버튼으로 종료할 수 있습니다.

---

## 4. 사용자 권한

| 역할 | 화면에 보이는 표시 | 할 수 있는 일 |
|------|---------------------|----------------|
| 관리자 | 관리자 | 모든 기능 + 사용자 관리, DB 연결 설정 |
| 편집자 | 편집자 | 요구사항/테스트 케이스 조회 **및 변경**(추가·편집·삭제·자동 생성·실행 기록) |
| 조회자 | 조회자 | 요구사항/테스트 케이스/대시보드 **조회만** 가능 |

- 조회자로 로그인하면 추가·편집·삭제·자동 생성·실행 기록 버튼이 화면에 보이지 않습니다.
- 버튼이 보이지 않더라도 서버 쪽에서도 동일하게 권한을 검사하므로, 직접 API를 호출해도 변경 작업은 거부됩니다.

---

## 5. 요구사항 작업

**요구사항 / 테스트 케이스** 메뉴로 이동합니다.

- **추가**: 목록 상단의 **+ 추가** 버튼(편집자/관리자만 표시) → 코드·제목·카테고리·우선순위·상태·출처·설명 입력 → **저장**.
- **편집**: 목록 행의 **편집** 버튼.
- **삭제**: 목록 행의 **삭제** 버튼. 해당 요구사항에 연결된 모든 테스트 케이스도 함께 삭제됩니다.
- 행을 클릭하면 하단에 해당 요구사항의 **테스트 케이스** 패널이 나타납니다.

---

## 6. 테스트 케이스

요구사항을 선택하면 아래에 테스트 케이스 목록이 표시됩니다.

- **+ 테스트 케이스 추가**로 코드·제목·전제 조건·예상 결과·단계(동작/예상 결과)를 입력합니다.
- **편집**으로 기존 테스트 케이스 내용과 단계를 수정합니다.
- **삭제**로 테스트 케이스를 제거합니다(연결된 실행 기록도 함께 삭제).

---

## 7. 테스트 케이스 자동 생성

요구사항 목록에서 **테스트 자동 생성** 버튼을 누르면, 해당 요구사항의 제목·설명·우선순위를 바탕으로 다음 테스트 케이스를 자동으로 만들어줍니다.

| 생성되는 케이스 | 조건 |
|-----------------|------|
| 정상 시나리오 (TC1) | 항상 생성. 설명의 문장을 단계로 분리해 자동 채움 |
| 잘못된/경계 입력 (TC2) | 항상 생성 |
| 경계 조건 (TC3) | 요구사항 우선순위가 **높음** 또는 **긴급**일 때만 생성 |

생성 후 몇 건이 추가되었는지 알림으로 표시됩니다. 생성된 내용은 필요에 따라 다시 편집할 수 있습니다.

---

## 8. 테스트 실행 기록

테스트 케이스의 **실행 기록** 버튼을 누르면 상태(통과/실패/차단/미실행)·실행자·메모를 입력해 기록을 남길 수 있습니다. 가장 최근 실행 상태가 테스트 케이스 옆 배지에 표시됩니다.

---

## 9. 대시보드

**대시보드** 메뉴(로그인 후 첫 화면)에서 다음을 파이 차트로 확인할 수 있습니다.

- 전체 요구사항 수, 전체 테스트 케이스 수, 테스트 커버리지(%), 통과율(%)
- **우선순위별 요구사항** 분포
- **상태별 요구사항** 분포
- **테스트 실행 결과**(최신 실행 기준) 분포

모든 역할(관리자/편집자/조회자)이 대시보드를 볼 수 있습니다.

---

## 10. 관리 콘솔의 세 페이지

`http://localhost:4000/admin`에 관리자로 로그인하면 상단 탭에서 다음 세 페이지를 오갈 수 있습니다.

### DB 설정

- 데이터베이스 연결 정보를 확인·수정합니다. 비밀번호 칸을 비워두면 기존 비밀번호가 유지됩니다.
- 연결되어 있으면 같은 페이지 하단에 **DB 내용**이 표시됩니다: 연결된 DB 종류/이름, 요구사항·테스트케이스·실행기록 수, 사용자 수(관리자/편집자/조회자 역할별 분포 포함), Node.js 버전, 서버 가동 시간.

### 사용자 설정

- **ID 변경** 버튼으로 사용자 ID를 바꿉니다(본인 계정도 가능, 단 다른 사용자가 쓰는 ID로는 바꿀 수 없습니다).
- 표의 **권한** 드롭다운에서 즉시 역할(관리자/편집자/조회자)을 변경할 수 있습니다(본인 계정은 변경 불가 — 실수로 자신의 관리자 권한을 없애는 것을 방지).
- **비밀번호 변경** 버튼으로 다른 사용자의 비밀번호를 재설정합니다.
- **삭제** 버튼으로 사용자를 제거합니다(본인 계정은 삭제할 수 없습니다).
- 하단 "사용자 추가" 폼으로 사용자 ID·비밀번호(6자 이상)·권한(조회자/편집자/관리자)을 지정해 새 계정을 만듭니다.

### 관리자 설정

- 현재 로그인한 **자신의** 관리자 계정 ID와 비밀번호를 변경합니다. 처음 로그인했다면 기본값(`admin`/`admin`)에서 바로 바꾸는 것을 권장합니다.
- ID를 변경하면 다음 로그인부터 새 ID를 사용해야 합니다.

## 11. 자주 묻는 질문

### 로그인이 안 됩니다

- 서버가 DB에 연결되어 있는지 확인하세요. 화면 상단의 "서버 DB 연결됨/연결되지 않음" 배지를 확인하거나, 관리 콘솔(`/admin`)에서 연결 상태를 확인하세요.
- 기본 관리자 ID/비밀번호(`admin`/`admin`)를 변경한 적이 있다면 새 ID/비밀번호로 로그인하세요.

### `admin`/`admin`으로 로그인이 안 됩니다 (이전에 admin/admin123이었습니다)

- 기본 관리자 계정은 **`users` 테이블이 처음 만들어질 때 단 한 번만** 생성됩니다. 예전에 한 번이라도 연결했던 DB나 SQLite 파일을 다시 연결한 경우, 그 안에는 예전 기본 비밀번호(`admin123`)로 만들어진 계정이 그대로 남아 있습니다.
- 예전 비밀번호로 로그인해 보거나, 완전히 새로운 빈 DB(또는 새 SQLite 파일 경로)로 연결해 다시 시드하세요.

### 관리 콘솔(`/admin`)에 로그인했는데 "DB 설정" 페이지만 보이고 탭이 안 보입니다

- 아직 DB에 연결되기 전(부트스트랩 단계)입니다. 부트스트랩 로그인(기본값 `admin`/`admin`)은 DB 연결을 구성하는 용도로만 쓰이며, 사용자 설정·관리자 설정 탭은 DB가 연결되고 DB에 저장된 진짜 관리자 계정으로 로그인한 뒤에야 나타납니다.

### 추가/편집/삭제 버튼이 안 보입니다

- 조회자(viewer) 권한 계정입니다. 변경 작업이 필요하면 관리자에게 편집자 권한으로 변경을 요청하세요.

### "Administrator privileges required" 또는 "view access" 오류가 납니다

- 권한이 없는 작업을 시도한 것입니다. 사용자 관리·DB 설정은 관리자만, 요구사항/테스트 케이스 변경은 편집자 이상만 가능합니다.

### 비밀번호를 잊어버렸습니다

- 다른 사용자라면 관리자에게 "사용자 설정" 페이지에서 비밀번호를 재설정해 달라고 하세요.
- 관리자 본인이 잊어버렸다면, DB를 직접 다루지 않는 한 콘솔에서 복구할 방법이 없습니다 — 다른 관리자 계정이 있다면 그 계정으로 로그인해 "사용자 설정"에서 재설정하세요.

### DB 연결을 바꾸고 싶습니다

- `/admin` 관리 콘솔에 관리자로 로그인한 뒤 "DB 설정" 페이지에서 변경하세요. 비밀번호 칸을 비워두면 기존 비밀번호가 유지됩니다.

### 서버를 재시작하면 DB 연결을 다시 설정해야 하나요?

- 아닙니다. 한 번 설정한 연결 정보는 서버에 저장되어 재시작 후에도 자동으로 다시 연결됩니다.
