# ReqTrace Web 사용자 가이드

ReqTrace Web은 브라우저에서 요구사항과 테스트 케이스를 관리하고 현황을 확인하는 웹 애플리케이션입니다. 데스크톱 ReqTrace 앱과 **같은 데이터베이스**를 공유할 수 있으며, 웹 전용 `users` 테이블로 로그인·권한을 관리합니다.

## 1. 구성 요소

| 화면 | 주소(기본값) | 용도 | 누가 쓰나요 |
|------|--------------|------|-------------|
| **서버 관리 콘솔** | `http://localhost:4000/admin` | DB 연결 설정, 사용자 추가/삭제/권한 변경, 서버 현황 확인 | 관리자 |
| **요구사항 관리 클라이언트** | `http://localhost:5173` | 요구사항/테스트 케이스 조회·편집, 대시보드 확인 | 모든 사용자 |

두 화면은 **별도 로그인 세션**입니다. 관리 콘솔에 로그인해도 클라이언트에 자동 로그인되지 않습니다.

헤더의 **서버 DB 연결됨/연결되지 않음** 배지는 서버가 DB에 연결되어 있는지 표시합니다. 클라이언트에서 DB를 직접 설정하지 않습니다.

---

## 2. 최초 설정 (서버 관리 콘솔)

1. `http://localhost:4000/admin` 접속
2. **부트스트랩 로그인** — 기본값 `admin` / `admin` (Enter 키로 로그인 가능)
3. **DB 설정** — DB 종류·서버·포트·데이터베이스 이름(기본 `reqtrace`)·계정 입력
4. **저장 및 연결** — DB·테이블 자동 생성, `users` 테이블에 `admin`/`admin` 시드
5. 연결 성공 후 **자동으로 DB 세션 전환** — 같은 계정으로 재로그인 없이 **DB 설정 / 사용자 설정 / 관리자 설정** 탭 사용

> 이미 `users`가 있는 DB를 연결하면 기존 계정·비밀번호를 사용합니다.

한 번 로그인한 뒤 탭을 바꿀 때마다 다시 로그인할 필요는 없습니다.

---

## 3. 로그인

`http://localhost:5173` 접속 → 사용자 ID·비밀번호 입력 (Enter 키로 로그인).

- 최초 DB 연결 직후: `admin` / `admin` (로그인 후 **관리자 설정** 또는 **관리** 메뉴에서 비밀번호 변경 권장)
- 다른 사용자: 관리 콘솔 **사용자 설정**에서 만든 계정
- **로그아웃**: 화면 우측 상단

---

## 4. 사용자 권한

| 역할 | 할 수 있는 일 |
|------|----------------|
| **관리자** | `/admin` 관리 콘솔 + 요구사항/테스트 케이스 **조회·변경** |
| **편집자** | 요구사항/테스트 케이스 **조회·변경**(추가·편집·삭제·자동 생성·실행 기록). DB/사용자 관리 불가 |
| **조회자** | **조회만** (추가·편집·삭제 버튼 숨김) |

**요구사항 / 테스트 케이스** 페이지 상단 배너:

- 편집자·관리자: "요구사항과 테스트 케이스를 추가·편집·삭제할 수 있습니다."
- 조회자: "조회만 가능합니다. … 편집자 권한을 요청하세요."

관리자가 역할을 변경하면 **페이지 새로고침** 후 버튼 표시가 갱신됩니다. 서버도 DB의 현재 역할로 권한을 검사합니다.

---

## 5. 요구사항 작업

**요구사항 / 테스트 케이스** 메뉴 (편집자·관리자만 변경 UI 표시)

| 작업 | 방법 |
|------|------|
| **추가** | **+ 추가** → 코드·제목·카테고리·우선순위·상태·출처·설명 → **저장** |
| **편집** | 목록 행 **편집** |
| **삭제** | 목록 행 **삭제** (연결 테스트 케이스 포함) |
| **테스트 보기** | 행 클릭 → 하단 테스트 케이스 패널 |

서버가 DB에 연결되지 않으면 "서버가 데이터베이스에 연결되어 있지 않습니다" 안내가 표시됩니다.

---

## 6. 테스트 케이스

요구사항 선택 후 하단 패널 (편집자·관리자):

- **+ 테스트 케이스 추가** — 코드·제목·전제 조건·예상 결과·단계(동작/예상 결과)
- **편집** / **삭제** / **실행 기록**
- 단계 표: `#` · 동작 · 예상 결과 열 정렬

---

## 7. 테스트 케이스 자동 생성

요구사항 목록 **테스트 자동 생성** (편집자·관리자):

| 생성 케이스 | 조건 |
|-------------|------|
| 정상 시나리오 (TC1) | 항상 |
| 잘못된/경계 입력 (TC2) | 항상 |
| 경계 조건 (TC3) | 우선순위 **High** 또는 **Critical** |

---

## 8. 테스트 실행 기록

**실행 기록** → 상태(Pass/Fail/Blocked/NotRun)·실행자·메모 → **저장**. 최근 상태가 배지로 표시됩니다.

---

## 9. 대시보드

**대시보드** — 요구사항·테스트 케이스 수, 커버리지, 통과율, 우선순위/상태/실행 결과 파이 차트. 모든 역할 조회 가능.

## 10. 관리 콘솔에서 사용자 관리하기

`http://localhost:4000/admin` (관리자, DB 연결 후)

### DB 설정

연결 정보 수정(비밀번호 빈 칸 = 유지), **DB 내용** 통계

### 사용자 설정

- **ID 변경** / **권한** 변경 / **비밀번호 변경** / **삭제**
- **사용자 추가** — ID·비밀번호(6자 이상)·권한(조회자/편집자/관리자)

### 관리자 설정

로그인한 관리자 **본인** ID·비밀번호 변경

---

## 11. 데스크톱 앱과 DB 공유

1. 데스크톱 ReqTrace → **데이터베이스 → 데이터베이스에 저장**
2. 웹 관리 콘솔 → **같은 DB** 연결
3. 웹 클라이언트 로그인 → 데스크톱에서 저장한 요구사항·테스트 케이스 조회·편집

웹 서버는 PascalCase(데스크톱) / camelCase(웹 단독) 스키마를 **자동 감지**합니다. `users` 테이블은 웹 로그인 전용입니다.

데스크톱 **파일(.reqtproj) 저장**과 DB 저장은 별개입니다. DB에 반영하려면 데스크톱에서 **데이터베이스에 저장**을 실행하세요.

## 12. 자주 묻는 질문

### 로그인이 안 됩니다

- 헤더 **서버 DB 연결됨** 확인, `/admin`에서 DB 연결 상태 확인
- `admin`/`admin` 변경 이력 있으면 새 비밀번호 사용
- `users` 테이블이 비어 있으면 서버 재시작 시 `admin`/`admin` 자동 생성

### `admin`/`admin`으로 로그인이 안 됩니다

- **`users`가 이미 있는 DB**를 연결한 경우 — 예전에 설정한 비밀번호 사용
- **`users`가 비어 있는 DB** — 서버 연결 시 `admin`/`admin` 시드. MariaDB/MySQL 날짜 형식 오류는 최신 서버 코드에서 수정됨

### 관리 콘솔에서 DB 연결 후 다시 로그인하라고 합니다

- 최신 `/admin` 페이지는 부트스트랩 로그인 후 **자동 DB 세션 전환**을 시도합니다. 브라우저 **새로고침(F5)** 후 재시도
- 자동 전환 실패 시 DB 계정 `admin`/`admin`으로 한 번 로그인

### 추가/편집/삭제 버튼이 안 보입니다

- **조회자** 계정입니다. `/admin` → 사용자 설정에서 **편집자**로 변경 후 클라이언트 **새로고침**

### 편집자로 바꿨는데 여전히 버튼이 없습니다

- 클라이언트 **새로고침(F5)** — `/auth/me`로 역할 갱신

### "조회 권한만 있습니다" 오류

- 조회자 계정으로 변경 API 호출. 편집자·관리자 권한 필요

### 서버 실행 오류 `EADDRINUSE :::4000`

- 포트 4000 점유 프로세스 종료 후 `npm run dev` **한 번만** 실행

```powershell
netstat -ano | findstr ":4000"
taskkill /PID <PID> /F
```

### DB 연결을 바꾸고 싶습니다

- `/admin` → **DB 설정** (비밀번호 빈 칸 = 유지)

### 서버 재시작 후 DB 설정을 다시 해야 하나요

- 아닙니다. `server/data/connection-config.json`에 저장되어 자동 재연결
