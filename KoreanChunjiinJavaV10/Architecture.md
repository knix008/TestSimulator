# 구조

## 큰 그림

```
                    ┌──────────────────────────────┐
                    │  engine  (순수 자바)          │
   키 인덱스 0~11 ─▶ │  Chunjiin.java  유니코드 조합  │ ─▶ state.text
   편집 명령      ─▶ │  Input.java     오토마타·편집  │    state.cursorPos
                    └──────────────────────────────┘
                                   ▲
                                   │ 이 경계 위로는 AWT 도 Swing 도 모른다
                    ┌──────────────┴───────────────┐
                    │  ui/MainFrame + ui/*          │  화면·키보드·명령
                    └──────────────┬───────────────┘
                                   │
                    ┌──────────────┴───────────────┐
                    │  Platform.java · Settings.java │  파일·클립보드·설정
                    └──────────────────────────────┘
```

엔진은 `java.awt` 도 `javax.swing` 도 쓰지 않습니다.
그래서 `./test.sh` 로 화면 없이 그대로 돌릴 수 있고, 화면 쪽과 **완전히 같은 조합 코드**를 씁니다.

### 옮기면서 지킨 것

- **함수 하나하나가 대응됩니다.** `hangul_make` → `hangulMake`, `write_hangul` → `writeHangul`
  처럼 이름과 차례를 그대로 두었습니다.
- **분기 순서를 바꾸지 않았습니다.** 특히 `getUnicode` 의 if-else 사슬은 목록에 없는 값이
  마지막 항목(ㅎ, ㅣ)으로 떨어지는데, 그 성질까지 `indexOf` 가 `-1` 이면 마지막 번호를 쓰는
  방식으로 옮겼습니다.
- **표는 값을 그대로 베꼈습니다.** 모음 전이표 24행, 자음 순환표, 영문·기호 배열,
  테마 색 96개가 원본과 같은 값입니다.
- **아이콘 경로 문자열까지 그대로입니다.** 웹판이 쓰던 SVG `d` 값을 손으로 도형으로 옮겨
  적지 않고, 작은 SVG 경로 파서(`ui/Icons.java`)를 두어 Java2D 로 그립니다.
  그래야 그림이 한 획도 어긋나지 않습니다.

### 옮기면서 달라진 것

| 자바스크립트 | 자바 | 왜 |
|---|---|---|
| `state.text` (문자열) | `StringBuilder` | 가운데를 자주 고치므로. 자바 문자열도 UTF-16 코드 단위라 커서 계산은 그대로 맞다 |
| `h[slot]` 동적 접근 | `HangulState.consAt(Slot)` / `setConsAt` | 자바에는 이름으로 필드를 고르는 문법이 없다 |
| `{ ...src }` 얕은 복사 | `HangulState.copy()` | 값 복사를 눈에 보이게 |
| `null` 이 섞인 모음 전이표 | `String[][]` 에 `null` 그대로 | 표 모양을 바꾸지 않으려고 |
| `Infinity` 길이 제한 | `Integer.MAX_VALUE` | `compositionText(state)` 오버로드가 이 값을 넘긴다 |
| React `useRef` + 강제 렌더 | 그냥 필드 하나 + `refresh()` | 원본 C 가 포인터로 제자리에서 고치는 코드라 결이 맞다 |
| CSS 사용자 지정 속성 | `Theme` 를 각 부품이 직접 읽는다 | Swing 에는 그런 장치가 없다 |
| `div` 에 직접 그린 편집 영역 | `EditorPanel` (`JComponent`) | 마찬가지로 캐럿을 엔진이 온전히 쥐어야 한다 |
| Electron 의 기본 창 테두리 | `TitleBar` 가 그리는 제목줄 | 운영체제 제목줄은 색을 바꿀 수 없다. 테마 색이 창 맨 위까지 이어져야 한다 |
| `Tooltip.jsx` (130ms 풍선) | `ToolTipManager` 지연 130ms | Swing 은 지연 시간을 바꿀 수 있어 직접 만들 까닭이 없다 |
| Electron IPC 로 창 크기 바꾸기 | `ResizeGrip` 과 `WindowResizer` 가 `JFrame` 을 바로 만진다 | 다리를 놓을 필요가 없다 |

## 오토마타

### 상태

한 음절은 네 칸(`chosung` · `jungsung` · `jongsung` · `jongsung2`)과
"마지막으로 채운 자리"(`step`)로 나타냅니다.
`jungsung` 에는 완성 모음뿐 아니라 중간 상태인 `·` 와 `‥` 도 들어갑니다.
`getUnicode()` 가 이 둘을 "아직 모음이 아님"으로 보고 초성만 돌려줍니다.

낱자는 `char` 가 아니라 `String` 입니다. 비어 있음을 나타내야 하기 때문입니다.
빈 문자열이 "비어 있음"이고, C 의 `L'\0'` 자리에 해당합니다.

### 모음

`VOWEL_RULES` 24행이 전부입니다. 각 행은
`[현재 모음, +ㅣ, +·, +ㅡ, 백스페이스로 돌아갈 곳]` 입니다.
`null` 이면 그 조합은 없으므로 현재 음절을 확정하고 새 음절을 시작합니다.

### 자음

`CONS_CYCLE` 이 키마다 순환 목록을 갖습니다(ㄱ→ㅋ→ㄲ).
같은 키를 연달아 누르면 `cycleConsonant()` 가 다음 후보로 돌리는데, 자리에 따라 걸러 냅니다.

- 받침 자리면 받침이 될 수 없는 자음(ㄸ ㅃ ㅉ)은 건너뜁니다
- 겹받침 둘째 자리면 겹받침을 이루지 못하는 자음은 건너뜁니다

### 연음

받침이 있는 상태에서 모음 키가 오면 `hangulVowel()` 이 마지막 자음을 떼어 앞 글자를 확정하고,
뗀 자음을 새 음절의 초성으로 삼습니다. 겹받침이면 둘째 자음만 넘어갑니다.

### 겹받침 되돌려 붙이기

`ㅎ` · `ㅁ` · `ㅌ` 처럼 순환의 첫 자리가 아닌 자음이 겹받침에 필요할 때가 있습니다
(`많` `삶` `핥`). 첫 타에는 겹받침이 되지 못해 새 음절로 떨어져 나가는데,
이때 `prevSyllable` 에 직전 음절을 기억해 둡니다.
같은 키를 한 번 더 눌러 겹받침이 되는 자음이 나오면 `tryMergeJong()` 이
`composeLen` 을 하나 늘려 앞 칸까지 다시 그리며 도로 합칩니다.

```
만  +  ㅅㅎ        →  만ㅅ       (ㅅ 은 ㄴ 과 겹받침이 안 된다)
       ㅅㅎ 한 번 더 →  많        (ㅎ 은 ㄴ 과 ㄶ 이 된다 → 되돌려 붙임)
```

이 기억은 모음·문장부호·백스페이스·커서 이동이 오면 곧바로 풀립니다.

### 화면에 그리기

조합 중인 글자는 `state.text` 안에 **이미 들어가 있습니다.**
`writeHangul()` 이 직전에 그린 `composeLen` 칸을 지우고 새로 그립니다.
`composeLen` 이 2가 되는 경우는 두 가지입니다.

- 아래아 중간 상태 — `ㄱ·` 처럼 초성과 점을 나란히 보여 줄 때
- 겹받침 되돌려 붙이기 — 앞 칸까지 다시 그려야 할 때

## 화면 쪽

### 상태 관리

엔진 상태는 `MainFrame` 이 들고 있는 **변경 가능한 객체 하나**(`ChunjiinState st`)입니다.
불변 상태로 감싸지 않았습니다. C 원본이 포인터로 제자리에서 고치는 코드라서,
그대로 옮긴 엔진과 결이 맞기 때문입니다.
화면 갱신은 `refresh()` 하나가 편집 영역 · 키패드 라벨 · 상태줄에 지금 값을 밀어 넣습니다.

### 편집 영역

`JTextArea` 대신 `JComponent` 에 직접 그립니다.

```
[확정된 글] [조합 중인 글자(밑줄)] |캐럿| [뒤쪽 글]
```

창 기본 폭은 400px 이고, 최소 폭은 **툴바가 정합니다**. 툴바 단추는 절대 접히거나
잘리지 않아야 하므로, `toolbar.getMinimumSize()` 를 재어 그것이 온전히 들어가는 폭
아래로는 줄지 않게 `setMinimumSize()` 를 겁니다. 단추를 더하거나 빼도 저절로 맞습니다.

폭에 맞춰 줄을 나누는 것도 직접 합니다(웹판이 `overflow-wrap: anywhere` 이므로
낱말이 아니라 글자 단위로 끊습니다). 클릭하면 그 자리의 글자 번호를 셈해
`Input.setCursor()` 를 부릅니다. 조합은 그때 확정됩니다.

### 아이콘

`ui/Icons.java` 는 SVG 경로 명령 가운데 아이콘들이 실제로 쓰는 `M L H V C A Z`
(대소문자)만 읽는 작은 파서입니다. 까다로운 곳이 둘 있습니다.

- **호(arc)** — SVG 는 끝점으로 적고 Java2D 는 중심점으로 받습니다.
  SVG 1.1 부록 F.6.5 의 셈법으로 바꿉니다.
- **숫자 자르기** — SVG 는 `-.6.3` 을 `-0.6` 과 `0.3` 두 개로 읽습니다.
  소수점을 하나만 받아 두 번째 점에서 끊습니다.

### 제목줄과 창 테두리

운영체제가 그려 주는 제목줄은 색을 바꿀 수 없습니다. 자바에 그럴 API 가 없고,
Windows 의 DWM 을 부르려면 네이티브 호출이 필요한데 그것도 Windows 에서만 듣습니다.
그래서 `setUndecorated(true)` 로 장식을 끄고 `ui/TitleBar.java` 가 직접 그립니다.
테마 4종의 색이 창 맨 위까지 이어지고, 세 운영체제에서 같은 모습이 됩니다.
대화상자도 같은 부품을 씁니다(닫기 단추만).

그 대신 운영체제가 해 주던 일을 이쪽이 맡습니다.

- **옮기기 · 최대화** — `TitleBar` 가 끌기와 두 번 누르기를 받습니다
- **크기 바꾸기** — `WindowResizer` 가 여덟 방향을 받습니다.
  본문을 가장자리에서 5px 안쪽으로 들여놓아 그 바깥 띠에는 부품이 없게 했습니다.
  Swing 은 마우스 아래 가장 깊은 부품에게 이벤트를 주므로, 그 띠에서만 이것이 불립니다.
- **창 경계** — 바탕 화면과 구분되도록 테두리 한 줄을 직접 긋습니다

### 키보드

`KeyboardFocusManager` 에 디스패처를 하나 걸어 창 어디에 있든 키를 받습니다.
웹판이 `window` 에 `keydown` 을 걸어 둔 것과 같은 자리입니다.
대화상자가 떠 있으면 그 쪽이 키를 갖습니다.

키를 받은 부품이 어느 창에 속하는지 셈할 때 한 곳을 조심해야 합니다.
`SwingUtilities.getWindowAncestor()` 는 **창 자신을 넘기면 `null`** 을 돌려줍니다
(창 위에는 창이 없으므로). 대화상자를 닫은 직후에는 포커스가 부품이 아니라 창 자체로
돌아오는데, 그것까지 챙기지 않으면 그때부터 키가 통째로 무시됩니다.
`MainFrame.windowOf()` 가 그 자리를 막습니다. 화면 시험에 이 경로를 넣어 두었습니다.

- 숫자패드는 모든 모드에서 키패드가 됩니다
- 숫자열은 한글 모드에서만 키패드가 됩니다(Shift 를 누르지 않았을 때)
- 영문 · 숫자 · 기호 모드에서는 `KEY_TYPED` 로 들어온 글자를 그대로 넣습니다

### 연타 시계

키를 누를 때마다 `settings.multitapMs` (기본 0.8초) 뒤에 `Input.breakMultitap()` 을
부르는 `javax.swing.Timer` 를 다시 겁니다. 시간이 지나면 같은 키를 눌러도 순환이 아니라
새 문자로 시작합니다.

커서 이동 · 모드 전환처럼 조합이 확정되는 자리에서는 `stopMultitap()` 이 타이머를 곧바로 끕니다.
상태줄의 `연타 0.8초 ●` 에서 ● 에 불이 들어와 있으면 지금 순환이 살아 있다는 뜻입니다.

> 그래서 오른쪽 화살표로 순환을 끊으면 커서가 움직이면서 **조합도 확정**됩니다.
> `글` 처럼 받침이 이어져야 하는 자리에서는 화살표 대신 잠시 기다려야 합니다.
> `AppSmokeTest` 도 그 자리에서는 화살표가 아니라 기다림을 씁니다.

### 상태줄

메뉴 막대를 없앴으므로 프로그램의 상태는 모두 상태줄이 짊어집니다.
두 줄로 나누어, 윗줄은 지금 치고 있는 것(모드 · 조합 · 알림),
아랫줄은 설정과 위치(테마 · 글꼴 · 연타 · 커서)를 보여 줍니다.
라벨을 여러 개 붙이지 않고 한 부품이 직접 그립니다. 글자를 칠 때마다 상태줄 전체가
바뀌는데, 부품이 하나면 다시 그리는 자리도 하나입니다.

### 대화상자

설정 · 사용법 · 프로그램 정보 · 오류 창은 모두 `ModalDialog` 껍데기를 씁니다.
본체 창과 같이 장식을 끄고 `TitleBar` 가 제목줄을 그립니다 - 창 하나만 테마 색이고
다른 하나는 운영체제 색이면 어울리지 않기 때문입니다.

**스크롤바를 두지 않습니다.** 내용이 다 보이는 크기로 뜨고, 화면(작업 영역)을
넘어설 것 같을 때만 거기에 맞춥니다.

사용법은 한 단으로 세우면 90줄이 넘어 어느 화면에도 들어가지 않으므로 두 단으로 나눴습니다.
표는 공백으로 자리를 맞추지 않습니다. 한글 글자 폭이 공백의 딱 두 배가 아니어서
(굴림체 13 대 7, `Monospaced` 13 대 8) 줄이 갈수록 어긋나기 때문입니다.
그 대신 **열마다 글상자를 따로 두고 나란히 세웁니다.** 그러면 글꼴이 무엇이든 맞습니다.

### 오류

`showError(무엇을, 원인)` 하나로 모읍니다.
창에는 `무엇을 하다가 · 언제 · 어디서 · 오류 · 자세한 내용`이 한자리에 나오고,
그 글이 그대로 클립보드에 들어갑니다(`ErrorDialog.format()` 이 화면과 복사본을
같은 한 곳에서 만듭니다). 창을 닫아도 상태줄에 자국이 남아 다시 열 수 있습니다.

### 테마

`Theme` 가 색을 들고 있고, 각 부품이 `paintComponent` 에서 그것을 읽어 칠합니다.
룩앤필이 칠하는 색은 쓰지 않습니다. 그래서 Windows · macOS · Linux 어디서나 같은 색이 나옵니다.

## 빌드 스크립트

빌드 도구를 쓰지 않습니다. Maven 도 Gradle 도 없고, 내려받을 의존성도 없습니다.
`javac` 와 `jar` 만 있으면 되므로 스크립트가 그것을 직접 부릅니다.

같은 일을 하는 것이 짝으로 있습니다. `.sh` 는 Linux · macOS 용이고 Windows 의
Git Bash · WSL 에서도 돕니다. `.ps1` 은 Windows PowerShell 용입니다.
`.bat` 둘은 `cmd.exe` 에서 `.ps1` 을 부르는 얇은 껍데기일 뿐, 스스로 하는 일이 없습니다.

```
scripts/find-jdk.sh   scripts/Find-Jdk.ps1     쓸 JDK 를 고르고 환경을 맞춘다
build.sh              build.ps1                컴파일하고 JAR 로 묶는다
run.sh                run.ps1                  빌드하고 창을 띄운다
test.sh               test.ps1    test.bat     시험을 돌린다
package.sh            package.ps1 package.bat  설치 파일을 만든다
clean.sh              clean.ps1                빌드 결과를 지운다
```

### JDK 고르기

나머지 전부가 `find-jdk` 하나를 거칩니다. 그래서 JDK 를 찾는 규칙이 한 군데에만 있습니다.

이 프로그램은 텍스트 블록(Java 15) 과 `instanceof` 패턴(Java 16) 을 쓰므로 **JDK 17
이상**이라야 합니다. 그냥 처음 만난 `javac` 를 쓰면 안 됩니다. 옛 JDK 가 `PATH`
앞자리에 있는 기계가 흔하고, 그러면 문법 오류가 수십 개 쏟아지는데 원인이 드러나지
않습니다. 그래서 후보를 모두 모아 **버전을 확인한 뒤** 조건에 맞는 것만 고릅니다.

| 차례 | 어디서 | 고르는 조건 |
|---|---|---|
| 1 | `JAVA_HOME` | 17 이상일 때만 |
| 2 | `PATH` 위의 `javac` | 17 이상일 때만 |
| 3 | JDK 가 흔히 놓이는 자리 | 그 가운데 가장 높은 버전 |

버전은 JDK 안의 `release` 파일에서 읽습니다. 프로그램을 띄우지 않아도 되어 빠릅니다.
없으면 `javac -version` 을 물어봅니다 (자바 8 은 이것을 표준 오류로 내므로 두 줄기를
다 받습니다). 비켜 간 것이 있으면 왜 비켜 갔는지 찍어 줍니다.

고른 JDK 는 그 셸의 `JAVA_HOME` 과 `PATH` 에도 얹습니다. 이어 도는 `jpackage` 나
`jlink`, 그리고 자식으로 부르는 `build` 까지 같은 것을 보게 하려는 것입니다.

하나도 없으면 꾸러미 관리자(winget · brew · apt · dnf · zypper · pacman) 로 **깔지
물어봅니다.** 사람이 답할 수 없는 자리(CI, 파이프)에서는 묻지 않고 안내만 하고 멎습니다.
물으면 아무도 답하지 않아 그대로 멈춰 버리기 때문입니다.

### 빌드가 찍는 것

단계마다 무엇을 얼마나 했는지, 어디서 시간이 걸렸는지 보여 줍니다.
`.sh` 와 `.ps1` 이 글자 하나까지 똑같이 찍습니다.

원본·클래스 수와 패키지별 분포, 자원 개수, JAR 크기와 항목 수, 단계마다 걸린 시간,
그리고 **바이트코드 대상**이 나옵니다. 마지막 것은 클래스 파일 머리(offset 6)에 적힌
값을 그대로 읽은 것입니다. 지금은 `javac` 에 `--release` 를 주지 않으므로 빌드에 쓴
JDK 가 곧 실행에 필요한 자바 버전이 됩니다. 그 사실이 눈에 보이도록 찍습니다.

컴파일은 `-Xlint:all,-serial` 로 합니다. `serial` 만 뺐습니다. Swing 창을 물려받은
클래스마다 `serialVersionUID` 가 없다고 하는데, 창을 파일로 저장할 일이 없으므로
들을 것이 없습니다. 그것만 빼면 경고가 0 입니다.

한글은 터미널에서 두 칸을 차지하므로 글자 수로 자리를 맞추면 어긋납니다. 두 스크립트
모두 칸 수를 세어 맞춥니다. `.sh` 쪽은 `wc -m` 을 쓰지 않습니다. 로케일이 UTF-8 이
아닌 자리(Git Bash 가 흔히 그렇습니다)에서는 바이트를 세어 버리기 때문입니다.
대신 UTF-8 의 이어 붙는 바이트를 빼서 글자 수를 냅니다.

## 설치 파일

`package.sh` · `package.ps1` 이 세 단계로 만듭니다.

1. `jdeps --print-module-deps` 로 이 프로그램이 실제로 쓰는 모듈을 알아냅니다
   (지금은 `java.base,java.desktop,java.prefs`)
2. `jlink` 가 그 모듈만 담은 45MB 남짓한 런타임을 만듭니다
3. `jpackage` 가 그 런타임을 **설치 파일 안에** 넣습니다

그래서 받는 쪽에는 자바가 필요 없고, 설치 중에 무엇을 더 내려받지도 않습니다.
이미 깔린 자바가 있어도 건드리지 않으므로 버전이 서로 어긋날 일이 없습니다.

### 다시 깔 때

`jpackage` 가 만든 MSI 를 그대로 두면, 같은 판을 다시 깔 때 새로 깔리지 않고,
이미 깔린 상태에서 설치 파일을 다시 실행하면 **아무것도 묻지 않고 지워 버립니다.**

`jpackage` 는 이것들을 옵션으로 열어 주지 않으므로, 지금 쓰는 JDK 안에 든 WiX 원본
(`jdk.jpackage.jmod` 의 `main.wxs`)을 꺼내 다섯 군데만 고쳐 `--resource-dir` 로 넘깁니다.
JDK 를 바꾸면 그때의 원본을 꺼내 쓰므로 낡지 않고, 고칠 자리를 못 찾으면 그 자리에서
알려 줍니다.

| 고치는 곳 | 무엇이 달라지나 |
|---|---|
| `Id="$(var.JpProductCode)"` → `Id="*"` | 빌드마다 새 제품이 된다 |
| `IncludeMaximum="..."` → `"yes"` | 같은 판도 "옛 것"으로 쳐서 지운다 |
| `REINSTALL=ALL`, `REINSTALLMODE=amus` | 무인으로 다시 깔면 통째로 새로 쓴다 |
| `MaintenanceWelcomeDlg` 를 차례에 추가 | 이미 깔려 있으면 "고치기 / 지우기" 를 묻는다 |
| `RemoveExistingProducts` 를 `After="InstallValidate"` 로 | 찾아낸 옛 것을 **정말로** 지운다 |

마지막 것이 빠지면 앞의 넷이 다 헛일입니다. jpackage 원본은

```xml
<RemoveExistingProducts Before="CostInitialize"/>
```

라고 적어 이 동작을 798번에 둡니다. 그 자리는 값을 찾아보는 **Search 구간**이라
윈도우 인스톨러가 거기서는 이 동작을 돌리지 않습니다. 옛 것을 찾아내기는 해도
지우지 않는다는 뜻입니다. WiX 의 검사 도구도 같은 말을 합니다.

```
ICE27: 'RemoveExistingProducts' Action in InstallExecuteSequence table
       in wrong place. Current: Search, Correct: Execution
```

그래서 `InstallValidate` 바로 뒤(1401)로 옮깁니다. 새 파일을 깔기 전에 옛 것을 먼저
지우는 자리이고, WiX 의 `MajorUpgrade` 가 기본으로 쓰는 자리이기도 합니다.
다섯 군데가 정말로 바뀌었는지 스크립트가 확인하므로, 앞으로 JDK 가 원본을 바꾸면
그 자리에서 걸립니다.

> 만든 MSI 는 WiX 의 검사 도구로 확인할 수 있습니다. 오류가 없어야 합니다.
>
> ```powershell
> .\tools\wix314\smoke.exe -nologo release\Chunjiin-1.0.0.msi
> ```
>
> `ICE61` 경고는 남습니다. "자기보다 옛 판만 지워야 한다" 는 것인데, 여기서는
> 같은 판도 지우려고 일부러 그렇게 둔 것입니다.

Windows 의 `exe`/`msi` 는 WiX Toolset 3.14 가 있어야 합니다.
없으면 스크립트가 공식 바이너리 묶음을 받아 `tools/wix314` 에 풀고 그대로 이어서 빌드합니다.
관리자 권한도, .NET 3.5 도 필요 없어서 winget 판보다 걸리는 데가 적습니다
(winget 판은 둘 다 요구합니다). 이미 깔린 WiX 가 있으면 그것을 먼저 씁니다.
받아 오지 않게 하려면 `-NoWix` / `--no-wix`.

받아 오는 일은 중간에 끊길 수 있으므로 세 가지를 지킵니다.

- **온전한 한 벌인지 본다.** `candle.exe` 와 `light.exe` 가 둘 다 있어야 인정합니다.
  `jpackage` 는 앞의 것으로 컴파일하고 뒤의 것으로 묶습니다. 앞의 것만 보고 넘어가면
  반만 풀린 폴더를 멀쩡한 줄 알고 지나가 한참 뒤 `jpackage` 안에서 넘어집니다.
- **다 되기 전에는 제자리에 앉히지 않는다.** 받는 동안은 `.part` 라는 이름으로 두었다가
  다 받으면 이름을 바꾸고, 푸는 것도 곁의 임시 폴더에 풀어 확인한 뒤 옮깁니다.
  그래서 중간에 멈춰도 반쪽짜리가 남지 않습니다.
- **받은 것이 zip 인지 본다.** 로그인을 요구하는 프록시는 zip 대신 로그인 쪽지를
  돌려주는데, 파일은 남으므로 열어 보아야 압니다.

한 가지 걸리는 곳이 있습니다. MSI 는 문자열을 코드 페이지 1252 로 담고 `jpackage` 는
`-cultures:en-us` 로 고정합니다. 그래서 `--description` 이나 `--win-menu-group` 에 한글을
쓰면 `light.exe` 가 `LGHT0311` 로 멈춥니다. 설치 프로그램이 쓰는 이름만 ASCII 로 두었고,
창 제목과 화면은 그대로 한글입니다.
