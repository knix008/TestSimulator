# MyDeskBox 구조

Tauri 2 앱입니다(Electron 33 판에서 옮겼습니다). 박스 하나는 창 하나입니다 — 판과 제목 줄과 그 안의 아이콘을 모두 그 창이 그립니다. **담는다는 것은 그 파일을 박스의 폴더로 옮긴다는 뜻입니다.** 옮기고 나면 바탕화면 폴더에서 빠지므로 탐색기가 그 아이콘을 더 그리지 않습니다.

앱의 판단(박스, 보관함, 바탕화면, 트레이, 저장)은 모두 Rust(`src-tauri/src`)에 있고, 창(`src/renderer`)은 웹뷰에서 그리기만 합니다. 창과 Rust 가 함께 읽는 것은 `src/shared` 에 한 벌만 둡니다.

## 프로세스

```
npm start
  tools/start.js                 tauri dev (디버그 빌드)
    src-tauri/src/main.rs        mydeskbox_lib::run()
      lib.rs                     단일 인스턴스, 트레이, 창 묶기, 끝날 때 되돌리기
        host/                    박스: 만들기·옮기기·담기·메뉴·묻기 (창과 운영체제 없이 돈다)
        app.rs                   켤 때(첫 실행 분류, 복구)와 끌 때(되돌리기)
        desktop/                 운영체제별 바탕화면 (Windows 는 탐색기 리스트뷰 FFI)
        tauri_ui.rs              host 가 부르는 창·메뉴·끌기를 Tauri 와 Win32 로 한다
        watch.rs                 바탕화면 감시: 폴더 변화, 끌기, 두 번 누르기
      WebView2 (msedgewebview2)  박스, 그리기, 설정, 확인, 속성, 끄는 그림, 큰 오류 창
```

한 번에 하나만 뜹니다. 같은 식별자로 두 번째가 뜨면 `tauri-plugin-single-instance` 가 먼저 뜬 쪽에 알리고(그쪽은 박스 그리기를 시작한다) 두 번째는 끝납니다. Windows 에서는 식별자가 달라도 바탕화면 아이콘을 동시에 다루지 않도록 `Local\MyDeskBox.DesktopOwner` 뮤텍스를 한 번 더 겁니다(`claim_single_instance`). 잡지 못하면 알림을 띄우고 끝납니다.

`--restore-desktop` 으로 띄우면 창 없이 바탕화면만 되돌리고 끝납니다(못 돌려보낸 파일이 있으면 끝 코드 2). 설치·제거 프로그램이 부릅니다. `--icon-list` 는 탐색기 목록을 JSON 으로 찍습니다(`tools/icon-check.js`).

창은 모두 테두리 없이(`decorations(false)`), 작업 표시줄 단추 없이(`skip_taskbar`) 띄웁니다. 박스와 그리기 덮개뿐 아니라 설정 창과 묻는 창도 그렇습니다. macOS 에서는 `ActivationPolicy::Accessory` 로 Dock 아이콘을 감춥니다. 창이 모두 닫혀도 프로세스는 트레이에 남습니다(`ExitRequested` 를 막는다).

### 실이 엉키지 않게

- **명령은 모두 `async` 입니다.** 동기 명령은 주 스레드에서 도는데, 그 안에서 창을 만들면 창 만들기가 주 스레드를 기다려 멈춥니다. `test/shared.test.js` 가 지킵니다.
- 박스 상태는 `Arc<Mutex<Host>>`(`host::Shared`) 하나입니다. **주 스레드는 이 자물쇠를 잡지 않습니다.** 묻는 창, 메뉴, 끌어내기처럼 기다리는 일은 자물쇠를 풀고 기다립니다(`host/flows.rs`).
- 창 손잡이(HWND)는 창을 만들 때 받아 둡니다. `WebviewWindow::hwnd()` 는 주 스레드에 묻는 일이라, 주 스레드가 끌기 같은 모달 고리에 들어가 있으면 영영 답이 오지 않습니다.
- 메뉴(`menu_win.rs`)는 `TrackPopupMenu` 로 그림과 단축키가 붙은 Win32 메뉴를 띄웁니다. 주 스레드에서 돌아야 하므로 `run_on_main_thread` 로 넘기고 답을 기다립니다. 트레이 메뉴는 Tauri 의 것입니다(`tray.rs`).

### 웹뷰는 하나의 렌더러를 나눠 쓴다

창마다 웹뷰가 있지만 같은 사용자 데이터 폴더의 WebView2 는 한 브라우저 프로세스를 나눠 씁니다. 여기에 `--process-per-site --renderer-process-limit=1` 을 주어 렌더러도 하나로 묶습니다. 박스 네 개에서 개인 메모리가 362 MB 에서 246 MB 로 줄었습니다(Electron 판 415 MB).

같은 프로필의 웹뷰는 **모두 같은 브라우저 인자**를 써야 합니다. 하나라도 다르면 두 번째 창부터 만들어지지 않습니다. 그래서 인자는 `tauri_ui::BROWSER_ARGS` 한 곳에 두고 큰 오류 창(`fatal.rs`)도 그것을 씁니다. `CalculateNativeWinOcclusion` 을 끄는 것도 여기 있습니다 — 박스는 늘 다른 창 아래에 있어, 가려졌다고 그리기를 멈추면 창을 치웠을 때 빈 자리가 남습니다.

### 창과 Rust 사이

창 코드는 `window.desk` 만 봅니다. `src/renderer/bridge.js` 가 모든 화면에서 맨 먼저 읽혀 그것을 만듭니다. 이름과 모양은 Electron 판의 preload 와 같고, 그 아래가 Tauri 명령(`invoke`)과 사건(`listen`)으로 바뀌었습니다.

- 명령: `bridge.js` 의 `invoke('fence_ready', …)` ↔ `commands.rs` 의 `#[tauri::command] pub async fn fence_ready` ↔ `lib.rs` 의 `generate_handler!`.
- 사건: Rust 의 `Ui::send(label, "fence:state", …)` ↔ `bridge.js` 의 `on('fence:state', …)`. 듣기 등록은 비동기라, '준비됐다'(`ready`, `prefsReady`, `boxReady`)는 등록이 다 끝난 뒤에 보냅니다. 그러지 않으면 메인이 곧바로 보낸 첫 상태를 놓칩니다.
- 창이 열릴 때 받을 값(박스 id 따위)은 `location.search` 대신 `window.__DESK_QUERY__` 로 넣어 주고 창은 `window.deskQuery` 로 읽습니다.
- 끄는 동안의 '다른 프로그램 위인가'(`overForeign`)는 Electron 판에서 동기로 물었습니다. 여기서는 기다리지 않고 마지막 답을 쓰고 새 답은 다음 움직임에 씁니다.
- 탐색기에서 끌어 온 파일은 HTML 의 `drop` 대신 Tauri 의 끌어 놓기 사건으로 옵니다(`desk.onFileDrag`). 자리는 물리 픽셀이라 CSS 픽셀로 바꿔 넘깁니다.
- 권한은 `src-tauri/capabilities/default.json` 이 창 이름(`fence-*`, `settings-*`, `prefs`, …)마다 줍니다.

`test/shared.test.js` 가 이 고리를 검사합니다. 창이 부르는 `desk.*` 가 `bridge.js` 에 있는지, 그 명령이 `commands.rs` 에 async 로 있고 `lib.rs` 에 등록됐는지, 창이 듣는 사건을 Rust 가 보내는지 봅니다.

### 좌표

박스 좌표는 DIP 입니다. Windows 의 창 자리와 리스트뷰 좌표는 물리 픽셀이라 `screen.rs` 가 바꿉니다. 모니터마다 배율이 달라도 Chromium(Electron)과 같은 방식으로 DIP 화면을 늘어놓으므로(`screen::lay_out`) `layout.json` 의 좌표를 그대로 이어서 씁니다. 반올림도 JS 와 같게 합니다(`js::round`).

창 크기는 `SetWindowPos` 로 바로 줍니다(`SWP_FRAMECHANGED`). 테두리 없는 창이라 바깥과 안쪽 크기가 같습니다.

### 로그인할 때 스스로 켜지기

`src-tauri/src/autostart.rs` 가 맡습니다. 설정의 `openAtLogin` 이 참이고 설치본일 때(`!tauri::is_dev()`)만 운영체제에 적습니다.

- Windows — `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 의 `MyDeskBox`. Electron 판과 같은 이름이라 예전 값을 이어받고, 제거 프로그램(`src-tauri/windows/hooks.nsh`)이 그 이름으로 찾아 치웁니다.
- macOS — `~/Library/LaunchAgents/com.suhokwon.mydeskbox.plist`.
- Linux — `~/.config/autostart/mydeskbox.desktop`. AppImage 면 `APPIMAGE` 를 `Exec` 에 적습니다. 안쪽 실행 파일은 켤 때마다 자리가 바뀌기 때문입니다.

켤 때마다 `sync_login` 이 한 번 돕니다. 설정 쪽을 참으로 보고 운영체제를 다시 맞추므로, 다시 설치했거나 사람이 시작프로그램 목록에서 지웠어도 지금 자리가 다시 적힙니다. 끄기로 해 둔 경우에는 남아 있을 때만 지웁니다.

개발본(`npm start`)을 등록하지 않는 까닭은 실행 파일이 `src-tauri/target` 안에 있기 때문입니다. 그것을 적어 두면 폴더를 지운 뒤에도 로그인할 때마다 없어진 자리를 부릅니다.

## 데이터

사용자 데이터 폴더(`%APPDATA%\MyDeskBox`, macOS `~/Library/Application Support/MyDeskBox`, Linux `~/.config/MyDeskBox`)에 둡니다. **Electron 판과 같은 자리, 같은 형식입니다.** 판을 바꿔 깔아도 박스가 그대로 돌아옵니다. `MYDESKBOX_DATA_DIR` 로 다른 자리를 줄 수 있습니다(검사와 손 확인용).

- `layout.json` — 박스 목록(박스가 쓰는 폴더 이름, 담은 항목의 이름과 경로와 담기 전 폴더), 언어, 새 박스 기본값, `didWelcome`. 저장은 임시 파일에 쓴 뒤 이름을 바꿉니다. `settings` 안의 모르는 값은 지우지 않고 그대로 다시 적습니다.
- `icon-homes.json` — 아이콘을 밀어내기 전 좌표(`homes`)와 무엇을 밀어냈는지(`nudged`), 자동 정렬을 껐는지, 셸 아이콘을 감추기 전의 레지스트리 값.
- `boxes/` — 박스마다 하나씩 있는 보관함 폴더. 그 안의 `restore.json` 은 담은 파일이 어디서 왔는지를 적어 둔 것이라, 설정 폴더가 없어져도 이것만으로 되돌릴 수 있습니다.

WebView2 의 캐시는 `%LOCALAPPDATA%\com.suhokwon.mydeskbox` 에 따로 생깁니다.

## 첫 실행 분류

`didWelcome` 이 거짓일 때만 `catalog::plan_fences` 를 부릅니다(`app.rs`). 순서는 폴더, 바로가기, 문서, 사진·영상, 시스템, 그 밖의 것입니다. 빈 종류는 박스를 만들지 않습니다. 박스는 작업 영역 오른쪽부터 아래로 쌓고, 높이를 넘으면 왼쪽 열로 갑니다.

나눠 담으면 **파일이 실제로 옮겨 가므로 먼저 묻습니다**(`app.rs` 의 `dialog.sort`). 거절하면 박스를 만들지 않고, 만든 것이 없으면 그리기 모드로 시작합니다.

## 박스에 담는다는 것

**담는다는 것은 파일을 옮긴다는 뜻입니다.** 바탕화면의 `보고서.txt` 를 박스에 넣으면 그 파일은 보관함 폴더 아래 그 박스의 폴더로 들어갑니다. 바탕화면 폴더에서 빠지므로 탐색기는 그 아이콘을 그리지 않고, 박스 창이 대신 그립니다. 한 파일이 두 곳에 보이는 일이 없습니다.

앞선 판은 파일을 두고 **아이콘 자리만** 박스 안으로 옮겼습니다. 그 길은 탐색기와 끝나지 않는 다툼이 됩니다. 자동 정렬, 격자에 맞춤, 새로 고침이 저마다 자리를 되돌려 놓기 때문입니다. 파일을 옮기면 다툴 거리가 없어집니다. 남는 일은 **박스가 깔고 앉은 자리의 아이콘을 옆으로 비켜 주는 것** 하나뿐입니다.

### 보관함 폴더

`src-tauri/src/hold.rs` 가 맡습니다. 자리는 **사용자 데이터 폴더 아래 `boxes`** 이고, 박스마다 그 아래 폴더를 하나씩 씁니다.

바탕화면 아래 숨김 폴더(`.MyDeskBox`)에 두어 보았으나, '숨긴 항목 표시'를 켜 두고 쓰는 사람에게는 바탕화면에 폴더가 하나 더 보입니다. 보관함은 사람이 들여다볼 자리가 아니므로 사용자 전용 폴더에 둡니다. 앞선 판이 바탕화면에 만들어 둔 보관함은 처음 켤 때 `hold::adopt_legacy` 가 옮겨 옵니다.

폴더 이름은 박스 이름에서 땁니다. 쓸 수 없는 글자는 걷어 내고, 같은 이름이 있으면 `(2)` 를 붙입니다. 한 번 정한 폴더는 박스 이름을 바꿔도 그대로 둡니다. 안에 든 파일의 경로가 흔들리면 안 되기 때문입니다. 설정의 `root` 로 다른 자리를 줄 수도 있고, 그 자리가 바탕화면 아래라면 숨김 속성을 붙입니다.

옮기기는 이름 바꾸기로 끝납니다. 드라이브가 다르면(`EXDEV`) 복사한 뒤 지웁니다.

### 이름이 부딪히면 묻는다

바탕화면과 박스에 이름이 같은 항목이 따로 있을 수 있습니다. 그것을 담으면 자리가 부딪힙니다. 말없이 뒤에 번호를 붙이면 둘이 나란히 남아 어느 것이 방금 담은 것인지 알 수 없습니다. 그래서 담기 전에 **대체할지 묻습니다**(`hold::clash` 로 찾고 `clear_clash` 가 묻습니다).

- **대체** — 박스에 있던 것을 휴지통으로 보내고, 담는 파일이 그 이름을 그대로 씁니다.
- **취소** — 담지 않습니다. 파일은 있던 자리에 그대로 남습니다.

항목 이름을 바꿀 때도 같은 길로 묻습니다. 묻지 않고 넘어가는 자리는 `hold::take` 하나뿐입니다. 예전 판에서 올라온 박스를 폴더와 맞추는 일(`settle_box`)은 사람이 시킨 것이 아니므로 거기서는 `(2)` 를 붙여 조용히 지나갑니다.

### 이름 바꾸기

두 가지가 있고 서로 다른 일입니다.

- **박스 이름**(`rename`) — `layout.json` 의 제목만 바뀝니다. 폴더 이름은 그대로 두어 안에 든 파일의 경로가 흔들리지 않게 합니다.
- **담긴 항목 이름**(`rename_item`) — 박스 폴더 안의 **파일 이름이 실제로 바뀝니다**(`hold::relabel`). 박스가 보여 주는 것이 그 폴더의 내용이므로, 이름만 따로 적어 두면 탐색기에서 본 이름과 박스에 적힌 이름이 갈립니다.

항목 이름은 창이 아이콘의 글자 자리에 입력칸을 얹어 받습니다(`fence:rename-item`). 박스에 적힌 이름은 탐색기가 확장자를 감추고 있으면 감춘 것이므로, 사람이 적어 준 것에 확장자가 없으면 원래 것을 그대로 붙여 줍니다(`wanted_name`). 확장자까지 보여 주고 있었다면 적어 준 그대로가 온 이름입니다.

폴더를 가리키는 글자가 든 이름은 받지 않고, 끝의 점과 빈칸은 미리 떼어 냅니다. Windows 가 말없이 떼어 내는 것을 우리가 먼저 하는 것입니다. 휴지통 같은 셸 항목은 바꿀 파일이 없어 메뉴에서 누를 수 없습니다. 이름을 바꾸면 `restore.json` 의 기록도 새 이름으로 따라갑니다. 그러지 않으면 꺼낼 때 돌아갈 자리를 잃습니다.

박스가 보여 주는 것은 **그 폴더의 내용**입니다. 탐색기에서 그 폴더에 파일을 넣거나 지운 것도 `settle_box` 를 거쳐 박스에 드러납니다.

### 어디서 왔는지 적어 둔다

파일을 옮겼으므로 되돌릴 자리를 알아야 합니다. 담기 전에 있던 폴더를 두 곳에 적습니다.

- `layout.json` 의 `items[].home`
- 보관함 폴더 안의 `restore.json`

두 곳에 적는 까닭은 갑작스러운 끝 때문입니다. 설정 폴더를 지운 채 앱을 지워도 `restore.json` 하나만 있으면 무엇이 어디서 왔는지 알 수 있습니다. 사람이 손으로 되돌릴 수도 있습니다.

박스에서 박스로 옮길 때가 까다롭습니다. 그때 '온 자리'는 앞 박스의 폴더입니다. 그것을 집으로 적으면 나중에 꺼낼 때 파일이 바탕화면 대신 앞 박스 폴더로 갑니다. 그래서 보관함 안에서 온 것은 적어 둔 기록을 집으로 봅니다(`hold::home_for`).

### 끌어 옮기기

#### 한 규칙: 끌어다 놓기는 옮기는 일이다

세 갈래(바탕화면↔박스, 박스↔박스, 박스 안)가 모두 이 한 규칙을 따릅니다.

1. **한 항목은 한 곳에만 있습니다.** 바탕화면에 있거나 어느 한 박스에 있습니다. 두 곳에 함께 있는 상태를 만들지 않습니다.
2. **옮기기는 대체가 아닙니다.** 옮길 때는 아무것도 묻지 않고 아무것도 버리지 않습니다. 이름이 같은 **다른** 파일이 받는 쪽에 있으면 `hold::spare_name` 이 뒤에 번호를 붙입니다.
3. **대체는 새로 만들 때만 묻습니다.** 박스가 들고 있는 이름으로 바탕화면에 새로 만들었을 때(`offer_replace`), 붙여넣기로 사본을 만들 때(`clear_clash`), 이름을 바꿔 이미 있는 이름이 될 때(`rename_item`) 입니다.
4. **옮기기는 실행이 아닙니다.** 어떤 항목 위에 놓아도 프로그램이 뜨지 않습니다. 받아 주는 것은 옮겨 넣을 수 있는 곳(폴더, 폴더 바로가기, 휴지통)뿐입니다.
5. **옮기지 못했으면 담지 않습니다.** `hold::take` 가 `stuck` 을 붙여 알리고, 새로 담는 길은 목록에 넣지 않습니다. 넣으면 파일은 바탕화면에 있으면서 박스에도 보입니다(1번을 깨뜨립니다).
6. **고른 모두가 함께 움직입니다.** 바탕화면에서 여러 개를 골라 끌면 `drag_group` 이 그 모두를 잡아 `accept_desktop_drop` 에 넘깁니다. 커서 아래의 하나만 옮기면 나머지는 바탕화면에 남아, 옮겼는데도 남아 있는 것처럼 보입니다.

손을 뗀 자리를 보고 `transfer` 가 고릅니다.

| 어디서 어디로 | 무엇이 일어나는가 |
| --- | --- |
| 박스 → 바탕화면 | 담기 전 폴더로 돌아가고, 아이콘은 적어 둔 자리에 놓인다. 돌려보내지 못하면 박스에 그대로 둔다 |
| 바탕화면 → 박스 | 그 박스의 폴더로 옮겨 간다. 확장자를 감춘 이름도 그 파일로 본다. 고른 것이 여럿이면 모두 옮겨 간다. 묻지 않는다 |
| 박스 → 박스 | 그 박스의 폴더로 옮겨 가되, 집은 처음 온 자리 그대로다 |
| 박스 안 | 차례만 바뀐다 |
| 다른 항목의 그림 위 | 그 항목이 받을 수 있으면 그리로 옮긴다(아래) |
| 다른 프로그램 | 그 파일 자체를 넘긴다. 휴지통 같은 셸 항목은 넘기지 않는다 |
| 바탕화면 | 박스에서 빼 놓은 자리에 둔다. 휴지통도 포함한다 |

끌어 놓기는 옮기는 일입니다. 복사와 잘라내기는 클립보드입니다. `clipfiles.rs` 가 탐색기와 같은 `CF_HDROP` 과 `Preferred DropEffect` 를 읽고 씁니다. 복사는 원본을 두고 박스 폴더에 하나 더 만들고, 잘라내기는 `drop_files` 로 옮긴 뒤 클립보드를 비웁니다. 박스에서 복사하거나 자른 파일은 바탕화면의 붙여넣기가 그대로 받습니다. 휴지통 같은 셸 항목은 파일이 아니라 이 길에 올리지 않습니다.

박스와 바탕화면 사이의 끌기는 창이 손을 따라가며, 손을 뗀 자리를 `transfer` 가 옮깁니다. 투명한 박스 창은 운영체제 끌기를 받지 못하므로, 그 끌기로 다른 박스에 놓으면 파일이 그 박스로 들어가지 않습니다. 다른 프로그램 위로 나갔을 때만 운영체제 끌기로 넘깁니다(`dragout.rs`: 셸 데이터 개체와 끌기 그림을 붙인 OLE `DoDragDrop`). 마우스를 움직이는 메시지 안에서 바로 넘기면 운영체제가 끌기를 곧 끝내므로, 창은 `dragOutLater` 로 부르고 Rust 가 그 메시지가 끝난 뒤에 넘깁니다. 끄는 동안 자물쇠는 풀어 둡니다. 받은 쪽이 파일을 가져가 그 자리가 비면 박스에서도 뺍니다. 다른 프로그램에 복사만 했으면 박스에 남습니다. 바탕화면에 놓으면 박스에 있던 파일은 지웁니다. 탐색기가 같은 이름으로 복사해 두었으면 그 복사만 남기고 박스 쪽은 지웁니다.

### 항목 위에 놓으면

칸 사이가 아니라 **다른 항목의 그림 위**에 놓았을 때입니다. 아래 있는 항목이 무엇이냐에 따라 갈립니다(`geom::receive_kind`, `send_into`).

| 아래 있는 것 | 무엇이 일어나는가 |
| --- | --- |
| 폴더, 폴더를 가리키는 바로가기 | 그 안으로 옮겨 간다. 박스에서는 빠진다(`moved`) |
| 휴지통 | 버린다. 박스에서는 빠진다(`moved`). 다른 박스에서 끌어다 놓아도 버린다. 같은 이름이 이미 있어도 묻지 않고 다른 항목으로 남긴다 |
| 그 밖의 항목 | 받지 않는다(빈 값). 부른 쪽이 그 박스로 옮겨 담는다 |

**끌어다 놓기는 언제나 옮기는 일입니다.** 그래서 받아 주는 것은 옮겨 넣을 수 있는 곳(폴더, 휴지통)뿐입니다.

앞서는 그 밖의 항목 위에 놓으면 그것을 실행하며 놓은 파일을 입력으로 넘겼습니다(`openPlan`, `handPlan`, `launch`). Windows 에서는 `handable` 이 모든 대상에 참을 주었으므로, 박스 안의 **아무 아이콘**이나 받는 항목이 되었습니다. 그림은 칸(86×88) 안에서 가로 56, 세로 52 를 차지하므로 칸의 절반이 넘습니다. 박스에 담으려고 놓다가 그림을 스치면, 옮기려던 파일은 제자리에 남고 엉뚱한 프로그램이 떴습니다. 같은 손짓이 파일 종류에 따라 옮기기도 하고 실행하기도 한 것입니다. 그 길을 걷어냈습니다. 프로그램으로 여는 일은 두 번 누르기와 메뉴의 **열기** 가 맡습니다.

#### 받아 주는 자리는 눈에 보이는 그림과 같아야 한다

칸 사이와 그림 위를 가르는 것은 창에서는 `deliver.onPicture`, Rust 에서는 `geom::on_picture` 이고, 그 자리는 `deliver.PICTURE`(15..71 × 2..54) 입니다. 그림 위가 아니면 밀어 배열하는 손짓이므로 넘겨주기로 보지 않습니다.

이 값은 `arrange.js` 의 칸 크기(86×88)와 `fence.css` 의 여백·그림 크기(`padding: 8px 4px 0`, 44×44, 가운데 정렬)에서 **셈해 냅니다**. 앞서는 가로를 `4..48` 로 적어 두었는데 그림은 `21..65` 에 놓입니다. 17픽셀이 어긋나 그림의 오른쪽 40%는 아무리 겨눠도 받지 않고, 그림 왼쪽의 빈 여백이 대신 받았습니다. 눈으로 겨눌 수 없는 과녁이었습니다.

끌고 가면서 44픽셀짜리 과녁을 맞히기는 어려우므로 둘레로 6픽셀을 더 받아 줍니다. 그래도 칸 좌우에는 '사이에 끼우기' 로 쓸 자리가 15픽셀씩 남습니다. 글자 줄은 넓히지 않습니다. 거기까지 받으면 아래 줄에 끼워 넣을 수 없습니다.

#### 빈 자리를 끌면 묶어 고른다

박스 안 빈 자리에서 누른 채 끌면 테두리가 생기고, 그 안에 닿은 아이콘이 골라집니다(`fence.js` 의 `paintBand`, `#band`). 어느 칸이 닿았는지는 `arrange.bandPicks` 가 셉니다. 창이 DOM 을 훑지 않고 칸 셈으로 고르므로, 아이콘 자리를 정하는 `reflowPoints` 와 늘 같은 자를 씁니다.

칸 전체로 재지 않습니다. 칸(86×88)은 서로 맞닿아 있어, 그렇게 재면 아이콘 사이의 빈틈을 스치기만 해도 양쪽이 골라집니다. 그래서 그림과 글자가 보이는 만큼만 남기고 둘레를 줄였습니다(`ITEM_X`, `ITEM_Y`).

테두리로 고른 것은 손을 떼어도 테두리가 남습니다(`marked`). Ctrl 로 누른 것과 달리 하나만 골라도 남깁니다 — 끌어 고른 뒤에 아무 표시도 없으면 무엇이 골라졌는지 알 수 없습니다. 창 위아래 끝까지 끌면 목록을 밀어 주므로(`bandStep`) 보이지 않는 아이콘도 고를 수 있습니다.

#### 어느 항목 위인지는 메인이 고른다

`host/mod.rs` 의 `receiver_at` 이 합니다.

앞서는 박스 창이 제 DOM 을 훑어 골랐습니다. 창은 제 안쪽만 볼 수 있어, **다른 박스에서 건너온 것과 바탕화면에서 끌어 온 것은 아무리 겨눠도 받아 주지 못했습니다**. 박스 A 에서 끌면 좌표가 A 창 밖이라 늘 빈 값이 나왔고, `accept_desktop_drop`(그때는 `acceptDesktopDrop`)은 아예 묻지도 않았습니다.

박스 안 아이콘의 자리는 창의 `arrange.slotPoint` 와 같은 셈(`geom::slot_point`)으로 Rust 도 그대로 셀 수 있습니다. `index_at` 이 이미 그렇게 하고 있으므로 같은 셈을 한 번 더 할 뿐입니다. 이제 네 갈래(같은 박스, 다른 박스, 바탕화면, 탐색기)가 모두 같은 자를 씁니다.

창은 끌고 가는 동안 `fence:hover` 로 받은 `into` 를 밝혀 보여 주기만 합니다(`.icon.hot`). 받을 항목이 정해지면 끼워 넣을 자리를 벌리지 않습니다 — 둘을 함께 보여 주면 무엇이 일어날지 알 수 없습니다. 탐색기에서 끌어다 놓는 길(Tauri 의 끌어 놓기 사건, `desk.onFileDrag`)만은 메인을 거치지 않으므로 창이 같은 셈을 직접 합니다.

끄는 동안 아이콘이 눈에서 사라지면 안 됩니다. 박스 위에서는 그 박스가 자리를 비우고 아이콘을 직접 그리고, 박스 밖에서는 **따라다니는 작은 창**(`renderer/ghost.*`)이 그립니다. 어느 박스 위인지는 `hover` 가 알려 줍니다. 이 길이 없으면 박스 밖으로 나간 아이콘이 보이지 않아 무엇을 끌고 있는지 알 수 없습니다.

### 휴지통 같은 셸 항목

휴지통은 파일이 아니라서 폴더로 옮길 것이 없습니다. 목록에만 담고, 바탕화면 쪽 아이콘은 레지스트리로 감춥니다(`sync_shell_icons`). 박스 창이 대신 그리므로 두 곳에 겹쳐 보이지 않습니다. 감추기 전의 값은 `icon-homes.json` 에 적어 두었다가 끝낼 때 `restore_shell_icons` 가 되돌립니다. 박스를 숨기거나 꺼내면 곧바로 되살립니다.

### 이름과 그림은 바탕화면과 같아야 한다

박스에 적는 이름은 **셸에게 묻습니다**(`Desktop::display_name`, `SHGFI_DISPLAYNAME`). 확장자를 감추는 설정, 폴더의 localized 이름(`Documents` → `문서`), `desktop.ini` 로 바꿔 둔 이름까지 셸이 붙여 줍니다. 우리가 이름을 지어내면 바탕화면과 박스에 다른 글이 적힙니다.

그림 파일은 **그림 자체를 줄여** 보여 줍니다(`picture_of`). 종류 그림만 보여 주면 어떤 사진인지 알 수 없습니다. 바탕화면에서는 미리 보기가 보이기 때문입니다. 너무 큰 그림(32MB 넘는 것)은 읽는 데만 한참 걸리므로 종류 그림으로 둡니다.

### 아이콘 그림

그 밖의 것은 운영체제가 바탕화면에 그리는 그림을 그대로 가져옵니다(`Desktop::file_icon`, `SHGetFileInfo` 와 시스템 그림 목록의 큰 그림). 그래야 폴더는 폴더답게, 바로가기는 가리키는 프로그램의 그림으로 보입니다. 확장자만 보고 고른 그림을 쓰면 폴더도 바로가기도 밋밋한 문서 그림이 됩니다. 그것으로도 안 되면 `.lnk` 가 가리키는 그림이나 프로그램에서 꺼냅니다.

## 박스와 바탕화면 아이콘은 같은 격자를 쓴다

박스는 바탕화면 아이콘과 나란히 놓여야 합니다. 다만 묶어 두지는 않습니다. 두 가지로 그렇게 합니다.

1. **박스를 격자에 붙인다** (`deskgrid::snap_rect`). 묶지는 않습니다. 칸의 배수로만 자리와 크기를 정할 수 있으면 박스를 원하는 대로 만들 수 없으므로, 칸 경계에서 **한 칸의 1/5 안에 들어올 때만** 자석처럼 붙입니다. 그 사이의 자리와 크기는 놓은 그대로 씁니다.
   - **화면 가장자리에도 붙입니다**(`edge_magnet`). 아이콘 격자는 화면 끝에서 조금 들어와 시작하므로(위상), 격자에만 붙이면 가장자리에 딱 붙여 놓은 박스가 그만큼 되튑니다.
   - **크기만 바꿨으면 자리는 손대지 않습니다.** 손이 무엇을 바꿨는지는 마지막으로 손을 뗀 자리(`settled`)와 견주어 압니다. 크기를 줄였을 뿐인데 박스가 옆으로 뛰면 무엇을 한 것인지 알 수 없습니다.
   - **끌고 가다 다른 박스에 닿으면 거기서 멈춥니다**(`deskgrid::slide_to`). 놓은 뒤에 밀어내면 박스가 갑자기 딴 자리로 뛰므로, 끄는 동안 벽처럼 막아 보이는 자리가 곧 놓일 자리가 되게 합니다. 이미 겹친 채로 저장된 상대는 벽으로 보지 않습니다 — 비켜 줄 길이 없기 때문입니다.
   - **줄을 맞추다 남의 자리를 덮으면 맞추지 않습니다.** 자석보다 겹치지 않는 것이 먼저입니다.
   - **켤 때는 아무것도 손보지 않습니다.** 줄 맞추기와 겹침 풀기는 손이 박스를 움직였을 때만 합니다. 켤 때마다 자리를 손보면 어제 놓아 둔 자리에 오늘 박스가 없습니다. 화면 밖으로 나간 자리만 `clamp_to_screen` 이 안으로 들입니다.
   - 칸 수는 **박스 제 크기에서만** 셉니다. 옮겨 간 모서리에서 재면 왼쪽으로 반 칸 움직일 때마다 한 칸씩 늘어, 몇 번 끌고 나면 박스가 화면을 덮습니다.
2. **자리는 박스가 먼저 잡는다** (`Desktop::nudge`). 박스가 덮은 칸에 남아 있는 아이콘은 밖의 빈 칸으로 비킵니다. 갈 곳은 **제자리에서 가장 가까운 빈 칸**입니다. 늘 맨 앞 빈 칸으로 보내면 오른쪽 아래에 있던 아이콘이 왼쪽 위로 날아가, 박스를 옮길 때마다 바탕화면 전체가 다시 정렬된 것처럼 보입니다. 비켜 주기만 하면 될 일이므로 한 걸음만 옮깁니다. 박스를 끄는 동안에도 40밀리초마다 따라옵니다.

### 박스끼리는 겹치지 않는다

겹친 만큼 **가장 적게 움직이는 쪽**으로 비킵니다(`deskgrid::push_out`). 값싼 쪽부터 보되 거기서 또 다른 박스와 겹치는 자리는 건너뜁니다. 그러지 않으면 박스 둘 사이에 낀 박스가 좌우로 오가기만 합니다. 크기를 키우다 옆 박스에 닿은 것이면 자리를 옮기지 않고 **닿은 데서 멈춥니다**(`trim_to_fit`).

### 격자는 흔들리지 않아야 한다

박스와 아이콘은 **같은 격자** 위에 서야 하고, 그 격자는 움직이지 않아야 합니다.

- 칸 크기는 **탐색기에게 직접 묻습니다**(`LVM_GETITEMSPACING`). 놓인 아이콘에서 재면 아이콘이 둘뿐일 때 두 칸 거리를 한 칸으로 잘못 봅니다. 못 물으면 `deskgrid::metrics` 로 잽니다. 어느 쪽이든 화면 배율이나 아이콘 크기 설정을 그대로 따라갑니다.
- 원점은 맨 앞 아이콘의 자리가 아니라 **위상**(`deskgrid::steady`)입니다. `metrics.x0` 는 '맨 왼쪽 아이콘의 자리'라서, 아이콘을 밀어내면 그 값이 바뀌고 격자가 통째로 움직입니다. 그 격자에 박스를 맞추면 **박스가 저 혼자 걸어 다닙니다**. 아이콘이 모두 한 격자 위에 있으면 나머지(위상)는 같으므로, 위상을 원점으로 삼아야 박스가 제자리에 머뭅니다.

`grid_info` 와 `nudge` 는 같은 `lattice_of` 를 씁니다. 둘이 다른 격자를 쓰면 박스와 아이콘의 줄이 어긋납니다.

**자동 정렬은 꺼야 합니다.** 켜져 있으면 탐색기가 밀어낸 아이콘을 곧바로 제자리로 되돌립니다. 되돌아간 자리는 박스 밑이라 그 아이콘은 고를 수도, 열 수도 없습니다. 그래서 `nudge` 는 아이콘을 옮기기 전에 자동 정렬을 끕니다. 끈 것은 `icon-homes.json` 에 적어 두었다가 끝낼 때 `restore_arrange` 가 되돌립니다. 격자에 맞춤은 건드리지 않습니다 — 그 비트를 보내는 것만으로 comctl32 가 모든 아이콘을 격자로 끌어모읍니다.

밀어내기 전의 자리는 `icon-homes.json` 의 `homes` 에, 무엇을 밀어냈는지는 `nudged` 에 적습니다.

### 박스가 비켜 간 자리로는 아이콘이 돌아온다

`homecoming` 이 합니다. 박스를 옮기면 그 자리가 비는데, 비켜 준 아이콘을 그대로 두면 박스가 지나간 자리마다 구멍이 남아 바탕화면이 점점 흐트러집니다. 적어 둔 자리가 이제 비었으면 돌려놓고, 아직 박스에 가렸거나 남이 쓰고 있으면 그대로 둡니다. 돌려놓은 것은 `nudged` 에서 빼야 끝낼 때 또 옮기지 않습니다.

끝낼 때는 `home_all` 이 남은 기록으로 제자리에 돌려놓습니다.

### 바탕화면을 두 번 누르면 박스를 감춘다

`watch_double_click` 이 16밀리초마다 버튼을 보고 **누름(내려감)** 을 센다. 뗌을 세면 손이 빠른 사람의 첫 클릭을 통째로 놓친다. 버튼 상태는 물어볼 때의 값만 알려 주므로, 누르고 떼는 일이 두 번의 물음 사이에 모두 끝나면 우리 눈에는 아무 일도 없던 것이 된다.

세는 규칙은 `deskpick::DeskTaps` 에 있다(순수한 셈이라 검사로 덮는다).

- 사이 시간은 `GetDoubleClickTime()` — 사용자가 정한 값이다. 320밀리초처럼 박아 두면 보통 속도로 두 번 누른 것이 세지지 않는다. 이 컴퓨터의 값은 500밀리초였다.
- 자리 범위는 넉넉히 잡는다(28픽셀). 운영체제가 주는 4픽셀은 아이콘을 두 번 눌러 여는 잣대다. 실제로 재 보니 손이 두 번 누르는 사이 20픽셀 넘게 움직였고, 4픽셀로 재면 그 모두를 놓쳤다.
- 커서 아래가 바탕화면이어야 한다(`desktop_at`). 앞 창만 보면 박스 위에서 누른 것도 잡힌다. 아이콘 위도 세지 않는다.

## 끝내면 바탕화면이 돌아온다

파일을 옮겼으므로 되돌리는 일이 앞선 판보다 무겁습니다. **어느 길로 끝나든 바탕화면은 켜기 전 모습이어야 합니다.**

되돌리는 차례는 `app::restore_desktop` 하나로 모읍니다. 감시(`watch.rs`)를 먼저 멈춰, 되돌리는 동안 다시 담지 않게 합니다. 두 번 불러도 한 번만 합니다.

1. `put_back` — 박스마다 담긴 파일을 `home` 으로 옮긴다. 빈 박스 폴더는 치운다.
2. `Desktop::release` — 밀어냈던 아이콘을 적어 둔 자리에 놓고, 감춘 셸 아이콘을 되살린다.
3. `Desktop::shutdown` — 자동 정렬 같은 탐색기 설정을 되돌린다.

파일을 먼저 돌려주고 아이콘 자리를 나중에 되돌립니다. 그래야 돌아온 파일의 아이콘도 제자리를 찾습니다.

| 어떻게 끝나는가 | 무엇이 부르는가 |
| --- | --- |
| 트레이의 종료 | `RunEvent::Exit` (`lib.rs`) |
| Ctrl+C, 콘솔 닫기 | `SetConsoleCtrlHandler` (`session.rs`) |
| 로그아웃, 시스템 종료, 설치·제거 프로그램이 닫을 때(Restart Manager) | 숨은 창이 받는 `WM_ENDSESSION` (`session.rs`) |
| 큰 오류(panic) | `std::panic::set_hook` (`fatal.rs`) |
| 전원 내림, 작업 관리자의 강제 종료 | 아무것도 부르지 못한다 → 다음에 켤 때 `recover_held` |

**큰 오류로 멈출 때**는 순서가 중요합니다. 먼저 바탕화면을 되돌리고, 그 다음에 시스템 창으로 알립니다. 알림 창 앞에서 손이 멈춰 있는 동안에도 담아 둔 파일은 이미 바탕화면에 돌아와 있어야 하기 때문입니다. 창에는 판, 운영체제, 때, 오류의 자취가 담기고 **복사** 단추로 그대로 클립보드에 담을 수 있습니다.

**아무것도 부르지 못하고 끝난 경우**는 다음에 켤 때 `recover_held` 가 치웁니다. `restore.json` 에 적힌 것 가운데 지금 어느 박스도 들고 있지 않은 파일을 담기 전 폴더로 돌려보냅니다. 박스가 아직 들고 있는 것은 남은 것이 아니라 담긴 것이므로 그대로 둡니다.

트레이의 **바탕화면으로 모두 돌려주기**(`return_all`)는 박스를 남기고 안의 것만 비웁니다. 박스를 지우면(`remove_fence`) 담긴 것을 모두 돌려준 뒤에 박스가 사라집니다.

박스는 화면 밖으로 나가지 않습니다. `clamp_to_screen` 이 가장 가까운 화면의 작업 영역 안으로 들입니다.

## 바탕화면에 보내면 안 되는 것

계측으로 확인한 것들입니다. 셋 다 한 번만 보내도 바탕화면이 망가집니다.

- **`LVM_SETWORKAREAS`** — 보내는 순간 바탕화면 아이콘의 **그림이 모두 사라지고 이름만 남습니다.** 탐색기를 다시 띄우기 전에는 돌아오지 않습니다. 앱을 켤 때마다 `normalize_list` 가 이것을 보내고 있었고, 그것이 "켜면 아이콘이 사라진다"의 까닭이었습니다. 탐색기를 새로 띄우고 27개를 센 결과: 아무것도 안 함 27개, 이 메시지만 보냄 **0개**, 아이콘 자리잡기만 27개, 이것만 빼고 전부 켬 27개.
- **`SHChangeNotify(SHCNE_ASSOCCHANGED, ...)`** — 셸이 아이콘 그림 곳간을 통째로 다시 만들고, 그동안 바탕화면이 그림 없이 이름만 그려집니다. 셸 아이콘을 감추거나 휴지통을 비운 뒤에도 쓰지 않습니다. 바탕화면 보기에 새로 고침(`WM_COMMAND` `0x7103`)만 보냅니다.
- **목록 창 크기(`SetWindowPos`)** — 같은 증상을 냅니다. `normalize_list` 는 앞선 판이 **넓혀 둔 것만** 좁히고, 넓히지는 않습니다.

아이콘을 화면 밖(x = 20000)으로 치우는 것도 쓰지 않습니다. 탐색기가 마우스를 뗄 때마다 되돌려 놓아 250밀리초 주기의 다툼이 됩니다.

### 살펴보는 길

- `MYDESKBOX_TRACE` 에 파일 경로를 주면 무슨 일이 언제 일어났는지 적습니다.
- `node tools/icon-check.js` — 바탕화면 아이콘에 그림이 남아 있는지 셉니다. 망가뜨리는 호출을 가려낼 때 씁니다.
- `bash tools/icon-trial.sh "이름" VAR=1` — 탐색기를 새로 띄우고, 앱을 켜기 앞뒤로 그 수를 견줍니다.
- `node tools/shoot-desktop.js <파일.png> [x y w h]` — 다른 창이 덮고 있어도 바탕화면 층만 찍습니다.

## 다른 운영체제

담기는 파일을 옮기는 일이라 어디서나 똑같이 됩니다. Finder와 데스크톱 환경은 아이콘 하나의 좌표를 바꾸는 API를 주지 않으므로, `Desktop::native_icons` 가 거짓이면 아이콘을 밀어내지도, 격자에 맞추지도 않습니다. 박스는 그린 자리에 그대로 서고, 담긴 것은 그대로 보여 줍니다. 셸 항목 목록은 Windows에서만 채웁니다.

`npm run test:js` 는 `tools/reporter.js` 로 파일별 결과와 검사마다의 시간을 찍습니다. 기호는 ASCII 만 써서 한글 콘솔에서 선 문자가 `?` 로 보이지 않게 합니다.

### 가짜 창과 가짜 바탕화면

앱의 판단은 `Host` 에 모여 있고, `Host` 는 창을 `Ui` 트레이트로, 바탕화면을 `Desktop` 트레이트로만 봅니다. 검사는 둘 다 가짜를 끼웁니다.

- `host/testkit.rs` 의 `FakeUi` 는 띄운 창과 보낸 사건(`messages("fence:state")`), 띄운 메뉴, 물은 것을 적어 두고 묻는 창의 답을 정해 둡니다. `kit(base_state(json!({ … })))` 가 검사마다 빈 임시 폴더와 함께 `Host` 를 만듭니다.
- `desktop/fake.rs` 의 `FakeDesktop` 은 운영체제를 부르지 않고 무엇이 불렸는지만 적어 둡니다. 파일은 검사마다 만든 임시 폴더 안에서 실제로 옮깁니다.
- Electron 판의 검사(`test/fences.test.js` 따위)를 같은 이름의 Rust 검사로 옮겼습니다. 파일 맨 위에 어느 검사를 옮긴 것인지 적어 두었습니다.

여기에 걸리는 함정이 하나 있습니다. **`k.h()` 로 자물쇠를 잡은 채 다시 `k.h()` 를 부르면 멈춥니다.** `std::sync::Mutex` 는 다시 들어갈 수 없습니다. 인자에 넣을 값은 먼저 따로 셈해 두고 부릅니다.

### 창을 띄우지 않고 보는 것

검사에는 진짜 창이 없으므로, 창이 하는 판단은 다음 두 가지로 봅니다.

- **좌표로 본다.** 받아 주는 자리(`deliver.PICTURE`, `geom::on_picture`)와 칸 번호(`slot_point`)는 순수 계산이라, 화면 좌표를 만들어 `transfer` 나 `accept_desktop_drop` 에 그대로 넘기면 실제로 지나가는 길과 같습니다. `host/tests_deliver.rs` 의 `on_picture(n, box)` 가 그 자리를 셈해 줍니다.
- **소스를 센다.** 창과 Rust 사이의 고리(`test/shared.test.js`)와 설치 훅의 약속(`test/build.test.js`)은 소스에서 직접 봅니다. 설치 프로그램은 사용자 컴퓨터를 바꾸므로 검사에서 돌리지 않습니다.

### 손으로 확인할 때

진짜 바탕화면과 사용자 데이터를 건드리지 않도록 늘 다른 폴더를 주고 띄웁니다.

```bash
MYDESKBOX_DATA_DIR=/tmp/mdb/data MYDESKBOX_DESKTOP_DIR=/tmp/mdb/desk \
WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9391 \
src-tauri/target/debug/mydeskbox.exe
```

`--remote-debugging-port` 를 주면 창마다 CDP 대상(`http://tauri.localhost/renderer/fence.html` 따위)이 생겨 창 안의 코드를 부르고 화면을 찍을 수 있습니다. 디버그 빌드에서만 `debug_quit` 명령이 있어, 트레이를 누르지 않고 끝내는 길(되돌리기 포함)을 부를 수 있습니다.
