# 구조

## 큰 그림

```
                    ┌──────────────────────────────┐
                    │  src/engine  (순수 자바스크립트) │
   키 인덱스 0~11 ─▶ │  chunjiin.js  유니코드 조합    │ ─▶ state.text
   편집 명령      ─▶ │  input.js     오토마타·편집 API │    state.cursorPos
                    └──────────────────────────────┘
                                   ▲
                                   │ 이 경계 위로는 DOM 도 Node 도 모른다
                    ┌──────────────┴───────────────┐
                    │  src/App.jsx + src/ui/*.jsx   │  화면·키보드·명령
                    └──────────────┬───────────────┘
                                   │
                    ┌──────────────┴───────────────┐
                    │  src/platform.js              │  파일·클립보드·창 크기
                    └──────┬────────────────┬───────┘
                           │                │
                  브라우저 API        electron/preload.cjs
                                            │
                                     electron/main.js
                                     electron/windowResize.js
```

엔진은 브라우저 API 도 Node API 도 쓰지 않습니다.
그래서 `node tests/engine.test.mjs` 로 화면 없이 그대로 돌릴 수 있고,
웹과 데스크톱이 **완전히 같은 조합 코드**를 씁니다.

## C 판과의 대응

| C 판 | 여기 | 하는 일 |
|---|---|---|
| `include/chunjiin.h` + `src/chunjiin.c` | `src/engine/chunjiin.js` | 상태 자료구조, `getUnicode`, `checkDouble` |
| `src/input.c` | `src/engine/input.js` | 천지인 오토마타, 편집 API, 키 라벨 |
| `src/main.c` (GUI) | `src/App.jsx` + `src/ui/*` | 키보드, 툴바, 상태줄, 대화상자 |
| `main.c` 의 `THEMES` 표 | `src/themes.js` | 테마 4종 (COLORREF 값을 그대로 옮김) |
| 레지스트리 `HKCU\Software\Chunjiin` | `src/settings.js` (`localStorage`) | 설정 저장 |
| `OPENFILENAMEW`, `OpenClipboard` | `src/platform.js` + `electron/main.js` | 파일·클립보드 |
| `tests/test_engine.c` | `tests/engine.test.mjs` | 회귀 시험 |

### 옮기면서 지킨 것

- **함수 하나하나가 대응됩니다.** `hangul_make` → `hangulMake`,
  `write_hangul` → `writeHangul` 처럼 이름과 차례를 그대로 두었습니다.
- **분기 순서를 바꾸지 않았습니다.** 특히 `get_unicode` 의 if-else 사슬은
  목록에 없는 값이 마지막 항목(ㅎ, ㅣ)으로 떨어지는데, 그 성질까지
  `indexOf` 가 `-1` 이면 마지막 번호를 쓰는 방식으로 옮겼습니다.
- **표는 값을 그대로 베꼈습니다.** 모음 전이표 24행, 자음 순환표,
  영문·기호 배열, 테마 색 96개가 원본과 같은 값입니다.

### 옮기면서 달라진 것

| C | 자바스크립트 | 왜 |
|---|---|---|
| `wchar_t text_buffer[4096]` | `state.text` (문자열) | UTF-16 코드 단위 기준이라 커서 계산이 같다 |
| 구조체 대입(값 복사) | `copyHangulState()` | 객체는 참조라서 명시적으로 복사한다 |
| `char *wchar_to_utf8()` | `wcharToUtf8()` | 자바스크립트는 이미 유니코드라 길이 제한만 흉내 |
| `chunjiin_composition_text(out, len)` | 문자열을 돌려준다 | 출력 버퍼가 필요 없다 |
| `Segoe MDL2 Assets` 글리프 | 인라인 SVG (`Icons.jsx`) | 그 글꼴은 Windows 에만 있다 |
| Win32 `EDIT` 컨트롤 | 직접 그리는 편집 영역 | 캐럿 위치를 엔진이 온전히 쥐어야 한다 |
| 메뉴 막대 (파일·편집·입력·설정·도움말) | 없앰 | 명령이 모두 툴바와 단축키에 있어 한 줄을 더 벌었다 |
| `MessageBoxW` 오류 알림 | `ErrorDialog.jsx` | 무엇을 하다가 어디서 틀어졌는지 통째로 복사할 수 있어야 한다 |
| 기본 `title` 풍선 | `Tooltip.jsx` | 브라우저 풍선은 1초 가까이 걸리고 그 시간을 바꿀 수 없다 |
| 창 테두리 끌기 | `ResizeGrip.jsx` + `windowResize.js` | 좁은 창이라 크기를 바꿀 수 있다는 표시가 눈에 보여야 한다 |

## 오토마타

### 상태

한 음절은 네 칸(`chosung` · `jungsung` · `jongsung` · `jongsung2`)과
"마지막으로 채운 자리"(`step`)로 나타냅니다.
`jungsung` 에는 완성 모음뿐 아니라 중간 상태인 `·` 와 `‥` 도 들어갑니다.
`getUnicode()` 가 이 둘을 "아직 모음이 아님"으로 보고 초성만 돌려줍니다.

### 모음

`VOWEL_RULES` 24행이 전부입니다. 각 행은
`[현재 모음, +ㅣ, +·, +ㅡ, 백스페이스로 돌아갈 곳]` 입니다.
`null` 이면 그 조합은 없으므로 현재 음절을 확정하고 새 음절을 시작합니다.

### 자음

`CONS_CYCLE` 이 키마다 순환 목록을 갖습니다(ㄱ→ㅋ→ㄲ).
같은 키를 연달아 누르면 `cycleConsonant()` 가 다음 후보로 돌리는데,
자리에 따라 걸러 냅니다.

- 받침 자리면 받침이 될 수 없는 자음(ㄸ ㅃ ㅉ)은 건너뜁니다
- 겹받침 둘째 자리면 겹받침을 이루지 못하는 자음은 건너뜁니다

### 연음

받침이 있는 상태에서 모음 키가 오면 `hangulVowel()` 이
마지막 자음을 떼어 앞 글자를 확정하고, 뗀 자음을 새 음절의 초성으로 삼습니다.
겹받침이면 둘째 자음만 넘어갑니다.

### 겹받침 되돌려 붙이기

`ㅎ` · `ㅁ` · `ㅌ` 처럼 순환의 첫 자리가 아닌 자음이 겹받침에 필요할 때가 있습니다
(`많` `삶` `핥`). 첫 타에는 겹받침이 되지 못해 새 음절로 떨어져 나가는데,
이때 `prevSyllable` 에 직전 음절을 기억해 둡니다.
같은 키를 한 번 더 눌러 겹받침이 되는 자음이 나오면 `tryMergeJong()` 이
`composeLen` 을 하나 늘려 앞 칸까지 다시 그리며 도로 합칩니다.

```
만  +  ㅅㅎ        →  만ㅅ       (ㅅ 은 ㄴ 과 겹받침이 안 된다)
       ㅅㅎ 한 번 더 →  많        (ㅎ 은 ㄴ 과 ㄶ 이 된다 → 되돌려 붙임)
```

이 기억은 모음·문장부호·백스페이스·커서 이동이 오면 곧바로 풀립니다.

### 화면에 그리기

조합 중인 글자는 `state.text` 안에 **이미 들어가 있습니다.**
`writeHangul()` 이 직전에 그린 `composeLen` 칸을 지우고 새로 그립니다.
`composeLen` 이 2가 되는 경우는 두 가지입니다.

- 아래아 중간 상태 — `ㄱ·` 처럼 초성과 점을 나란히 보여 줄 때
- 겹받침 되돌려 붙이기 — 앞 칸까지 다시 그려야 할 때

## 화면 쪽

### 상태 관리

엔진 상태는 `useRef` 에 담긴 **변경 가능한 객체 하나**입니다.
React 의 불변 상태로 감싸지 않았습니다. C 원본이 포인터로 제자리에서
고치는 코드라서, 그대로 옮긴 엔진과 결이 맞기 때문입니다.
화면 갱신은 `useReducer` 로 만든 카운터를 올려서 일으킵니다.

### 편집 영역

`textarea` 대신 `div` 에 직접 그립니다.

```
[확정된 글] [조합 중인 글자(밑줄)] |캐럿| [뒤쪽 글]
```

클릭하면 `caretPositionFromPoint` 로 짚은 글자 번호를 알아내
`chunjiinSetCursor()` 를 부릅니다. 조합은 그때 확정됩니다.

### 연타 시계

키를 누를 때마다 `settings.multitapMs` (기본 0.8초) 뒤에
`chunjiinBreakMultitap()` 을 부르는 타이머를 다시 겁니다.
시간이 지나면 같은 키를 눌러도 순환이 아니라 새 문자로 시작합니다.

커서 이동 · 모드 전환처럼 조합이 확정되는 자리에서는 `stopMultitap()` 이
타이머를 곧바로 끕니다. 상태줄의 `연타 0.8초 ●` 에서 ● 에 불이 들어와 있으면
지금 순환이 살아 있다는 뜻입니다.

### 상태줄

메뉴 막대를 없앴으므로 프로그램의 상태는 모두 상태줄이 짊어집니다.
두 줄로 나누어, 윗줄은 지금 치고 있는 것(모드 · 조합 · 알림),
아랫줄은 설정과 위치(테마 · 글꼴 · 연타 · 커서)를 보여 줍니다.

### 오류

`showError(무엇을, 원인)` 하나로 모읍니다. 파일 · 클립보드 명령이 실패할 때는
물론, `window` 의 `error` 와 `unhandledrejection` 도 여기로 흘려보내
조용히 사라지는 오류가 없게 했습니다.

창에는 `무엇을 하다가 · 언제 · 어디서 · 오류 · 자세한 내용`이 한자리에 나오고,
그 글이 그대로 클립보드에 들어갑니다(`formatError()` 가 화면과 복사본을
같은 한 곳에서 만듭니다). 창을 닫아도 상태줄에 자국이 남아 다시 열 수 있습니다.

### 설명 풍선

브라우저 기본 `title` 풍선은 1초 가까이 기다려야 뜨고 그 시간을 바꿀 수 없습니다.
`Tooltip.jsx` 하나가 문서 전체의 마우스를 지켜보다가 `data-tip` 이 달린 것 위에서
0.13초 만에 띄웁니다. 버튼마다 상태를 두지 않으므로 글자를 아무리 쳐도
풍선 때문에 다시 그려지는 일이 없습니다.

### 창 크기 손잡이

오른쪽 아래 손잡이는 창 **안쪽**에 그려져 있어 운영체제의 조절 테두리가 아닙니다.
그래서 끌기를 직접 받아 `win:resize-begin / -by / -end` 로 넘깁니다.
main 쪽은 누른 순간의 크기를 기억해 두고 끌린 거리만큼 더합니다
(`electron/windowResize.js`). 최소 크기는 `BrowserWindow` 가 지켜 줍니다.
브라우저에서는 창 크기를 건드릴 수 없으므로 아예 그리지 않습니다.

### 테마

`themes.js` 가 테마 하나를 CSS 사용자 지정 속성 묶음으로 바꾸고,
`App.jsx` 가 그것을 최상위 `div` 의 `style` 로 내려 줍니다.
`styles.css` 에는 색 값이 하나도 없고 `var(--...)` 만 있습니다.

## 시험

`tests/engine.test.mjs` 는 C 판 `test_engine.c` 를 그대로 옮긴 것입니다.
키 시퀀스 문법도 같습니다.

```
0~9  키 0~9        a 키 10      b 키 11
_ 스페이스   < 백스페이스   | 연타 순환 끊기   ! 조합 확정
~ 전체 지우기   / 줄바꿈   [ ] 커서 이동   { } 맨 앞·맨 뒤
H E U N S 모드 지정   M 모드 순환
```

34구역 584항목입니다. C 판은 585항목인데, 하나가 `NULL` 포인터를 넘겨도
죽지 않는지 보는 시험이라 자바스크립트에는 대응이 없습니다.

```bash
npm test        # 항목마다 PASS/FAIL
npm run test:quiet   # 실패한 것과 요약만
```

화면까지 도는지는 `npm run test:app` 이 봅니다. 창을 띄워 키패드를 눌러 보고
17가지를 확인한 뒤, 하나라도 어긋나면 실패로 끝납니다.

| 무엇 | |
|---|---|
| 한글 조합 · 영문 멀티탭 | 키패드를 눌러 `한글` · `hi` 가 찍히는지 |
| 키패드 · 기능 버튼 | 12키와 6개가 다 있는지 |
| 대화상자 | 설정 · 정보 · 사용법이 열리고 닫히는지 |
| 오류 창 | 뜨는지 · 복사 버튼이 있는지 · 본문을 고를 수 있는지 · 자국이 남는지 |
| 툴바 | 잘리지 않는지 · 정보 버튼이 오른쪽 끝인지 · 사용법 버튼이 없는지 |
| 상태줄 | 두 줄인지 |
| 손잡이 · 풍선 | 손잡이가 있는지 · 풍선이 뜨고 화면 안에 들어오는지 |
| 콘솔 | 오류가 하나도 없는지 |

검사 목록은 `scripts/probe.js` 에 평범한 파일로 두고 `smoke.cjs` 가 읽어 실행합니다.
문자열 안에 코드를 끼워 넣으면 따옴표와 줄바꿈 이스케이프가 겹쳐 금방 깨지기 때문입니다.

`scripts/shot.cjs` 는 테마 4종과 풍선 · 오류 창을 찍어 `docs/images` 에 넣습니다.
문서에 쓰인 그림이 모두 이것으로 만들어진 것입니다.
