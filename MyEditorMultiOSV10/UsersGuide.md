# My Editor — 사용자 가이드

## 0. 설치 (Windows)

- 설치 프로그램에서 바로가기 다음 페이지가 **파일 형식 등록**입니다. "'연결 프로그램' 목록에 My Editor 추가"를 켜면 JavaScript · TypeScript · Python · C/C++ · C# · Java · Go · Rust · Markdown · JSON · HTML/CSS · SQL · 셸 스크립트 · 텍스트 등 35가지 형식(90여 개 확장자)이 오른쪽 클릭 › 연결 프로그램에 나타나고 각 형식에 **언어별 아이콘**이 붙습니다. "**기본 편집기로 등록**"까지 켜면 더블클릭으로 My Editor 가 열리고 탐색기가 그 아이콘을 보여 줍니다(현재 사용자 계정에만 등록, 제거 시 되돌림). 나중에 Windows 설정 › 앱 › 기본 앱에서 바꿀 수 있습니다.

- 맨 위 **제목 표시줄**(로고 · 이름 · 창 버튼)은 빈 곳을 드래그하면 창이 움직이고 더블클릭하면 최대화됩니다. 그 아래 **메뉴 바**(각 메뉴에 아이콘), 그 아래 **도구 모음**이 있고, 테마 · UI 언어(국기) · 설정 · 정보 버튼은 도구 모음 오른쪽 끝에 있습니다(도구 모음을 숨기면 메뉴 바 오른쪽으로 옮겨집니다). 빈 곳을 드래그하면 창이 움직이고, 더블클릭하면 최대화됩니다.
- 오른쪽 위 **테마** 버튼은 누를 때마다 다음 테마로 바뀌고, ▾ 를 누르면 20개 테마(와 직접 만든 ★ 테마) 목록이 나옵니다. **국기** 버튼은 한국어 ↔ 영어를 전환합니다.
- **상태 표시줄**의 들여쓰기 · 줄 끝 · 인코딩 · 언어 · 확대율은 모두 버튼입니다. 눌러서 바로 바꿀 수 있습니다.
- 우측 하단 ⋱ 마커를 드래그하면 창 크기가 바뀝니다(데스크톱).

## 2. 문서 열기 · 저장

| 동작 | 방법 |
|---|---|
| 새 문서 | Ctrl+N, 도구 모음 첫 버튼, 탭 줄의 `+` |
| 열기 | Ctrl+O(여러 파일 선택 가능), 도구 모음 두 번째 버튼, 파일을 창에 끌어다 놓기, 탐색기에서 더블클릭, 폴더 트리에서 클릭 |
| 폴더 열기 | Ctrl+Shift+O, 도구 모음 세 번째 버튼 — 폴더 트리에 표시 |
| 저장 / 다른 이름으로 | Ctrl+S / Ctrl+Alt+S — 새 문서는 저장 위치를 묻습니다 |
| 모두 저장 | Ctrl+Shift+S |
| 다시 불러오기 | 파일 › 다시 불러오기(수정 중이면 확인) |
| 닫기 | Ctrl+W, 탭의 ×, 탭 가운데 클릭 — 저장하지 않은 문서는 저장 / 저장 안 함 / 취소를 묻습니다 |
| 최근 파일 | 파일 메뉴 아래쪽(최근 12개) |
| 인쇄 | Ctrl+P, 파일 › 인쇄…, 도구 모음의 인쇄 버튼 — Markdown 은 미리보기와 같은 렌더 결과(이미지 포함, 로컬 이미지는 문서에 포함해 인쇄), 그 밖의 문서는 줄 번호가 있는 목록으로 시스템 인쇄 대화상자에 보냅니다 |

- 다른 프로그램이 파일을 바꾸면, 편집하지 않은 문서는 자동으로 다시 읽고(설정에서 끌 수 있음) 편집 중인 문서는 물어봅니다. 디스크에서 지워진 파일은 알려 주고 탭을 유지합니다.
- 프로그램을 닫았다가 다시 열면 열려 있던 탭, 커서 위치, 저장하지 않은 **새 문서의 내용**까지 그대로 돌아옵니다(설정 › 시작할 때 이전 세션 복원). 그사이 지워지거나 옮겨진 파일의 탭은 복원하지 않고(저장하지 않은 변경이 있었다면 그 내용은 새 문서로 돌아옵니다), 열려 있던 폴더가 없어졌으면 폴더 없이 시작합니다. 복원할 것이 하나도 없으면 빈 새 문서로 시작합니다.
- 64 MB 를 넘는 파일과 이진 파일은 열기 전에 알려 줍니다.

## 3. 탭

- 드래그해서 순서를 바꿀 수 있습니다.
- 탭이 창 폭보다 많아지면 오른쪽 끝에 `<` `>` 버튼이 나타납니다. 마우스 휠로도 스크롤됩니다. 활성 탭은 항상 보이게 유지됩니다.
- Ctrl+Tab / Ctrl+Shift+Tab, Ctrl+PgDn / PgUp 으로 이동, Ctrl+1 ~ Ctrl+9 로 n번째 탭.
- 오른쪽 클릭: 저장, 다른 이름으로, 다시 불러오기, 닫기 / 다른 탭 모두 닫기 / 오른쪽 탭 모두 닫기 / 모두 닫기, 탐색기에서 보기, 기본 앱으로 열기, 경로 · 파일 이름 복사.
- 이탤릭 이름 + ● 은 저장하지 않은 문서, 👁 은 읽기 전용 파일입니다.

## 5. 찾기 · 바꾸기

- Ctrl+F 로 찾기 줄이 열립니다. 입력하는 대로 일치하는 곳이 강조되고 `현재 / 전체` 개수가 표시됩니다.
- Enter = 다음, Shift+Enter = 이전, F3 / Shift+F3 도 같습니다. ≡ 버튼은 일치하는 곳을 모두 선택합니다(다중 커서).
- `Aa` 대/소문자 구분, `ab` 단어 단위, `.*` 정규식. 정규식이 잘못되면 입력 칸이 빨갛게 표시됩니다.
- Ctrl+H 로 바꾸기 줄이 추가됩니다. 바꾸기 칸에서 Enter = 하나 바꾸기, Ctrl+Enter = 모두 바꾸기. 정규식일 때 `$1` 같은 그룹 참조를 쓸 수 있습니다.
- Ctrl+G 줄로 이동: `12` 또는 `12:5`(줄:열).
- Esc 로 닫습니다.
- **폴더에서 찾기**(Ctrl+Shift+F, 찾기 메뉴, 폴더 패널 머리의 🔍): 폴더 패널 **아래 절반에 검색 영역**이 열리고(폴더 트리와 검색 영역이 반반; 구분선을 끌어 비율 조절, × 로 닫기) 폴더 트리에 열린 폴더의 모든 파일을 뒤집니다. `Aa` · `ab` · `.*` 옵션, 포함/제외 패턴(`*.js, src/**`)을 쓸 수 있고, 검색은 백그라운드에서 돌며 취소할 수 있습니다. .git · node_modules · dist 같은 폴더, 2MB 넘는 파일, 바이너리는 건너뜁니다. 결과는 파일별로 묶여 줄 번호와 해당 줄(일치 부분 강조)로 나오고, 누르면 그 파일이 그 자리에 열립니다(최대 2,000개).
- **열린 문서에서 찾기**(Ctrl+Alt+F): 같은 검색 영역에서 범위를 "열린 문서"로 두면 저장하지 않은 내용까지 포함해 열려 있는 모든 문서를 찾습니다.

## 6. 언어 · 인코딩 · 줄 끝

- **언어**는 확장자로 자동 판별됩니다. 언어 메뉴(자주 쓰는 25개) 또는 `언어…` 로 열리는 검색 목록(150+)에서 직접 고를 수 있고, 상태 표시줄의 언어 이름을 눌러도 됩니다. 문법은 처음 쓸 때만 내려받듯 로드됩니다. 메뉴와 목록의 각 언어 앞에는 그 언어의 고유 색과 약칭(JS · TS · Py · C++ …)으로 된 아이콘이 붙고, 현재 선택된 언어는 오른쪽 체크 표시로 구분됩니다.
- **인코딩**은 열 때 BOM · UTF-8 · UTF-16 · 시스템 코드 페이지(한국어 Windows 는 CP949) 순으로 판별합니다. 인코딩 메뉴에서 다른 인코딩을 고르면 **저장할 때** 그 인코딩으로 씁니다. 잘못 판별된 파일은 `다른 인코딩으로 다시 열기…` 로 다시 읽으세요. 표현할 수 없는 문자가 있으면 저장 전에 경고합니다.
- **줄 끝**(CRLF / LF / CR) 은 파일에서 감지하며, 인코딩 메뉴 아래쪽이나 상태 표시줄에서 바꿀 수 있습니다. 새 문서의 기본값은 설정 › 파일에서 정합니다.

## 7. 폴더 트리 (Ctrl+B)

- 파일 › 폴더 열기(Ctrl+Shift+O) 또는 트리 상단의 📂 로 폴더를 열면 연결선이 있는 **트리 뷰**로 보입니다. 처음에는 최상위 항목만 보이고, 폴더(⊞)를 클릭하면 그 폴더만 펼쳐집니다(⊟ 클릭으로 닫기). 다른 폴더를 여닫아도 이미 펼친 폴더는 그대로 유지됩니다.
- 파일을 클릭하면 열리고, 열린 파일은 강조 색으로, 현재 문서는 선택 색으로 표시됩니다.
- 상단 버튼: 폴더 열기, 새로 고침(펼친 상태 유지), 모두 펼치기(`node_modules`·`.git` 등은 제외, 수천 개를 넘으면 중단), 모두 접기, 숨김 파일 표시, 폴더 닫기. 필터 칸에 글자를 넣으면 이름이 맞는 항목만 남습니다.
- 오른쪽 클릭: 새 파일 · 새 폴더 · 이름 바꾸기 · 삭제 · 탐색기에서 보기 · 경로 복사 · 새로 고침.
- 경계선을 드래그하면 너비가 바뀝니다.

## 8. Markdown 편집

`.md` 문서를 열면 탭 아래에 Markdown 도구 모음이 나타납니다.

| 버튼 | 단축키 | 동작 |
|---|---|---|
| H1 ~ H6 | Ctrl+1 ~ Ctrl+6 | 선택한 줄을 제목으로(같은 단계를 다시 누르면 해제) |
| **B** / *I* / ~~S~~ / `<>` | Ctrl+B / Ctrl+I / Ctrl+Shift+X / Ctrl+` | 선택 영역(없으면 커서 위치의 단어)을 굵게 · 기울임 · 취소선 · 인라인 코드로 감싸기, 이미 감싸져 있으면 풀기 |
| 인용 / 목록 / 번호 목록 / 체크리스트 | Ctrl+Shift+Q / 8 / 7 / 9 | 선택한 줄 앞에 기호 추가(다시 누르면 제거) |
| 코드 블록 | Ctrl+Shift+C | 선택 영역을 ``` 로 감싸기 |
| 링크 / 이미지 / 표 / 구분선 | Ctrl+K / Ctrl+Shift+I | 틀을 넣고 URL 부분을 선택해 둠 |

- **WYSIWYG** 버튼(Ctrl+Shift+W)이 켜져 있으면 제목은 크게, 굵게·기울임은 그대로, 목록은 •, 체크리스트는 실제 체크박스(클릭으로 토글), 인용은 왼쪽 막대, 코드 블록은 상자, 구분선은 선으로 **문서 안에서 바로** 보입니다. 기호(`#`, `**`, `-` …)는 **커서가 있는 줄에서만** 나타나므로 언제든 직접 고칠 수 있습니다. 끄면 원본 기호가 모두 보입니다. 끄면(소스 보기) 원본 기호가 모두 보이고 제목도 본문과 같은 크기의 고정폭 글꼴로 표시됩니다.
- **이미지**: WYSIWYG 에서 `![설명](경로)` 와 `<img src=… width=…>` 는 실제 그림으로 보입니다(문서 폴더 기준 상대 경로 · 절대 경로 · http(s) · data URL). 다른 기호와 달리 커서가 그 줄에 있어도 구문이 아니라 항상 그림으로 보이며(끌어다 놓은 이미지도 바로 그림으로), 커서는 그림을 한 글자처럼 건너뛰고 Backspace/Delete 는 그림을 통째로 지웁니다. 구문을 고치려면 WYSIWYG 를 끄세요. 그림 오른쪽 아래 모서리의 **핸들을 끌면 크기**가 바뀌며, 크기는 모든 Markdown 렌더러가 이해하는 `<img src="…" alt="…" width="N">` 형태로 기록됩니다.
- **이미지 넣기**: 도구 모음의 이미지 버튼(Ctrl+Shift+I)을 누르면 대화상자에서 파일을 고르거나(찾아보기…) 경로/URL 을 입력하고, 대체 텍스트와 **링크**(문서 폴더 기준 상대 경로로 참조) / **내장**(Base64 로 문서 안에 포함, 용량 표시) 중 하나, 필요하면 너비(px)를 정해 넣습니다. 미리보기가 함께 보입니다. 또는 PNG · JPEG · GIF · WebP · SVG · BMP · AVIF · ICO 파일을 Markdown 문서에 **끌어다 놓거나**(놓은 위치에 삽입) 클립보드의 이미지를 **붙여넣으면**(Ctrl+V) 파일 참조가 아니라 **Base64 data URL 로 문서 안에 포함**되어 문서 하나로 어디서나 열립니다. (다른 종류의 파일을 끌어다 놓으면 그 파일이 열립니다.)
- **이미지 파일**(SVG · PNG · JPEG · GIF · WebP · BMP · ICO · AVIF)을 열면 오른쪽 미리보기에 그림이 보입니다 — SVG 는 왼쪽에서 편집하는 대로 다시 그려지고, 그 밖의 이미지는 왼쪽에 16진수가 나옵니다. 클릭하면 창에 맞춤 ↔ 1:1, Ctrl+Shift+M 으로 켜고 끕니다.
- **미리보기** 버튼(Ctrl+Shift+M)은 오른쪽에 렌더링된 HTML 창을 엽니다. 문서 폴더 기준의 로컬 이미지도 표시됩니다. 편집기와 미리보기는 **양방향으로 따라갑니다**: 편집기에서 커서를 옮기거나 스크롤하면 미리보기가 그 자리로, 미리보기를 스크롤하면 편집기가 미리보기 맨 위에 보이는 내용의 줄로 이동합니다. 미리보기에서 **오른쪽 클릭**하면 메뉴가 나옵니다: 그림 위에서는 **이미지 복사**(클립보드로, 다른 프로그램에 붙여넣기 가능)와 **이미지 다른 이름으로 저장…**(PNG 등으로 내보내기), 그 밖에 복사 · 모두 선택 · 인쇄. 이미지 저장 창에서는 **파일 형식**(PNG · JPEG · WebP · BMP, 또는 원본 파일 그대로), JPEG/WebP 의 **품질**, 그리고 그림에 투명한 부분이 있으면 **투명 배경 유지**(PNG · WebP) 또는 **배경색으로 채우기**(JPEG · BMP 는 항상, 색 선택 가능)를 고릅니다. 미리보기의 바둑판 무늬가 투명한 부분입니다. 미리보기는 **편집 위치와 같은 곳**을 보여 줍니다: 커서가 있는 문단·제목·목록 블록이 편집기에서 커서 줄이 있는 높이에 오도록 스크롤되고, 편집기를 스크롤하면 맨 위에 보이는 블록을 따라갑니다. 편집하는 대로 갱신되고 편집기 스크롤을 따라갑니다. 경계선을 드래그해 너비를 조절합니다.
- Markdown 문서에서는 Ctrl+B 가 굵게이므로 폴더 트리는 Ctrl+Shift+B 로 여닫습니다.

## 9. 스펠링 체크 (영어)

- 내장 en_US 사전으로 검사하며 틀린 단어에 물결 밑줄이 생깁니다. 일반 텍스트·Markdown 은 전체를, 코드는 **주석과 문자열만** 검사합니다. 숫자·밑줄·`.`·`/`·`@` 가 섞인 토큰(URL, 식별자, 파일 이름), camelCase, 짧은 대문자 약어는 건너뜁니다.
- 틀린 단어를 오른쪽 클릭하면 제안 단어, **사전에 추가**(설정에 저장되어 계속 유지), **이번만 무시**가 나옵니다.
- 코드 파일(.c, .js …)에서 주석·문자열 밖의 단어까지 검사하려면 설정 › 편집기 › **코드 파일에서도 모든 단어 검사** 또는 보기 메뉴의 같은 항목을 켜세요(식별자가 많이 걸릴 수 있습니다).
- 켜고 끄기: 도구 모음의 ✓ 버튼, F7, 편집기 메뉴, 설정 › 일반 › 편집 보조.

## 10. 자동 들여쓰기

- 켜져 있으면 Enter 로 새 줄을 만들 때 이전 줄의 들여쓰기를 유지하고 닫는 괄호를 입력하면 자동으로 맞춥니다. 끄면 Enter 는 그냥 줄만 바꿉니다.
- 들여쓰기 문자(공백 삽입 / 탭 문자 삽입)와 탭 크기(탭 1개 = 공백 n자리)는 설정 › 편집기 또는 상태 표시줄의 `공백: 4` 버튼에서 바꿉니다. Tab 키는 이 설정대로 공백 또는 탭을 넣고, Shift+Tab 은 내어씁니다.
- 켜고 끄기: 도구 모음 버튼, 편집기 메뉴, 설정 › 일반 › 들여쓰기, 상태 표시줄 들여쓰기 메뉴.

## 11. 글꼴

- 도구 모음 오른쪽의 글꼴 칸을 클릭하면 **시스템에 설치된 모든 글꼴**이 스크롤되는 목록으로 나옵니다(처음 클릭할 때 읽어 오며, 각 항목은 그 글꼴로 그려집니다). 글자를 입력하면 목록이 걸러지고, ↑ ↓ Enter 로 고를 수 있습니다. 비우면 기본 고정폭 글꼴을 씁니다. 옆의 `−` `14` `+` 로 크기(px)를 바꿉니다(Ctrl+휠, Ctrl+= / − 와 같은 값).
- 설정 › 일반에도 같은 항목이 있습니다.

## 11. 문서 정렬 (코드 포매팅)

- 편집 › **문서 정렬**(Shift+Alt+F), 도구 모음의 정렬 버튼, 편집기 오른쪽 클릭 메뉴 — 편집 중인 문서 전체를 그 언어의 정렬 도구로 보기 좋게 정리합니다. 커서는 같은 줄에 유지되고, 실패하면 상태 표시줄에 이유가 나옵니다.
- **설정 › 정렬** 탭에서 언어마다 어떤 도구를 쓸지 고릅니다: "자동"(설치된 첫 도구) · 각 도구(설치 안 된 것은 표시됨) · "편집기 들여쓰기만"(편집기 문법 규칙으로 들여쓰기만 정리) · "사용 안 함". **저장할 때 자동 정렬** 도 켤 수 있습니다.
- 앱에 **Prettier 가 내장**되어 있어 JavaScript · TypeScript · JSX/TSX · JSON · HTML · CSS/SCSS/LESS · Markdown · YAML · Vue 는 아무것도 설치하지 않아도 정렬됩니다(파일 옆의 .prettierrc 를 따름, 탭 크기·탭/공백은 편집기 설정). JSON · XML 은 내장 정렬도 따로 있습니다.
- 그 밖의 언어는 설치되어 있으면 사용: Python — black · ruff format · autopep8 · yapf, C/C++/C#/Objective-C — clang-format, Java — google-java-format · clang-format, Go — gofmt · goimports, Rust — rustfmt, Shell — shfmt, PowerShell — PSScriptAnalyzer(Invoke-Formatter), SQL — sql-formatter, XML — xmllint, Ruby — rubocop · rufo, PHP — php-cs-fixer, Lua — stylua, Dart — dart format, Kotlin — ktlint, Swift — swiftformat. 도구는 프로젝트의 node_modules/.bin 을 먼저, 그다음 PATH(및 ~/.cargo/bin, ~/go/bin, Python 모듈)에서 찾습니다. 아무것도 없으면 들여쓰기만 정리합니다.
- **자동 설치**: 설정에서 "설치 안 됨 · 정렬할 때 자동 설치" 라고 표시된 도구를 고른 뒤 문서 정렬을 누르면 설치 여부를 묻고, 승낙하면 패키지 관리자로 내려받아 설치하는 과정을 **진행 팝업**(진행 막대 · 명령 · 실시간 출력, 취소 가능)으로 보여 준 뒤 바로 정렬합니다. npm 도구(Prettier · sql-formatter)는 앱의 설정 폴더 안(tools/node)에, Python 도구(black · ruff · autopep8 · yapf · clang-format)는 `pip install --user`(실행은 `python -m …`), stylua 는 cargo, shfmt · goimports 는 go, rubocop · rufo 는 gem, rustfmt 는 rustup, PSScriptAnalyzer 는 Install-Module 로 설치합니다. 설정 › 정렬의 각 언어 옆 버튼(⬇ 설치 / ↻ 다시 설치)으로 직접 설치할 수도 있으며, 이미 설치된 도구는 **"지우고 새로 설치" / "위에 덮어 설치" / 취소** 중에서 고릅니다. 해당 패키지 관리자가 없으면 무엇이 필요한지 알려 주고, "직접 설치 필요" 인 도구(gofmt · dart · ktlint · swiftformat · php-cs-fixer · google-java-format · xmllint)는 설치 방법을 안내합니다.

## 11a. 코드 검사 (Lint)

- 문서를 열거나 고치고 잠시 후(0.7초) 그 언어의 검사 도구가 **백그라운드**(별도 프로세스)에서 돌아 문제를 찾아 줍니다. 입력은 전혀 막히지 않고, 결과는 준비되는 대로 표시됩니다: 줄 번호 **오른쪽 거터의 점**(빨강 오류 · 노랑 경고 · 파랑 정보), 해당 위치의 물결 밑줄, 마우스를 올리면 메시지. F8 로 다음 문제로 이동, 보기 › 문제 목록(또는 상태 표시줄의 검사 항목 클릭)으로 목록 패널.
- 상태 표시줄에 `✕ 오류 수 ⚠ 경고 수`(문제 없으면 ✓, 도구가 없으면 —)가 보이고, 툴팁에 사용한 도구 이름이 나옵니다.
- 사용하는 도구(설치되어 있을 때만; 프로젝트의 node_modules/.bin 을 먼저, 그다음 PATH): JavaScript/JSX/TypeScript/TSX — **eslint**(없으면 JS 는 `node --check` 문법 검사) · Python — **ruff** → **pyflakes** → 문법 검사 · JSON — 내장 · YAML — yamllint · Shell — shellcheck · PowerShell — PSScriptAnalyzer · C/C++ — gcc/clang `-fsyntax-only -Wall` · Go — gofmt · PHP — `php -l` · Ruby — rubocop → `ruby -c` · Dockerfile — hadolint · Markdown — markdownlint · CSS/SCSS/LESS — stylelint · Java — javac. 저장하지 않은 내용을 그대로 검사하며(표준 입력), 파일 옆에 아무것도 만들지 않습니다.
- 켜고 끄기: 도구 모음의 벌레 버튼, 편집기 › 코드 검사, 설정 › 일반 › 편집 보조.

## 11b. 편집 창 나누기

- 도구 모음의 **창 나누기** 버튼(Ctrl+\)은 누를 때마다 창을 하나씩 늘립니다(최대 9개, 균형 잡힌 격자 배치). 창 머리의 × 는 그 문서를 닫으면서 창도 없애고(저장 안 한 변경은 먼저 물어봄), 남은 창들이 다시 배치됩니다. 창 사이의 경계선을 드래그하면 폭·높이가 바뀝니다(세션에 저장). 보기 › **편집 창 하나 / 좌우로 나누기 / 상하로 나누기 / 4개로 나누기**(Ctrl+Alt+1~4), 도구 모음의 나누기 버튼(Ctrl+\ 로 좌우 ↔ 하나). 새로 생긴 창에는 다른 창에 없는 문서가 자동으로 들어갑니다.
- 각 창은 문서 하나를 보여 주고(같은 문서는 한 창에만), 창 위 이름 ▾(빈 창은 "문서 고르기…")를 누르면 **열린 문서**와 **폴더 트리에 열린 폴더의 파일**(없으면 현재 문서의 폴더) 목록이 나와 그 창에 넣을 것을 고를 수 있고, 맨 아래 "열기…" 로 다른 파일도 열 수 있습니다. × 는 그 창의 문서를 닫습니다. **클릭한 창이 활성 창**이며 탭 바 · 찾기 · Markdown 미리보기 · 상태 표시줄이 그 창을 따릅니다. 탭을 누르면 활성 창에 그 문서가 보이고, 다른 창에 이미 있는 문서의 탭을 누르면 그 창이 활성 창이 됩니다. F6 은 다음 창.
- 하나로 되돌려도 문서와 편집 상태는 그대로이며, 나눈 상태와 각 창의 문서는 다음 실행 때 복원됩니다.

## 12. 터미널 (Ctrl+`)

- 보기 › 터미널, 도구 모음의 터미널 버튼, Ctrl+` 로 편집기 아래에 터미널 패널이 열립니다. `+` 로 터미널을 여러 개 열 수 있고 각각 **탭**으로 표시됩니다(▾ 로 셸 선택: Windows 는 명령 프롬프트 · PowerShell · Git Bash(설치된 경우), 그 외에는 기본 셸 · bash · sh). Ctrl+Shift+` 는 바로 새 터미널을 엽니다.
- 터미널은 설정 › 터미널의 **시작 디렉터리**(비우면 폴더 트리에 열린 폴더, 없으면 현재 문서의 폴더)에서, **기본 셸**로 시작합니다.
- 출력 맨 아래의 **프롬프트** 바로 뒤에서 명령을 입력하고 Enter — 입력한 줄이 프롬프트와 함께 그 자리에 남고 결과가 이어집니다. ↑ ↓ 로 기록, Ctrl+L / `clear` 로 지우기, Ctrl+C 로 중단. 명령이 실행 중일 때는 프롬프트가 사라지고, 그때 입력한 줄은 실행 중인 프로그램의 입력으로 전달됩니다.
- **Tab 자동완성**: 첫 단어는 셸 내장 명령과 PATH 의 실행 파일에서, 그 외 단어는 경로(`..`, `~`, 절대 경로, 따옴표 포함)에서 완성합니다. 후보가 하나면 바로 채우고(파일·명령 뒤에는 공백, 디렉터리 뒤에는 구분자), 여럿이면 공통 부분까지 채운 뒤 한 번 더 Tab 하면 후보 목록을 보여줍니다.
- 프롬프트는 **프롬프트 테마**로 그립니다(설정 › 터미널 › 프롬프트, 터미널 헤더의 ⚙ 로도 열림): 프리셋 20종 카드에서 고르거나, 간단 설정(표시할 세그먼트 · 파워라인/일반/다이아몬드 모양 · 경로 스타일 · 두 줄)과 고급 편집(세그먼트별 종류·색·템플릿, 블록 추가)으로 다듬고, **현재 프롬프트를 저장**하면 ★ 카드(사용자 정의 프롬프트)로 남습니다. 세그먼트: 경로 · git · 사용자@호스트 · 셸 · OS · 시각 · 종료 코드 · 실행 시간 · 텍스트. 어떤 프리셋이든 브랜치(git) 블록만 저장소 상태 색으로 칠해지고 나머지는 테마 색 그대로입니다 — 기본: **초록** 정상(푸시됨) → **빨강** 수정됨 → **노랑** add 됨 → **주황** 커밋됨(푸시 필요) → 푸시하면 다시 초록; 진홍 충돌 · 파랑 pull 필요. 간단 설정의 **git 상태색** 줄에서 상태마다 색을 직접 고르고(기본색 버튼으로 되돌림), 체크를 끄면 프리셋 고유의 색을 씁니다. 기본 프리셋은 📁 현재 디렉터리 ▶ (Git 저장소 안이면) ⎇ 브랜치와 상태 ▶ 그리고 바로 뒤에 입력. Git 블록은 "main"부터 통째로 저장소 상태 색으로 칠해집니다(해당하는 첫 번째 것): **빨강** 충돌 · **노랑** add(스테이지)된 변경 · **빨강** 수정된 파일 있음 · **노랑** 커밋했지만 푸시 안 함 · **파랑** 원격보다 뒤짐 · **밝은 초록** 모두 커밋·푸시되어 정상(추적하지 않는 새 파일과 서브모듈 안의 변경은 색에 영향을 주지 않고 새 파일은  기호로만 표시). 브랜치 이름 뒤에는 해당하는 상태 기호만 숫자 없이 붙습니다: `↑` 앞섬 `↓` 뒤짐 `+` 스테이지 `~` 수정 `?` 추적 안 함 `!` 충돌(마우스를 올리면 개수). Git 상태는 명령이 끝날 때마다 다시 읽습니다. 처음 들어간 디렉터리에서는 상태를 읽은 뒤 프롬프트를 그리고, 그다음부터는 직전 상태로 프롬프트를 바로 그린 뒤 새 상태가 다르면 색을 바꿉니다 — 큰 저장소에서는 `git status` 가 수백 ms 걸리기 때문입니다. 더 빠르게 하려면 저장소에서 `git config core.fsmonitor true`, `git config core.untrackedCache true` 를 켜 두세요.
- 출력은 색으로 표시됩니다(설정 › 터미널 › **출력을 색으로 표시**, 기본 켜짐): 프로그램이 내는 ANSI 색 그대로에 더해 error/failed 로 시작하는 줄은 빨강, warning 은 노랑, ok/done 은 초록, URL 과 파일:줄 참조도 강조합니다. `dir` · `ls -l` · `Get-ChildItem` 같은 목록은 폴더(파랑) · 링크 · 실행 파일(초록) · 압축(빨강) · 이미지(보라) · 문서(노랑) · 코드(하늘) 로 이름을 칠하고 날짜·크기 열은 흐리게 보입니다. 셸은 파이프로 연결되어 프로그램이 스스로는 색을 내지 않으므로, 색 옵션이 있는 프로그램에는 켜 달라고 알려 줍니다(git · npm · pytest · cargo · gcc/cmake · .NET 등의 환경 변수, Git Bash/posix 셸에서는 `ls` · `grep` · `diff` · `tree` 에 `--color=always` 별칭). 끄면 흑백입니다.
- 터미널의 셸은 항상 UTF-8 로케일로 시작합니다(LANG 이 `ko_KR` 처럼 문자 집합 없이 설정되어 있으면 Git Bash 의 `ls` 가 한글 파일 이름을 EUC-KR 로 써서 깨져 보였습니다). Git Bash 의 `dir` 은 한글을 8진수 이스케이프로 바꾸는 대신 `ls -C` 처럼 보여 줍니다. Command Prompt/PowerShell 에서 UTF-8 로 쓰는 프로그램(node, Cygwin/MSYS 의 `ls` 등)의 출력도 코드 페이지(CP949) 출력과 섞여 있어도 올바르게 읽습니다.
- `ls -al` 의 세 번째·네 번째 열(예: `shkwon 197121`)은 소유자와 **그룹**입니다. Windows 의 그룹은 이름이 없어 Git Bash/Cygwin 의 `ls` 가 숫자 ID(197121 = 로컬 사용자 그룹)를 그대로 보여 주는 것으로, 깨진 글자가 아닙니다. 그룹 열을 빼려면 `ls -alG` 를 쓰면 됩니다.
- 셸은 의사 터미널(PTY) 없이 파이프로 연결되므로 줄 단위로 동작합니다. 화면을 직접 그리는 프로그램(vim, top 등)은 맞지 않습니다. 명령이 실패하거나 문법이 틀려도 셸은 종료되지 않고 오류 메시지가 그대로 표시됩니다(명령은 작은 스크립트 파일로 실행되어, 실행 중인 프로그램이 읽는 입력에 다음 명령이 섞이지 않습니다). 진행 표시줄처럼 CR 로 같은 줄을 다시 그리는 출력은 터미널과 똑같이 그 줄을 덮어씁니다. 한글 등 다국어 입력·출력은 콘솔 코드 페이지(예: CP949)로 변환되어 정상 처리되고, 출력의 **ANSI 색**(git · npm · ls --color 등)도 그대로 표시됩니다(`FORCE_COLOR`, `color.ui=always` 설정).
- 경계선을 드래그해 높이를 조절합니다.

## 13. 보기 · 설정

- 데스크톱 앱의 메뉴 바 메뉴는 OS 의 네이티브 메뉴로 열리므로 항목이 많아도 창 밖까지 펼쳐집니다(웹 판은 페이지 안의 메뉴 — 창에 맞춰 여러 열로 표시). 메뉴 제목은 같은 폭의 칸에 놓여 간격이 일정합니다.
- 편집기 메뉴: 자동 들여쓰기, 자동 완성, 자동 줄 바꿈, 줄 번호, 미니맵, 공백 문자 표시, 현재 줄 강조, 코드 접기(모두 접기/펼치기), 스펠링 체크, 코드 검사, Markdown WYSIWYG · 미리보기 · 구조, HTML 미리보기. 보기 메뉴: 폴더 트리 / 도구 모음 / 상태 표시줄 표시, 편집 창 나누기, 터미널, 확대 / 축소 / 기본 크기(Ctrl+= / Ctrl+− / Ctrl+0, Ctrl+휠), 전체 화면(F11).
- 설정(Ctrl+,) — **일반**: UI 언어, 테마, 글꼴(고정폭 글꼴 이름 입력 또는 목록에서 선택), 글꼴 크기, 세션 복원, 닫을 때 확인. **편집기**: 자동 들여쓰기, 들여쓰기 문자(공백/탭), 탭 크기, 줄 바꿈 · 줄 번호 · 공백 표시 · 현재 줄 · 괄호 자동 닫기 · 짝 괄호 강조 · 코드 접기 · 스펠링 체크. **파일**: 새 문서 인코딩 · 줄 끝, **저장할 때 줄 끝**(파일의 원래 줄 끝 유지 / 항상 LF / 항상 CRLF), 저장할 때 줄 끝 공백 제거 · 마지막 줄 바꿈 추가, 외부 변경 자동 다시 읽기 — 화면(줄 높이 · 폴더 트리/도구 모음/상태 표시줄 표시) · 세션(**자동 저장**: 포커스를 잃을 때 / 마지막 편집 n초 뒤) · 파일(**새 문서 언어**) · 폴더 트리(숨김 파일) · 들여쓰기 · 표시 · 편집 보조 그룹이 테두리 상자로 나뉘어 한 탭(두 열)에 있고, 글꼴 크기·줄 높이·탭 크기는 − / + 버튼으로도 바꿉니다. **테마**: 어두운 테마 12 · 밝은 테마 8 카드(클릭 즉시 적용)와 사용자 정의 테마 만들기/편집/삭제. **터미널**: 새 터미널의 기본 셸, 시작 디렉터리, 프롬프트 테마(12장 참고). **정렬**: 언어별 정렬 도구. **검사**: 언어마다 어떤 코드 검사(Lint) 도구를 쓸지 — 자동(설치된 첫 도구) · 특정 도구(ESLint / node --check, ruff / pyflakes / python, gcc / clang, gofmt / go vet, RuboCop / ruby -c …) · 사용 안 함(비우면 폴더 트리에 열린 폴더).
- 모든 설정은 바꾸는 즉시 적용되고 저장됩니다.
- 설정 · 정보 · 단축키는 데스크톱에서 **별도의 창**으로 열립니다(크기 고정, 내용이 모두 보여 스크롤 없음): 화면 어디로든(메인 창 밖으로도) 옮길 수 있고, 메인 창 위에 떠 있으며, 메인 창을 최소화하거나 닫으면 함께 최소화·닫힙니다. 설정 창에서 바꾼 값은 즉시 메인 창(테마·언어 포함)에 적용되고, 메인 창에서 바꾼 테마·언어도 설정 창에 반영됩니다. 웹 판에서는 페이지 안의 옮길 수 있는 창으로 열립니다. 저장/닫기 확인처럼 답이 필요한 창은 뒤를 흐리게 하고 답을 기다립니다.

## 14. 웹 버전

```bash
npm run web                       # http://127.0.0.1:5190
node server/server.js --host 0.0.0.0 --port 8080 --token 비밀값
```

- 브라우저에서 같은 화면을 씁니다. 파일은 **서버가 실행되는 컴퓨터**의 것이며, 열기 / 저장 / 폴더 선택 대화상자는 앱 안에서 그립니다(드라이브 목록, 상위 폴더, 경로 직접 입력, 숨김 파일).
- 브라우저에서 끌어다 놓은 파일은 내용을 읽어 새 문서로 엽니다(저장하려면 위치를 고릅니다).
- 창 버튼 · 탐색기에서 보기 · 기본 앱으로 열기는 웹 버전에 없습니다.
- 다른 컴퓨터에서 접속을 허용할 때는 반드시 `--token` 을 쓰세요. 주소 뒤에 `?token=…` 을 붙이면 브라우저가 기억합니다.

## 15. 데이터 파일과 문제 해결

- 세션·설정: `session.json` (위치는 README 의 표 참고). 지우면 기본값으로 시작합니다.
- 오류 대화상자의 **자세히 복사**로 코드 · 경로 · 스택을 클립보드에 담아 문의할 수 있습니다.
- 시작이 안 되고 `Cannot find module 'electron'` 류의 메시지가 나오면 시스템 환경 변수 `ELECTRON_RUN_AS_NODE` 를 지우세요(`npm start` 는 자동으로 제거합니다).
- `npm start` 가 포트 5189 때문에 실패하면 이전 실행이 남아 있는 것입니다 — `npm run free:port` 가 먼저 실행되지만, 그래도 안 되면 작업 관리자에서 electron 을 종료하세요.
