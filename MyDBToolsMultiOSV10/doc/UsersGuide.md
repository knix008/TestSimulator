# DBTools 사용자 설명서

DBTools는 ER 다이어그램 및 데이터베이스 스키마 설계 프로그램입니다.
**웹 브라우저, Windows, macOS, Linux** 에서 동일하게 동작합니다. 데스크톱 판은
**Tauri** 셸(Rust + 운영체제 웹뷰)로 실행됩니다.

> 처음이라면 [튜토리얼](Tutorial.md)을 먼저 따라 해 보세요. 예제를 열어 테이블과 관계를
> 만들고, 분석하고, 인쇄하고, 테마를 바꾸는 과정을 차례대로 안내합니다.

## 1. 시작하기

### 웹에서 사용

`npm run build:web` 으로 만든 `dist/` 폴더를 정적 호스팅하거나,
개발 중에는 `npm run web` 후 <http://127.0.0.1:5174> 에 접속합니다.
설치가 필요 없고 파일은 브라우저의 파일 선택 대화상자로 열고 저장합니다.

### 데스크톱에서 사용

- **설치본**: 시작 메뉴·바탕 화면의 **DBTools** 실행. `.mdprj` 파일을 더블클릭해도 열립니다.
  이미 실행 중이면 새 창 대신 실행 중인 창이 앞으로 나오고 그 파일이 새 탭으로 열립니다.
- **개발 실행**: `npm start` — Vite 개발 서버(기본 5174, 사용 중이면 다음 빈 포트)를 띄운 뒤
  `tauri dev` 로 창을 엽니다. Rust(`cargo`)가 설치되어 있어야 합니다.

창은 **제목 표시줄을 프로그램이 직접 그리는** 테두리 없는 창입니다. 제목 표시줄을 끌어
옮기고, 두 번 클릭해 최대화하며, 오른쪽 끝의 최소화·최대화·닫기 단추를 씁니다.
창 위치와 크기는 다음 실행 때 그대로 복원됩니다.

### 설치 파일 만들기

```bash
npm run build:win      # Windows — DBTools_1.0.1_x64-setup.exe (NSIS)
npm run build:mac      # macOS   — DBTools_1.0.1_*.dmg
npm run build:linux    # Linux   — DBTools_1.0.1_amd64.deb, .AppImage
```

각 명령은 해당 운영체제에서 실행합니다. 빌드가 끝나면 이번 버전의 설치 파일이
**프로젝트 루트에 복사**되고, 루트에 있던 이전 버전 설치 파일은 지워집니다
(원본은 `src-tauri/target/release/bundle/` 에 남습니다).

### 새 프로젝트

**파일 → 새로 만들기** (Ctrl+N). 빈 스키마가 열리며, 기본 대상 DB는 설정에서 정한 값
(초기값 SQLite)입니다.

## 2. 화면 구성

```
┌──────────────────────────────────────────────────────────────────────┐
│  제목 표시줄 (아이콘 · DBTools v1.0.1 · 문서 이름 · ─ □ ✕)               │
├──────────────────────────────────────────────────────────────────────┤
│  메뉴 막대 (홈 | 파일 | 편집 | 보기 | 분석 | 도움말 …… 테마 ▾ 🏳 ⚙ ⓘ)   │
├──────────────────────────────────────────────────────────────────────┤
│  도구 모음                                                            │
├──────────────────────────────────────────────────────────────────────┤
│  문서 탭                                                         < >  │
├──────────┬───────────────────────────────────────┬───────────────────┤
│ 도구     │         ER 다이어그램 캔버스           │ 스키마 패널     › │
│          │         (눈금자 · 테이블 · 관계선)     │ 구조 / 정규화 /   │
│          │                                       │ 인덱스 어드바이저 │
│          ├───────────────────────────────────────┤───────────────────│
│          │ 출력 (문제점 · 로그 · 정보)          ˅ │ 속성              │
├──────────┴───────────────────────────────────────┴───────────────────┤
│  상태 표시줄                                                          │
└──────────────────────────────────────────────────────────────────────┘
```

**제목 표시줄** — 프로그램 이름과 버전(`DBTools v1.0.1`), 현재 문서 이름이 표시됩니다.
저장하지 않은 변경이 있으면 문서 이름 뒤에 `●` 가 붙습니다. 운영체제 작업 표시줄에는
`문서 이름 — DBTools v1.0.1` 형식으로 나옵니다.

**메뉴 막대** — 맨 앞의 **홈** 단추는 [시작 화면](#10-시작-화면과-예제)을 열고 닫습니다.
오른쪽 끝에는 **테마 드롭다운 · 언어 전환 · 설정 · 프로그램 정보** 가 있습니다.

**도구 모음** — 파일·실행 취소·내보내기·테이블/관계·확대/축소·격자·자동 배치·분석·
보고서·대상 DB·예제 단추가 한 줄로 놓이고, 오른쪽 끝에 **하단 · 오른쪽 패널 접기/펼치기**
단추 두 개가 있습니다(펼쳐진 패널의 단추가 강조됩니다). 인쇄 단추는 **다른 이름으로 저장** 바로 오른쪽에 있습니다.
도구 모음은 잘리지 않도록 창의 최소 너비가 자동으로 맞춰집니다.

아이콘은 뜻에 따라 색이 다릅니다(열기는 주황, 저장은 파랑, 삭제는 빨강, 새로 만들기는 초록 등).
다크 테마에서는 같은 색의 밝은 쪽이 쓰입니다.

### 패널 접기 · 크기 조절

오른쪽 **스키마 패널**과 캔버스 아래 **출력** 패널은 같은 방식으로 다룹니다. 왼쪽 **도구** 패널은
접지 않는 좁은 고정 패널입니다.

- 패널 제목 막대 왼쪽에 아이콘과 제목, **오른쪽 끝에 접기/펼치기 단추**가 있습니다.
- 접으면 패널이 얇은 막대로 줄어들되 **아이콘과 제목은 그대로 보입니다**(좌우 패널은 세로 글씨).
  막대를 누르면 다시 펼쳐집니다.
- 패널과 캔버스 사이의 **구분자**를 끌어 크기를 바꿉니다. 오른쪽 패널 너비는 설정에 저장되고,
  나머지 크기와 접힘 상태는 다음 실행 때 그대로 복원됩니다.
- 도구 모음 오른쪽 끝의 두 단추와 **보기** 메뉴로도 접고 펼칠 수 있습니다.
- 출력 패널은 **좌우 패널 사이, 캔버스 바로 아래**에 있습니다.

### 출력 패널 (하단)

| 탭 | 내용 |
|----|------|
| 문제점 | 정규화 검사 결과와 꼭 필요한 인덱스 제안. 항목을 누르면 해당 테이블로 이동합니다 |
| 로그 | 상태 표시줄에 나왔던 메시지와 오류를 시각과 함께 기록합니다(최신이 위). 오류 수가 탭에 표시됩니다 |
| 정보 | 스키마 이름 · 대상 DB · 파일 경로 · 테이블/컬럼/관계 수 · 열린 탭 수 · 테마 · 배율 · 버전 |

**복사** 는 지금 탭의 내용을 클립보드에 텍스트로 복사하고, 로그 탭의 **지우기** 는 기록을 비웁니다.

### 좌측 도구 패널

| 도구 | 설명 |
|------|------|
| 선택 | 테이블·관계 선택 및 이동 |
| 테이블 | 캔버스를 클릭해 새 테이블 배치 |
| 1:1 / 1:N / N:M | 관계 유형을 고른 뒤 테이블에서 테이블로 드래그 |
| 확대 / 축소 / 화면 맞춤 | 캔버스 뷰 조절 |

### 우측 패널

- **구조** — 스키마 트리(테이블·컬럼·관계). 상단 검색창으로 이름 필터
- **정규화** — 1NF~5NF 검사 결과. 검사할 수준을 칩 버튼으로 선택
- **인덱스 어드바이저** — 컬럼별 인덱스 제안과 `CREATE INDEX` 문
- **속성** — 선택 항목의 속성. 상단에서 **분류별** / **사전순** 정렬 전환

우측 패널은 제목 막대의 접기 단추, 도구 모음 버튼, **보기 → 오른쪽 패널 접기/펼치기** 로 접습니다.

## 3. 프로젝트 관리

### 프로젝트 파일 (.mdprj)

JSON 형식(UTF-8)이며 스키마 이름, 대상 DB, 테이블·컬럼·관계, 다이어그램 레이아웃을 담습니다.
**DBToolsWinV10이 만든 `.mdprj` 파일과 완전히 호환**되므로 양쪽에서 같은 파일을 열 수 있습니다.

| 동작 | 단축키 |
|------|--------|
| 프로젝트 열기 | Ctrl+O |
| 저장 | Ctrl+S |
| 다른 이름으로 저장 | Ctrl+Shift+S |

변경 사항이 있으면 제목 표시줄과 상태 표시줄에 `●` 표시가 나타나며,
새 프로젝트·다른 파일 열기·종료 시 저장 여부를 묻습니다.
실제로 내용이 바뀐 경우에만 확인 대화상자가 뜹니다.

### 최근 파일

**파일 → 최근 파일**. 데스크톱 앱 전용이며, 웹에서는 브라우저가 절대 경로에 접근할 수 없어
지원하지 않습니다. 보관 개수는 설정에서 바꿀 수 있습니다(기본 10개).

## 4. DB 파일 가져오기

**파일 → 데이터베이스 가져오기** (Ctrl+Shift+O)

| 형식 | 확장자 | 비고 |
|------|--------|------|
| SQLite | `.db`, `.sqlite`, `.sqlite3`, `.db3` | 테이블·컬럼·PK·UNIQUE·외래 키를 읽습니다 |
| SQL DDL | `.sql` | `CREATE TABLE` / `ALTER TABLE ... FOREIGN KEY` 파싱 |
| Vector Index | `.faiss`, `.findex`, `.hnsw`, `.index` | Faiss · hnswlib 인덱스 메타데이터 |
| 프로젝트 | `.mdprj`, `.json` | DBTools 프로젝트 파일 |

가져온 스키마는 자동 배치되며, `.mdprj` 로 저장하기 전까지 프로젝트 파일과 연결되지 않습니다.

> **지원하지 않는 형식** — Access(`.mdb`/`.accdb`)와 SQL Server(`.mdf`)는 Windows 전용
> 네이티브 드라이버가 필요해 지원하지 않습니다. 해당 도구에서 `.sql` 로 스크립트를
> 내보낸 뒤 가져오세요. 암호화된 SQLite(SQLCipher)도 지원하지 않습니다.
> 이런 파일을 열면 원인과 대안을 설명하는 안내가 표시됩니다.

## 5. 스키마 편집

### 테이블 추가

| 방법 | 설명 |
|------|------|
| **편집 → 테이블 추가** (Ctrl+T) | 기존 테이블 오른쪽에 배치 |
| 좌측 **테이블** 도구 → 캔버스 클릭 | 클릭 위치에 배치 |
| 캔버스 빈 곳 우클릭 → **여기에 새 테이블 추가** | 클릭 위치에 배치 |

새 테이블에는 자동 증가 PK `id` 컬럼이 하나 만들어집니다.

### 컬럼 추가 / 편집

- 테이블 선택 후 **편집 → 컬럼 추가** (Ctrl+L)
- 테이블 더블클릭 → 테이블 편집 대화상자에서 **추가 / 편집 / 삭제 / 위·아래 이동**
- 캔버스에서 컬럼 행을 더블클릭하면 바로 해당 컬럼 편집
- 우측 **속성** 패널에서 직접 편집

컬럼 속성: 이름, 데이터 타입, 길이, 정밀도, 스케일, PK, 자동 증가, NULL 허용, UNIQUE,
외래 키, 기본값, 설명. 길이·정밀도 입력란은 선택한 타입에 해당할 때만 표시됩니다.

### 관계 추가

1. 좌측에서 **1:1**, **1:N**, **N:M** 중 하나를 선택합니다.
2. **부모 테이블에서 자식 테이블로** 드래그합니다.

부모의 기본 키와, 자식에서 `<부모이름>_id` 형태로 추정되는 컬럼이 자동 연결됩니다.
정확한 컬럼을 지정하려면 **편집 → 관계 추가** (Ctrl+R) 또는 관계선 더블클릭으로
대화상자를 사용하세요.

> 관계에서 **소스**는 참조되는 쪽(부모, PK), **타겟**은 외래 키를 가진 쪽(자식)입니다.
> 캔버스의 `FK` 배지는 자식 컬럼에 표시되고, 생성되는 DDL도 자식 테이블에
> `ALTER TABLE <자식> ADD CONSTRAINT ... REFERENCES <부모>` 형태로 만들어집니다.

### 관계선 스타일

**직선**, **곡선(Bezier)**, **꺾은선(직교)** 을 지원합니다.

| 방법 | 설명 |
|------|------|
| 도구 모음 **선 스타일** 드롭다운 | 선택한 관계(그리고 이후 새 관계)의 스타일 변경 |
| 관계선 우클릭 → **선 스타일** | 해당 관계만 변경 |
| 관계선 더블클릭 | 관계 편집 대화상자 |

- **곡선**: 관계를 선택하면 파란색·초록색 마름모 제어점이 나타나며 드래그로 곡률을 조절합니다.
- **꺾은선**: 노란색 사각형 핸들(구간 중점)을 드래그해 경로를 옮깁니다.
  우클릭 메뉴의 **꺾임 점 추가** / **경로 초기화** 를 사용할 수 있고,
  테이블을 옮기는 동안 경로가 실시간으로 다시 계산됩니다.
  꺾임 점(모서리)을 끌면 이웃한 꺾임 점이 함께 따라와 모든 꺾임이 직각으로 유지되고,
  양 끝이 거의 같은 높이면 작은 계단 없이 곧은 선으로 이어집니다.

#### 마우스 포인터

| 포인터 | 위치 | 끌면 |
|--------|------|------|
| 네 방향 화살표 | 테이블 위 | 테이블(여러 개 선택 시 함께) 이동 |
| 위아래 화살표 | 꺾은선의 가로 구간 핸들 | 구간을 위아래로 이동 |
| 좌우 화살표 | 꺾은선의 세로 구간 핸들 | 구간을 좌우로 이동 |
| 십자 | 꺾임 점 · 곡선 제어점 | 그 점을 정확한 위치로 이동 |
| 손가락 | 선택하지 않은 관계선 | (클릭하면 선택) |

#### 선 교차 브리지

관계선끼리 교차하는 곳에서는 한 선이 작은 반원으로 **건너뛰어**, 교차가 연결로 보이지 않게 합니다.
두 선 중 더 수평에 가까운 선이 건너뛰고(기울기가 같으면 나중에 그린 선), 꺾이는 모서리나 테이블 끝 바로
옆의 교차는 건너뛰지 않습니다. 도구 모음의 **브리지** 단추나 **보기 → 선 교차 브리지** 로 켜고 끄며(기본 켜짐),
화면·이미지 내보내기·인쇄에 똑같이 적용됩니다.

### 여러 스키마를 탭으로

여러 개의 스키마를 동시에 열어 둘 수 있습니다. 도구 모음 아래의 **탭 줄**에 열린 스키마가
모두 표시되며, 하나만 열려 있어도 늘 보입니다 — 새 탭을 만드는 **+** 버튼이 여기 있고,
줄이 나타났다 사라지면 화면이 튀기 때문입니다.

- **새로 만들기**(Ctrl+N)와 **열기**·**데이터베이스 가져오기**는 모두 **새 탭**에서 열립니다
  — 이미 열어 둔 작업은 건드리지 않습니다
- 마지막 탭 바로 옆에 **새 탭 +** 가 따라다닙니다. 누르면 새 스키마가 탭으로 열리고,
  **새 탭 +** 는 다시 그 옆으로 옮겨갑니다
- 탭이 한 줄에 다 들어가지 않으면 탭 줄 **양 끝의 ‹ ›** 로 좌우로 넘길 수 있습니다.
  화살표 옆 숫자는 그쪽에 가려진 탭이 몇 개인지 알려 줍니다
- 탭을 클릭하면 그 스키마로 전환됩니다. **선택·화면 배율·되돌리기 이력까지 탭마다 따로**
  보관되므로, 돌아오면 하던 그대로입니다
- 저장하지 않은 탭에는 **●** 표시가 붙습니다
- 탭의 **×** 또는 가운데 클릭으로 닫습니다. 저장하지 않은 변경이 있으면 먼저 묻습니다
- 마지막 탭을 닫으면 창이 닫히는 대신 빈 스키마로 비워집니다

아무것도 손대지 않은 빈 탭에서 파일을 열면 **그 탭을 그대로 씁니다** — 빈 탭이 쌓이지
않습니다.

### 작업 공간 저장 · 열기

**파일 → 작업 공간 저장** 은 그때 열려 있던 **모든 탭**을 `.mdwsp` 파일 하나에 담습니다.
각 탭의 스키마, 그 탭이 어느 파일에서 왔는지, 어떤 탭이 앞에 있었는지가 함께 기록되므로
**파일 → 작업 공간 열기** 로 그 상태를 그대로 되살릴 수 있습니다.

기존 프로젝트 파일(`.mdprj`)은 **스키마 하나**를 담는 형식 그대로입니다 — DBToolsWinV10과
주고받는 형식이라 건드리지 않았고, 작업 공간은 그 옆에 더해진 별도 형식입니다.

### 내보내기·보고서의 대상 탭 고르기

탭을 여러 개 열어 둔 상태에서 내보내기·보고서 작성·이미지 내보내기를 실행하면 **어느
스키마를 대상으로 할지 묻는 창**이 먼저 뜹니다. 현재 탭이 미리 선택되어 있으니 그대로
확인만 누르면 됩니다.

- **여러 개를 고를 수 있습니다** — `전체 선택` / `전체 해제` 버튼도 있습니다
- 하나만 고르면 저장 위치를 물어보고 파일 하나를 만듭니다
- 여러 개를 고르면 **폴더를 한 번만 물어보고** 그 안에 전부 저장합니다. 이름이 겹치면
  뒤에 `_2`, `_3` 이 붙습니다
- 탭이 하나뿐이면 묻지 않고 바로 진행합니다

> PDF는 웹뷰(WebView2)의 인쇄 기능으로 만들어져 파일마다 저장 위치를 따로 물어봅니다. 여러
> 스키마를 고르면 그만큼 저장 대화상자가 차례로 뜹니다.

### 여러 테이블 선택

**Ctrl** 또는 **Shift** 를 누른 채 테이블을 클릭하면 선택에 더해지고, 이미 선택된
테이블을 같은 방법으로 다시 누르면 빠집니다. 같은 수식어를 누른 채 **빈 캔버스에서
끌면 사각형 영역**이 그려지고, 놓았을 때 그 안에 걸친 테이블이 모두 선택에 더해집니다
(수식어 없이 끌면 화면 이동입니다). 선택된 테이블은 모두 강조 테두리로
표시됩니다.

- 선택된 테이블 중 하나를 그냥 끌면 **선택한 테이블이 함께 이동**합니다
- **Delete** 키나 컨텍스트 메뉴의 삭제를 쓰면 선택한 테이블이 한 번에 지워집니다
- 속성 패널은 마지막으로 누른 테이블을 따라갑니다

수식어 없이 빈 캔버스를 클릭하면 선택이 모두 풀립니다.

### 자동 정렬

도구 모음의 **자동 정렬** 버튼은 테이블을 **관계에 따라 층으로** 배치합니다. 참조되는
테이블이 왼쪽, 외래 키를 가진 테이블이 그 오른쪽에 놓이므로 관계선이 왼→우로
흘러가며, 같은 층 안에서는 연결된 테이블끼리 가깝게 모여 선이 서로 엉키지
않습니다. 서로 관계가 없는 테이블 묶음은 **가로로도 나란히** 놓입니다. 한 줄에 몇 개를 둘지는
테이블(묶음) 개수에서 정해지므로, 외래 키가 선언되지 않은 데이터베이스를 열어도
한 줄로 길게 늘어서지 않고 네모진 블록으로 배치됩니다 — 예를 들어 관계 없는 테이블
12개는 4열 × 3행이 됩니다.

정렬이 끝나면 배율이 **100%로 맞춰집니다** — 층 사이 간격이 실제 픽셀 단위로 계산되므로
1:1로 봐야 의도한 간격이 그대로 보이기 때문입니다. 다이어그램이 화면보다 크면 왼쪽 위
모서리부터 보여 줍니다.

층 사이 간격은 **관계선이 다른 테이블에 가려지지 않을 만큼만** 벌어집니다. 컬럼이
짧으면 빽빽하게 붙고, 한 테이블에 자식 테이블이 많아 층이 길어지면 선이 가려지지
않을 만큼만 더 벌려 줍니다. **DB 파일을 열어 ERD를 만들 때도 같은 배치**가 쓰입니다.

### 캔버스 조작

캔버스 컨텍스트 메뉴는 **실행 취소 / 다시 실행**으로 시작합니다 — 실수한 직후에 가장
먼저 찾게 되는 항목이기 때문입니다(도구 모음와 **편집** 메뉴에도 있습니다).

캔버스에서 **마우스 오른쪽 버튼**을 누르면 누른 자리에 따라 메뉴가 달라집니다
(테이블 본문 / 컴럼 행 / 관계선 / 빈 곳). 어느 자리에서 누르든
메뉴 맨 아래에는 **다이어그램 내보내기**(PNG · JPEG · WebP · GIF)와
**분석 보고서 작성**(Markdown · Word · PDF · HTML)이 항상 들어 있습니다 —
둘 다 스키마 전체를 다루는 기능이라 무엇을 눌렀는지와 무관하기 때문입니다.

| 동작 | 방법 |
|------|------|
| 테이블 이동 | 선택 도구로 드래그 |
| 캔버스 이동(팬) | 빈 영역 드래그, 가운데 버튼 드래그, 또는 Space+드래그 |
| 확대/축소 | 마우스 휠(커서 위치 기준, **한 칸에 5%씩**), 줌 버튼, Ctrl + `+`/`-` |
| 가로 스크롤 | Shift+휠 |
| 전체 맞춤 | Ctrl+0 |
| 배율 100% 복원 | 도구 모음의 배율(%) 버튼 클릭 |
| 선택 도구로 복귀 | Esc |

**보기 → 자동 배치** 로 모든 테이블을 격자로 다시 배열하고,
**테이블 너비 맞춤** 으로 컬럼 내용에 맞게 폭을 조정할 수 있습니다.
**격자 표시** 와 **격자에 맞추기** 는 보기 메뉴 또는 설정에서 켤 수 있습니다.

### 삭제 / 실행 취소

- **편집 → 선택 항목 삭제** (Delete). 테이블·컬럼 삭제 시 확인을 거치며,
  관련된 관계도 함께 정리됩니다.
- **실행 취소 / 다시 실행** (Ctrl+Z / Ctrl+Y) — 최대 50단계

## 6. 대상 데이터베이스 종류

도구 모음 오른쪽의 DB 드롭다운 또는 **보기 → DB 종류** 에서 선택합니다.

| DB | 용도 |
|----|------|
| SQLite | 기본값 |
| PostgreSQL | `SERIAL`, `TIMESTAMPTZ`, `COMMENT ON` 등 |
| MySQL / MariaDB | `AUTO_INCREMENT`, `ENGINE=InnoDB`, 인라인 `COMMENT` |
| SQL Server | `IDENTITY(1,1)`, `[대괄호]` 인용 |
| FAISS (Vector DB) | 벡터 DB 스키마 설계 및 `VECTOR` 타입 |

대상 DB를 바꾸면 컬럼 타입 후보 목록, 테이블 헤더 색, SQL 내보내기 결과가 함께 바뀝니다.

> 대상 DB를 바꿔도 **이미 입력된 컬럼 타입과 기본값은 그대로 유지됩니다**(원본과 동일).
> 예를 들어 PostgreSQL 스키마를 MySQL로 바꾸면 `BIGSERIAL` 이 그대로 남습니다.
> 필요하면 컬럼 타입을 직접 수정하세요.

## 7. 내보내기

**파일 → 내보내기** 또는 도구 모음 **내보내기** 드롭다운.

### 설계 보고서

스키마 전체를 문서로 내보냅니다. 네 가지 문서 형식 모두 같은 내용이며, 기본적으로
**표지(커버 페이지)** 로 시작합니다.

| 항목 | 형식 | 내용 | 표지 |
|------|------|------|------|
| Markdown... | `.md` | 스키마 개요, 테이블별 컬럼 표, 관계 목록, 정규화 결과 | 제목 블록 + 구분선 |
| Word... | `.docx` | 위와 같은 내용의 Word 문서 | 표지 다음 페이지 나눔 |
| PDF... | `.pdf` | ERD 이미지를 포함한 보고서 | 표지 전용 페이지 |
| HTML... | `.html` | PDF와 같은 문서를 단독 실행 가능한 HTML 파일로 | 표지 전용 페이지 |
| Excel... | `.xlsx` | 요약 · ERD · 테이블 · 관계 · 정규화 시트 | **표지** 시트가 맨 앞 |

### 분석 보고서

정규화 검사 결과와 인덱스 권장 사항을 담은 별도 문서입니다. **Markdown · Word · PDF ·
HTML** 네 형식으로 만들 수 있고, 파일 이름에 `_analysis` 가 붙어 설계 보고서를 덮어쓰지
않습니다.

| 절 | 내용 |
|----|------|
| 요약 | 검사 수준별 판정 한 줄, 오류·경고·정보·인덱스 권장 건수 |
| ERD 다이어그램 | **캔버스에 그려진 그대로의 ERD** — 현재 테마 그대로, 화면 밖 테이블 포함. 배경은 투명하고 원본 비율을 유지합니다 |
| 정규화 수준별 결과 | 1NF~5NF 각각의 검사 여부·충족/위반·발견 건수 |
| 정규화 검사 결과 | 항목별 수준·심각도·테이블·문제 컬럼·내용·권장 |
| 인덱스 권장 사항 | 필수 / 권장 / 검토 / 이미 인덱스 구분과 근거 |

검사 대상 정규형은 **설정 → 정규화** 에서 고른 것을 그대로 따르므로, 화면의 분석 패널과
문서의 내용이 항상 일치합니다.

**분석 → 분석 보고서 작성** 하위 메뉴, 도구 모음의 **보고서** 버튼(네 형식 목록이 열립니다),
또는 Ctrl+Shift+R(Markdown 바로 저장)로도 만들 수 있습니다.

> PDF는 웹뷰(Windows는 WebView2)의 인쇄 기능을 사용합니다. 데스크톱 앱에서는 저장 위치를 물은 뒤 바로
> PDF가 생성되고, 웹에서는 인쇄 대화상자가 열리므로 대상을 **"PDF로 저장"** 으로 선택하세요.

### 이미지 (ER 다이어그램)

테이블과 관계선만 렌더링하며 눈금자·격자는 포함되지 않습니다. 2배 해상도로 저장됩니다.

| 항목 | 형식 | 투명 배경 |
|------|------|-----------|
| PNG... | `.png` | 지원 |
| WebP... | `.webp` | 지원 |
| GIF... | `.gif` | 지원 (1비트) |
| JPEG... | `.jpg` | **불가** — 형식에 알파 채널이 없습니다 |

배경은 **기본적으로 투명**하며, **설정 → 이미지 내보내기**의 `배경을 투명하게` 를 끄면
흰색(어두운 테마에서는 캔버스 색)으로 채워집니다. JPEG는 형식상 투명도를 담을 수 없어
설정과 무관하게 항상 채워집니다. GIF의 투명도는 1비트라 반투명이 없어 가장자리가
계단처럼 보일 수 있습니다.

관계 이름 라벨의 배경도 투명하게 나갑니다 — 글자 아래의 선을 지워 읽히게 하므로, 라벨
자리에 색칠된 사각형이 남지 않습니다.

관계선 경로까지 포함해 영역을 자동 계산하며, 매우 큰 다이어그램은 메모리 보호를 위해
해상도가 자동으로 제한될 수 있습니다.

### 데이터 · SQL

| 항목 | 형식 | 설명 |
|------|------|------|
| JSON 내보내기... | `.json` | 스키마 전체 (`.mdprj` 와 동일 구조) |
| SQL DDL 내보내기... | `.sql` | 현재 대상 DB용 `CREATE TABLE` DDL |
| SQLite DB (.db)... | `.db` | 실제 SQLite 데이터베이스 파일 |
| PostgreSQL / MySQL / MariaDB / SQL Server SQL... | `.sql` | 해당 DB 형식으로 변환한 DDL |

> 웹에서는 브라우저가 File System Access API를 지원하면 저장 위치를 고를 수 있고,
> 지원하지 않으면 다운로드 폴더에 저장됩니다.

### 인쇄 (별도 창)

**파일 → 인쇄…** (Ctrl+P) 또는 도구 모음의 프린터 단추를 누르면 **인쇄 창이 따로** 열립니다.
메인 창은 그대로 쓸 수 있고, 인쇄 창은 크기를 바꾸거나 최대화할 수 있습니다.

| 도구 | 설명 |
|------|------|
| 다이어그램 / 스키마 보고서 / 분석 보고서 | 무엇을 인쇄할지 고릅니다. 미리 보기가 바로 바뀝니다 |
| 세로 / 가로 | A4 용지 방향. 다이어그램은 가로, 보고서는 세로가 기본입니다 |
| 색 (다이어그램) | **흰 종이**(라이트 색) 또는 **현재 테마 색** |
| 프린터 · 매수 | Windows 데스크톱 판에서 표시됩니다. 고른 프린터로 대화 상자 없이 바로 인쇄합니다 |
| PDF로 저장 | 저장 위치를 물은 뒤 미리 보기와 같은 내용을 PDF로 저장합니다 |
| 인쇄 | 인쇄합니다. 창 안에서 Ctrl+P 를 눌러도 됩니다 |

다이어그램은 한 쪽에 맞게 축소되고, 위쪽에 스키마 이름·대상 DB·테이블/관계 수·인쇄 시각이
한 줄로 찍힙니다. 보고서는 [보고서 설정](#보고서-설정)의 표지·글꼴·머리말·꼬리말을 그대로 따릅니다.

> "Microsoft Print to PDF" 처럼 파일로만 출력하는 프린터를 고르면, 그 드라이버의 저장 창 대신
> 프로그램의 저장 대화 상자가 열려 PDF로 저장합니다.
> 웹 브라우저와 macOS·Linux 판에서는 **인쇄** 가 시스템 인쇄 대화 상자를 엽니다.

## 8. 정규화 분석

우측 **정규화** 탭 또는 **분석 → 정규화 분석 실행** (F5).

검사 수준을 칩 버튼(**1NF · 2NF · 3NF · BCNF · 4NF · 5NF**)으로 개별 선택합니다.
선택은 설정에 저장되며, 스키마를 수정하면 결과가 자동으로 갱신됩니다.

| 수준 | 검사 내용 |
|------|-----------|
| 1NF | 기본 키 없음(오류), 반복 그룹 컬럼(`phone1`, `phone2` …), 원자적이지 않은 타입(JSON/ARRAY) |
| 2NF | 복합 기본 키 — 부분 종속 가능성 |
| 3NF | 비키 속성 간 이행 종속 (`dept_id` → `dept_name`) |
| BCNF | 비슈퍼키 결정자 가능성 |
| 4NF | 독립적인 다중값 속성, 조인 테이블의 관계 외 속성 |
| 5NF | 3개 이상 엔티티를 잇는 복합 키, 조인 종속 가능성 |

결과 항목을 클릭하면 해당 테이블이 선택되고 캔버스가 그 위치로 이동하며,
문제가 된 컬럼이 노란색으로 강조됩니다.
심각도는 **오류(빨강) · 경고(노랑) · 정보(보라)** 로 구분됩니다.

## 9. 인덱스 어드바이저

우측 **인덱스 어드바이저** 탭.

| 구분 | 의미 |
|------|------|
| **이미 인덱싱됨** | PK 또는 UNIQUE — 별도 인덱스 불필요 |
| **필수** | 외래 키 컬럼. JOIN·참조 무결성 검사에 사용되므로 인덱스 권장 |

**필수**·**권장** 항목에는 바로 쓸 수 있는 `CREATE INDEX` 문이 함께 표시됩니다.
항목을 클릭하면 해당 컬럼이 선택됩니다.

#### 카드 옮기기 · 크기 바꾸기

제목 카드를 뺀 나머지 카드는 자유롭게 배치할 수 있습니다.

- 카드 제목 왼쪽의 **⠿ 손잡이**를 끌면 반투명한 카드가 포인터를 따라오고, 다른 카드 위에 놓으면
  그 자리로 옮겨집니다.
- 카드 **오른쪽 아래 모서리**를 끌면 너비(1~3칸)와 높이가 바뀝니다. 모서리를 **두 번 클릭**하면
  원래 크기로 돌아갑니다.
- 제목 카드의 **카드 정렬** 은 모든 카드를 처음 위치와 크기로 되돌립니다.

#### 움직이는 배경

### 보고서 설정

설정에서 정한 값은 설계 보고서와 분석 보고서 **모든 형식에 동일하게** 적용됩니다.

**표지** — 끄면 문서가 본문부터 시작합니다. 제목과 부제를 비워 두면 각각 보고서 기본
제목과 스키마 이름이 쓰입니다. 소속과 작성자를 적으면 부제 아래에 `소속 · 작성자` 한 줄로
표시됩니다.

**글꼴** — 목록에는 **시스템에 설치된 글꼴이 모두** 나옵니다(처음 열 때 글꼴 목록 접근
권한을 한 번 묻습니다. 거부하면 기본 글꼴 목록만 표시되며, 설정 자체는 그대로 동작합니다).
고른 글꼴 뒤에는 항상 한글 대체 글꼴이 붙으므로, 한글을 지원하지 않는 글꼴을 골라도
본문이 깨지지 않습니다. 크기는 pt 단위(7~20)이며 **표지 제목과 각 제목 크기가 이 값에
비례해** 함께 커집니다. 표지 제목은 본문의 3.4배 크기에 굵게 표시됩니다.

**제목 번호 매기기** — `번호 없음` / `1. · 1.1` / `1) · 1.1)` / `I. · I.1` 중에서 고릅니다.
기본값은 번호 없음입니다.

**머리말 · 꼬리말** — 내용에 다음 치환어를 쓸 수 있습니다.

| 치환어 | 값 |
|--------|-----|
| `{schema}` | 스키마 이름 |
| `{db}` | 대상 데이터베이스 |
| `{title}` | 보고서 제목 (설계 / 분석) |
| `{date}` | 작성 일시 |
| `{path}` | 프로젝트 파일 경로 |

위치는 왼쪽 · 가운데 · 오른쪽 중에서 고르며, 머리말과 꼬리말을 따로 정할 수 있습니다.

**쪽 번호** — 머리말 또는 꼬리말에 넣을 수 있고, 정렬을 머리말·꼬리말 본문과 별도로
지정할 수 있습니다. 형식에는 `{page}`(현재 쪽)와 `{total}`(전체 쪽수)을 씁니다.

> 글꼴 설정은 HTML·PDF·Word·Excel에 적용됩니다. **Markdown은 서식을 담지 않는 형식**이라
> 글꼴이 적용되지 않고, 보는 프로그램이 글꼴을 정합니다.

> 형식별 한계: Markdown에는 쪽 개념이 없어 머리말과 꼬리말이 문서 맨 위와 맨 아래에 한 번씩만
> 나오고 쪽 번호는 표시되지 않습니다. HTML은 화면에서는 고정된 띠로 보이고 인쇄할 때 쪽마다
> 반복됩니다. **쪽 번호가 실제로 매겨지는 것은 PDF와 Word** 이며, Word에서는 문서를 편집해도
> 값이 다시 계산되는 진짜 필드로 들어갑니다. 데스크톱 판의 PDF는 머리말·꼬리말이나 쪽 번호를 켜 두면
> 웹뷰의 머리말(작성 일시·보고서 제목)과 꼬리말(`쪽/전체`)이 쪽마다 함께 찍힙니다.

- 메뉴 막대 오른쪽의 **테마 드롭다운** — 팔레트 아이콘과 현재 테마 이름이 적힌 단추를 누르면
  **라이트 20 | 다크 20** 이 두 열로, 그 아래 사용자 정의 테마가 펼쳐집니다. 맨 위 왼쪽의
  **테마 설정…** 은 테마 설정 창을, **다음 테마** 는 목록 순서대로 다음 테마를 적용합니다.
- **보기 → 테마** 하위 메뉴 (각 항목에 색상 칩 표시)
- **설정 → 모양** 의 테마 목록
- **테마 설정** 창 (아래)

테마는 UI뿐 아니라 **ER 다이어그램 캔버스**(캔버스 바탕·격자·테이블 배경·관계선·PK/FK 글자색)와
시작 화면·대화 상자·인쇄 창·사용자 설명서 창에도 함께 적용되며, 이미지로 내보낼 때도 반영됩니다.

#### 테마 설정 창

**보기 → 테마 → 테마 설정…**, 설정 창의 **테마 설정…** 단추, 시작 화면의 **테마 설정** 으로 엽니다.
고르는 즉시 메인 창에 적용되므로 창을 열어 둔 채 결과를 확인할 수 있습니다.

- **라이트 20 / 다크 20** — 각 칸에 그 테마의 캔버스·패널·강조색 미리 보기가 그려집니다.
- **캔버스 배경** — 다이어그램 뒤에 깔리는 무늬를 고릅니다. 모두 현재 테마의 캔버스 색으로 그려집니다.

  | 배경 | 모양 |
  |------|------|
  | 단색 | 캔버스 색 한 가지 |
  | 점 (기본) | 24px 간격의 점 |
  | 모눈 | 가는 격자선 |
  | 그라데이션 | 캔버스 색에서 행 색으로 비스듬히 |
  | 청사진 | 강조색을 섞은 그라데이션 위에 격자 |

  무늬는 다이어그램에 붙어 있어 화면을 끌거나 확대하면 함께 움직입니다. 보기 → 격자 표시의
  격자(스냅 간격)는 이 배경 위에 따로 그려집니다.
- **사용자 정의 테마** — 다섯 가지 색(창 배경 · 패널 · 캔버스 · 강조색 · 글자)과 종류(라이트/다크),
  이름만 정하면 나머지 40여 가지 색(테두리, 보조 글자, 행 줄무늬, 관계선, 눈금자 등)은 자동으로
  만들어집니다. 오른쪽 미리 보기에 창·캔버스·테이블 모양이 바로 나타납니다.
  - **현재 테마에서 시작** — 지금 화면의 색을 출발점으로 가져옵니다.
  - **테마로 저장** — 목록에 추가하고 바로 적용합니다. 목록의 테마를 누르면 다시 편집할 수 있고,
    **변경 저장** 으로 덮어씁니다. 휴지통 단추로 지웁니다(쓰고 있던 테마를 지우면 라이트로 돌아갑니다).
  - 사용자 정의 테마는 설정 파일(`settings.json`)에 함께 저장됩니다.

### 대화상자는 별도의 창입니다

테이블 편집·컬럼 편집·관계 편집·설정·정보 등 모든 대화상자는 **독립된 창**으로 열립니다.

- 테두리 없는 창으로, 제목 막대(아이콘·제목·빨간 ✕ 닫기 단추)를 끌어 옮깁니다
- 대화 상자가 열려 있는 동안 메인 창은 입력을 받지 않습니다(인쇄 창은 예외)
- 창 크기는 내용에 맞게 자동으로 맞춰지므로 **스크롤바가 생기지 않습니다**
- **설정 창은 3단**으로 배치됩니다. 항목이 늘어도 세로로 길어지는 대신 가로로 넓어지므로
  스크롤 없이 한눈에 들어옵니다. 창을 좁히면 2단 → 1단으로 자동으로 접힙니다
- 메인 창과 같은 테마가 적용되며, 테마를 바꾸면 열려 있는 창도 함께 바뀝니다
- **Esc** 또는 창 닫기 버튼으로 닫습니다
- 메인 창 오른쪽 아래 모서리의 **크기 조절 마크**를 끌어 메인 창 크기를 바꿀 수 있습니다
  (브라우저 탭에서는 탭 크기를 바꿀 수 없어 마크가 숨겨집니다)
- 저장·내보내기·보고서 작성이 끝나면 **완료 창**이 열려 저장된 경로를 알려 줍니다
  (프로그램을 닫으면서 저장할 때는 뜨지 않습니다 — 곧 닫힐 창이라 깜빡이기만 하기 때문입니다)

> 브라우저에서 팝업이 차단되어 있으면 별도 창을 열 수 없습니다.
> 이때는 기존처럼 화면 안쪽 대화상자로 표시되며 기능은 동일합니다.
> 이 사이트의 팝업을 허용하면 별도 창으로 열립니다.

## 13. 자주 묻는 질문

### Q. DBToolsWinV10에서 만든 `.mdprj` 파일을 열 수 있나요?

네. 파일 형식이 동일하며, 원본이 저장한 UTF-8 BOM도 처리합니다.
반대로 이 앱이 저장한 파일도 DBToolsWinV10에서 열 수 있습니다.

### Q. 내보낸 SQL의 외래 키 방향이 원본과 다릅니다.

원본은 제약을 **부모 테이블**에 선언하고 자식을 참조하도록 만들어서,
실제 서버에서 실행하면 오류가 납니다(참조되는 컬럼에 UNIQUE 제약이 없음).
이 앱은 표준에 맞게 **자식 테이블**에 제약을 선언하고 부모를 참조합니다.
자세한 내용은 [README.md](README.md)의 "원본 대비 변경 사항" 을 참고하세요.

### Q. Access(.accdb)나 SQL Server(.mdf) 파일을 열 수 없습니다.

두 형식은 Windows 전용 네이티브 드라이버(ACE OLEDB, LocalDB)가 필요해 지원하지 않습니다.
Access에서는 **외부 데이터 → 내보내기**, SSMS에서는 **스크립트 생성** 으로 `.sql` 파일을
만든 뒤 가져오세요. 관계 정보도 함께 보존됩니다.

### Q. AVIF로 내보낼 수 없습니다.

브라우저와 Chromium에는 AVIF **인코더**가 없습니다(디코더만 있습니다).
PNG 또는 WebP를 사용하세요. WebP가 파일 크기와 품질 면에서 AVIF에 가장 근접합니다.

### Q. 웹에서 저장하면 파일이 어디로 가나요?

Chrome·Edge 등 File System Access API를 지원하는 브라우저에서는 저장 위치를 직접
고를 수 있고, 이후 **저장**(Ctrl+S)은 같은 파일에 덮어씁니다.
Firefox·Safari에서는 다운로드 폴더에 저장됩니다.

### Q. 대상 DB를 바꿨는데 컬럼 타입이 그대로입니다.

의도된 동작입니다(원본과 동일). 직접 입력한 타입을 임의로 바꾸지 않기 위해서입니다.
단, **SQLite `.db` 내보내기**는 SQLite가 해석하지 못하는 기본값
(`NOW()`, `GETDATE()` 등)만 등가 표현으로 바꿔 파일 생성이 실패하지 않도록 합니다.

### Q. 관계선 라벨이 테이블에 가려집니다.

이 포팅에서는 관계 이름을 테이블보다 위에 그리므로 가려지지 않습니다.

### Q. `npm start` 가 "Port 5174 is in use" 라고 합니다.

다른 프로그램이 5174 포트를 쓰고 있으면 `npm start` 는 그 포트를 건드리지 않고 다음 빈 포트를
골라 그 주소로 창을 엽니다. 터미널에 실제로 쓴 포트가 표시됩니다.

### Q. 설정과 최근 파일은 어디에 저장되나요?

| 운영체제 | 폴더 |
|----------|------|
| Windows | `%APPDATA%\DBTools` |
| macOS | `~/Library/Application Support/DBTools` |
| Linux | `~/.config/DBTools` |

`settings.json`(설정·사용자 정의 테마), `recent.json`(최근 파일), `window.json`(창 위치·크기)이
있습니다. 이전 Electron 판과 같은 폴더라 설정이 그대로 이어집니다. 웹 판은 브라우저 저장소에 둡니다.

### Q. 인쇄 단추를 눌러도 아무 대화 상자가 뜨지 않습니다.

Windows 데스크톱 판은 인쇄 창에서 고른 프린터로 **대화 상자 없이 바로** 보냅니다. 상태 줄에
"…(으)로 보냈습니다" 가 표시되면 인쇄 작업이 프린터 대기열에 들어간 것입니다.
