# MyWorkspace 사용자 가이드

MyWorkspace는 Notion과 유사하게 **Workspace**와 **Page**를 트리로 관리하고, Markdown으로 문서를 작성·미리보기할 수 있는 Windows 프로그램입니다. 이 문서는 일상적인 사용 방법을 설명합니다.

## 1. 시작하기

### 프로그램 실행

- **MSI 설치 후**: 시작 메뉴 또는 바탕 화면의 **MyWorkspace** 실행
- **개발 빌드**: `dotnet run --project src/MyWorkspace.Win/MyWorkspace.Win.csproj`

### 최초 실행 흐름

1. **MariaDB**가 실행 중이어야 합니다. 기본 연결 정보는 설치 폴더 `appsettings.json`에 있습니다 (`localhost:3306`, DB `myworkspace`, 사용자 `root`).
2. **로그인 화면**이 표시됩니다. 앱 시작 시 위 설정으로 DB에 연결하며, DB가 없으면 자동 생성됩니다.
3. 기본 관리자로 로그인합니다.
   - ID: `admin`
   - 비밀번호: `admin`
4. 다른 DB 서버·종류를 쓰려면 **관리 → DB 연결 설정...** 에서 변경합니다.
5. 로그인 후 **비밀번호 변경**을 권장합니다.

> DB 연결 설정은 **관리자 로그인 후**에만 사용할 수 있습니다. 로그인 화면에서는 DB 설정을 열 수 없습니다.

> 이메일 서버는 설정하지 않아도 앱을 사용할 수 있습니다.

## 2. 화면 구성

```
┌──────────────────────────────────────────────────────────────────┐
│  메뉴 (파일 | Workspace | 관리 | 계정)                           │
├────────────┬───────────────────────────────────────────────────┤
│ Workspace  │  [제목]                                           │
│ 트리       │  [Markdown 툴바]                                  │
│            │  ┌──────────┬──────────────────────────────────┐  │
│ · 즐겨찾기 │  │ 문서구조 │  편집기  │  WebView2 미리보기   │  │
│ · Workspace│  │ (Outline)│          │                      │  │
│   ├ Page   │  └──────────┴──────────────────────────────────┘  │
│   └ 하위 WS│                                                   │
├────────────┴───────────────────────────────────────────────────┤
│  상태 표시줄 (역할, Page 이름, 저장 상태)                        │
└──────────────────────────────────────────────────────────────────┘
```

| 영역 | 설명 |
|------|------|
| **좌측 트리** | Workspace·Page 계층, 즐겨찾기, 드래그 앤 드롭, 트리 연결선 표시 |
| **문서 구조** | `#` 제목( H1~H3 ) 기반 Outline, 클릭 시 해당 위치로 이동 |
| **편집기** | Markdown 원문 입력 |
| **미리보기** | WebView2 실시간 HTML 렌더링 |

좌측 트리·문서 구조 패널 너비는 분할선을 드래그하여 조절할 수 있습니다. 문서 구조 패널은 **구조** 버튼으로 접거나 펼칩니다.

### 파일 메뉴

| 메뉴 | 설명 |
|------|------|
| **Page 저장** | 현재 Page 수동 저장 (Ctrl+S) |
| **Page 버전 이력...** | 선택한 Page의 이전 버전 보기·복원 |
| **트리 새로 고침** | Workspace 트리 다시 로드 |
| **환경 설정...** | 테마(밝게/어둡게), 언어 변경 |
| **프로그램 정보...** | 버전, 저작권 정보 |

## 3. 환경 설정

**파일 → 환경 설정...** 에서 UI 모양을 변경합니다.

| 항목 | 설명 |
|------|------|
| **테마** | **밝게** / **어둡게** — 메뉴, 트리, 편집기, 대화상자에 일괄 적용 |
| **언어** | 한국어 / English |

- 설정은 `%LocalAppData%\MyWorkspaceWinV10\appsettings.local.json`에 저장됩니다.
- 테마 변경은 즉시 반영됩니다. 어두운 테마에서는 Markdown 툴바 아이콘이 자동으로 밝게 보이도록 조정됩니다.
- 일부 열려 있는 대화상자는 다시 열면 테마가 적용됩니다.

## 4. 데이터베이스 설정

### 지원 DB

| DB 종류 | 설명 |
|---------|------|
| MariaDB | 권장 (기본값) |
| MySQL | MariaDB와 동일 드라이버 |
| PostgreSQL | |
| Microsoft SQL Server | |
| SQLite 3 | 단일 파일 DB (로컬·테스트용) |

### 연결 설정 열기

- **관리자 로그인 후**: **관리 → DB 연결 설정...**

> 일반 사용자는 DB 연결 설정 메뉴를 볼 수 없습니다.

### 연결 테스트

- **연결 테스트** 버튼: 서버 접속 및 DB 존재 여부 확인
- DB가 없으면 **자동 생성** 후 "연결 성공 (DB 생성됨)" 메시지 표시
- **저장** 시에도 연결 테스트가 수행됩니다

### 설정 저장 위치

연결 정보(비밀번호 포함)는 다음 파일에 저장됩니다.

```
%LocalAppData%\MyWorkspaceWinV10\appsettings.local.json
```

> DB **접속 계정**(root 등)과 앱 **로그인 계정**(admin 등)은 별개입니다. 앱 사용자는 DB `users` 테이블에서 관리됩니다.

## 6. Workspace와 Page

### 트리 구조

하나의 Workspace 아래에는 **Page**와 **하위 Workspace**가 **같은 레벨(형제)** 로 함께 표시될 수 있습니다.

```
Workspace A
├── Page 1
├── Page 2
├── 하위 Workspace B
│   └── Page 3
└── 하위 Workspace C
```

- Page 아래에는 Page나 Workspace를 만들 수 **없습니다** (Page는 leaf 노드).
- Page가 이미 있는 Workspace에도 **하위 Workspace**를 추가할 수 있습니다.

### Workspace

- **루트 Workspace**: **Workspace → 새 Workspace**
- **하위 Workspace**: Workspace 선택 후 **Workspace → 하위 Workspace 추가** 또는 트리 우클릭
- **이름 변경·삭제**: Workspace 선택 후 메뉴 또는 우클릭
- **이동**: Workspace를 다른 Workspace 위로 **드래그 앤 드롭** (하위로 이동, 자기 자신·하위 Workspace로는 불가)

**삭제 조건**: 하위 Workspace와 Page가 **모두 없어야** 합니다. Page가 남아 있으면 먼저 Page를 삭제하세요.

### Page

- Workspace 선택 후 **Workspace → 새 Page (양식)...** 또는 우클릭 **새 Page (양식)...**
- **빠른 작성**: Workspace를 선택한 뒤 편집기에서 바로 입력하면, 첫 저장 시 **제목 없음** Page가 자동 생성됩니다.
- **이동**: Page를 대상 Workspace로 드래그 앤 드롭

### 트리 우클릭 메뉴

| 항목 | 대상 |
|------|------|
| 하위 Workspace 추가 | Workspace |
| 새 Page (양식)... | Workspace |
| 이름 변경 | Workspace, Page |
| 삭제 | Workspace, Page |
| 즐겨찾기 추가/제거 | 등록된 Workspace |
| 멤버 관리 | Workspace |

## 7. Page 편집

### 편집기

- **제목**과 **Markdown 본문**을 편집합니다.
- **자동 저장**: 입력 후 약 2초 뒤 자동 저장 (상태 표시줄: "수정됨" → "저장됨")
- **수동 저장**: **파일 → Page 저장** (Ctrl+S)

### Workspace에서 바로 편집하기

1. 좌측 트리에서 **Workspace**를 선택합니다 (Page가 아님).
2. 편집기가 비워지고 제목이 **제목 없음**으로 표시됩니다.
3. 제목·본문을 입력하면 첫 저장 시 해당 Workspace에 Page가 생성되고, 트리에서 새 Page가 선택됩니다.

### Markdown 툴바

| 버튼 | 기능 |
|------|------|
| H1, H2, H3 | 제목 삽입 |
| B, I, S | 굵게, 기울임, 취소선 |
| 코드, 블록 | 인라인·블록 코드 |
| 링크, 이미지 | Markdown 링크/이미지 |
| -, 1., > | 목록, 번호 목록, 인용 |
| ---, 표 | 구분선, 표 템플릿 |
| 구조 | 문서 구조 패널 토글 |

### 미리보기

- WebView2로 Markdown을 HTML로 렌더링합니다.
- 커서 위치의 제목과 Outline·미리보기가 연동됩니다.

## 8. 즐겨찾기

자신이 **등록된(소유자 또는 멤버)** Workspace만 즐겨찾기할 수 있습니다.

### 추가 / 제거

1. Workspace를 트리에서 선택
2. 우클릭 → **즐겨찾기 추가** (또는 **즐겨찾기 제거**)

### 표시

- 트리 최상단 **즐겨찾기** 노드 아래에 등록한 Workspace가 표시됩니다.
- 즐겨찾기 Workspace는 **노란색 폴더 아이콘**으로 구분됩니다.
- 즐겨찾기 정보는 DB `workspace_favorites` 테이블에 사용자별로 저장됩니다.

## 9. 멤버 관리

Workspace **Owner** 또는 **Editor** 이상 권한이 있는 사용자가 멤버를 관리할 수 있습니다.

1. Workspace 선택 → **Workspace → 멤버 관리** (또는 우클릭)
2. **멤버 추가**: 사용자 선택, 역할(Viewer / Editor) 지정
3. **멤버 제거**: 목록에서 선택 후 제거 (Owner는 제거 불가)

| 역할 | 권한 |
|------|------|
| **Owner** | Workspace 생성 시 자동 지정, 제거 불가 |
| **Editor** | Page·Workspace 편집, 멤버 관리 |
| **Viewer** | 읽기 전용 |

## 10. Page 버전 이력

Page 내용이 변경될 때마다 이전 버전이 자동 저장됩니다 (Page당 최대 **50**개).

1. Page 선택 후 **파일 → Page 버전 이력...**
2. 목록에서 버전 선택 → 내용 확인
3. **복원**으로 해당 버전으로 되돌립니다

## 11. Page 템플릿

### 새 Page 만들 때

**새 Page (양식)...** 대화상자에서 템플릿을 선택합니다.

- **미리보기**로 내용 확인
- **새로 고침**으로 템플릿 목록 갱신
- **폴더 열기**로 사용자 템플릿 폴더 탐색

### 템플릿 위치

| 종류 | 경로 |
|------|------|
| **내장** | 설치 폴더 `Templates\Pages\` |
| **사용자** | `%LocalAppData%\MyWorkspaceWinV10\Templates\Pages\` |

### 템플릿 파일 형식 (`.mdtemplate`)

YAML front matter + Markdown 본문:

```markdown
---
id: my-template
name: 내 템플릿
description: 설명
order: 10
---
# {title}

본문...
```

- `{title}`: 새 Page 제목으로 치환됩니다.

## 12. 알림 설정 (선택)

이메일 알림은 **완전히 선택 사항**입니다. SMTP 서버 없이도 모든 기능을 사용할 수 있습니다.

### 사용자 — 알림 수신 설정

**계정 → 알림 설정**

| 항목 | 설명 |
|------|------|
| **이메일** | 알림 수신 주소 |
| **Page 생성·수정·삭제 알림** | 해당 Workspace의 Page 변경 |
| **Workspace 변경·멤버 변경 알림** | 이름 변경, 멤버 추가/제거 |

알림을 받으려면 **이메일 주소 등록 + 해당 옵션 체크 + 관리자 SMTP 설정**이 모두 필요합니다.

### 관리자 — 이메일 서버 설정

**관리 → 이메일 서버 설정**

| 항목 | 설명 |
|------|------|
| **이메일 알림 사용** | 체크 해제 시 알림 비활성 (앱 운영에는 영향 없음) |
| **SMTP 서버 / 포트** | 예: `smtp.example.com`, `587` |
| **SSL/TLS** | 대부분의 SMTP에서 사용 |
| **발신 주소** | 수신자에게 표시되는 From |

설정은 `appsettings.local.json`의 `Email` 섹션에 저장됩니다.

### 알림이 발송되는 경우 (예)

- Page 생성·수정·삭제
- Workspace 이름 변경
- Workspace 멤버 추가·제거

변경을 수행한 본인에게는 알림이 가지 않습니다. 이메일 발송 실패 시에도 Page 저장 등 작업은 정상 완료됩니다.

## 15. 자주 묻는 질문

### Q. DB 없이 실행할 수 있나요?

아니요. 앱 시작 시 DB 연결이 필요합니다. **기본값은 MariaDB**이며 `appsettings.json`의 설정으로 연결합니다. SQLite 등 다른 DB를 쓰려면 관리자가 **DB 연결 설정**에서 변경할 수 있습니다.

### Q. Page가 있는 Workspace에 하위 Workspace를 추가할 수 있나요?

**예.** Page와 하위 Workspace는 같은 Workspace 아래 형제로 공존할 수 있습니다. Page **아래**에만 하위 Workspace를 만들 수 없습니다.

### Q. Workspace를 선택했는데 Page가 없어도 바로 글을 쓸 수 있나요?

**예.** Workspace를 선택한 뒤 편집기에 입력하면 **제목 없음** Page가 자동으로 생성됩니다. 템플릿을 쓰려면 **새 Page (양식)...** 메뉴를 사용하세요.

### Q. 기본 admin 비밀번호를 잊었어요.

DB에 직접 접속하여 `users` 테이블의 `password_hash`를 갱신하거나, DB를 초기화 후 다시 시드해야 합니다. 운영 환경에서는 설치 직후 비밀번호 변경을 권장합니다.

### Q. 이메일 알림이 오지 않아요.

다음을 확인하세요.

1. 관리자가 **이메일 알림 사용**을 켰는지
2. SMTP 서버·발신 주소가 올바른지
3. 본인 **알림 설정**에 이메일과 알림 종류가 켜져 있는지
4. 해당 Workspace의 **멤버 또는 Owner**인지

### Q. 즐겨찾기에 Workspace가 안 보여요.

본인이 **Owner 또는 멤버**로 등록된 Workspace만 즐겨찾기할 수 있습니다. 하위 Workspace만 접근 가능한 경우, 상위 Workspace에 직접 등록되어 있지 않으면 즐겨찾기 대상이 아닐 수 있습니다.

### Q. Page가 저장되지 않아요.

Page가 선택되어 있는지, Workspace에 **Editor 이상** 권한이 있는지 확인하세요. 상태 표시줄의 "저장 실패" 메시지를 참고하세요.

### Q. 다른 PC에서도 같은 데이터를 보려면?

동일한 DB 서버(MariaDB 등)를 가리키도록 **DB 연결 설정**을 각 PC에서 동일하게 구성하세요. `appsettings.local.json`은 PC마다 별도입니다.
