# 분석 결과 해석 가이드

CodeFactory가 내놓는 숫자를 **무엇을 고칠지 결정하는 데** 쓰는 방법을 설명합니다.
화면 조작은 [UsersGuide.md](UsersGuide.md)를 보세요.

> 모든 메트릭은 **신호**이지 판결이 아닙니다. 임계값을 넘었다는 것은
> "여기를 한 번 보라"는 뜻이지 "여기가 틀렸다"는 뜻이 아닙니다.

---

## 1. 어디서부터 볼 것인가

1. **분석 Summary → 우선 조치** — 도구가 계산한 순서. 대개 이대로 따르면 됩니다.
2. **코드 건강 점수의 가장 낮은 항목** — 어느 축이 무너져 있는지
3. **Git 핫스팟 ∩ 높은 복잡도** — 자주 바뀌면서 복잡한 파일. 투자 대비 효과가 가장 큽니다.
4. **심각(빨강) 표시** — 임계값의 2배(또는 절반)를 넘은 값

한 번에 모든 경고를 없애려 하지 마세요. 건강 점수를 등급 한 칸 올리는 것을 한 분기 목표로 잡는 편이 현실적입니다.

## 2. 함수 메트릭

### 순환 복잡도 (Cyclomatic) — 기본 임계값 15

함수를 통과하는 독립 실행 경로의 수입니다. `if`, `for`, `while`, `case`, `catch`,
`&&`, `||`, 삼항 연산자마다 1씩 늘어납니다.

- **의미**: 이 함수를 완전히 덮으려면 최소 몇 개의 테스트가 필요한가
- **10 이하**: 편안함 · **15~30**: 분해를 검토 · **30 이상**: 거의 확실히 분해 대상
- **조치**: 조기 반환(guard clause), 분기 덩어리를 함수로 추출, 조회 테이블/다형성으로 `switch` 대체

### 인지 복잡도 (Cognitive) — 기본 임계값 15

순환 복잡도에 **중첩 깊이 가중치**를 더한 값입니다.

```
if (a) { if (b) { if (c) { } } }   ← 인지 복잡도가 훨씬 높다
if (a) { }  if (b) { }  if (c) { } ← 순환 복잡도는 같지만 읽기 쉽다
```

- 순환 복잡도는 같은데 인지 복잡도만 높다면 → **중첩을 펴는 것**만으로 크게 개선됩니다.
- **조치**: 조기 반환, 조건 반전, 중첩된 블록을 이름 있는 함수로 추출

### 중첩 깊이 — 기본 임계값 4

가장 깊은 블록 중첩. 3단계를 넘으면 사람이 문맥을 놓치기 시작합니다.

### 매개변수 수 — 기본 임계값 6

많을수록 호출부에서 인자 순서를 틀리기 쉽습니다.
같은 타입 인자가 연달아 있으면 특히 위험합니다.

- **조치**: 파라미터 객체 도입, 함수 분리, 기본값 활용

### return 수 — 기본 임계값 5

종료 지점이 많으면 정리 코드(리소스 해제, 로깅)를 빠뜨리기 쉽습니다.
단, 조기 반환은 중첩을 줄이므로 **인지 복잡도가 낮다면 문제가 아닙니다.**
두 값을 함께 보세요.

### 매직 넘버 — 기본 임계값 5

`0`, `1`, `-1`을 제외한 숫자 리터럴 개수. 같은 숫자가 여러 곳에 흩어지면
한쪽만 바뀌는 버그가 생깁니다.

### Fan-out — 기본 임계값 10

이 함수가 **직접 호출하는** 함수 수. 높으면 조정자(orchestrator) 역할이 한 곳에 몰린 것입니다.

### Fan-in

이 함수를 **호출하는 곳의 수**. 높다는 것 자체는 좋은 신호(재사용됨)지만,
**변경 파급이 크다**는 뜻이기도 합니다. Fan-in이 높은 함수부터 회귀 테스트를 붙이세요.

> Fan-in/out은 **호출 그래프에 잡힌 호출**만 셉니다. 동적 호출·리플렉션·콜백은 빠집니다.

### 유지보수 지수 MI (0~171) — 기본 임계값 65 미만

줄 수, 순환 복잡도, 인지 복잡도, 매개변수 수를 합성한 값입니다. **높을수록 좋습니다.**

| MI | 뜻 |
|----|-----|
| 85 이상 | 편하게 손댈 수 있음 |
| 65~85 | 보통 |
| 33~65 | 손대기 부담스러움 (경고) |
| 33 미만 | 재작성을 검토 (심각) |

**우선 조치의 1번은 거의 항상 MI가 가장 낮은 함수들**입니다.

### Halstead 볼륨

연산자·피연산자 어휘로 계산한 코드 규모. 절대값보다 **같은 프로젝트 안의 상대 비교**에 쓰세요.

### 문장 수 · switch/case 수

문장 50개 이상이면 함수 하나가 너무 많은 일을 합니다.
case 10개 이상이면 다형성이나 조회 테이블로 대체할 여지가 큽니다.

## 3. 파일 메트릭

### God 파일 — 기본 임계값 800줄

한 파일이 지나치게 많은 책임을 안고 있습니다.

- **조치**: 커밋 이력을 보고 **함께 바뀌는 함수끼리** 묶어 분리하세요.
  이름이 비슷한 것끼리 묶는 것보다 훨씬 효과적입니다.

### 주석 비율 — 기본 임계값 10% 미만

코드 100줄당 주석 줄 수. 낮다고 무조건 나쁘지는 않지만,
**복잡도가 높으면서 주석이 없는 파일**은 확실한 위험 신호입니다.

### TODO 밀도 — 기본 임계값 100줄당 3개

미완성 의도가 쌓인 곳. 오래된 TODO는 대개 영원히 안 고쳐지므로, 이슈로 옮기거나 지우세요.

### public API 수 — 기본 임계값 30

파일이 외부에 노출하는 표면적. 넓을수록 바꾸기 어려워집니다.

### 테스트 코드 비율 — 기본 임계값 10% 미만

파일 경로·이름 규칙(`test/`, `*.test.*`, `*_spec.rb` 등)으로 **근사**한 값입니다.
커버리지 도구를 대체하지 않습니다.

### Git 변경 핫스팟 — 기본 임계값 최근 1년 500줄

`git log --numstat`으로 센 변경 줄 수입니다. **복잡도 열과 함께** 보세요.

| 변경 빈도 | 복잡도 | 판정 |
|-----------|--------|------|
| 높음 | 높음 | **최우선 리팩터링** — 계속 만지는데 계속 어렵다 |
| 높음 | 낮음 | 정상 (활발히 개발 중) |
| 낮음 | 높음 | 당장은 방치 가능 (안 건드리는 코드) |
| 낮음 | 낮음 | 문제 없음 |

## 4. 타입 메트릭

### LCOM — 응집도 부족 — 기본 임계값 0.6

**타입의 메서드 중 자기 필드를 하나도 쓰지 않는 비율**입니다. 0에 가까울수록 응집도가 높습니다.

- 0.6 이상이면 한 타입이 서로 무관한 책임을 겸하고 있을 가능성이 큽니다.
- **조치**: 같은 필드를 쓰는 메서드끼리 묶어 타입을 나누세요.

### DIT — 상속 깊이 — 기본 임계값 5

상속 트리에서의 깊이. 깊으면 어느 조상이 동작을 결정하는지 추적하기 어렵습니다.

- **조치**: 상속 대신 합성(composition)을 검토

### NOC — 자식 수

직계 자식 타입 수. 많으면 이 타입을 바꿀 때 파급이 큽니다.

### WMC — 가중 메서드 수

타입 내 모든 메서드의 순환 복잡도 합. 타입 전체의 "무게"입니다.

### RFC — 응답 집합

이 타입이 호출할 수 있는 메서드의 총수. 테스트 난이도의 지표입니다.

### God 타입 — 기본 임계값 멤버 20개

속성 + 연산의 합. 넘으면 단일 책임 원칙을 다시 보세요.

## 5. 패키지(디렉터리) 메트릭

Robert Martin의 패키지 지표입니다.

| 기호 | 뜻 |
|------|-----|
| **Ca** (구심 결합) | 이 디렉터리에 의존하는 다른 디렉터리 수 |
| **Ce** (원심 결합) | 이 디렉터리가 의존하는 다른 디렉터리 수 |
| **I** (불안정성) | `Ce / (Ca + Ce)` — 0은 안정, 1은 불안정 |
| **A** (추상도) | 인터페이스·추상 타입 비율 |
| **D** (주계열 거리) | `\|A + I − 1\|` — 0에 가까울수록 균형 |

### 어떻게 읽는가

- **I가 높음(≥0.7)**: 남에게 많이 의존 → 외부 변경에 끌려다님.
  UI·앱 진입점이라면 정상. **핵심 도메인 로직이라면 문제**입니다.
- **I는 낮은데 A도 낮음** (D가 큼): 많은 곳이 의존하는데 구체 구현이 노출됨 → **고통스러운 패키지**.
  인터페이스를 앞에 세우세요.
- **I도 높고 A도 높음** (D가 큼): 아무도 안 쓰는 추상화 → **쓸모없는 패키지**. 지울 후보.

### 계층 위반

`ui / view / controller` → `service / domain` → `data / repository / model`
순서를 기대하고, **역방향 호출**(데이터 계층이 UI를 호출)을 찾습니다.

- **조치**: 의존 방향을 뒤집으세요. 하위 계층은 인터페이스만 노출하고,
  상위 계층이 그 구현을 주입받아야 합니다.

## 6. 아키텍처 인사이트

### 순환 호출

호출 그래프의 사이클(자기 재귀 포함). 순환이 있으면 변경 영향 범위를 예측할 수 없고
단위 테스트에서 한쪽만 떼어내기 어렵습니다.

- **조치**: 고리에서 **가장 약한 의존**을 골라 인터페이스·이벤트·콜백으로 뒤집으세요.
- 자기 재귀는 종료 조건만 확인하면 됩니다.

### Fan-out 허브 / Fan-in 허브

- Fan-out 허브 = 지휘자. 단계별 하위 함수로 나누거나 파사드를 도입
- Fan-in 허브 = 기반 함수. 시그니처를 안정화하고 테스트를 먼저 붙이세요

### 고립 함수

호출하지도, 호출되지도 않는 함수. 진입점·이벤트 핸들러·리플렉션 대상·외부 API가 아니라면 삭제 후보입니다.

> 정적 분석이 **동적 호출을 놓친** 것일 수도 있습니다. 지우기 전에 문자열 검색으로 확인하세요.

### 중복 코드

최소 줄 수(기본 10줄) 이상 연속으로 일치하는 블록. 공백·문자열·숫자 리터럴은
정규화 후 비교하므로 포맷만 다른 복사본도 찾습니다.

- **조치**: 가장 긴 그룹부터 공통 함수로 추출
- 중복은 **한쪽만 고쳐지는 버그**의 가장 흔한 원인입니다

### 전역 변수

상수가 아닌 전역을 **두 곳 이상에서 쓰는** 경우가 위험합니다.
경쟁 조건과 재현 불가 버그의 출처입니다.

- **조치**: 소유자를 하나로 정하고, 접근을 함수로 감싸 쓰기 지점을 한 곳으로 모으세요

## 7. 데이터베이스

### 접근 코드가 없는 테이블

두 가지 중 하나입니다.

1. 런타임에 조립되는 SQL로만 접근 → 정상, 도구의 한계
2. 실제로 아무도 안 씀 → 마이그레이션으로 정리

### 쓰기 집중 테이블

5곳 이상에서 변경하는 테이블. 쓰기 경로가 흩어져 있으면 불변식이 깨지기 쉽습니다.

- **조치**: 저장소(repository) 한 곳으로 모으세요

### 컬럼 접근

함수 본문이 실제로 이름을 언급한 컬럼만 기록합니다.
`SELECT *`는 컬럼을 식별할 수 없으므로 테이블 접근만 남습니다.

### CRUD 표기

| 문자 | 검출 대상 |
|------|-----------|
| **C** | `INSERT`, `CREATE TABLE`, EF `Add`, ORM `create`/`save` |
| **R** | `SELECT`, `JOIN`, `Find`/`Where`/`ToList`, ORM `findAll`/`get` |
| **U** | `UPDATE`, `ALTER TABLE`, EF `Update`, ORM `update`/`upsert` |
| **D** | `DELETE`, `DROP`/`TRUNCATE`, EF `Remove`, ORM `destroy`/`delete` |

## 8. 버그 위험

| 분류 | 왜 위험한가 |
|------|-------------|
| **빈 catch** | 예외가 조용히 사라져 원인 추적이 불가능해집니다 (심각) |
| **async void** | 예외가 호출자로 전파되지 않아 프로세스가 비정상 종료됩니다 (심각) |
| **복잡도 + 깊은 중첩** | 두 위험이 겹치면 결함이 숨을 자리가 많아집니다 (심각) |
| **도달 불가 코드** | `return`/`throw` 뒤의 코드 — 의도한 로직이 실행되지 않고 있습니다 |
| **항상 참/거짓 조건** | 디버깅 흔적이거나 조건 실수 |
| **자기 자신과 비교** | `x == x` — 거의 항상 오타 |
| **중복 조건** | `else-if` 체인의 같은 조건 — 뒤쪽 분기가 죽어 있습니다 |
| **조건문 내 대입** | `if (x = y)` — `==`를 의도했을 가능성 |
| **리소스 누수** | `IDisposable`을 `using` 없이 생성 |
| **빈 블록** | 미완성이거나 지우다 만 코드 |
| **미사용 가능 함수** | 호출 그래프에 참조 없음 — 삭제 후보 |

## 9. 정보 보호 및 보안

정규식 휴리스틱이며 **전용 SAST 도구를 대체하지 않습니다.** 오탐이 있을 수 있습니다.

### 심각 — 지금 처리

| 규칙 | 조치 |
|------|------|
| **하드코딩 비밀** | 값 자체를 **폐기·회전**해야 합니다. 코드에서 지우는 것만으로는 끝나지 않습니다 (커밋 이력에 남음) |
| **SQL 문자열 연결** | 파라미터 바인딩(Prepared Statement)으로 교체 |
| **개인 키 리터럴** | 저장소에서 제거 후 즉시 재발급 |
| **eval / exec / pickle** | 동적 실행 제거, `ast.literal_eval`·JSON으로 대체 |
| **shell=True / 명령 실행** | 인자를 배열로 전달, `shell` 옵션 해제 |
| **취약 암호화 (MD5/SHA1/DES)** | SHA-256 이상, 비밀번호는 PBKDF2/bcrypt/Argon2 |
| **인증서·호스트명 검증 우회** | 중간자 공격에 그대로 노출됩니다 |
| **취약 C 함수 (strcpy/gets/sprintf)** | 길이를 받는 안전한 대체 함수로 |
| **BinaryFormatter** | 원격 코드 실행 위험. `System.Text.Json` 등으로 교체 |

### 경고 — 계획에 넣기

`innerHTML`, `dangerouslySetInnerHTML`, `document.write`, `Runtime.exec`,
`os.system`, `unsafe` 블록, 동기 대기(`.Result`/`.Wait()`) 등.

### 정보 — 알고만 있기

평문 HTTP URL, `unwrap`/`expect`, 강제 언래핑, 무시된 오류.

## 10. 코드 건강 점수

8개 축을 가중 평균한 0~100 값입니다.

| 축 | 가중치 | 무엇을 보는가 |
|----|--------|----------------|
| 복잡도 | 3 | 순환 복잡도·중첩이 임계값을 넘은 함수 비율 |
| 유지보수성 | 3 | MI가 임계값 미만인 함수 비율 |
| 보안 | 3 | 보안 smell이 있는 파일 비율 |
| 중복 | 2 | 프로젝트 중복률 |
| 구조 | 2 | 순환 호출 + 계층 위반 |
| 오류 처리 | 2 | 빈 catch + async void |
| 테스트 | 2 | 테스트 코드 비율(근사) |
| 주석 | 1 | 주석 비율이 낮은 파일 비율 |

| 등급 | 점수 |
|------|------|
| A | 90 이상 |
| B | 80 이상 |
| C | 65 이상 |
| D | 50 이상 |
| F | 50 미만 |

**절대 평가가 아닙니다.** 같은 프로젝트를 시간에 따라 비교하거나,
리팩터링 전후를 비교하는 데 쓰세요.

## 11. 임계값 조정

기본값은 널리 쓰이는 관례를 따랐지만, 프로젝트마다 적정선이 다릅니다.

**조정 방법**: 처음 분석한 뒤 경고가 수백 개 나온다면, 그 항목의 임계값을
**현재 분포의 상위 10~20% 지점**으로 올리세요. 그러면 "정말 이상한 것"만 남습니다.
이후 그 값을 조금씩 낮추며 개선해 나가는 편이, 처음부터 이상적인 값을 두고
전부 빨갛게 보는 것보다 실제로 고쳐집니다.

`설정 → 분석 항목`에서 항목별로 바꾸고, `.cfproj` 프로젝트 파일에 저장해 팀과 공유하세요.

## 12. 정적 분석의 한계

| 놓치는 것 | 이유 |
|-----------|------|
| 동적 호출, 리플렉션, DI 컨테이너 | 호출 대상이 런타임에 정해집니다 |
| 매크로, 전처리기, 코드 생성 | 분석 시점에 존재하지 않는 코드입니다 |
| 조건부 컴파일 | 어떤 분기가 실제로 빌드되는지 알 수 없습니다 |
| 런타임 조립 SQL | 문자열이 완성되지 않은 상태입니다 |
| 크로스 언어 호출 (FFI, RPC) | 언어 경계를 넘는 이름 해석이 불가능합니다 |

**이름이 같은 함수가 여러 파일에 있을 때**는 같은 파일 → 같은 디렉터리 →
같은 언어 순으로 우선해 연결합니다. 오버로드가 많은 코드베이스에서는
호출 관계가 실제와 다를 수 있습니다.
