# DBTools 사용자 가이드

DBTools는 ER 다이어그램 및 데이터베이스 스키마 설계 프로그램입니다.
**웹 브라우저, Windows, macOS, Linux** 에서 동일하게 동작합니다.

## 1. 시작하기

### 웹에서 사용

`npm run build:web` 으로 만든 `dist/` 폴더를 정적 호스팅하거나,
개발 중에는 `npm run web` 후 <http://127.0.0.1:5174> 에 접속합니다.
설치가 필요 없고 파일은 브라우저의 파일 선택 대화상자로 열고 저장합니다.

### 데스크톱에서 사용

- **설치본**: 시작 메뉴·바탕 화면의 **DBTools** 실행. `.mdprj` 파일을 더블클릭해도 열립니다.
- **개발 실행**: `npm start`

### 설치 파일 만들기

```bash
npm run build:win      # Windows — DBTools Setup 1.0.0.exe
npm run build:mac      # macOS   — DBTools-1.0.0.dmg
npm run build:linux    # Linux   — DBTools-1.0.0.AppImage, .deb
```

빌드가 끝나면 설치 파일이 **프로젝트 루트에 복사**되어 바로 찾을 수 있습니다
(원본은 `release/` 폴더에도 남아 있습니다).

Windows 설치 파일은 설치 중에 바탕 화면·시작 메뉴 바로 가기 생성 여부를 고를 수 있고,
`.mdprj` 확장자를 DBTools와 연결하며, 제거할 때 작업 데이터 삭제 여부를 묻습니다.

### 새 프로젝트

**파일 → 새로 만들기** (Ctrl+N). 빈 스키마가 열리며, 기본 대상 DB는 설정에서 정한 값
(초기값 SQLite)입니다.

## 2. 화면 구성

```
┌──────────────────────────────────────────────────────────────────────┐
│  메뉴 (파일 | 편집 | 보기 | 분석 | 도움말)                             │
├──────────────────────────────────────────────────────────────────────┤
│  툴바                                                                 │
├──────────┬───────────────────────────────────────┬───────────────────┤
│  도구    │         ER 다이어그램 캔버스           │  구조 / 정규화 /  │
│  패널    │         (눈금자 · 테이블 · 관계선)     │  인덱스 어드바이저 │
│          │                                       │───────────────────│
│          │                                       │  속성 패널        │
├──────────┴───────────────────────────────────────┴───────────────────┤
│  상태 표시줄                                                          │
└──────────────────────────────────────────────────────────────────────┘
```

### 좌측 도구 패널

| 도구 | 설명 |
|------|------|
| 선택 | 테이블·관계 선택 및 이동 |
| 테이블 | 캔버스를 클릭해 새 테이블 배치 |
| 1:1 / 1:N / N:M | 관계 유형을 고른 뒤 테이블에서 테이블로 드래그 |
| 확대 / 축소 / 화면 맞춤 | 캔버스 뷰 조절 |

### 우측 패널

- **구조** — 스키마 트리(테이블·컬럼·관계). 상단 검색창으로 이름 필터
- **정규화** — 1NF~5NF 검사 결과. 검사할 수준을 칩 버튼으로 선택
- **인덱스 어드바이저** — 컬럼별 인덱스 제안과 `CREATE INDEX` 문
- **속성** — 선택 항목의 속성. 상단에서 **분류별** / **사전순** 정렬 전환

우측 패널은 **보기 → 우측 패널 접기/펼치기** 또는 툴바 버튼으로 숨길 수 있습니다.

## 3. 프로젝트 관리

### 프로젝트 파일 (.mdprj)

JSON 형식(UTF-8)이며 스키마 이름, 대상 DB, 테이블·컬럼·관계, 다이어그램 레이아웃을 담습니다.
**DBToolsWinV10이 만든 `.mdprj` 파일과 완전히 호환**되므로 양쪽에서 같은 파일을 열 수 있습니다.

| 동작 | 단축키 |
|------|--------|
| 프로젝트 열기 | Ctrl+O |
| 저장 | Ctrl+S |
| 다른 이름으로 저장 | Ctrl+Shift+S |

변경 사항이 있으면 제목 표시줄과 상태 표시줄에 `●` 표시가 나타나며,
새 프로젝트·다른 파일 열기·종료 시 저장 여부를 묻습니다.
실제로 내용이 바뀐 경우에만 확인 대화상자가 뜹니다.

### 최근 파일

**파일 → 최근 파일**. 데스크톱 앱 전용이며, 웹에서는 브라우저가 절대 경로에 접근할 수 없어
지원하지 않습니다. 보관 개수는 설정에서 바꿀 수 있습니다(기본 10개).

## 4. DB 파일 가져오기

**파일 → 데이터베이스 가져오기** (Ctrl+Shift+O)

| 형식 | 확장자 | 비고 |
|------|--------|------|
| SQLite | `.db`, `.sqlite`, `.sqlite3`, `.db3` | 테이블·컬럼·PK·UNIQUE·외래 키를 읽습니다 |
| SQL DDL | `.sql` | `CREATE TABLE` / `ALTER TABLE ... FOREIGN KEY` 파싱 |
| Vector Index | `.faiss`, `.findex`, `.hnsw`, `.index` | Faiss · hnswlib 인덱스 메타데이터 |
| 프로젝트 | `.mdprj`, `.json` | DBTools 프로젝트 파일 |

가져온 스키마는 자동 배치되며, `.mdprj` 로 저장하기 전까지 프로젝트 파일과 연결되지 않습니다.

> **지원하지 않는 형식** — Access(`.mdb`/`.accdb`)와 SQL Server(`.mdf`)는 Windows 전용
> 네이티브 드라이버가 필요해 지원하지 않습니다. 해당 도구에서 `.sql` 로 스크립트를
> 내보낸 뒤 가져오세요. 암호화된 SQLite(SQLCipher)도 지원하지 않습니다.
> 이런 파일을 열면 원인과 대안을 설명하는 안내가 표시됩니다.

## 5. 스키마 편집

### 테이블 추가

| 방법 | 설명 |
|------|------|
| **편집 → 테이블 추가** (Ctrl+T) | 기존 테이블 오른쪽에 배치 |
| 좌측 **테이블** 도구 → 캔버스 클릭 | 클릭 위치에 배치 |
| 캔버스 빈 곳 우클릭 → **여기에 새 테이블 추가** | 클릭 위치에 배치 |

새 테이블에는 자동 증가 PK `id` 컬럼이 하나 만들어집니다.

### 컬럼 추가 / 편집

- 테이블 선택 후 **편집 → 컬럼 추가** (Ctrl+L)
- 테이블 더블클릭 → 테이블 편집 대화상자에서 **추가 / 편집 / 삭제 / 위·아래 이동**
- 캔버스에서 컬럼 행을 더블클릭하면 바로 해당 컬럼 편집
- 우측 **속성** 패널에서 직접 편집

컬럼 속성: 이름, 데이터 타입, 길이, 정밀도, 스케일, PK, 자동 증가, NULL 허용, UNIQUE,
외래 키, 기본값, 설명. 길이·정밀도 입력란은 선택한 타입에 해당할 때만 표시됩니다.

### 관계 추가

1. 좌측에서 **1:1**, **1:N**, **N:M** 중 하나를 선택합니다.
2. **부모 테이블에서 자식 테이블로** 드래그합니다.

부모의 기본 키와, 자식에서 `<부모이름>_id` 형태로 추정되는 컬럼이 자동 연결됩니다.
정확한 컬럼을 지정하려면 **편집 → 관계 추가** (Ctrl+R) 또는 관계선 더블클릭으로
대화상자를 사용하세요.

> 관계에서 **소스**는 참조되는 쪽(부모, PK), **타겟**은 외래 키를 가진 쪽(자식)입니다.
> 캔버스의 `FK` 배지는 자식 컬럼에 표시되고, 생성되는 DDL도 자식 테이블에
> `ALTER TABLE <자식> ADD CONSTRAINT ... REFERENCES <부모>` 형태로 만들어집니다.

### 관계선 스타일

**직선**, **곡선(Bezier)**, **꺾은선(직교)** 을 지원합니다.

| 방법 | 설명 |
|------|------|
| 툴바 **선 스타일** 드롭다운 | 선택한 관계(그리고 이후 새 관계)의 스타일 변경 |
| 관계선 우클릭 → **선 스타일** | 해당 관계만 변경 |
| 관계선 더블클릭 | 관계 편집 대화상자 |

- **곡선**: 관계를 선택하면 파란색·초록색 마름모 제어점이 나타나며 드래그로 곡률을 조절합니다.
- **꺾은선**: 노란색 사각형 핸들(구간 중점)을 드래그해 경로를 옮깁니다.
  우클릭 메뉴의 **꺾임 점 추가** / **경로 초기화** 를 사용할 수 있고,
  테이블을 옮기는 동안 경로가 실시간으로 다시 계산됩니다.

### 캔버스 조작

| 동작 | 방법 |
|------|------|
| 테이블 이동 | 선택 도구로 드래그 |
| 캔버스 이동(팬) | 빈 영역 드래그, 가운데 버튼 드래그, 또는 Space+드래그 |
| 확대/축소 | 마우스 휠(커서 위치 기준), 툴바 버튼, Ctrl + `+`/`-` |
| 가로 스크롤 | Shift+휠 |
| 전체 맞춤 | Ctrl+0 |
| 배율 100% 복원 | 툴바의 배율(%) 버튼 클릭 |
| 선택 도구로 복귀 | Esc |

**보기 → 자동 배치** 로 모든 테이블을 격자로 다시 배열하고,
**테이블 너비 맞춤** 으로 컬럼 내용에 맞게 폭을 조정할 수 있습니다.
**격자 표시** 와 **격자에 맞추기** 는 보기 메뉴 또는 설정에서 켤 수 있습니다.

### 삭제 / 실행 취소

- **편집 → 선택 항목 삭제** (Delete). 테이블·컬럼 삭제 시 확인을 거치며,
  관련된 관계도 함께 정리됩니다.
- **실행 취소 / 다시 실행** (Ctrl+Z / Ctrl+Y) — 최대 50단계

## 6. 대상 데이터베이스 종류

툴바 오른쪽의 DB 드롭다운 또는 **보기 → DB 종류** 에서 선택합니다.

| DB | 용도 |
|----|------|
| SQLite | 기본값 |
| PostgreSQL | `SERIAL`, `TIMESTAMPTZ`, `COMMENT ON` 등 |
| MySQL / MariaDB | `AUTO_INCREMENT`, `ENGINE=InnoDB`, 인라인 `COMMENT` |
| SQL Server | `IDENTITY(1,1)`, `[대괄호]` 인용 |
| FAISS (Vector DB) | 벡터 DB 스키마 설계 및 `VECTOR` 타입 |

대상 DB를 바꾸면 컬럼 타입 후보 목록, 테이블 헤더 색, SQL 내보내기 결과가 함께 바뀝니다.

> 대상 DB를 바꿔도 **이미 입력된 컬럼 타입과 기본값은 그대로 유지됩니다**(원본과 동일).
> 예를 들어 PostgreSQL 스키마를 MySQL로 바꾸면 `BIGSERIAL` 이 그대로 남습니다.
> 필요하면 컬럼 타입을 직접 수정하세요.

## 7. 내보내기

**파일 → 내보내기** 또는 툴바 **내보내기** 드롭다운.

### 문서

모든 문서 형식은 **표지(커버 페이지)** 로 시작합니다. 표지에는 스키마 이름, 대상 데이터베이스,
테이블 수, 관계 수, 작성 일시, 프로젝트 파일 경로가 들어갑니다.

| 항목 | 형식 | 내용 | 표지 |
|------|------|------|------|
| Markdown... | `.md` | 스키마 개요, 테이블별 컬럼 표, 관계 목록, 정규화 결과 | 제목 블록 + 구분선 |
| Excel... | `.xlsx` | 요약 · ERD · 테이블 · 관계 · 정규화 시트 | **표지** 시트가 맨 앞 |
| Word... | `.docx` | 위와 같은 내용의 Word 문서 | 표지 다음 페이지 나눔 |
| PDF... | `.pdf` | ERD 이미지를 포함한 보고서 | 표지 전용 페이지 |

**분석 → 분석 보고서 작성** (Ctrl+Shift+R) 으로도 Markdown 보고서를 만들 수 있습니다.

> PDF는 Chromium의 인쇄 기능을 사용합니다. 데스크톱 앱에서는 저장 위치를 물은 뒤 바로
> PDF가 생성되고, 웹에서는 인쇄 대화상자가 열리므로 대상을 **"PDF로 저장"** 으로 선택하세요.

### 이미지 (ER 다이어그램)

테이블과 관계선만 렌더링하며 눈금자·격자는 포함되지 않습니다. 2배 해상도로 저장됩니다.

| 항목 | 형식 | 배경 |
|------|------|------|
| PNG (배경 투명)... | `.png` | 투명 |
| JPEG... | `.jpg` | 흰색 |
| WebP... | `.webp` | 흰색 |
| GIF... | `.gif` | 흰색 |

관계선 경로까지 포함해 영역을 자동 계산하며, 매우 큰 다이어그램은 메모리 보호를 위해
해상도가 자동으로 제한될 수 있습니다.

### 데이터 · SQL

| 항목 | 형식 | 설명 |
|------|------|------|
| JSON 내보내기... | `.json` | 스키마 전체 (`.mdprj` 와 동일 구조) |
| SQL DDL 내보내기... | `.sql` | 현재 대상 DB용 `CREATE TABLE` DDL |
| SQLite DB (.db)... | `.db` | 실제 SQLite 데이터베이스 파일 |
| PostgreSQL / MySQL / MariaDB / SQL Server SQL... | `.sql` | 해당 DB 형식으로 변환한 DDL |

> 웹에서는 브라우저가 File System Access API를 지원하면 저장 위치를 고를 수 있고,
> 지원하지 않으면 다운로드 폴더에 저장됩니다.

## 8. 정규화 분석

우측 **정규화** 탭 또는 **분석 → 정규화 분석 실행** (F5).

검사 수준을 칩 버튼(**1NF · 2NF · 3NF · BCNF · 4NF · 5NF**)으로 개별 선택합니다.
선택은 설정에 저장되며, 스키마를 수정하면 결과가 자동으로 갱신됩니다.

| 수준 | 검사 내용 |
|------|-----------|
| 1NF | 기본 키 없음(오류), 반복 그룹 컬럼(`phone1`, `phone2` …), 원자적이지 않은 타입(JSON/ARRAY) |
| 2NF | 복합 기본 키 — 부분 종속 가능성 |
| 3NF | 비키 속성 간 이행 종속 (`dept_id` → `dept_name`) |
| BCNF | 비슈퍼키 결정자 가능성 |
| 4NF | 독립적인 다중값 속성, 조인 테이블의 관계 외 속성 |
| 5NF | 3개 이상 엔티티를 잇는 복합 키, 조인 종속 가능성 |

결과 항목을 클릭하면 해당 테이블이 선택되고 캔버스가 그 위치로 이동하며,
문제가 된 컬럼이 노란색으로 강조됩니다.
심각도는 **오류(빨강) · 경고(노랑) · 정보(보라)** 로 구분됩니다.

## 9. 인덱스 어드바이저

우측 **인덱스 어드바이저** 탭.

| 구분 | 의미 |
|------|------|
| **이미 인덱싱됨** | PK 또는 UNIQUE — 별도 인덱스 불필요 |
| **필수** | 외래 키 컬럼. JOIN·참조 무결성 검사에 사용되므로 인덱스 권장 |
| **권장** | 이름이 `_id` / `_code` / `_no` 로 끝나는 조회 기준 컬럼 |
| **검토** | 이름이 `_name` / `_date` / `_status` / `_type` 로 끝나는 검색·필터 후보 |

**필수**·**권장** 항목에는 바로 쓸 수 있는 `CREATE INDEX` 문이 함께 표시됩니다.
항목을 클릭하면 해당 컬럼이 선택됩니다.

## 11. 설정

**파일 → 설정** 또는 툴바 톱니바퀴 버튼.

| 그룹 | 항목 |
|------|------|
| 모양 | UI 언어 (한국어 / English), 테마 16종 미리보기 선택 |
| 기본값 | 새 프로젝트의 DB 종류, 기본 관계선 스타일 |
| 캔버스 | 격자 표시, 격자에 맞추기, 격자 간격 (5~100) |
| 정규화 | 검사할 정규형 선택 |
| 파일 | 최근 파일 보관 개수 (1~50) |

언어와 테마는 즉시 적용되며 다시 시작할 필요가 없습니다.

### 테마 (16종)

| 라이트 계열 | 다크 계열 |
|-------------|-----------|
| 라이트 (기본) | 다크 |
| 페이퍼 | 미드나이트 |
| 솔라라이즈드 라이트 | 솔라라이즈드 다크 |
| 노르드 라이트 | 노르드 |
| 로즈 | 드라큘라 |
| 포레스트 | 원 다크 |
| 오션 | 그루브박스 |
| 고대비 라이트 | 고대비 다크 |

선택 방법은 세 가지입니다.

- 툴바의 **테마 분할 버튼** — 버튼 왼쪽(팔레트 아이콘 + 테마 이름)을 누르면 다음 테마로
  차례대로 바뀌고, 오른쪽 **▾** 를 누르면 16종 목록에서 원하는 테마를 바로 고를 수 있습니다.
  팔레트 아이콘은 현재 테마의 강조색으로 칠해지며, 목록에 표시되는 그 테마의 색상 칩과 같은 색입니다.
- **보기 → 테마** 서브메뉴 (각 항목에 색상 칩 표시)
- **설정 → 모양** 의 미리보기 그리드 (4×4, 각 칸에 실제 색상 미리보기)

테마는 UI뿐 아니라 ER 다이어그램 캔버스(테이블 배경·격자·관계선·PK/FK 글자색)에도
함께 적용되며, 이미지로 내보낼 때도 현재 테마가 반영됩니다.

### 대화상자는 별도의 창입니다

테이블 편집·컬럼 편집·관계 편집·설정·정보 등 모든 대화상자는 **독립된 창**으로 열립니다.

- 자체 타이틀바에 아이콘과 제목이 표시되고, 작업 표시줄에도 따로 나타납니다
- 창 크기는 내용에 맞게 자동으로 맞춰지므로 **스크롤바가 생기지 않습니다**
- 필요하면 창 가장자리를 끌어 크기를 바꿀 수 있습니다
- 메인 창과 같은 테마가 적용되며, 테마를 바꾸면 열려 있는 창도 함께 바뀝니다
- **Esc** 또는 창 닫기 버튼으로 닫습니다

> 브라우저에서 팝업이 차단되어 있으면 별도 창을 열 수 없습니다.
> 이때는 기존처럼 화면 안쪽 대화상자로 표시되며 기능은 동일합니다.
> 이 사이트의 팝업을 허용하면 별도 창으로 열립니다.

### 툴바 빠른 전환 버튼

툴바는 항상 한 줄로 표시되며, 버튼이 잘리지 않도록 창 최소 너비가 자동으로 맞춰집니다.
오른쪽 끝의 **설정 · 우측 패널 토글 · 프로그램 정보** 를 제외한 모든 버튼은 왼쪽에 있습니다.

| 버튼 | 동작 |
|------|------|
| 격자 아이콘 | 캔버스 격자 표시/숨김 (켜지면 버튼이 강조됩니다) |
| 자동 배치 아이콘 | 모든 테이블을 격자로 다시 배열하고 화면에 맞춥니다 |
| 테마 (분할 버튼) | 왼쪽을 누르면 다음 테마로 순환, 오른쪽 ▾ 를 누르면 16종 목록에서 직접 선택 |
| 언어 아이콘 | 한국어 ↔ English 전환. 현재 언어에 따라 **가**(한국어) / **A**(English) 아이콘이 표시됩니다 |

## 13. 자주 묻는 질문

### Q. DBToolsWinV10에서 만든 `.mdprj` 파일을 열 수 있나요?

네. 파일 형식이 동일하며, 원본이 저장한 UTF-8 BOM도 처리합니다.
반대로 이 앱이 저장한 파일도 DBToolsWinV10에서 열 수 있습니다.

### Q. 내보낸 SQL의 외래 키 방향이 원본과 다릅니다.

원본은 제약을 **부모 테이블**에 선언하고 자식을 참조하도록 만들어서,
실제 서버에서 실행하면 오류가 납니다(참조되는 컬럼에 UNIQUE 제약이 없음).
이 앱은 표준에 맞게 **자식 테이블**에 제약을 선언하고 부모를 참조합니다.
자세한 내용은 [README.md](README.md)의 "원본 대비 변경 사항" 을 참고하세요.

### Q. Access(.accdb)나 SQL Server(.mdf) 파일을 열 수 없습니다.

두 형식은 Windows 전용 네이티브 드라이버(ACE OLEDB, LocalDB)가 필요해 지원하지 않습니다.
Access에서는 **외부 데이터 → 내보내기**, SSMS에서는 **스크립트 생성** 으로 `.sql` 파일을
만든 뒤 가져오세요. 관계 정보도 함께 보존됩니다.

### Q. AVIF로 내보낼 수 없습니다.

브라우저와 Chromium에는 AVIF **인코더**가 없습니다(디코더만 있습니다).
PNG 또는 WebP를 사용하세요. WebP가 파일 크기와 품질 면에서 AVIF에 가장 근접합니다.

### Q. 웹에서 저장하면 파일이 어디로 가나요?

Chrome·Edge 등 File System Access API를 지원하는 브라우저에서는 저장 위치를 직접
고를 수 있고, 이후 **저장**(Ctrl+S)은 같은 파일에 덮어씁니다.
Firefox·Safari에서는 다운로드 폴더에 저장됩니다.

### Q. 대상 DB를 바꿨는데 컬럼 타입이 그대로입니다.

의도된 동작입니다(원본과 동일). 직접 입력한 타입을 임의로 바꾸지 않기 위해서입니다.
단, **SQLite `.db` 내보내기**는 SQLite가 해석하지 못하는 기본값
(`NOW()`, `GETDATE()` 등)만 등가 표현으로 바꿔 파일 생성이 실패하지 않도록 합니다.

### Q. 관계선 라벨이 테이블에 가려집니다.

이 포팅에서는 관계 이름을 테이블보다 위에 그리므로 가려지지 않습니다.

### Q. `npm start` 를 했는데 창이 비어 있습니다.

이 문제는 해결되었습니다. 원인은 두 가지였습니다.

1. **`sql.js` 가 개발 모드에서 로드되지 않음** — `sql.js` 는 CommonJS/UMD 모듈이라
   Vite가 미리 번들해야 `import ... from 'sql.js'` 가 동작합니다.
   `optimizeDeps` 설정 때문에 제외되어 있어 개발 서버에서만 모듈 오류가 났고,
   React가 마운트되지 못해 빈 화면이 됐습니다. (프로덕션 빌드는 정상이었습니다.)
2. **`localhost` 의 IPv4/IPv6 모호성** — Vite가 IPv6(`::1`)에만 바인딩되는데
   Chromium이 IPv4(`127.0.0.1`)로 접속을 시도해 연결이 거부되었습니다.

이제 개발 서버 주소를 `http://127.0.0.1:5174` 로 고정했고, 화면을 불러오지 못하면
빈 창 대신 원인을 설명하는 오류 화면이 표시됩니다.

여전히 빈 화면이 보인다면 터미널 출력을 확인하세요. `[dbtools] loading dev server ...`
또는 `[dbtools] failed to load ...` 메시지가 원인을 알려줍니다.

### Q. `npm start` 가 `Cannot read properties of undefined (reading 'isPackaged')` 로 죽습니다.

셸에 `ELECTRON_RUN_AS_NODE=1` 환경 변수가 설정되어 있으면 Electron 바이너리가
일반 Node처럼 동작해 창이 열리지 않습니다. `scripts/start-electron.mjs` 런처가
이 변수를 제거한 뒤 Electron을 실행하므로 `npm start` 는 영향을 받지 않습니다.
